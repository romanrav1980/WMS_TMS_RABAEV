# Автоматическая локальная установка retailcase

Установщик предназначен для локального стенда на Windows x64. Он загружает Oracle XE 21c непосредственно с сайта Oracle и устанавливает API, административный интерфейс и терминал. На компьютере с существующей Oracle используйте отдельный режим подключения.

## Быстрый запуск

1. [Скачать ZIP](https://github.com/romanrav1980/WMS_TMS_RABAEV/archive/refs/tags/retailcase-2026.10.14-installer.zip) и распаковать в постоянную папку, например `C:\retail_case`.
2. Запустить `INSTALL-RETAIL-CASE.cmd` **от имени администратора** под своей обычной учётной записью Windows.
3. Ввести и повторить пароль пользователя `admin`: 12–50 печатных ASCII-символов: английские буквы, цифры и знаки без пробелов. Это соответствует текущему Basic Auth в локальных интерфейсах.
4. Дождаться завершения. Откроется `http://127.0.0.1:3000`.

Все остальные пароли создаются установщиком. В дальнейшем запускайте `START-RETAIL-CASE.cmd` под той же учётной записью Windows. `STOP-RETAIL-CASE.cmd` останавливает только процессы приложения, созданные этим запускателем; Oracle и данные сохраняются.

## Что устанавливается

| Компонент | Способ |
|---|---|
| Python 3.13 | Используется установленная версия или пакет `Python.Python.3.13` из Microsoft winget |
| Node.js 22 | Используется установленная версия 22 либо пакет 22.15.0 из winget |
| Oracle XE 21c x64 | Официальный ZIP Oracle, проверка SHA-256, тихая установка через response file |
| Сервис orcl | Создаётся в XEPDB1 для существующих контрактов приложения, запускается при открытии PDB |
| Схема RABAEV | Новая пустая схема, прямые права, актуальный SQL-снимок и минимальные начальные данные |
| API | Собственный Python venv, версии из requirements-release-20261014.txt |
| ARM и терминал | Зависимости через npm ci по package-lock.json |
| Запуск | Локальные процессы на 127.0.0.1, порты 8088 / 3000 / 3010 |

Git, Docker и .NET для этого пути установки не требуются. Oracle не входит в ZIP приложения: примерно 2 ГБ загружаются с официального сервера, лицензия и дистрибутив остаются Oracle.

## Требования к компьютеру

Windows x64, административные права для установки Oracle, Интернет, Microsoft App Installer/winget, минимум 15 ГБ свободного места. Для одновременной работы Oracle и интерфейсов рекомендуется от 8 ГБ RAM. Учтите дополнительный объём для введённых данных.

Официальная документация XE 21c перечисляет Windows 10 Pro/Enterprise/Education и Windows Server 2012 R2/2016/2019. Автоматический скрипт проверяет x64; наличие Windows 11 не означает подтверждённую Oracle сертификацию этого дистрибутива. Для других систем используйте существующую совместимую Oracle и ручную настройку приложения.

[Oracle: загрузка и контрольная сумма](https://www.oracle.com/database/technologies/xe-downloads.html) · [Тихая установка](https://docs.oracle.com/en/database/oracle/oracle-database/21/xeinw/installing-oracle-database-xe.html) · [Требования Oracle](https://docs.oracle.com/en/database/oracle/oracle-database/21/xeinw/requirements.html).

Если winget отсутствует, установите [Microsoft App Installer](https://apps.microsoft.com/detail/9nblggh4nns1), затем повторите запуск. Скрипт не обходит ограничения Windows и не меняет системную ExecutionPolicy; Bypass применяется только к текущему процессу запуска.

## Уже установленная Oracle

Укажите сервис `orcl` целевой БД. Учётная запись SYS должна разрешать SYSDBA-подключение. Схема RABAEV должна отсутствовать: установщик создаст её и задаст сгенерированный пароль. Существующая RABAEV, даже пустая, не переименовывается и её пароль не сбрасывается; для неё есть [ручная инструкция](../db/releases/2026-10-14/README.md).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-retail-case.ps1 `
  -UseExistingOracle -OracleDsn '127.0.0.1:1521/orcl'
```

Введите пароль администратора приложения и пароль SYS целевой Oracle. Переустановка ПО Oracle в этом режиме не выполняется. Не используйте рабочую базу для ознакомительного стенда.

## Дополнительные параметры

Проверка комплекта и вывод плана **без установки, загрузок и подключения к БД**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-retail-case.ps1 -Plan
```

Использовать заранее загруженный официальный ZIP Oracle:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-retail-case.ps1 `
  -OracleArchive 'C:\Downloads\OracleXE213_Win64.zip'
```

Проверка SHA-256 остаётся обязательной. Для установки без немедленного запуска добавьте `-NoStart`. Для запуска без открытия браузера: `scripts/start-retail-case.ps1 -NoBrowser`.

## Конфигурация и запуск

Настройки и состояние находятся в `runtime/install/private`. Каталог доступен текущему пользователю Windows и SYSTEM. Пароли сохранены через Windows DPAPI, не в открытом .env. Response file с паролем Oracle удаляется после завершения или ошибки; служебный журнал Oracle остаётся в защищённой папке.

Приложение использует существующие `serv.bat`, `front.bat` и `terminal.bat`. Запускатель сначала проверяет порты и не останавливает чужие процессы. В локальном ARM используется dev Basic Auth из окружения; это не промышленная модель выдачи клиентского доступа. Для развёртывания в сети требуется отдельная настройка входа и HTTPS.

Административный вход: `admin` с заданным при установке паролем. Созданы GLOBAL_ADMIN, исходный склад1, технические каталоги, пустая начальная точка учёта и активное ядро проводки. Товары, заказы и остатки конкретного склада нужно загрузить и настроить перед операциями.

## Повторный запуск и ошибки

- Если установка завершена, повторный INSTALL запускает приложение, не применяет SQL повторно.
- При ошибке зависимостей или загрузки архива до запуска Oracle можно повторить запуск: зависимости устанавливаются заново при необходимости.
- При ошибке npm после успешной установки схемы повторный INSTALL продолжает установку UI, не меняет Oracle.
- Если остановилась установка Oracle или SQL, скрипт прекращает работу и сохраняет фазу. Oracle DDL фиксируется отдельно от транзакции данных; автоматического удаления частично созданной базы нет. Проверьте `state.json` и защищённые журналы, исправьте конкретную причину. Для повторной чистой установки нужен действительно пустой целевой стенд.
- Входящие сообщения, остатки и журналы в текущей базе не удаляются при запуске/остановке.

DPAPI привязан к пользователю Windows. Для переноса установки на другой компьютер используйте резервную копию БД и новую настройку секретов; копирование secrets.json не переносит доступ.

## Проверка комплекта

Синтаксис PowerShell, план без изменений, контрольные суммы SQL и защитные отказы проверяются отдельно от установки Oracle. Полный прогон на чистой Windows с загрузкой XE, импортом схемы и запуском всех процессов в текущей публикации не выполнялся. Текущая рабочая RABAEV не использовалась как цель установки и не изменялась.
