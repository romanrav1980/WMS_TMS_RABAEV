Шаги приемки

Что делает пользователь

1

Оператор создает волну, добавляет pick plans и нажимает расчет.

2

Оператор запускает волну, система создает hard reservations и доменные задачи.

3

Водитель ричтрака пополняет pick face по задаче REPLENISHMENT.

4

Водитель подает полный паллет со стеллажа через PICKING_MOVE.

5

Комплектовщик закрывает CASE_PICK фактическим количеством коробок.

6

Диспетчер открывает readiness и видит READY или понятные блокеры.

Readiness

Финальная готовность волны

READY Все пополнения, staging и case-pick закрыты, domain sync дошел до `SYNCED`, shortage отсутствует.
BLOCKED Система показывает, что именно мешает закрытию: пополнение, полный паллет, коробочный отбор, sync error или shortage.
GET /api/picking/waves/{pick_wave_id}/readiness summary.open_replenishment_count = 0 summary.open_staging_count = 0 summary.open_case_pick_count = 0 summary.sync_error_count = 0 summary.shortage_count = 0
Контроль качества

Negative и Oracle-проверки

Negative Неверный паллет, неверная ячейка источника, неверная целевая ячейка, повторный staging release, попытка закрытия при `BLOCKED` readiness.
Oracle Нет дублей `RRL_WAREHOUSE_TASK`, нет двойных source reservations, invalid objects = 0, все completed tasks имеют `SYNCED`.
duplicate WHT = 0 source duplicates = 0 SYNCED READY
