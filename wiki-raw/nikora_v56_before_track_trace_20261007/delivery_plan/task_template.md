# Задание модели на одну законченную функцию

Спринт и задача: NSxx.a. Автор, независимый проверяющий и владелец.

1. Требования: постоянные ID и точные ссылки на правила редакции 55.
2. Цель: одно наблюдаемое изменение поведения и границы функции.
3. Исходная реализация: файлы, методы, API и Oracle-объекты, подтверждённые GAP.
4. Разрешённые изменения: список файлов и объектов; совместимость действующих клиентов.
5. Контракт: вход, выход, состояния, права, ключ повтора и транзакционная граница.
6. Данные проверки: конкретный SKU, упаковка, количество, партия, ячейка, волна и рейс; ожидаемые балансы.
7. Приёмка: штатный случай, ошибка, повтор и конкуренция согласно риску; интерфейс и реальное оборудование при необходимости.
8. Установка: миграция, проверка, порядок включения; откат кода не отменяет подтверждённые товарные факты.
9. Результат: patch или файлы, команды и протокол проверки, решение по медленным SQL.
10. Условия остановки: неизвестный контракт, непроверенная схема, невозможность испытания, изменение утверждённого бизнес-правила. Записать причину и передать владельцу.

Сначала независимый проверяющий готовит сценарии из требований, затем автор реализует функцию. На ревью передаются точная версия результата и фактические данные проверки. После изменения результата затронутые проверки повторяются. Продолжительные циклы без результата ограничиваются: после двух неудачных исправлений задача возвращается сильной облачной модели или владельцу с диагностикой.

## Архитектурный договор задания

Указать владельца модуля по config/architecture/nicora-policy.json, публичные зависимости, место окончательного исполнения каждого правила (Python/PLSQL), владельца транзакции и допустимые переходы состояния. Использовать wiki/architecture/nicora_modular_development_contract.md. До приёмки выполнить python scripts/nicora_quality_gate.py; добавление нового долга или повышение baseline/порогов не считается исправлением. При выделении ответственности уменьшить baseline через --tighten-baseline. Приложить фактический отчёт и состояние независимой проверки.
