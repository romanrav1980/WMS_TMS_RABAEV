# NS38. Срочная инвентаризация пустой ячейки

Статус: предложен. Основание: требования редакции 55; уточнение состава после NS02–NS04. Предварительная оценка: 2–4 рабочих дней.

## Законченный результат

Сообщение комплектовщика, подтверждение нуля им по настройке либо задача ближайшему свободному аудитору с правом, красный монитор и расследование по камере.

## Вход и зависимости

[NS31](ns31.md), [NS34](ns34.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [04_storage_replenishment_picking.md](../../nikora_business_processes/04_storage_replenishment_picking.md), [resource_management.md](../../nikora_business_processes/resource_management.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [picking_service.py](../../../../api/wms_api_server/app/services/picking_service.py), [stock_reservation_service.py](../../../../api/wms_api_server/app/services/stock_reservation_service.py); точный список разрешённых файлов устанавливается по GAP.

## Разработка и независимая проверка

Автор: **Claude Code**. Подготовка приёмочных сценариев и независимая проверка: **OpenAI Codex**. Владелец принимает результат. 

## Проверяемое поведение

1. Неполномочный сотрудник не корректирует остаток.
2. Сообщение запускает один инцидент.
3. Приоритет выше обычной работы.
4. Подтверждение нуля и причина записаны отдельно.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.

## Условия приёмки

- Выполнены все конкретные случаи выше, результаты приложены к номеру требования.
- Проверены затронутые штатные сценарии и отсутствие регрессии.
- Oracle-изменения имеют SQL применения и проверки, актуальное описание схемы и проверку установленного стенда; SQLite не заменяет Oracle.
- Для API, SQL и функциональных испытаний разобраны самые долгие запросы и принято решение по каждому существенному отклонению. Для чисто документальной карточки этот пункт не применяется.
- Русские файлы прошли scripts/check-encoding.ps1.
- Рабочий результат показан владельцу; неизвестные ограничения записаны, обязательные условия не скрыты.

## Пакет результата

Изменённые файлы или patch, список требований, команды проверки, сведения о стенде, фактические результаты, SQL-проверки и порядок установки. Тесты и пути evidence определяются до исполнения карточки; план не утверждает, что они уже существуют или пройдены. Облачные и локальные модели не меняют ожидаемый результат ради прохождения проверки.
