# NS40. Малая тара поштучного отбора

Статус: предложен. Основание: требования редакции 55; уточнение состава после NS02–NS04. Предварительная оценка: 2–4 рабочих дней.

## Законченный результат

Отдельный SSCC коробки, точный завершающий вес с тарой и вложение в родительское место.

## Вход и зависимости

[NS36](ns36.md), [NS23](ns23.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [04_storage_replenishment_picking.md](../../nikora_business_processes/04_storage_replenishment_picking.md), [05_quality_release.md](../../nikora_business_processes/05_quality_release.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [picking_service.py](../../../../api/wms_api_server/app/services/picking_service.py), [stock_reservation_service.py](../../../../api/wms_api_server/app/services/stock_reservation_service.py); точный список разрешённых файлов устанавливается по GAP.

## Разработка и независимая проверка

Автор: **Claude Code**. Подготовка приёмочных сценариев и независимая проверка: **OpenAI Codex**. Владелец принимает результат. 

## Проверяемое поведение

1. Каждая малая коробка взвешена.
2. Тара учтена один раз.
3. Исключение родительской паллеты не отменяет контроль коробки.
4. Вес доступен для сравнения магазином.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.

- Проверены затронутые штатные сценарии и отсутствие регрессии.
