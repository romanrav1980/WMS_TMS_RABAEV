# NS19. Слотирование и правила партий

Статус: предложен. Основание: требования редакции 57; уточнение состава после NS02–NS04. Предварительная оценка: 2–4 рабочих дней.

## Законченный результат

Назначенные ячейки и диапазоны SKU, флаг смешения только отбора, административный резерв около 15 процентов, переход старого диапазона в новый.

[NS14](ns14.md), [NS18](ns18.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [14_pickface_replenishment.md](../../nikora_business_processes/14_pickface_replenishment.md), [01_master_data.md](../../nikora_business_processes/01_master_data.md), [03_warehouse_receipt.md](../../nikora_business_processes/03_warehouse_receipt.md), [dynamic_slotting.md](../../nikora_business_processes/dynamic_slotting.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [picking_service.py](../../../../api/wms_api_server/app/services/picking_service.py), [stock_reservation_service.py](../../../../api/wms_api_server/app/services/stock_reservation_service.py); точный список разрешённых файлов устанавливается по GAP.

## Проверяемое поведение

1. По умолчанию разные партии не смешиваются.
2. Разрешение руководителя действует только для SKU.
3. Новый отбор появляется при недостатке старого.
4. Оба диапазона обслуживаются без возврата по аллее.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.

## Условия приёмки

- Выполнены все конкретные случаи выше, результаты приложены к номеру требования.
- Проверены затронутые штатные сценарии и отсутствие регрессии.
- Oracle-изменения имеют SQL применения и проверки, актуальное описание схемы и проверку установленного стенда; SQLite не заменяет Oracle.
- Для API, SQL и функциональных испытаний разобраны самые долгие запросы и принято решение по каждому существенному отклонению. Для чисто документальной карточки этот пункт не применяется.
- Русские файлы прошли scripts/check-encoding.ps1.
- Рабочий результат показан владельцу; неизвестные ограничения записаны, обязательные условия не скрыты.
