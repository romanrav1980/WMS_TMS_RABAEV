# NS16. Обмен справочниками ERP

Статус: предложен. Основание: требования редакции 57; уточнение состава после NS02–NS04. Предварительная оценка: 2–4 рабочих дней.

## Законченный результат

Соответствие кодов, версии данных, проверка полноты и ошибок, рабочий адаптер одного согласованного источника.

## Вход и зависимости

[NS05](ns05.md), [NS09](ns09.md), [NS13](ns13.md), [NS15](ns15.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [01_master_data.md](../../nikora_business_processes/01_master_data.md), [02_store_orders.md](../../nikora_business_processes/02_store_orders.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [oracle_gateway.py](../../../../api/wms_api_server/app/oracle_gateway.py), [db.py](../../../../api/wms_api_server/app/db.py); точный список разрешённых файлов устанавливается по GAP.

## Разработка и независимая проверка

Автор: **Qwen Code (облачная Qwen)**. Подготовка приёмочных сценариев и независимая проверка: **OpenAI Codex**. Владелец принимает результат. Исполнитель допускается после NS05; иначе функцию выполняет Codex или Claude Code. Критические изменения Oracle и товарного баланса проверяет облачный агент.

## Проверяемое поведение

1. Повтор не дублирует SKU и адрес.
2. Неоднозначный код отклонён.
3. Изменения не нарушают выданный состав.
4. Факт принятия подтверждается чтением данных.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.

## Условия приёмки

- Выполнены все конкретные случаи выше, результаты приложены к номеру требования.
- Проверены затронутые штатные сценарии и отсутствие регрессии.
- Oracle-изменения имеют SQL применения и проверки, актуальное описание схемы и проверку установленного стенда; SQLite не заменяет Oracle.
- Для API, SQL и функциональных испытаний разобраны самые долгие запросы и принято решение по каждому существенному отклонению. Для чисто документальной карточки этот пункт не применяется.
- Русские файлы прошли scripts/check-encoding.ps1.
- Рабочий результат показан владельцу; неизвестные ограничения записаны, обязательные условия не скрыты.

## Пакет результата

Изменённые файлы или patch, список требований, команды проверки, сведения о стенде, фактические результаты, SQL-проверки и порядок установки. Тесты и пути evidence определяются до исполнения карточки; план не утверждает, что они уже существуют или пройдены. Облачные и локальные модели не меняют ожидаемый результат ради прохождения проверки.


## Обязательное дополнение маркировки редакция 57

Обмен SKU-профилями и отдельные адаптеры CRPT, ЕГАИС и расширяемой Track & Trace.

[Сквозной процесс маркировки](../../nikora_business_processes/marked_goods.md) и [требования к данным RABAEV](../../../database/nicora_track_trace_requirements.md) обязательны для применимых SKU. Постоянные ID правил назначает NS01; исходные названия не заменяют реестр.

Объём разбивается: NS16.tt-refs — версии SKU-профилей; NS16.tt-crpt — применимый адаптер CRPT; NS16.tt-egais — применимый адаптер ЕГАИС; NS16.tt-other — расширяемый договор другого провайдера. Каждый адаптер имеет отдельные права, тестовые данные, формат, квитанции и независимую проверку. Заглушка даёт только PASS_CONTRACT; отсутствие согласованного внешнего контура — PENDING_EXTERNAL_DATA, не успешная интеграция.

| Сценарий | Исходные данные | Действие | Обязательный результат |
|---|---|---|---|
| NS16-TT01 | Действующая версия профиля SAP | Передать более старую или неполную настройку | Старая версия не перезаписывает новую; неполная обязательность отклонена и имеет владельца |
| NS16-TT02 | Согласованные тестовые контуры CRPT и ЕГАИС | Выполнить отдельные допустимые проверки и получить ответы | Каждый адаптер имеет доказательство своего формата и квитанции; успех одного не принимается за успех другого; mock только PASS_CONTRACT |
| NS16-TT03 | Новый профиль OTHER_TEST по общему договору | Подключить адаптер и провести событие | Складской баланс не переписан, типы и статусы нового профиля изолированы; неизвестная обязательная система блокирует операцию |

Данные: общий синтетический track_trace.json и профиль спринта. Реальные форматы и внешние квитанции проверяются на утверждённых данных оператора; синтетический код не объявляется действительной государственной маркой. Для каждого случая сверяются количество, коды, текущий состав, история и обязательства каждой системы. Состояние дополнения — план; бизнес-проверки ещё не выполнялись. Прежние часы и рассчитанные дни требуют пересчёта после GAP редакции 57.
