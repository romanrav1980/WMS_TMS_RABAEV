# NS44. Выборочная проверка перепикиванием

Статус: предложен. Основание: требования редакции 57; уточнение состава после NS02–NS04. Предварительная оценка: 2–4 рабочих дней.

## Законченный результат

Частота по подскладу, случайный выбор грузового места, обязательная полная проверка при 100 процентах, сохранение назначения при повторе.

## Вход и зависимости

[NS43](ns43.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [05_quality_release.md](../../nikora_business_processes/05_quality_release.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [oracle_gateway.py](../../../../api/wms_api_server/app/oracle_gateway.py), [db.py](../../../../api/wms_api_server/app/db.py); точный список разрешённых файлов устанавливается по GAP.

## Разработка и независимая проверка

Автор: **Claude Code**. Подготовка приёмочных сценариев и независимая проверка: **OpenAI Codex**. Владелец принимает результат. 

## Проверяемое поведение

1. 100 процентов назначает проверку всем местам.
2. Повтор предъявления не снимает назначение.
3. Уменьшение процента не освобождает выбранное место.
4. Проверены ошибки количества и состава.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.

## Условия приёмки

- Выполнены все конкретные случаи выше, результаты приложены к номеру требования.
- Проверены затронутые штатные сценарии и отсутствие регрессии.
- Oracle-изменения имеют SQL применения и проверки, актуальное описание схемы и проверку установленного стенда; SQLite не заменяет Oracle.
- Для API, SQL и функциональных испытаний разобраны самые долгие запросы и принято решение по каждому существенному отклонению. Для чисто документальной карточки этот пункт не применяется.
- Русские файлы прошли scripts/check-encoding.ps1.
- Рабочий результат показан владельцу; неизвестные ограничения записаны, обязательные условия не скрыты.

## Пакет результата

Изменённые файлы или patch, список требований, команды проверки, сведения о стенде, фактические результаты, SQL-проверки и порядок установки. Тесты и пути evidence определяются до исполнения карточки; план не утверждает, что они уже существуют или пройдены. Облачные и локальные модели не меняют ожидаемый результат ради прохождения проверки.


## Обязательное дополнение маркировки редакция 57

Перепикивание сверяет уникальные единицы, а не только одинаковые EAN.

[Сквозной процесс маркировки](../../nikora_business_processes/marked_goods.md) и [требования к данным RABAEV](../../../database/nicora_track_trace_requirements.md) обязательны для применимых SKU. Постоянные ID правил назначает NS01; исходные названия не заменяют реестр.

| Сценарий | Исходные данные | Действие | Обязательный результат |
|---|---|---|---|
| NS44-TT01 | В месте 12 единиц, одна марка чужая, общий вес верен | Выполнить контроль состава | Чужая марка и отсутствующая назначенная единица обнаружены; сверка 12 EAN не считается успешной помарочной проверкой |

Данные: общий синтетический track_trace.json и профиль спринта. Реальные форматы и внешние квитанции проверяются на утверждённых данных оператора; синтетический код не объявляется действительной государственной маркой. Для каждого случая сверяются количество, коды, текущий состав, история и обязательства каждой системы. Состояние дополнения — план; бизнес-проверки ещё не выполнялись. Прежние часы и рассчитанные дни требуют пересчёта после GAP редакции 57.
