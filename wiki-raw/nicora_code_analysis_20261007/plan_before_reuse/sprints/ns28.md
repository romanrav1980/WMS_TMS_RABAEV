# NS28. Пополнение под волну целым поддоном

Статус: предложен. Основание: требования редакции 57; уточнение состава после NS02–NS04. Предварительная оценка: 3–5 рабочих дней.

## Законченный результат

Потребность волны, кратность паллете хранения, свободные слоты, резервный отбор и общий баланс с мини-макс.

[NS27](ns27.md), [NS26](ns26.md). До начала разработки фиксируются требования NK-Pxx-nnn/NK-Mxx-nnn, установленные NS01, версия кода, схема Oracle и исходные данные. Номера правил не придумываются исполнителем заново.

Бизнес-источники: [14_pickface_replenishment.md](../../nikora_business_processes/14_pickface_replenishment.md). Наличие кода в файле не означает соответствие. Исходные точки обследования: [picking_service.py](../../../../api/wms_api_server/app/services/picking_service.py), [stock_reservation_service.py](../../../../api/wms_api_server/app/services/stock_reservation_service.py); точный список разрешённых файлов устанавливается по GAP.

## Проверяемое поведение

1. Волна и мини-макс не подают одно количество дважды.
2. Целая паллета не переполняет адрес.
3. Без подходящего слота выбрана разрешённая резервная зона.
4. Резерв источника не дублируется.

Проверка проводится на API и Oracle; для рабочего места также через интерфейс. Независимый проверяющий заранее задаёт исходные количества и ожидаемые товарные балансы. Для изменяющей состояние команды проверяются права, дубликат, конфликт и прерывание между шагами.
