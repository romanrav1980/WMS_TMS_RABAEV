# NICORA: выбор моделей, времени и бюджета

7 октября 2026 года. Оптимизация относится к выбранной организации проекта и имеющимся подпискам. Превосходство моделей на нашем коде не измерено; допуск и фактическая скорость проверяются первой серией задач.

## Рабочий вариант

| Роль | Инструмент | Зачем |
|---|---|---|
| Ядро, Oracle и сложные команды | Codex / GPT-6.1 Sol, обычная скорость | Основная реализация, уже доступная в заданной подписке |
| Интерфейсы и независимая проверка | Claude Code / Sonnet | Вторая линия и другой проверяющий для работы Codex |
| Проверка работы Claude | Codex / GPT-6.1 Sol | Отдельные ожидаемые результаты и разбор фактического теста |
| Данные, формы и документация | Локальная Qwen2.5-Coder-14B Q4 через Ollama/Aider | Ограниченные задания, проверяемые облачной моделью |
| Резерв подготовки данных | Облачная Qwen через уже доступный аккаунт | Не покупать отдельный обязательный тариф до замера потребления |
| Сложный спор по транзакции или балансу | Claude Opus после Sonnet либо усиленный режим Codex | Только адресное усиление, не постоянная третья линия всех задач |

Фактический ID модели и версия инструмента сохраняются в протоколе. Название CLI не принимается за название модели. Нет обязательного Ultrafast, дорогого API-оркестратора или нового GPU. Локальная модель не проверяет сама своё изменение товарного баланса.

Codex рекомендует современные общие модели для программирования; основной выбор GPT-6.1 Sol соответствует текущей официальной документации. Доступ по аккаунту проверяется перед стартом. [OpenAI: программирование](https://developers.openai.com/api/docs/guides/code-generation), [выбор модели](https://learn.chatgpt.com/docs/models).

Claude Code предоставляет выбор Sonnet и Opus; алиасы и точные версии зависят от провайдера. Выбранный здесь Sonnet — рабочее решение проекта, а не обещание лучшего результата на каждом файле. [Настройка моделей Claude Code](https://code.claude.com/docs/en/model-config).

## Как экономим время

Данные и тесты подготавливаются до готовности кода по закреплённым требованиям. Пока Codex пишет функцию, Claude выполняет независимое изменение либо проверяет предыдущий результат. Каждая подписка имеет одну совокупную ёмкость исполнения: параллельные сессии не считаются бесплатным увеличением лимита.

Все карточки идут по зависимостям, с ограничением ресурсов. В расчёте Codex и Claude имеют по 6 часов циклов в день, локальная линия 4, владелец 2 часа приёмки. Эти ёмкости — допущения для календаря, не измеренные лимиты подписки. Скрипт учитывает одновременно занятые линии и ежедневный час владельца во время пилотов. Проверяющие не принимают работу до окончания предшественников.

Сравнение двух вариантов при одних и тех же функциях и оценках:

| Организация | Плановые рабочие дни | Периоды подписок, грубо | Стоимость двух подписок |
|---|---:|---:|---:|
| Одна последовательная облачная линия, роли авторов и проверяющих сохранены | 93 | 5 | 1 500 долларов |
| Две облачные линии с локальной подготовкой | 60 | 3 | 900 долларов |
| Две линии, активные работы увеличены на 30 процентов | 78 | 4 | 1 200 долларов |

Пилоты по 10 дней сохранены во всех вариантах. Периоды посчитаны как округление вверх рабочих дней / 21.75; реальное выставление счетов зависит от дат подписок и пауз. Электричество, оборудование, внешнее ожидание, API и труд площадки не включены. Это сравнение календарных сценариев, а не результаты реальной разработки.

Из этих вариантов рекомендуется вторая организация с резервом третьего сценария. Быстрая работа может экономить и месяцы подписок. Но если первая неделя покажет, что проверка владельцем или квота ограничивает поток, календарь меняется, а не объявляется автоматически сохранённым.

## Денежный предел

База: существующий OpenAI 200 долларов в месяц и предлагаемый Claude Max 5x 100. Номинально 900 долларов за три периода, с резервом 1 200 за четыре. Новая часть при уже оплачиваемом OpenAI — Claude 300–400 за эти периоды, если Claude ещё не оплачен. Это расходы на инструменты разработки; Oracle production покупает NICORA.

Переход Claude на Max 20x стоит 200 в месяц вместо 100 и добавляет 100 за каждый соответствующий период. Его рассматриваем, если фактическая нехватка квоты блокирует критическую очередь. Больше квоты само по себе не означает ускорение одного ответа или пропорциональное сокращение проекта. [Тарифы Claude](https://support.claude.com/en/articles/11049741-what-is-the-max-plan).

API-вызовы не включены в подписочную базу; оплачиваемую автоматику не запускать без отдельного бюджета. У Codex есть общий бюджет использования и отдельные API-условия. [OpenAI: подписки и использование](https://learn.chatgpt.com/docs/pricing).

Новые GPU не нужны для начала. В NS05 измеряем, действительно ли локальная работа уменьшает время и расходы: считаются принятые решения, повторные исправления, время владельца, OOM и контекст. Если квалификация отрицательная, данные готовит проверяющий в облаке, локальные авторства передаются независимой от проверяющего облачной модели. Основной проект не ждёт покупки GPU.

## Контроль первой недели

Начать со стенда и GAP, параллельно квалифицировать локальную модель. Взять пять реально необходимых представительных изменений. Записывать время по стадиям F — данные, T — тест, C — код, Q — проверка, A — приёмка. Облачные часы, активное время владельца и ожидание оборудования не смешивать.

После пяти приёмок пересчитать оценки каждой группы. Если 30-процентный резерв регулярно исчерпывается или на проверке лежит более двух результатов, сократить параллельную выдачу и устранить причину. Нагрузка миллионов операций принимается только измерением, а не сроком в календаре.
