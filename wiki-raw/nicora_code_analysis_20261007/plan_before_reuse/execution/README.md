# NICORA: исполнимый план разработки моделями

Редакция плана 3, 7 октября 2026 года. Текущие требования — редакция 57; стек принят. Владелец — заказчик и программист. Все карточки имеют статус «план», код и испытания этим документом не объявлены выполненными. План содержит 68 ТЗ и 363 конкретных сценария с исходными данными, действиями и ожидаемыми результатами.

## Порядок работы

Данные готовятся отдельно от реализации. Независимый проверяющий утверждает данные и ожидаемые результаты, пишет проверки по требованию. Затем автор реализует функцию; проверяющий запускает реальные тесты на её точной версии. Владелец принимает результат и установку. Для Oracle и общих контрактов применяется одна очередь изменений; параллельно готовятся независимые функции и тесты в изолированных копиях кода; изменения Oracle выполняются последовательно в RABAEV.

Основная линия — Codex / GPT-6.1 Sol. Вторая — Claude Code / Sonnet. Локальная Qwen готовит фикстуры и два ограниченных результата; облачная Qwen — резерв при уже доступном аккаунте, без обязательной новой подписки. Назначение ролей по задачам: O=39, C=27, L=2 авторств. Сложные проверки могут потребовать Opus после первичного Sonnet-ревью; это исключение, не постоянный режим всех задач.

## Расчёт времени

Каждая карточка имеет отдельные часы данных, проектирования теста, реализации, проверки и участия владельца. Ограничения расчёта: Codex 6 часов циклов в рабочий день, Claude 6, Qwen 4, владелец 2 часа приёмки. Часы моделей — плановая продолжительность циклов, а не измеренное число токенов или гарантированная доступность по подписке. Полная ручная работа с оборудованием и подготовка мастер-данных площадкой учитываются отдельно.

Исторический расчёт редакции 55 давал 60 рабочих дней; для расширенного объёма 57 он не пересчитан и не используется для запуска задач. С увеличением всех активных работ на 30 процентов — 78 дней. Оба сценария сохраняют два наблюдаемых пилота по 10 рабочих дней. Это 12–15.6 рабочих недель по пятидневной неделе, без внешних ожиданий. Указанные часы не измерены на данном проекте; до GAP и первой серии принятых задач календарь является рабочей оценкой.

В расчёте не выдумана доля уже готовых функций. Если GAP подтверждает готовую функцию, её реализация заменяется проверкой и план пересчитывается. Если выявлен отсутствующий контракт, сложная миграция или дефицит оборудования, работа расширяется до исполнения, а задержка показывается отдельно. После первых пяти результатов сверяются запланированные и фактические часы.

## Первый пилот

NS50 — сквозная стендовая репетиция. NS64 начинается после NS50, базовых нормативных затрат NS56 и восстановления NS61, через отдельный допуск PG-D. Полное завершение всех процессов фреша и кросс-дока не требуется для малого сухого scope.

PG-D требует реальные терминалы, принтер и применимые весы, корректные мастер-данные выбранного ассортимента, все сухие отрицательные сценарии, инструкции и 30-минутный прогон на двойном плановом пике пилота. Миллионы операций таким прогоном не объявляются подтверждёнными. До допуска нет живых операций. Пилот работает на зафиксированной версии; дальнейшая разработка идёт отдельно.

Общая NS63 по-прежнему требует NS62 и все расширенные процессы. NS65 требует NS63 и завершённый сухой пилот. Полная приёмка NS67 не сокращена. Лицензию production-Oracle приобретает NICORA перед вводом, а не разработчик.

## Ограничение риска и расходов

Никаких дополнительных GPU или платных API до квалификации и измерения лимитов. Обязательные облачные подписки: заданный OpenAI 200 долларов и предложенный Claude Max 5x 100. При недостатке существующего Claude-плана бюджет уточняется по реальному аккаунту. Локальная квалификация не блокирует основную разработку: при отрицательном результате фикстуры делает проверяющий в облаке, локальные авторства передаются другой облачной модели.

Исходные 175–304 дня больше не используются как текущий календарь. Старые карточки сохранены для истории, действующие подробные ТЗ находятся в этой папке. Отдельный GAP и привязка конкретных URL/SQL объектов к требованиям выполняются NS01–NS04; план не выдаёт проектные команды за уже работающие API.


## Обязательный сквозной учёт маркировки

[Покрытие](../track_trace_coverage.md) и [дополнительные данные](fixtures/track_trace.json) входят в требования каждой применимой товарной операции. У 43 спринтов явные дополнения; 55 новых сценариев обязательны. NS13 создаёт основу данных и профилей; NS16 делится на refs/crpt/egais/other; NS18 требует NS10 и NS16. Наличие заглушки не закрывает внешний адаптер. Синтетические коды не являются действительными национальными марками.

Старые часы, schedule и дни остаются снимком оценки baseline 55; scheduleUseAllowed=false и scheduleRequiresRecalculation=true. До NS04/GAP 57 эти даты не являются разрешённой очередью исполнения. Авторства и статусы готовности не повышены.
