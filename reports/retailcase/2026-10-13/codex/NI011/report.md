# NI01.1 — исправление одного скана при приёмке

14 октября2026. Ведомый Codex.

Переиспользование проверено: `receiving-history.js` уже выводит принятые паллеты с точной ссылкой `warehouse-tasks.html?task_id=...`; `receiving-layout.js` уже предлагает число паллет/свои количества через существующий pallet-plan. Эти функции повторно не создавались. Сквозной реальный B01 ранее подтверждён отчётом43: SAP25240 →2×18EA →размещение1163/1164DONE.

Новый законченный операторский шаг: возле каждого кода в форме приёмки появилась кнопка «Убрать этот скан». Удаляется только выбранный профиль одной физической единицы или одна агрегация. Остальные профили/единицы сохраняются. Единица и её количество удаляются из draft только при удалении последнего кода; прежнее введённое количество возвращается в поле для пересканирования. Выбираются соответствующие профиль/способ/номер единицы, фокус возвращается сканеру. Количество всей паллеты автоматически не меняется. Состав агрегации не выводится предположительно.

Коды выводятся textContent, даже строка с HTML остаётся текстом. Старый обработчик кнопки не может удалить новый объект после смены формы. Во время команды, при повреждённом intent или pending того же operation_id/идентификатора паллеты удаление, добавление и полная очистка блокируются. Исходный запрос остаётся неизменным. Серверный приёмочный writer, маркировка из WMS-карточки, требования SAP-основания не изменены.

Файлы: receiving.js — небольшая интеграция/guard; новый receiving-scan-list.js — renderer; receiving.html — подключение helper. Backend/DDL отсутствуют.
