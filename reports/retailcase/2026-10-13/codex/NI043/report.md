# NI04.3 — принадлежность и восстановление сканов задания

14 октября2026, ведомый Codex. Изменён только `wiki-raw/wms_admin_ui_reference/warehouse-task-scans.js`; backend контракт сохранён.

Панель общая для admin и ТСД ричтрака. Исправлены реальные пробелы:

- Ответ GET/POST применяется только к захваченным API base + actor + task_id + generation. После смены пользователя очищаются сканы формы, профиль и подтверждённый draft. Старый ответ не очищает busy новой операции и не показывает старую ошибку.
- `draftId` заново проверяет пользователя/задачу/права даже без события выбора. Для ТСД дополнительно наблюдается существующий DOM идентификатора задания. При незавершённом localStorage запросе/ошибке хранилища draftId недоступен.
- Профиль и latest draft проверяются по task_id/actor/draft_id. Серверный набор доступен к проведению только при совпадающих profile_signature/stock_version как в строке, так и в сохранённом request.
- Перед отправкой exact intent записывается с readback; пустой retry не превращается в GET. Повтор использует тот же draft_id и body. Повреждённый intent блокирует отправку, не стирается молча.
- Ответ сохранения сверяется по draft_id. Только точное совпадение ответа и неизменённого локального intent разрешает очистку. Затем снова читаются server context/latest. Устаревший набор не объявляется подтверждённым.
- Смена task/actor не удаляет прежний pending. Backend ранее проверял actor/task и подпись/версию; второй исполнитель товарного эффекта не добавлен.
