## 1. Каталог магазинов: ERP-связи (C-0028)
- **Поиск** — одна строка на ADDR. Код ERP находится через EXISTS; число связей отдельным полем; код отдаётся только при единственной связи.
- **Карточка** — `erp_links` и `erp_link_state` NONE/SINGLE/AMBIGUOUS, произвольной первой связи нет. Календари — одним ограниченным запросом в scope пользователя.
- **LIKE** экранируется символом `!`.
- **Live:** активных дублей `LEGACY_ADDR` — 0. Ограничения, которое гарантировало бы `LEGACY_ADDR = LEGACY_ADDR_KEY`, нет; неоднозначность проверена моделью.

## 3. Профиль магазина (контракт root C-0031 / STORE_PROFILE_TRANSPORT_CONTRACT)

**Пакет миграции** `db/migrations/2026-10-14_ni051_store_profile/` — `001_schema.sql`, `apply.sql` (журнал `RRL_SCHEMA_MIGRATIONS`, ID `2026-10-14-1490-ni051-store-profile`), `verify.sql`, `rollback.sql` (только до первой истории). Не применён.

`RRL_STORE_PROFILE` — текущая версия, ключ `STORE_ADDR`:
- окна приёма: режим `RECEIVING_WINDOW_MODE` UNCONFIGURED/WEEKLY; `TIMEZONE_REGION` обязателен при WEEKLY;
- подсобка: есть ли, вместимость в паллетах и ролл-кейджах, можно ли оставить без получателя (справочно), температурный класс;
- рампа и высота рампы;
- `MAX_VEHICLE_OUTER_HEIGHT_MM` / `MAX_VEHICLE_OUTER_LENGTH_MM` — внешние габариты ТС, строго больше 0, NULL = ограничение не задано;
- способ разгрузки, нужен ли грузчик, примечание о подъезде;
- контактов и кодов доступа нет.

`RRL_STORE_RECEIVING_WINDOW`:
- ISO-день недели 1–7, полуоткрытые интервалы [FROM, TO) в минутах;
- PK по (адрес, день, начало); FK на профиль;
- guard принимает строки только при режиме WEEKLY.

`RRL_STORE_PROFILE_CHANGE` — неизменяемая история: `OPERATION_ID`, `REQUEST_HASH`, запрос и результат, основание.

**Guard-триггеры:**
- запись только в CONFIG с правом `warehouse_settings_edit`;
- адрес обязан быть неудалённым в `RRL_ADDR` — FK не используется, у `RRL_ADDR` нет PK-ограничения;
- удаление профиля и правка истории запрещены.

**API** (`master_data`): `GET` и `PUT /api/master-data/stores/profile`.
- **PUT:**
  - одна транзакция `stock_configuration_transaction`;
  - проверка `expected_version`;
  - повтор того же `operation_id` с теми же данными возвращает прежний результат, с другими — конфликт;
  - часовой пояс проверяется по `V$TIMEZONE_NAMES`;
  - не больше 8 интервалов в день и 56 в неделю, без пересечений; лишнее отклоняется, а не обрезается;
  - окна заменяются целиком в той же версии.
- **Пока таблиц нет:** GET отвечает `installed=false`, PUT — 503 `STORE_PROFILE_NOT_INSTALLED`, без записи.
- **Права:** чтение — любое из прав справочника магазинов; запись — `warehouse_settings_edit`.
- **Правила профиля** вынесены в `domain/store_profile.py`; модульные тесты `tests/retailcase/test_store_profile_domain.py` — 14 passed.

**UI** — новая страница `store-directory.html` с файлами `.js`, `.css`, `store-profile-form.js` и пункт «Магазины» в `admin-nav` (разрешение C-0031):
- поиск, карточка с источниками данных и неоднозначностью ERP;
- профиль: «не задано» или «недельное расписание» с явным часовым поясом; день без интервалов показан как «закрыто»; ночной приём — двумя днями;
- трёхзначные поля «да / нет / не задано»; внешние габариты подписаны явно;
- команда сохраняется до отправки, повтор — тем же телом, ответ сверяется по `operation_id`, адресу и версии + 1; архив повреждённой команды;
- незавершённая команда другого магазина блокирует правку.
