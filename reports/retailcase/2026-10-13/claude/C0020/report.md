# C-0020 — NI06.3: недостача оборотной тары и независимое решение (REJECT)

Исполнитель: Claude Code · 14.10.2026 · dev RABAEV/orcl. Проверка авторская; внешняя и независимая приёмка не заявляются. Проверен только исход REJECT; WRITE_OFF по недостаче в этом прогоне не проводился.

## Нативный контракт (RRL_STOCK_TARE_LOSS)
- **`TARE_LOSS_REPORT`** подаёт держатель с правом `tare_loss_report`:
  - для магазина нужен исходный долг (`source_claim_id`) и количество не больше остатка долга за вычетом открытых заявлений;
  - физический баланс не меняется, количество удерживается (`RRL_TARE_LOSS_PENDING` → `held_quantity`).
- **`TARE_LOSS_DECIDE`** принимает решение:
  - право `tare_writeoff`, и решающий — не автор заявления (`TARE_INDEPENDENT_LOSS_DECISION_REQUIRED`);
  - на одно заявление одно решение;
  - REJECT снимает удержание без списания, WRITE_OFF уменьшает баланс.

## Что сделано
**Реестр недостач** (`wiki-raw/wms_admin_ui_reference/tare-loss.html`, `tare-loss.js`, новый `tare-loss-cases.js`):
- **Переход по ссылке** `?warehouse_id=&claim_id=`: склад выбирается, случай подсвечивается и выбирается в форме решения. Решение автоматически не проводится.
- **Карточки случаев:**
  - тип и состояние, количество, держатель, заявитель, исходный долг или выдача, рейс;
  - решение (исход, кто решил, ID) или «ожидает независимого решения»;
  - кнопка «Принять решение» только выбирает заявление в форме.
- **Автор заявления** видит причину блокировки в карточке и в форме решения; кнопка и проведение заблокированы.
- **Запись намерения** проверяется чтением; при сбое хранилища команда не отправляется. Повреждённая запись блокирует новые команды. Повтор отправляет тот же ID и тело.
- **Успех** засчитывается только при совпадении `operation_id`, статуса и `goods_stock_changed=false`; после успеха реестр перечитывается.
- **Мобильная вёрстка** — классы `tl-page`.

**React-панель тары** (`features/inventory`):
- новый `TareLossCase.tsx` — карточка подтверждённого заявления: склад, держатель, количество, ID и переход в реестр (`VITE_RAW_ADMIN_BASE`; без него — точные склад и ID для поиска);
- `useTare.ts` — отдаёт последний подтверждённый результат;
- `TarePanel.tsx` — показывает карточку;
- `tareResult.ts` — строгая проверка ответа на заявление: количество и отсутствие изменения баланса (native отдаёт `total_tare_changed=null`).

`TareLossForm.tsx` не менялся. Backend, Oracle и общие стили не менялись.
