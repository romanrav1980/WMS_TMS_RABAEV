# 75. retailcase: автоматическая локальная установка и новое имя

## Выполнено

Добавлены INSTALL-RETAIL-CASE.cmd, START-RETAIL-CASE.cmd и STOP-RETAIL-CASE.cmd. Установщик подготавливает Python 3.13, Node.js22, официальный Oracle XE21c, сервис orcl, пустую RABAEV, SQL-снимок, минимальные данные и зависимости UI. Секреты хранятся локально через Windows DPAPI в каталоге с ограниченными правами. Запуск привязан к 127.0.0.1; чужие процессы на занятых портах не останавливаются.

README описывает назначение системы, основной процесс и 14 функциональных модулей. Имя продукта — retailcase. Переименованы текущие каталоги/ссылки и текст; старые Git-коммиты сохраняются. Новая публикация основной ветки выполняется fast-forward.

Переименование browser storage сохраняет исходный запрос и operation_id. Конфликт разных значений либо отказ записи останавливает перенос. В базе косметическая миграция меняет только WAVE_NAME двух minimax-волн; checkpoint хранит ID, склад, статус и предыдущее имя в hex.

## Границы

На действующем стенде не устанавливались новый Oracle или вторая копия базы. Полная репетиция на чистой Windows с XE21c пока не выполнена; в пользовательской инструкции это указано. Автоматический путь ориентирован на локальный dev/ознакомительный стенд, не на промышленный запуск.

SQL-решение: имя волн меняется по ограничению WAVE_NAME в двух строках, без пересчёта запасов, журналов и назначений. Новые индексы ради косметической операции не создаются. Provisioning проверяет словарь до DDL и прекращает работу при существующей RABAEV.

Claude продолжает роль/UI C0049 в coordination/retailcase-claude. Незавершённые proposals и отчёты нового блока исключены из публикации установщика.
