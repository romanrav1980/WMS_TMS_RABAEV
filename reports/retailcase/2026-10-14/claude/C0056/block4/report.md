# C0056 · блок 4 — рабочие места в стиле цифрового двойника

Исполнитель: Claude Code · 15.10.2026. По указанию владельца (C-0072) места построены как операционный двойник:
- в центре — схема РЦ;
- слева — процессы и исключения;
- справа — выбранный объект;
- снизу — лента «план/факт» и ресурсы.

Все данные — живые существующие API, без демо-событий. Replay/WarehouseScene — отдельный режим «3D-модель смены», он явно подписан как модель.

Маршрут в оболочку — `proposals/C0056/integration/03_workspace_entry.patch` (`PlatformEntry`, кнопка «Моё рабочее место», `?page=workspace&workspace=director|dispatcher|picker|driver`). Проверка шла через dev-превью.

## Состав (`features/platform/workspaces/`)

- **WorkplaceHome** — переключатель мест (права не меняет, данные режет сервер), дата, «Обновить», «3D-модель смены».
- **TwinDesk** — общий стол директора и диспетчера:
  - плитки — счётчики объектов из выборки API, не KPI;
  - **SourceStrip** — момент последнего успешного чтения по каждому источнику, ошибка с «показаны данные от …», «текущая» или «архивная» дата; ложного LIVE нет;
  - процессы двух видов: фильтр рейсов на схеме или список объектов этапа справа с переходом к экрану-владельцу;
  - одна выбранная сущность — из сцены, ленты или клавиатуры.
- **DockYardScene** — изометрическая схема РЦ (SVG):
  - ворота — фактические `DOCK` рейсов; машины у ворот, рейсы без ворот — во дворе;
  - цвет — `CONDITION` (Спланирован / Отгружен / Закрыт / другое), подпись — номер машины;
  - доступна с клавиатуры (Tab/Enter), ARIA, title.

  Геометрия здания условная, это подписано.
- **DockGantt** — операции рейсов по машинам из `vehicles/gantt`: план, метка факта, линия «сейчас» только для текущей даты. Время API без пересчёта пояса — подписано.
- **TripCard** — машина, перевозчик, водитель, ворота, груз, готовность, операции план/факт. «Открыть рейс N» → `/?page=transport&task_id=N` (C-0073). «Ганта (без выбора рейса)» — выделение рейса там пока не поддержано.
- **ResourceList** — сессии со статусом ACTIVE: ресурс, техника, зона, задание, последний сигнал.
- **Директор РЦ** — плитки:
  - рейсы по состояниям;
  - рейсы с неготовым грузом;
  - волны (выборка до 100 → «100+»);
  - открытые сессии.

  Процессы: приёмка SAP, волны, комплектация (списки с переходами), срочное восстановление, «груз не готов», «отгружено» (фильтры схемы).
- **Диспетчер** — плитки: рейсы; без ворот / водителя; неготовый груз; «операции с отметкой факта N/M». Опоздание не рассчитывается, пока пояс РЦ не утверждён. Процессы-фильтры: спланированы, без ворот, без водителя, груз не готов, отгружены, закрыты.
- **Комплектовщик (ТСД)** — только своё задание по обеспеченной волне:
  - следующая ячейка крупно, товар и остаток;
  - маршрут по ячейкам, прогресс, остановка с подсказкой «позовите старшего»;
  - «Продолжить сборку» → существующий ТСД сборки, сканы там.
- **Водитель (телефон)** — существующий вход по привязке и отметки (`useDriverWorkspace`):
  - крупно текущая операция с кнопкой «Начать/Завершить»;
  - остановки с окнами;
  - неподтверждённая отметка и её повтор.

Статья `workspaces` опубликована (v2) из `docs/help/authoring/workspaces.md`. У кнопок есть `help_id` и tooltip, «Подробнее» → статья.

## Ограничения и GAP

- Схема здания условная. Реальной топологии ворот и двора в API нет — ворота выводятся из рейсов. Позиций машин нет (`vehicles/positions` пуст).
- Выборки волн, сборки и поставок ограничены 100/200/100 — подписано. Итогов по РЦ API не даёт.
- Выделения рейса в Ганте/старых экранах нет — нужен отдельный контракт root.
- Отметки водителя проверены только на экране входа: тестовых учётных данных водителя в проекте не нашёл.
