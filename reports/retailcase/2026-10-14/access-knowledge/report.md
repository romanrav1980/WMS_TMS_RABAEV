## Реализовано

- Принятое решение в wiki/architecture/retailcase_scoped_access_and_knowledge.md и 8 спринтов в wiki/roadmap/retailcase_access_knowledge_plan.md. Противоречие исторического запрета новых таблиц явно уточнено в legacy_rights_model.
- Типизированные AccessScope/RoleAssignment: обязательные идентификаторы, автор/основание, интервал с timezone, версия и явный snapshot группы. Это контракт, не альтернативный движок авторизации; действующие права не меняет.
- Read-only GET /api/help/articles и /api/help/articles/{article_id}, подключены к существующей auth. Каталог загружается из одного подготовленного docs/help/published.json, ограничен по объёму. API не читает произвольные пути wiki. Видимость фильтруется до поиска/detail/связей; недоступная статья возвращает 404.
- React KnowledgePanel в общей оболочке admin: 3 подготовленные статьи с источниками wiki, поиск, связанные инструкции, локальная ссылка через ?help=article-id, восстановление статьи после reload, F1/Escape, возвращение к рабочему экрану, ошибка и повтор. Текст выводится безопасным React-текстом без raw HTML. Новые кнопки используют help_id, tooltip, связь со статьёй; input и раскрытие источников также объяснены.

## Slow SQL и решение

Перед UI зафиксирован RRL_SQL_SLOW_LOG3975; после — новые3976–3981. Для /api/help/* новых slow-строк нет, содержимое статей читается из памяти. Существующая auth и API-аудит продолжают использовать Oracle. Локальный api_audit/2026-10-14.jsonl содержит реальные GET /api/help/*.

На фоновом экране диспетчера обнаружены /warehouses1753мс/291строка и /transport/drivers1378мс/1861строка. Решение: backlog AK05-PERF01, owner Codex: bounded поиск/страницы справочников и при необходимости короткий cache с ключом effective access revision; перед изменением замер/план/равенство результата. Причина отдельного блока — текущий инкремент не меняет справочники и ещё не имеет нового scoped-фильтра. Вернуться обязательно до приёмки диспетчера AK05; сетевые/большие списки не считать быстрыми по одному замеру.

/tasks784мс/4строки: сохранить ограниченный период, проверить повторный p95 в AK05. /available-sts517–627мс: сохранить серверную пагинацию/ограничение области, замерить в AK05; без нового индекса до плана. Это явное решение по наблюдённым запросам, не заявление о промышленной производительности.
