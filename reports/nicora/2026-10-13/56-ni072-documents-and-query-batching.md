# 56. NI07.2 — документы сверки, короткие обращения и переходы

14.10.2026. RABAEV/orcl, существующий finance API и raw admin UI. Авторская адресная проверка; внешняя приёмка не заявлена.

## Результат

Сверка дня показывает до 20 идентификаторов документов за каждым из 16 текущих backlog-показателей. Складские задания, расхождения магазина и расходы открывают существующее досье. Общее количество остаётся точным; текущий backlog явно отделён от операций выбранного дня. Для производных показателей stock/ERP/регуляторных систем идентификаторы ещё не предоставляются — UI прямо сообщает это.

32 отдельных обращения счётчиков заменены двумя пакетными SQL в прежнем read-only snapshot: 16 daily COUNT и 16 backlog-ветвей. Backlog возвращает COUNT OVER и первые 20 ID. Это ограничение ответа, а не обещание прочитать только 20 строк для точного подсчёта. Исходные условия отбора сохранены в reconciliation_sources.py.

Переходы interwarehouse, supplier-handover и logistics-costs читают warehouse_id. Четыре страницы возвратов уже поддерживали его. Досье магазина принимает настоящий строковый CASE_ID. External-outbox и каталожные селекторы тары не объявлены поддерживающими этот параметр.

Ошибка сети/503 при восстановлении admin-сессии больше не удаляет сохранённые реквизиты: права не выдаются до успешного серверного ответа, доступна кнопка повтора. 401/403 очищают сессию.

## SQL-решение

read1395_reconciliation_sql.py, tmp/result1395.json: V$SQL daily gxsts0jf654t4 — 62.309 мс/1 исполнение/370 buffer gets; backlog 8s8utfxypth89 — 61.585 мс/2 и 37.619 мс/3 по двум дочерним курсорам, соответственно 1000 и 1011 buffer gets суммарно. Это средние измеренных курсоров, не p95 промышленной нагрузки.

Решение: оставить ограниченные ответы и пакетное выполнение, новый индекс для этих запросов не добавлять. При росте времени выше 500 мс исследовать конкретную ветвь и её план; владелец finance. Широкий список СТ остаётся отдельной задачей report53: индекс1381 применяется, но вся история ещё 4–8 секунд.

Новые файлы: reconciliation_documents.py, day-reconciliation-documents.js, store-investigation-link.js. Товарные проводки и транзакционные пакеты не изменялись.
