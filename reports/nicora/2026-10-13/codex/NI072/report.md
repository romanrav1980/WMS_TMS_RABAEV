# NI07.2 — ключи конфликтующих строк запаса

14 октября 2026. Исполнитель: ведомый Codex; ведущий: root Codex.

В сверке дня два показателя `stock_quantity_invariants` и `physical_unit_composition` получают до20 точных ключей UID паллеты + ячейка. Ключ сериализуется JSON-массивом; разделитель в значении не создаёт коллизии. Количества остаются строками Oracle TM9, NULL не превращается в0. UI показывает UID, ячейку, физический остаток, резерв и базовую единицу.

Предикаты существующей сверки вынесены без изменения в общие константы. Выборка документов выполняется только для ненулевых счётчиков, одним дополнительным UNION ALL, в прежней READ ONLY транзакции. Повторного COUNT нет; has_more использует уже вычисленный счётчик. Ограничение20 ограничивает ответ, не гарантирует чтение всего20 исходных строк Oracle. Никакие данные/DDL не изменены.

Досье pallet-composition принимает внешний identifier; UID строки не является гарантированно тем же идентификатором. Поэтому ложной ссылки по UID нет. Экран честно сообщает, что это текущий снимок, а не исторический остаток на конец выбранных суток. Остальные конфликты требуют отдельной выборки по складу; отдельный полный реестр конфликтов пока не создан.

## Проверено

- Реальная Oracle: просмотр до60 складов с остатками не обнаружил ненулевых конфликтов; API9807 возвращает прежние нулевые счётчики. Обе новые SQL-ветви отдельно исполнены на реальном складе9807 и вернули пустые выборки. `result_stock_keys.json`.
- Положительный случай — **синтетический read-only WITH CTE в Oracle**, не изменение таблиц:25 конфликтов каждого вида, возвращаются первые20 в порядке числового UID; has_more=true; точные десятичные строки .3/.4; ключи `["1","CELL:A"]` … `["20","CELL:A"]`. `synthetic_stock_keys.json`.
- Браузер существующей страницы, затем явно помеченный синтетический блок renderer:40 строк,0 выдуманных ссылок,0 записывающих API-запросов,0 JS errors. `stock-keys-synthetic.png`, `browser_stock_keys.json`. Это не доказательство реального ненулевого конфликта в базе.
- Python compileall и node --check PASS. Общий quality gate и encoding выполняет ведущий после интеграции, не выдаются за пройденные здесь.

## SQL

Нативный запрос `6dd5793ktn6nq`:65.384мс,1120 buffer gets,1 исполнение в момент наблюдения. Решение: дополнительный индекс не нужен по этому малому dev-набору; если выборка превысит500мс, finance исследует план конкретной ветви и индексы UID/CELL receipt-unit. Полный production объём и фактический план строк не измерялись. Конкурентных записей не было; сохранена существующая согласованная read-only транзакция.
