# NI04.3 — точная граница внешнего подключения

14.10.2026. Адресное чтение текущего кода, без внешних отправок, Oracle mutations или широких тестов.

## Решение владельца после сверки

Маркировка подключается через интеграционный шлюз, который реализуется отдельно позже. Direct provider/UTM connector сейчас не разрабатывается. Отсутствие шлюза — явно отложенная владельцем область, а не только недостающий сертификат. Внешние входы ниже относятся к будущему контракту шлюза.

## Вывод

Внешний обмен нельзя считать готовым кодом, ожидающим только сертификат. Реализации production RegulatoryAdapter нет. `NICORA_REGULATORY_MODE=REAL` сейчас возвращает DisabledRegulatoryAdapter. Настройка URL или сертификата не подключит отправку. Локальные QR/агрегации/SKU policy/lifecycle и надёжная очередь — отдельные реализованные части NI04.3.

## Реализовано и переиспользуется

- `api/wms_api_server/app/modules/integrations/contracts_regulatory.py`: RegulatoryAdapter.send(event) и типизированный RegulatoryResponse, сведения о подписи/сертификате.
- `.../infrastructure/regulatory_runtime.py`: явный DISABLED, отдельно разрешаемый MOCK; никакого неявного успешного симулятора. Factory единственный штатный выбор адаптера.
- `app/services/outbox_service.py`: disabled до claim, существующая доставка/журнал/сохранение результата и восстановление. `.../infrastructure/outbox_delivery.py`: claim с поколением/lease, begin_attempt до отправки, finish_attempt атомарно; сетевой вызов вне Oracle locks. В событии есть target_system, event_type, correlation_id, idempotency_key, payload_json.
- `app/workers/outbox_worker.py`: существующий worker с фильтром target-system, bounded batch/loop; NOT_CONFIGURED не исчерпывает попытки. Использовать его, не создавать вторую очередь или worker.
- GET `/api/integrations/regulatory/runtime`, право external_outbox_view: существующая честная диагностика сервера. Она не подтверждает конфигурацию отдельно запущенного worker.
- Adapter journal хранит request/response/external IDs и безопасные cert alias/thumbprint/signature_status. Секреты не выводятся.

## Отсутствующий обязательный код

1. Provider-specific connector: transport/auth/signature и mapping фактических событий WMS в согласованный формат внешнего API или корпоративного шлюза. В текущем app найдены только DisabledRegulatoryAdapter и MockRegulatoryAdapter; HTTP/SOAP/UTM отправителя нет.
2. Штатная конфигурация/выбор production connector по целевой системе вместо REAL→DISABLED; проверка обязательных настроек до claim. Названия переменных URL/secret пока не определены — не придумывать фиктивные настройки.
3. Разбор настоящего бизнес-ответа, проверка его подлинности и корреляции с операцией, обработка отложенной квитанции по согласованному протоколу. HTTP200/DONE не является государственным ACK.
4. Read projection доказательства ACK после реализации проверки: `.../domain/adapter_evidence.py` сейчас всегда выдаёт external_ack_verified=false и NOT_VERIFIED для не-MOCK. Просто выставить флаг по ответу транспортного слоя нельзя.

Это один интеграционный блок поверх существующей очереди. Нет оснований переписывать локальные сканы, stock root или lifecycle. Универсальный HTTP sender без согласованного контракта не реализован намеренно: невозможно корректно определить формат, подпись, корреляцию и повтор после неопределённого результата.

## Минимальные внешние входы для реализации

| Вход | Что требуется от владельца интеграции |
|---|---|
| Реальный маршрут | Для каждой используемой системы: прямое подключение или корпоративный шлюз/UTM; кто подписывает и кто проверяет квитанцию |
| Контракт | Версия API/WSDL/OpenAPI/файлового протокола, обязательные операции и пример обезличенных request/response/отказа/отложенной квитанции |
| Подключение | Адрес тестового endpoint, доступ с worker-host, proxy/TLS trust; production endpoint отдельно |
| Идентификация | Идентификаторы участника/площадки/организации, применимые товарные группы, разрешения технического аккаунта |
| Подпись и секреты | Способ auth/signing; ссылка на локальный secret store/контейнер и безопасный alias/thumbprint, срок действия; приватные ключи/пароли не передавать в чат |
| Повтор | Область idempotency key, поиск результата по correlation/external ID, timeout/retry/error mapping, лимиты; кто отвечает за polling/callback |
| Приёмка | Владелец тестовой площадки, разрешённые тестовые идентификаторы и один реальный цикл с подтверждённой квитанцией и отказом |

Для ЕГАИС требуется отдельно подтвердить фактический UTM/шлюз и его контракт; для Mercury/CRPT также нельзя считать единым вымышленным протоколом. Список выше — входы для проектной интеграции, не утверждение о текущих публичных государственных спецификациях.

## Готовность / следующая работа

Локальный NI04.3 функционал и доставка с восстановлением переиспользуются. Production connector и доказательство внешнего ACK остаются **отсутствующим кодом, зависящим от контракта**, а доступ/сертификаты/реальная квитанция — внешними условиями. До получения минимального маршрута/контракта нет подтверждённого дополнительного локального исправления; новая диагностика дублировала бы существующий runtime.

SQL не выполнялся: эта работа — сверка адаптеров, без нового бизнес-сценария и изменений выборок. Массовые проверки не запускались. Root обновляет общий план/index/log; runtime файлы не изменены.

## Локальное исправление диагностики — RELEASE

По результату сверки исправлен silent fallback REAL→DISABLED. Совместимые mode=DISABLED и worker status=NOT_CONFIGURED сохранены; добавлены reason_code, next_action, requested_mode_supported, implementation_available. REAL явно сообщает PRODUCTION_CONNECTOR_NOT_IMPLEMENTED и действие «Настроить интеграционный шлюз после его реализации». Неизвестный режим сообщает UNSUPPORTED_MODE; неразрешённый MOCK — MOCK_NOT_ALLOWED. Worker получает ту же причину, UI показывает код и безопасный текст через textContent. Никаких адресов/секретов не публикуется.

Изменены runtime.py, services/outbox_service.py и existing external-outbox.js. Проверка scripts/ni043_connection_diagnostics_case.py: пять режимов PASS, REAL не вызывает claim/send, без Oracle/сети; JS syntax PASS. Evidence connection_diagnostics.json. Это адресная проверка конфигурации, а не симуляция государственного ACK. Общий gate и live server restart выполняет ведущий.
