# NI04.2 — восстановление ввода CASE до проведения

14 октября2026, ведомый Codex. Активный путь использует case-pick-posting.js, который заменяет legacy cpTsdConfirmLine: точные количества, отдельные weighted-box/weigh-line, прежний товарный writer. Legacy Number(fact) не объявлен действующей ошибкой. Готовые алгоритмы/36EA повторно не реализовывались.

Реальный пробел: cpTsdRender/обновление очищали ещё не отправленные QR всех профилей и поля сканирования. Новый case-pick-draft.js сохраняет только ввод формы по API/actor/CASE/line. Существующий casePickIntent остаётся единственным журналом отправленной команды.

После обновления явная кнопка восстанавливает точные строки и управляющий GS-разделитель, если совпали task/SSCC/status/line и возвращённые API настройки профилей. При изменении снимка восстановление блокируется. Архивное показание весов не восстанавливается: требуется новый выбор текущего разрешённого пакета. При pending сначала повторяется команда, форма не заменяет её. Повреждённая запись видима и сохраняется; отдельная кнопка архивирует её с readback. Ошибки записи показываются, сохранение проверяется чтением. Успешная команда очищает только draft revision, захваченный при её создании; запись из другой вкладки с новой revision сохраняется. Никакой автоматической отправки.

Предел контракта: marking-policy возвращает system/profile, но не profile_version/scan_mode. Сигнатура формы отражает именно возвращённый снимок, это не native signature маркировки. Сервер остаётся authority для актуальных правил и физического состава при проведении.
