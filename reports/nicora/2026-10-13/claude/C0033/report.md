# C-0033 — расчётный маршрут сервера в preflight (NI08.1)

Исполнитель: Claude Code · 14.10.2026. Проверка авторская. Новых рейсов и приёмок не было; новых SQL-запросов нет: используется существующий GET.

## Переиспользование
Сервер уже отдаёт native-расчёт `RRL_TT_ROUTE_SCHEDULE` через `GET /api/transport/preflight/trips/{id}/delivery-windows?time_zone=`: статус, остановки (окно, прибытие, начало и конец разгрузки, ожидание, опоздание, строгость, причины), сегменты (дорога, перерыв, ожидание, работы), предупреждения, политика расчёта. Второй расчёт не строился, CONTRACT_REQUEST на чтение не понадобился.

Существующий `TransportDeliveryWindows.tsx` внутри `TransportRouteInput` (файлы root) показывает тот же ответ упрощённо:
- сырые ISO-метки;
- непонятные коды → «Нужно уточнение» без кода;
- нет разницы между строгим и плановым окном, нет источника окна.

Я его не менял — см. предложение ниже.

## Сделано
- **Новые файлы:**
  - `TransportRouteSchedule.tsx` — отображение;
  - `TransportRouteScheduleView.ts` — форма ответа, подписи, тон статуса, время в часовом поясе отчёта;
  - `TransportRouteSchedule.css`.
- **Встраивание:** `TransportTimePreflight.tsx` — блок «Расчётный маршрут сервера» с тем же часовым поясом.
- **Сводка:** статус сервера — неизвестный статус и «недостаточно данных» не показываются зелёными; явный часовой пояс; выезд и возврат; минуты вождения; база; основа и политика расчёта.
- **Остановки:**
  - адрес и СТ, прибытие, разгрузка с нормой, ожидание и опоздание;
  - окна приёма: несколько интервалов не склеиваются через обед (поддержаны будущие поля `windows`, `window_time_zone`);
  - строгость: «строгое — пропуск запрещён» или «плановое — пропуск даёт предупреждение»;
  - источник окна (`ST_MATERIALIZED` или `STORE_WEEKLY`) и версия профиля, если сервер их вернул.
- **Причины:** «Препятствия» (`issues`) и «Предупреждения» (`warnings`) разделены; русский текст и исходный код в деталях; незнакомый код — «Требуется уточнение» плюс код.
- **Лента:** дорога, перерыв водителя, ожидание окна, разгрузка и складские работы с длительностью.
- **Сброс:** смена рейса или пояса сбрасывает результат; старый ответ отбрасывается по счётчику поколений.
- **Подписи о статусе расчёта:** не допуск к выезду; утверждение — отдельным шагом; нормы перерывов — проектные, соответствие законодательству не проверено.
- **Старый ответ** без новых полей отображается без ошибок.

## Коррекция по C-0038 / C-0039 (текущий native-контракт)
- **Источник один** — `GET /delivery-windows`. Второго запроса `time-context` нет (в тесте 0 обращений), гонки снимков нет.
- **Остановка:** показывается одно окно `window_from/to`, выбранное расчётом. Оно уже в поясе отчёта и в пояс магазина не переводится.
- **«Настроенная неделя»** — отдельная справка из `profile_version`, `store_window_mode`, `store_time_zone`, `configured_weekly_windows`:
  - интервалы дня не склеиваются; день без интервалов — «закрыто»;
  - UNCONFIGURED → «окна приёма не заданы»; без версии → «профиль магазина отсутствует».

  Это не разрешение работать за пределами выбранного окна.
- **Старый ответ** без этих полей: справка не показывается, ошибок нет.
- **Источник окна:** добавлен `ST_AND_STORE_WEEKLY` — «окно СТ и расписание магазина». Для `ST_MATERIALIZED` подпись прежняя — «окно СТ».
- **Новые коды native** получили русский текст: STORE_CLOSED, STORE_NO_FEASIBLE_INTERVAL, DELIVERY_WINDOW_UNCONFIGURED/PARTIAL/REVERSED_OR_EMPTY/DISJOINT, STORE_TIMEZONE_REQUIRED, STORE_TIMEZONE_OR_WINDOW_INVALID, STORE_WINDOW_DST_AMBIGUOUS_OR_NONEXISTENT, STORE_WEEKLY_INTERVAL_INVALID, DELIVERY_MEMBERS_MISSING, ROUTE_ARRIVAL_UNKNOWN.
