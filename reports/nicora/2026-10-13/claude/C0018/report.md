# C-0018 — NI02.2: доступные СТ страницами по 200 в диспетчере

Исполнитель: Claude Code · 14.10.2026 · `C:\projects\TMS`. Проверка авторская; независимая и промышленная приёмка не заявляются.

## Было
- `loadAvailableSts` вызывал `/api/admin/transport/available-sts` без `page`/`page_size`.
- Фильтр склада работал только по загруженным строкам; список складов собирался из этих же строк.
- При любой ошибке API подставлялись демоданные (`demoAvailableSts`).
- «Всего СТ» и итоги выдавали загруженное за общее количество.

## Сделано
- **Новые файлы в `features/transport`:**
  - `useAvailableStPages.ts`:
    - страницы по 200 с сервера;
    - «есть ещё» показывается только при полной странице — общего числа сервер не отдаёт, оно не обещается;
    - смена параметров отменяет прошлый запрос (AbortController + счётчик) и загружает страницу 1;
    - `reload` после назначения, WS или автообновления перечитывает то же число уже загруженных страниц, не все;
    - ошибки: 401/403/422/5xx/сеть, без демоданных;
  - `availableStQuery` — все фильтры, включая склад, уходят на сервер;
  - `useVisibleSelection` — выбор живёт только среди видимых СТ; в режиме районов видимыми считаются и СТ из `/clusters`;
  - `useWarehouseCatalog` — существующий `/api/admin/warehouses`; без права на справочник фильтр становится вводом номера склада, список не выдумывается;
  - `StPagesBar.tsx` + `StPages.css` — «Загружено N СТ · страниц P · есть ещё / всё по фильтру», «Загрузить ещё 200», период, ошибка и «Повторить».
- **`TransportDispatchPage.tsx`** (только блок доступных СТ):
  - загрузка через хук, серверный склад, строка страниц;
  - подписи: итоги, «выделить всё», CSV и «несобранные» относятся к загруженным строкам; внизу таблицы «Загружено СТ: N · есть ещё на сервере»;
  - назначение, проверка вместимости и действия не менялись; второй allocator не создан;
  - debounce фильтров прежний; период «Дата СТ» / «Дата до» по-прежнему видим.
- **Legacy-долг уменьшен:** файл 4170 → 4158 строк, функция 2528 → 2516. В `config/architecture/legacy-debt.json` по `--tighten-baseline` изменены только эти две записи.
