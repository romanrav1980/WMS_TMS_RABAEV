# NI07.2 — обзор сверки дня (назначение C-0001, задача A)

Исполнитель: Claude Code · 14.10.2026 · рабочий каталог C:\projects\TMS · авторская проверка, не независимое ревью.

## Требование
TASK.md, задача A: начальник смены выбирает склад и день и видит:
- факты дня, незавершённые обязательства и внешние подтверждения;
- причину каждой группы и куда перейти для решения.

Источник: `GET /api/finance/day-reconciliation/warehouses/{ware_id}?business_date&timezone_region`, право `transport_dispatch_view`. Схема ответа взята из `modules/finance/infrastructure/day_reconciliation.py` и `reconciliation_*.py`.

## Что уже было
- Поля склада, даты и пояса; кнопка загрузки.
- Абзацы `подпись · число` в шести контейнерах.
- Защита от смены пользователя и номера запроса.

Дефекты:
- для ключей `interwarehouse_*` (5 в обязательствах, 2 в фактах) не было подписей, выводилось «undefined · N»;
- не показывались причина, следующее действие и ссылки;
- не было фильтра, контекста отчёта и блока известной неполноты;
- статусы ERP и маркировки шли в одной строке;
- на мобильном экране страница не перестраивалась.

## Что сделано
- **Каталог показателей** `day-reconciliation-catalog.js`. Каждый ключ ответа API описан: подпись, процесс, смысл, следующее действие и ссылка.
  - Ссылки ведут только на существующие реестры, потому что ответ агрегатный и ID документов в нём нет. Такие ссылки подписаны «· реестр», в подсказке сказано, что откроется общий реестр.
  - Для групп без экрана (незавершённая выгрузка магазина, ERP, инварианты запаса) честно написано «Отдельного экрана нет».
  - Неизвестный ключ API показывается с исходным кодом и пометкой «без описания», а не как undefined.
- **Пять групп:**
  - «За сутки» — факты дня;
  - «Сейчас» — обязательства, включая прошлые дни, и остатки и резервы;
  - «Внешнее» — ERP и государственные системы.

  Факты и обязательства сгруппированы по процессам. Нулевые обязательства свёрнуты в «Без открытых пунктов: N». Открытые показаны карточками: число, причина, «Дальше: …» и ссылка.
  - В обязательства включены коды `open_items`, которые сервер выводит из грузовой зоны, остатков и внешних систем. Например, `shipping_zone_classification_incomplete` даёт ссылку на «Грузовую зону на этой странице».
- **Контекст отчёта:** склад, операционный день, пояс, границы суток в этом поясе, время чтения, признак согласованного снимка.
- **Сводка из четырёх карточек:** открытые пункты, факты за день, ERP без подтверждения, сообщения маркировки.
- **ERP и маркировка.**
  - В ERP различаются «Отправлено в ERP, ответ ожидается», «ERP отклонила» и «Ожидает выгрузки».
  - Для маркировки отдельно показаны отправка и принятие госсистемой. Принятие всегда «Не сверялось» (серое): API возвращает `NOT_VERIFIED_BY_THIS_REPORT`, поэтому зелёного нуля нет.
  - Пустой список ERP сопровождается оговоркой о привязке к складу.
- **Блок «Известная неполнота данных»** строится из флагов ответа:
  - `consistent_snapshot`;
  - неполная страница и неполная классификация грузовой зоны;
  - `full_regulatory_reconciliation_verified=false`;
  - `coverage_complete=false`;
  - задания без часового пояса;
  - «День не закрыт».
- **Фильтр по загруженным группам.** Он клиентский и подписан: «Найдено X из Y строк — только среди загруженных групп этого отчёта, не поиск по базе».
- **Состояния.**
  - Загрузка: `aria-busy`, сообщение.
  - Ошибки с подсказкой: 422 (пояс), 403 (права), 401, недоступность сервера.
  - Пустые данные, проверка ввода с фокусом на поле, Enter в полях запускает загрузку.
  - Устаревший ответ отменяется через `AbortController` и номер запроса и не перерисовывает новый выбор. При смене параметров пишется «Параметры изменены — сформируйте сверку заново».
  - Последний склад запоминается для пары «пользователь + API».
- **Доступность и адаптивность.**
  - Подписи `label for`, подсказки `aria-describedby`, `role=status`/`aria-live`, видимый фокус, датасписок поясов.
  - Колонки сетки 4 → 2 → 1, таблицы с собственной горизонтальной прокруткой.
  - Общий `styles.css` задаёт `body{min-width:1280px}`, из-за чего мобильные правила страницы не срабатывали. Ограничение снято только для `body.day-page` при ширине меньше 1280px в `day-reconciliation.css`. Общий `styles.css` не менялся.
- **Соседние блоки** (фиксация и журнал сверок, совместный осмотр, грузовая зона, перенос СТ, ожидание, выбор рейса): разметка, ID и подключения скриптов сохранены. Поля `drWare`/`drDay`/`drZone` остаются input с теми же ID; при программной подстановке склада генерируется `input`, чтобы соседи сбросили свои данные.

## Долгий запрос и решение
`GET …/day-reconciliation/warehouses/1`: самый долгий SQL в `RRL_SQL_SLOW_LOG` — 666 мс на первом (холодном) вызове, затем 8–10 мс (`sql_text_hash 5bb495c4…`). Общее время ответа около 0,97 с. Решение: оставить. Отчёт строится одним явным действием пользователя в read-only транзакции, автообновления и опроса нет.

- **Полный спринт NI07.2** самостоятельно не закрываю.

## Предложение контракта на будущее (не блокирует)
Для перехода к конкретному документу нужен необязательный параметр, например `include_samples=true`. По каждому коду `current_backlog`/`open_items` он возвращал бы до N идентификаторов источника: `kind`, `id`, ссылочный экран. Без него интерфейс честно ведёт в реестр.
