# C-0032 — восстановление утверждения времени рейса после перезагрузки (NI08.1)

Исполнитель: Claude Code · 14.10.2026. Проверка авторская. **POST `/time-approvals` перехватывался** (mocked evidence): реальный рейс повторно не утверждался. Новых SQL-запросов нет.

## Было
- `TransportTimeApproval.tsx` сохранял намерение, но после перезагрузки его никак не показывал.
- Основание и признак «после погрузки» не восстанавливались; при расхождении оператор видел JSON-строку и должен был угадывать прежний ввод.
- Повреждённая запись давала непонятную ошибку.

## Сделано
- **Новый `TransportTimeApprovalIntent.ts`:**
  - чтение с проверкой формы;
  - запись с проверкой чтением, без которой команда не отправляется;
  - удаление только неизменённой записи;
  - архив повреждённой записи.

  Область хранения прежняя: `apiBase` + actor.
- **Новый `TransportTimeApprovalPending.tsx`** — баннер: рейс, часовой пояс, основание, фаза, версия плана, операция. Варианты:
  - тот же рейс и пояс → «Повторить сохранённое утверждение»: точный прежний intent с тем же `operation_id`, версией и hash, без подмены свежим контекстом;
  - другой рейс → «откройте рейс #N», команда от текущего рейса не отправляется;
  - другой пояс → «выберите часовой пояс X в поле выше» (родительский компонент не менялся);
  - повреждённая запись → новое утверждение заблокировано, архив только после подтверждения оператором.
- **`TransportTimeApproval.tsx`:**
  - основание и «после погрузки» восстанавливаются из команды того же рейса;
  - при незавершённой команде ввод и кнопка утверждения заблокированы и показана причина.
- **Удаление записи** — только после подтверждённого результата: ответ сверен по `operation_id`, `trip_id` и actor, либо подтверждённый отказ по прежнему контракту 400/404/409/422 с кодом сервера.
- **Сеть, 5xx и некорректный ответ** сохраняют команду. Функции «забыть» для неизвестного результата нет.
- Серверные правила не дублируются.

## Коррекция по ревью C-0036
Подтверждённым отказом считается только структурированный ответ API `{detail:{code,message}}` со статусом 400/404/409/422 и кодом вида `UPPER_CASE`. HTML 404 от прокси или неполное тело не подтверждают отказ — команда сохраняется как неизвестный результат.

Адресная модель (`c0032_malformed404.json`, POST перехвачен):
- HTML 404 → «Результат не подтверждён (HTTP 404)», запись сохранена, есть кнопка повтора;
- повтор с ответом 409 `TIME_SOURCE_APPROVAL_CHANGED` → «Отказ подтверждён», запись удалена.
