# Норматив тары физического верхнего места —14 октября2026
Общий Root погрузки теперь проверяет тип верхнего места по существующей карточке CASE или закреплённой таре HU. Вложения не умножают места. Вместимость повторно проверяется под прежней блокировкой машины до списания; тип и версия профиля сохраняются в immutable доказательстве рядом с прежним LOADfact, в одной транзакции.

Прежний планировщик теперь объединяет подготовленные типы с immutable LOADED TOP: один LOAD учитывается один раз независимо от числа СТ/дочерних CASE. Исторические LOAD без доказанного типа остаются неизвестными. Полная STOCK-паллета без подтверждённого типа при новой матрице не получает тип автоматически — это ещё открытый сценарий.
