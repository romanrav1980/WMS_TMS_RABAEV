# C-0160 — торговый остаток в общем пуле (Claude)

Native-комплект **NOT_APPLIED**. Компиляцию на Oracle и товарные команды выполняет root. SAP/СКМ и программа в целом не объявляются пройденными.

## Причина пробела (READ ONLY, `src/`)
- `RRL_STOCK_POOL_READ.snapshot_json` проверяет поддон через `RRL_STOCK_ELIGIBILITY.reason` без строки заказа.
- На торговой площадке последним шагом этой проверки стоит `RRL_TRADE_STOCK_GUARD.reason` → `RRL_TRADE_PICK_CONTEXT.reason`, который без контекста строки отвечает `TRADE_ORDER_BINDING_REQUIRED`. Этот ответ появляется только после того, как пройдены все проверки самого поддона: место, срок, атрибуты, однородность, коды, выкуп, диапазон собственника.
- Совместимость строки и источника — binding, SKU/МРЦ, ОСГ, собственник, выкуп BEFORE_PICK, целый короб, удержание добивки — есть только в `RRL_TRADE_PICK_CONTEXT.reason`.
- Этот пакет `accessible by` закрыт для пула и проверяет права текущего читателя. Снимок пула должен быть одинаковым для всех: его хэш сравнивается в плане, compile и execute.

## Кандидат `db/migrations/2026-10-23_trade_pool_eligibility/`
| Объект | Изменение |
|---|---|
| `RRL_TRADE_PICK_CONTEXT` spec (+6 строк) | `RRL_STOCK_POOL_READ` в accessible by; функция `compatible(row, uid, cell, ware)` |
| `RRL_TRADE_PICK_CONTEXT` body (+14) | тело reason → приватная `check_source(p_access)`; `reason` = check_source(true), поведение для всех прежних вызовов то же; `compatible` = enter_line + check_source(false), контекст вызывающего восстанавливается (и при ошибке) |
| `RRL_STOCK_POOL_READ` body (+32) | только торговая площадка и включённый пул: поддон, у которого остался лишь `TRADE_ORDER_BINDING_REQUIRED`, становится источником класса `owner\|SKU\|МРЦ\|срок` (однородность гарантирует guard); каждая открытая строка получает `classes` (совместимые классы) либо конкретный `pool_reason`; предел 2000 пар класс×строка (`POOL_TRADE_MATRIX_BOUND_2000`); неторговый снимок **байт-в-байт прежний** |
| `RRL_STOCK_POOL_CMD` body (+48) | compile торгового плана — `prove_trade`: каждая доля строки названа по классам; класс совместим со строкой; доли кратны шагу; сумма долей = доле строки; по классу не больше свободного; у строки с `pool_reason` 0. execute после блокировок и сверки снимка требует от actor `operate` на собственника каждого использованного класса (`RRL_TRADE_STOCK_GUARD.assert_owner`) |

- Порядок: preflight (4 before SHA) → spec → body → read → cmd → recompile (`compile_schema(compile_all=>false)`, только INVALID) → verify (4 after SHA, INVALID 0, ошибок нет) → ledger.
- Откат возвращает четыре before-текста. SOFT-доли, созданные за это время, остаются: их пересчитает прежний пул.
- Python:
  - `domain/pool_allocation.py: allocate_trade_pool` — строки с одинаковым набором классов делят их прежним пропорциональным алгоритмом; при пересечении наборов — по порядку отгрузки с FEFO внутри строки;
  - `infrastructure/pool_plan.py` — подсказка `sources`, строки с `pool_reason` получают 0.
  - Всё это native проверяет заново. Метка алгоритма прежняя (её требует native), неторговый путь не меняется.

## Стоимость SQL
- Снимок пула (анонимный блок, одиночные прогоны): торговый склад до 22 мс, после 35 мс, с включённой политикой 68 мс (1 класс, 4 строки); неторговые SKU 6–7 мс (первый прогон 139 мс — холодный разбор блока).
- `compatible` выполняется по разу на пару класс×строка: несколько запросов по PK и индексам; граница — 2000 пар.
- Пары на большом складе не измерялись: такой торговой потребности в БД нет.

## Ограничения
- Пересекающиеся наборы классов распределяются по порядку отгрузки, а не пропорционально. Native доказывает допустимость, не оптимальность.
- SOFT-доля хранится по строке, без привязки к классу (прежняя модель пула). Классы фиксируются в разбивке плана (resolved plan операции), а при отборе источник снова выбирает `create_plan` с контекстом строки.
- Права: снимок не зависит от читателя, право `operate` на собственника проверяет execute. Доля, выданная до отзыва права, сохраняется до следующего пересчёта.
- Добивка обслуживается своим удержанием (C-0157); её строки в пуле не получают классов сверх удержания.
