# C-0165 — скорость bulk-box-preview и outgoing-quality, T12 (Claude)

**Итог: задержка подтверждена, но это холодная загрузка кода PL/SQL в shared pool, а не SQL, план или индекс. Кандидат на правку runtime мотивированно отклонён: код, native и API не менялись.** Локальные замеры — не промышленный SLA; T12 этим не закрывается.

## Условия
- Идентификатор `099999990000026027` (CASE1169, склад 220793322), actor `admin`. Только чтения: груз, маршрут, настройки и права не менялись; 225837931 не трогался.
- Те же Python-функции, что у маршрутов: `bulk_loading_preview` и `OutgoingQuality.status`. Каждый `execute`/`callproc` замерен отдельно (`scripts/measure.py`).
- Проба 0 — на новом OracleGateway, пробы 1–5 — тёплые.
- Для CASE1169 bulk-box-preview отвечает деловым отказом `BULK_BOX_REQUIRED` (это не самостоятельный короб). Тяжёлая часть — снимок HU и допуск — выполняется полностью до этого отказа.

## Разложение
1. **Тёплый вызов.** Основная стоимость — один native-вызов:
   - `RRL_STOCK_HU_READ.case_snapshot_json` около 72–76 мс;
   - `RRL_STOCK_QC_GATE.status_json` около 53–59 мс;
   - допуск (`RRL_ACCESS_API.allowed`, `RRL_OUTGOING_QC_ACCESS.assert_identifier`), поиск места и склада (`RRL_PALLETS`, `RRL_SBORKA_PALLETS`, `RUSERS`) и `reset_connection` — по 1.5–2.5 мс каждый.
   Явного узкого SQL нет.
2. **Первый вызов.** Почти всё время уходит на тот же native-вызов (1087.6 мс и 791.2 мс против около 75 мс тёплых); соединение и Python — около 150 мс.
3. **Новая сессия без холодного кэша** (`scripts/fresh_session.py`, три отдельных процесса): первый `case_snapshot_json` 103–115 мс, `status_json` 57–69 мс. Цена новой сессии и инициализации пакетов мала.
4. **Полный разбор SQL** (новый текст с уникальным комментарием вокруг того же вызова, `hard-parse.json`): HU 86–98 мс, QC 87–112 мс — на уровне тёплых. Разбор верхнего SQL не причина.
5. **Курсоры холодного вызова** (`cold-cursors-083220.json`, по V$SQL, окно загрузки 08:32:15–20):
   - заново загружено 28 курсоров; на собственные курсоры пакетов (HU_READ, QC_GATE, WH_FINAL_SCALE_ADMISSION, THERMAL_READ, CASE_PICK_CMD и других) приходится около 180 мс;
   - верхний курсор `case_snapshot_json` набрал около 1164 мс за 6 выполнений, то есть около 1.1 с первого вызова прошли внутри PL/SQL вне его SQL-курсоров.
   Это загрузка скомпилированных модулей в library cache. Дерево зависимостей обоих маршрутов — по 97 PL/SQL-модулей (USER_DEPENDENCIES).
6. **История** (`RRL_API_CALL_LOG`, 14 дней):
   - outgoing-quality: 170 вызовов, медиана 99 мс, 15 вызовов не быстрее 500 мс;
   - медленным почти всегда оказывается первый вызов после паузы (35–822 мин) или после перекомпиляции, а следующие вызовы того же идентификатора быстрые (например, 04:25:54 — 1119 мс, затем 122–279 мс);
   - slow log 6633/6635 (04:25–04:26) пришёлся через 3–4 мин после перекомпиляции `RRL_STOCK_POSTING_API` и `RRL_STOCK_POOL_CMD` (04:22) при apply root.

## Решение
Отклоняю правку runtime:
- оптимизация SQL или индекс не уменьшат загрузку кода — тёплое выполнение уже 70–130 мс;
- кэш допусков или ответа запрещён заданием и не нужен;
- сокращение дерева зависимостей (97 модулей) — большой рефакторинг, а не минимальная правка;
- фоновый «прогрев» запросами — обходной путь, который скрывает задержку и добавляет нагрузку; вводить его без решения владельца не стал.

Варианты для владельца или DBA, не выполнялись:
- `DBMS_SHARED_POOL.KEEP` для `RRL_STOCK_HU_READ`, `RRL_STOCK_QC_GATE`, `RRL_OUTGOING_QC_ACCESS`, `RRL_STOCK_LOADING_READ` и общих зависимостей;
- размер shared pool на промышленном стенде;
- не применять миграции в рабочие часы погрузки — после перекомпиляции первый вызов неизбежно холодный.

## Доступность диагностики
- V$SQL читается.
- V$SQLSTATS, V$MYSTAT/V$STATNAME, V$DB_OBJECT_CACHE недоступны (ORA-00942): точную долю library cache load по объектам измерить нельзя; вывод сделан по разности «верхний курсор минус собственные курсоры».
- DBMS_PROFILER не запускался: загрузку модулей он не атрибутирует, а холодный вызов не повторяется без ожидания вытеснения.
- Системная трасса не включалась, права DBA не запрашивались.
