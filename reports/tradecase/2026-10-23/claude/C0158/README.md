# C-0158 — плановые интервалы ворот (Claude)

Native-комплект **NOT_APPLIED**. API :8088 не перезапускался. Весь T10 не объявляется завершённым.

## Что уже было (READ ONLY изучение, `src/`)
- Двор `RRL_YARD_VISIT_API`:
  - визиты исходящих рейсов и входящих поставок с фактами;
  - команды ASSIGN/REASSIGN_DOCK;
  - уникальные индексы активной занятости ворот, машины и рейса;
  - порядок блокировок: право → `RRL_ACCESS_REV` share → `RRL_TRADE_SITE` FOR UPDATE → визит;
  - owner-проверки;
  - источник `yard` общего Ганта.
- Справочник ворот площадки — `RRL_TT_DOCK`.
- Плана интервала ворот не было:
  - у визита есть только точка `PLANNED_ARRIVAL_AT`;
  - у рейса — `planned_dock` без времени;
  - legacy `RRL_TRANSPORT_TASK.DOCK_REZERV_TIME_FROM/TO` мёртв: последняя запись 2011, читают 2 legacy-функции. Не использовался.
- Источники не задают норматив длительности, поэтому начало и конец вводит сотрудник.

## Сделано
### Native `db/migrations/2026-10-23_yard_dock_plan/` (NOT_APPLIED)
- `RRL_YARD_DOCK_PLAN`: один ACTIVE план на визит (уникальный функциональный индекс), CHECK `PLANNED_TO>PLANNED_FROM`, версия.
- `RRL_YARD_DOCK_PLAN_EVENT`: operation_id, hash, actor, квитанция; append-only триггер.
- `RRL_YARD_DOCK_PLAN_API.command` (PLAN / MOVE / CANCEL):
  - порядок: право → ACCESS_REV share → TRADE_SITE row → право ещё раз → строка визита → строка плана → замок машины (dbms_lock по номеру, после замка площадки);
  - текущие owner-права визита — через новую обёртку `RRL_YARD_VISIT_API.assert_visit_owners`;
  - ворота должны быть воротами этой площадки и не заблокированы;
  - конфликт: пересечение [от, до) на тех же воротах площадки; пересечение для той же машины на любом складе (межскладская машина); касание интервалов — не конфликт; планы ушедших (DEPARTED/CANCELLED) визитов не держат;
  - только будущее начало; план ставится и переносится только для визитов EXPECTED или ARRIVED, отменяется в любом состоянии;
  - факты визита планом не пишутся;
  - повтор: тот же склад, текущие права, тот же actor и hash → исходная квитанция с `replayed:true`, иначе `YARD_OPERATION_CONFLICT`;
  - план скрытого визита отвечает как отсутствующий.
- `plans()`: `tradecase_view`, окно не больше 7 суток, скрытые owners отфильтрованы до лимита 500, `observed_at` — часы сервера.
- `RRL_YARD_VISIT_API`: +2 строки spec и +5 строк body (обёртка над существующей `require_visit_owners`).
- Хэши before/after — в `manifest.json`, `000_preflight.sql`, `verify.sql`, `rollback_verify.sql`. `rollback` отказывает, если уже есть история планов.

### Backend
- `GET/POST /api/tradecase/warehouses/{w}/yard/dock-plans`, `POST …/{plan}/move`, `POST …/{plan}/cancel`.
- Модульная граница: `contracts_yard_plan.py`, `infrastructure/yard_dock_plans.py`, `api/yard_plan_routes.py`, `app/yard_plan_composition.py`.
- Квитанция принимается только своей операции; неизвестный исход — 503 с `retry_same_operation_id`.
- Общий Гант: в источнике `yard` после фактов читаются планы. На дорожке ворот появляется событие `YARD_DOCK_PLAN`: только плановое время, факт null. Отсутствие объектов плана — плана нет, и это не «ворота свободны».

### UI (рабочее место смены → «Двор и ворота» → «План ворот»)
- Список планов рядом с фактами визита и отклонения только по реальным данным:
  - не приехала к началу плана;
  - на площадке, но не у ворот;
  - встала позже плана;
  - стоит у других ворот;
  - занимает ворота дольше плана;
  - ворота сейчас заняты другим визитом.
- Явная надпись: план не факт и сам не пересчитывается.
- Действия «Запланировать», «Перенести», «Отменить план», «План в Ганте».
- Журнал команды в браузере:
  - перед сетью сверяются вход и точная запись;
  - ответ после смены входа не показывается;
  - снятие только по своей квитанции или подтверждённому отказу;
  - конфликт номера операции запись сохраняет.
- В карточке события на Ганте план подписан как намерение диспетчера.
- Справка: `public/help/tradecase-documents.html#yard-plan`.

## SQL
- Чтение Ганта с источником yard: 100–480 мс на двух складах (одиночные dev-прогоны).
- Новые чтения ограничены: окно ≤ 7 суток, ≤ 500 строк, индексы `(WARE_ID, STATUS, PLANNED_FROM, PLANNED_TO)` и `(WARE_ID, DOCK, STATUS, PLANNED_FROM)`.
- Проверка конфликта — два count по индексам в пределах одной площадки или машины.
- Производительность команд на нагрузке не измерялась, нужна установка.

## Незакрытые ограничения
- Пакет не скомпилирован: нужны новые таблицы. Компиляцию проверит `verify.sql` при apply у root.
- Номер машины у исходящего EXPECTED-визита информативный и уточняется при приезде. Конфликт машины проверяется по номеру на момент планирования.
- Автоматического пересчёта плана при задержке нет, и он не обещан. Отклонения показываются по фактам.
- План не резервирует ворота физически. Фактическая занятость — только двор.
- Прочие пункты T10 (полный набор рисков смены, прочие ресурсы) не затрагивались.
