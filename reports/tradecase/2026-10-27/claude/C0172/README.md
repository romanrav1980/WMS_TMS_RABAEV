# C-0172 — T09: полный маршрут по настоящей дороге, окна, перерыв, согласование

Источник: программа 21.10, разделы 10/12 (проверки 32–34, 38–44); правило владельца: 15 минут отдыха после 120 минут вождения.

## Что уже было и что сделано
- Было:
  - дорожные плечи OSRM для 2–3 точек, без окон;
  - нативный RRL_TT_ROUTE_SCHEDULE на фиксированной матрице программы.
- Пробел: ни одного прогона, где настоящие плечи идут в окна, перерыв, возврат и утверждение. Все тестовые плечи были по 4–6 минут, поэтому перерыв дорогой не проверялся.
- Прогон `tests/tradecase/live_route_windows.py`, доказательство `runtime/test-evidence/tradecase/2026-10-27/T09/RW27dc7ba57b35.json`:
  - свой отсутствовавший склад, рейс 33695, настоящие координаты: Екатеринбург → Каменск-Уральский → Богданович → Сухой Лог → Екатеринбург;
  - работающий OSRM через 8088;
  - только действующие команды: road-refreshes, route-inputs, delivery-windows, time-context, time-approvals;
  - набор выведен в конце, INVALID 0.

## Результаты (время московское, рейс на 29.10)
1. Четыре настоящих направленных плеча: 101,65 / 68,4 / 19,92 / 97,4 мин. Точный повтор обновления даёт ту же квитанцию.
2. Перерыв 120/15 на настоящей дороге: REST 11:09–11:24, ровно после 101,65 + 18,35 мин вождения, и REST 14:09–14:24 на возврате. Прибытие: хаб 10:35, филиал 12:14, магазин 12:48. Возврат 15:11.
3. **Найдено:**
   - если диспетчер вводит в «оценку длительности» только сумму дорожных плеч, план машины кончается раньше настоящего возврата (`ROUTE_EXCEEDS_PLANNED_RESOURCE_ENVELOPE`), потому что разгрузка и отдых не входят;
   - даже минуты из расчёта (235/113) не хватили на 5 минут: нативный план ставит у последней точки свои операции;
   - после добавления показанной нехватки (возврат 119 мин) нарушений нет.
4. Достижимые окна (10:05–11:20 / 11:44–12:59 / 12:18–13:33): нарушений нет. Утверждение времени и точный повтор прошли.
5. Окно магазина до 12:38 при прибытии 12:48:
   - показано `DELIVERY_HARD_WINDOW_MISSED` (опоздание 26 мин);
   - прежнее утверждение помечено SOURCE_CHANGED, старая основа отклонена `TT_TIME_SOURCE_CHANGED`;
   - утверждение расписания с нарушением отклонено `TT_TIME_ROUTE_SCHEDULE_REJECTED:DELIVERY_HARD_WINDOW_MISSED`.
6. Решение по исходному процессу: окно согласовано заново, расчёт без нарушений, новое утверждение (версия 2).
7. **Дефект экрана:**
   - расчёт с `time_zone=UTC` возвращает те же местные часы, только с подписью +00:00;
   - экран TRADECASE «План маршрута» запрашивал UTC и показывал прибытие в магазин как «12:48 UTC», хотя это 12:48 МСК (09:48 UTC).

## Исправлено (только `RoutePlan.tsx`)
- Выбор часового пояса (по умолчанию МСК, есть Тбилиси и UTC) с title и help id `tradecase.route.zone`; подпись времени берётся из выбора. Если пояс в карточке магазина отличается от выбранного — предупреждение.
- Строка «Отдых водителя по правилу 120/15: 11:09–11:24, 14:09–14:24» из сегментов расчёта.
- При `ROUTE_EXCEEDS_PLANNED_RESOURCE_ENVELOPE`: возврат по расчёту, до какого времени рассчитан план машины, сколько минут не хватает, и куда добавить («Возврат на склад, мин»).
- Команды, контракты, native и права не менялись. Архитектурный gate PASS.

## Ограничения и остаток
- Координаты — настоящие города, но не адреса СНС/BLC. Свежесть графа OSRM (timestamp) не подтверждена. Пробки, грузовые ограничения и законность режима водителя не подтверждаются (`legal_compliance_verified=false`).
- Экран 1440/390 не снят: экран TRADECASE требует привязанного торгового рейса. Сценарий для Codex на собранном приложении: открыть торговый рейс с привязкой и 3 точками → «План маршрута» →
  - пояс МСК по умолчанию;
  - время с подписью «МСК»;
  - строка отдыха;
  - при нарушении плана машины — нехватка в минутах;
  - на 390 нет горизонтальной прокрутки.
- `ExtraStop.tsx` (не мой файл) так же запрашивает `zone=UTC` и подписывает «UTC» — нужна та же правка.
- Пересчёт плана машины из расчёта маршрута одним действием не добавлен: это новое правило оценки. Сейчас экран показывает точную нехватку.
- T09 целиком не закрыт: промышленные адреса, перевозчик, фактическое исполнение маршрута.
