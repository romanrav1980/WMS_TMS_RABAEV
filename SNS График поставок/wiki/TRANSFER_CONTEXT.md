# SNS: контекст переноса — 10.11.2026

## Начало работы на новом компьютере

Откройте в Codex распакованную папку `install` как рабочий проект. Прочитайте её `AGENTS.md`, эту страницу, `wiki/index.md` и `wiki/deployment.md`. Все пути определяйте относительно текущей папки: прежний `C:\projects\TMS` на новом компьютере может отсутствовать. Подпроект независим от WMS, TMS-2, Oracle и SAP GUI.

Для запуска есть `START.cmd` и встроенный Python 3.13 x64. Рабочий адрес один: `http://127.0.0.1:4379/site/`. `START_DEBUG.cmd` открывает консоль для диагностики. Не запускайте вторую копию сервера на том же порту. База: `runtime/schedule.sqlite3`, данные: `data`, интерфейс: `site`. Python/SQLite/Leaflet включены; интернет нужен только для подложки карты.

## Данные и бизнес-правила

- VBAK-VDATU — плановая дата поставки заказа и связанных поставок, BLC, транспортировок. Источник: `Данные/babak8.txt`. Сопоставление по торговому документу заказа → VBELN, затем поставка/операция в пределах рейса. В файле 112399 заказов; с проектом связаны 2854 строки заказов в 1350 транспортировках.
- Окончание BLC (`end`) считается фактической датой сдачи. Не заменять его планом. Если VDATU не найден, владелец разрешил подставлять фактическую дату в план с явным признаком источника. При нескольких датах хранить набор, не выбирать произвольно одну.
- В 15 конфликтных связях номер BLC заказа отличается от номера в товарных строках поставки. По прямому решению владельца оба номера получили VDATU заказа: 30 связей; расхождение номеров остаётся в отчёте. Всего 2858 связей операций с планом VBAK.
- 98 транспортировок остаются без плана и факта; даты не выдумывать. Историческая таблица 116 — список без факта, у 18 из них появился план VBAK.
- В графике зелёная строка: источник задан и не содержит «уточнить»; выбраны дни, их число минимум max(1, частота − 1). Минимальная партия не участвует в критерии. Цвет означает заполненность, сохранение показывает отдельный индикатор.
- Последняя UI-правка: строка над таблицей объясняет причину незелёной записи при наведении или фокусе. `fixationReasons` в `site/schedule.js` используется и цветом, и текстом. Проверены 192 сочетания, клавиатура и экран 390 px.

## Перенос и сборка

Полный XML через `/api/database.xml`: рабочие JSON, источники, рекомендации, настройки. Импорт хранит файлы в SQLite `project_files` и переключает чтение API на них. При непустой этой таблице исходные JSON на диске могут не отражать текущие данные — сначала проверить активную базу. Импорт одной транзакцией, SHA-256, backup; старый XML v1 сохраняет совместимость. Реальный round-trip: 35 файлов, 19 рекомендаций на момент проверок; актуальное число в переданной базе проверить заново.

Сборщик установщика: `python\python.exe installer\build.py --db runtime\schedule.sqlite3`. Нужен стандартный Windows .NET Framework C# compiler по пути, указанному в build.py; дополнительных Python-пакетов не требуется. Сборщик умеет использовать уже упакованную стандартную библиотеку встроенного Python. Само приложение не требует сборки.

Постоянная папка публикации, разрешённая владельцем: https://drive.google.com/drive/folders/1tQ2p7smQue5fd8-sySYfqsmRU4Ygw7Dc . Коннектор загрузки ограничен 100 МиБ, большие дистрибутивы публиковались частями по 90 МБ с CMD сборки и проверкой SHA-256. История и ссылки — в `wiki/deployment.md`. GitHub не используется.

## Известная проблема у владельца и текущие исправления

Владелец сообщил: после окна установки всё закрывается. Причина на его ноутбуке ещё НЕ подтверждена. Выявлено локально: прежний INSTALL.cmd игнорировал exit code установщика; прежний Setup после успешной установки сам не запускал приложение.

В исходниках Setup добавлены журнал `%TEMP%\SNS-Setup.log`, проверка Python/импорта приложения/целостности SQLite и предложение открыть приложение после успеха. Launcher использует `start_server.py`, пишет `runtime/launcher.log`; сервер пишет `runtime/server.log`. В архиве используется прямой переносимый запуск, без необходимости устанавливать приложение через Setup. Не утверждать, что ошибка именно на ноутбуке владельца устранена, до запуска там.

Ещё известная UI-ошибка, НЕ исправлена: в `site/trip-details.js` у заказа с пустым operation функция orderDates показывает даты всех операций рейса вместо восстановления операции по поставке. Пример: рейс 562065, заказ 1177229122 / поставка 8203063061 → BLC 1101844 → факт 17.10.2026; 1177261608 / 8203108708 → 1102829 → факт 16.10.2026. План VDATU у обоих корректный 16.10.2026. Не смешивать эту проблему с планом заказа.
