# Qwen: смены ричтраков и расследование SHORT
Независимое задание; авторские bounded cases не заменяют его исполнение. Только собственные dev fixtures.

- MAIN начинается/заканчивается на2 часа раньше базовой смены; DUTY совпадает с базовой,1–2 места. Повтор создания возвращает те же IDs, другие параметры дают конфликт.
- Login не превышает EXPECTED_DRIVERS; один operator/resource/equipment не получает две active sessions. При пересечении derived shifts ТСД требует явный shift_id.
- Уже начатый шаг завершается после конца времени своей открытой смены, новый шаг за пределами окна запрещён. Logout при незавершённой физической работе не переписывает владельца/запас.
- Передача carrier только через существующее подтверждение scan/version; новый владелец принимает сохранённый фактический состав, история/возраст задания остаются.
- CCTV_VIEWPOINT формирует архивное окно с явным offset, экранирует параметры, отвергает опасные URL/неизвестные placeholders. Никаких заявлений о полученном видео без реального NVR.
- Review SHORT: expected version, exact replay, changed same-event conflict, concurrent stale review; неизменностьP/H/резервов. Нельзя разрешить недостачу записью вывода расследования.
Отчёт: собственные IDs, шаги/результат, ограничения внешнего доступа, longest SQL и решение. Восстановить собственный запас через root и отключить свои нормы/камеры; не удалять immutable history.
