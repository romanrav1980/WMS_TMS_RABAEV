# Задание Qwen: NI03.2, альтернативная ячейка

Проверить существующий RRL_PICK_FACE_ASSIGNMENT и AlternativePickFaces, миграцию 039. Своя основная ячейка capacity 2, спрос 3, свободная динамическая capacity 3, маршрут с этим адресом: согласованно меняются RT, demand, PT/WT/CASE, версия состава и одно событие. Нельзя перенаправлять собранный CASE, физическое задание или принадлежащий старому адресу HARD изменением metadata.

Неподходящий склад/маршрут, блокировка ячейки, другая партия/SKU, занятость/активное входящее задание, недостаточная вместимость фактической целой паллеты — отказ/ожидание. Динамический PICK допускается только владельцу HARD той же волны. Проверить BASE norm/весовые товары; BOX нельзя считать BASE.

Два конкурирующих назначения не получают одну ячейку. После исчезновения P/H/входящих задач и окончания спроса назначение можно снять; занятое снимать нельзя. Несколько строк RT одного артикула не должны повторно переносить уже изменённую closure.

Канонический RESERVE_REQUEST_JSON/RESERVE_OPERATION_ID сохраняются до команды. Утерянный ответ повторяется тем же телом/ID. После APPLIED без источника новое решение имеет новый ID. Обычная волна и continuation используют один mechanism; реальный 20+30 суммарный факт не дублируется.

Новые инциденты SHORT имеют CREATED_AT_INSTANT: архивное окно строится по реальному UTC instant; legacy rows остаются с явно заданным offset, без NOW backfill. Не подключаться к NVR при отсутствии реальной конфигурации.

Авторский сценарий scripts/ni032_alternative_face_case.py уже проходил. Независимо проверить альтернативные состояния и долгий SQL; писать найденные дефекты и реальные ограничения. Несколько ячеек/разделение demand остаются открытым объёмом, не считать их реализованными по одному alternate-cell случаю.
