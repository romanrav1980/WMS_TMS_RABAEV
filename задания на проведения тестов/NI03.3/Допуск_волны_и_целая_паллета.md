# Задание Qwen: NI03.3, допуск волны и целая паллета

Использовать актуальные исходники и RABAEV dev. Только собственные фикстуры; P/H/движения — команды RRL_STOCK_POSTING_API, историю не удалять. Не повторять авторские assertions как единственное доказательство: искать альтернативные входы/состояния и ошибки владения.

1. WAVE_LAUNCH готовит пополнение; CASE CLAIM/START/CONFIRM и FULLPAL START/COMPLETE до PICK_RELEASED_AT запрещены даже администратору. Незавершённое физическое пополнение показывает WH задание/ресурс и запрещает допуск.
2. После Root движения, передачи собственного HARD в правильный отбор и полного покрытия выбранного состава WAVE_PICK_RELEASE разрешает отбор. EA и KG не суммируются. Изменённая closure, источник в карантине, незавершённая инвентаризация и чужой HARD запрещены.
3. Лишняя QUEUED строка без источника/активного WH может быть закрыта только при полном фактическом покрытии. Выделенное пополнение не отменяется этим правилом. P/H остаются прежними.
4. Целая паллета требует APPLIED PICKING_MOVE, скан UID, свежую STOCK_VERSION, свой полный HARD и точный состав СТ. Подготовленная СТ остаётся PLANNED без физического подтверждения.
5. 3 EA и 0.125 BOX при норме 24 дают один факт 3 EA. SHIP потребляет конкретный связанный UID; другой HARD того же заказа остаётся прежним. Изменение СТ до 1 EA после whole binding не должно дать частичную отгрузку.
6. Неверный скан/версия, другое содержимое с тем же ID, попытка привязать одну физическую паллету к двум СТ, изменение прав и параллельные действия: либо один подтверждённый результат, либо полный откат. После потерянного HTTP ответа используется сохранённый запрос; локальный intent изолирован по API/пользователю.
7. Для маркированного SKU проверить реальный состав физических единиц/несколько профилей и отсутствие двойного количества при перемещении/отгрузке; профильные коды не подменять ШК товара. Для немаркированного SKU уникальные коды не требуются.
