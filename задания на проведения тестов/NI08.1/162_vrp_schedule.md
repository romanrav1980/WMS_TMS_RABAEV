# Qwen: расписание прежнего VRP

Запусти scripts/ni081_vrp_schedule_case.py на установленном OR-Tools. Подтверди начало10/60, собственную разгрузку40/20, return leg25км/end101, сохранение actual cumul values, неотрицательное ожидание. Дополнительно проверь мягкое раннее/позднее окно и непомещающийся строгий заказ без вымышленного успешного расписания.

Прочитай существующий план633: stop_schedule сохранён, operational_admission=false. Не применять этот план: его входы и машина специально заданы автором для проверки сервиса и архива. Для HTTP-сценария создай отдельные принадлежащие проверке СТ/машину через существующие механизмы, без товарных проводок.

UI: расчётные времена видны; перенос СТ удаляет ETA обеих изменённых маршрутов и требует пересчёта. Savings/cluster/attention без расписания не должны выглядеть как проверка окон. Строгий native admission пока отказывает PLAN_STRICT_TIME_SCHEDULE_REQUIRED. Фактические ответы и ограничения приложить; не объявлять внешний/независимый gate выполненным заранее.
