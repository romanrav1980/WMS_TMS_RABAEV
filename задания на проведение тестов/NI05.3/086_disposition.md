# Qwen: NI05.3, фактическая приёмка с расхождениями
Среда: выделенный RABAEV/orcl, обычный BARCODE SKU; не использовать чужой P/H. Читать wiki/database/nicora_ni053_discrepancy_20261010.md. Не принимать авторские PASS за независимую приёмку.

Собственное фактическое место: существующая СТ → физическая погрузка → выезд; original shipped3. Принять2, недостача1, излишек1 с причиной. Проверить immutable shipped3, receipt DISCREPANCY, exact BASE строки, два OPEN обязательства, один existing outbox, P/H0 и отсутствие второго количественного журнала. Повтор exact body/ID возвращает то же; новая причина на том же ID отклоняется; новый ID для уже принятого load отклоняется.

Отказы: неполное/чужое/дублирующее покрытие, сумма не равна3, отрицательные/float/дробь сверх BASE_SCALE, пустая причина, чужой адрес, недостаточное право. Нулевые счётчики допустимы. Несколько различных BASE_UOM не складывать в одно число.

Диспетчер: transport_dispatch_view, курсор по адресу/ID, строки exact decimal, нельзя считать OPEN обязательство одобренным возвратом. Прямые update/delete case/obligation/receipt должны отклоняться. Подтвердить старый full-place replay до086 без добавления observations/case_note в исходный canonical body.

UI: реальный браузер, счётчики/причина/неопределённый ответ и exact retry; смена пользователя/адреса не показывает чужой поздний ответ. WEIGHT_PHOTO/marked не должны проходить barcode fallback. Фотоархив не заменяет приёмку.

Результат сохранить со своим evidence, крупнейшими SQL и решением по каждому, scoped cleanup только собственного P/H через ядро. Не запускать широкую нагрузку и не публиковать GitHub.
