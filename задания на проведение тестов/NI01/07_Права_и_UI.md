# 07 — рабочий интерфейс и права

Существующий UI `/wms-admin/receiving.html`, карточка `/finished-goods.html`, warehouse tasks и reachtruck. Создай собственных ограниченных пользователей/группы только разрешённым rights-admin API и верни owned настройки; не меняй GLOBAL_ADMIN и чужие группы.

1. GLOBAL_ADMIN: вход, список SAP заказов/строк/остатка, norm proposal и ручная укладка, scan немаркированного SKU, полный receipt → task → placement.
2. Marked: выбрать профиль/единицу/aggregation, добавить все коды, quantity кг/л, удалить ошибочный scan, очистить новую паллету; не сохраняется состав предыдущей паллеты.
3. Label: открытие HTML, authenticated ZPL download/dpi, отдельное поле printed scan; UI не автоподтверждает выданный SSCC.
4. Configuration: чтение/изменение warehouse/SKU/cell rule, пустые границы/некорректные значения, отсутствие права edit.
5. Close/reopen/replan: обязательные причины, отображение ответов и повтор на потерянном ответе; кнопки не создают второго бизнес-эффекта.
6. Exchange: статусы/ошибки/внешний номер, retry только допустимого события.
7. Отдельно вызвать каждый mutation API без права, с read-only пользователем, с подменённым actor и с чужим идентификатором. Получить 401/403 либо business rejection; эффект в Oracle отсутствует. Проверить finished_goods_view/edit, sap_article_import, sap_supply_import/view, warehouse_receipt_confirm/reconcile, warehouse_task_execute/assign, warehouse_settings_view/edit, traceability_view. Наличие GLOBAL_ADMIN не заменяет отрицательные проверки.
8. Неверный пароль/истекший клиентский контекст, потеря сети до/после commit и повтор запроса: пользователь видит ошибку, серверный факт не удваивается.

Сохранить screenshots ключевых шагов, запросы/ответы с удалёнными Authorization/паролями, сопоставление PK результата и UI. Проверить русские подписи и ведущие нули/GS, отсутствие скрипта из данных в HTML. Не выполнять общий UI-аудит вне NI01. Если доступен лишь API, UI case BLOCKED, не PASS.
