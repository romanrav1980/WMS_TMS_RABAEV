# 01 — ARTMAS10, заказ и файловый шлюз

Следуй общему README. Источники: modules/integrations/{domain,infrastructure}, workers/sap_artmas_worker.py, exchange/contracts/ni01. Используй отдельный временный каталог шлюза внутри своего evidence, не рабочий inbox. Экземпляры worker ограничивай собственным root.

| Case | Действия | Ожидаемый результат |
|---|---|---|
| 01 | Импортировать корректный ARTMAS10 нового SKU с ведущими нулями, EAN/упаковками | Один article/meta/inbox APPLIED; идентификатор не преобразован в число; raw/hash сохранены |
| 02 | Передать изменение только названия, потом старый timestamp/DOCNUM | Непереданные поля/настройки маркировки сохранены; старое сообщение не откатывает master |
| 03 | Повторить DOCNUM с тем же и другим payload | Идемпотентный результат; конфликт другого payload без эффекта |
| 04 | Нет EAN/base UoM/name у нового товара; FUNCTION=003; смена mapped base UoM | Явный отказ/ERROR, фиктивный SKU/EAN не создан |
| 05 | Неверные MESTYP/IDOCTYP/DOCNUM, два IDOC, неверная дата, DTD/entities, >4 MiB | Контролируемый отказ, товарные данные неизменны |
| 06 | WarehouseSupplyOrder с существующим складом/ReceiveCell и альтернативной UoM | Один legacy приход/строки, корректный Decimal-план в base UoM; RRL_REMAINS не меняется |
| 07 | Неверный склад/ячейка, дубликат line/material, неизвестный коэффициент | Нет частичного прихода/строк; ошибка с причиной |
| 08 | Повтор MessageId и другая версия с тем же ID | Повтор безопасен; payload conflict отклонён |
| 09 | Файл публиковать сначала временным именем, потом rename .xml | Недописанный файл не импортирован; завершённый архивирован с result JSON |
| 10 | Два worker на одном root; незавершённый .processing после остановки своего worker | Один владелец, автоматическое восстановление; повтор не создаёт второй документ |

Проверь source ownership разных SAP Sender и raw UTF-8/base64 Code с GS. Архивный успешный файл не считается принятым реальной SAP. В конце отчёт по общему формату и slow SQL.
