# Qwen — независимая приёмка размещения возврата
Источник: wiki/database/retailcase_ni062_return_putaway_20261010.md, исходники db/migrations/2026-10-10_ni062_return_putaway/. Oracle RABAEV/orcl dev. Не запускать одноразовый author-case на уже размещённом возврате. Создать отдельную разрешённую цепочку либо использовать непринятый остаточный возврат с согласованием своей тестовой политики.
1. Раздельные blocked receiving/target зоны: другой склад/приёмка вместо target/отбор/неизвестная высота/слоты — отказ без P/H/history/outbox.
2. Root PLAN создаёт обычный MANUAL/PUTAWAY с SOURCE_TASK_ID; replay тот же TASK_ID, другой payload того же ID — отказ, второй активный план запрещён.
3. Через прежние assign/start/complete: чужие сканы, частичный qty, другой UID/WARE/policy — отказ. Полное движение сохраняет сумму P/H, DONE/SYNCED, источник0/назначениеполныйqty.
4. Одна immutable placement и один STORE_RETURN_PLACED в существующем SAP outbox; документ STORE_RETURN CONDITION2, новой закупки нет. EXPORTED означает локальный XML-файл, не ACK.
5. Права: warehouse_return_place + warehouse_task_execute + QUARANTINE_MOVE и привязка к принимающему складу. Проверить действительным пользователем не GLOBAL_ADMIN.
6. Две конкурирующие паллеты на последнюю ёмкость: только допустимая сумма; исходное qty не потеряно. Отмена/повторный план не удаляют историю.
7. Посмотреть slow SQL конкретного кейса. UNION UID по конкретной ячейке вместо полного сканирования PP; не повышать тайм-аут и не менять товарный баланс для прохождения.
Сохранить команды/ответы/точные Oracle факты отдельно от author evidence. Недоступные условия не отмечать пройденными.
