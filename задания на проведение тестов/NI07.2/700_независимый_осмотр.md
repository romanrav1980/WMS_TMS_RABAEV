# NI07.2: независимые заявления осмотра

Использовать существующую последнюю сверку дня на выделенном dev-складе. Не менять товарные остатки и защищённые источники.

1. Пользователь начальника склада с warehouse_day_inspect сохраняет EMPTY или NON_EMPTY и пояснение.
2. Другой пользователь диспетчера с transport_dispatch_edit сохраняет независимое заявление. Один пользователь не подписывает обе роли.
3. Повтор неизменённого operation_id возвращает исходный результат. Другое тело того же ID, дубль роли, чужой склад, удалённый пользователь и неверный source_hash отвергаются.
4. После потери ответа используйте исходную сохранённую команду и resolve. Смена пользователя не должна отправлять старый intent.
5. Если captured shipping register не подтверждает пустоту, две подписи EMPTY не дают shipping_zone_confirmed_for_frozen_review=true. Day/stock/external closure всегда false.
6. Прямой update/delete журнала запрещён. Native metadata rollback отдельно от приёмочных исходников; не удалять сохранённую историю case698.

Авторская адресная проверка case698 пройдена. Qwen выполняет независимый разбор и браузерный сценарий, сохраняет фактические результаты без автоматического закрытия спринта.
