# Qwen — количественный баланс оборотной тары
Источник: процесс11 и wiki/database/nicora_ni063_tare_ledger_20261010.md. Oracle dev RABAEV/orcl. Авторские факты не выдавать за независимую приёмку.
1. На собственном owner/type/source разрешённый COUNT с версией/причиной/решением. Неверная версия, дробь, отрицательное количество, чужой склад, прямой DML/удаление истории — отказ.
2. Склад→машина→магазин6, обратно4→машина→склад: магазин2, склад4, машина0; до складской приёмки возврат4 остаётся у машины.
3. SOURCE/DEST текущие владельцы; действительный dedicated driver, адресный store receiver; две разные подписи, чужой рейс/машина/магазин/скан запрещены.
4. GOOD/DAMAGED отдельны. Товарные P/H/марки/вложенные SSCC не меняются и не умножают тару.
5. OFFER не меняет/не резервирует количество. ACCEPT partial≤offered, непринятое у источника; duplicateofferaccept отвергается. Replay исходного actor/body/ID возвращает прежнее количество без повторной дельты.
6. Два ACCEPT на общий source: одна и та же единица не расходуется дважды; отказ без журнала/баланса/outbox. После неизвестного результата повтор исходной операции.
7. Raw tare-ledger и React inventory TarePanel: тип/склад выбраны изсправочника, пароль в памяти; смена пользователя/рейса очищает старые формы, восстановление intent ограничено actor/trip/API.
8. Bounded SQL/slow decision, независимые Oracle факты/ответы. Исходный авторский fixture6 уже проведён, не запускать повторно.
Открытые сроки/претензии/повреждения/планирование не помечать passed этим сценарием.
