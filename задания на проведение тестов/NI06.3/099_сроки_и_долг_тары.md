# Qwen — сроки и задолженность оборотной тары
Источник: процесс11/wiki/database/nicora_ni063_tare_deadlines_20261010.md. RABAEV/orcl dev. Не запускать одноразовый seed на уже проведённом6/4.
1. STORE override/CUSTOMER fallback через существующий активный точный адрес. Неоднозначный клиент/неизвестный адрес/невалидный timezone/DAYS без daycount — отказ.
2. Новая VEHICLE→STORE приёмка без политики запрещена без частичного баланса/journal/outbox. После настройки policy snapshot входит в тот же commit, sourceQty точно уменьшается.
3. SAME_DAY, DAYS до конца N-го следующего календарного дня в явно заданномtimezone, граница местной полуночи. API due — явный UTC ISO8601, не локальная дата без зоны.
4. NEXT_DELIVERY: план/отмена/выезд сами не дают просрочку; реальная последующая STORE_RECEIPT_FACT и другой TT вызывают наступление срока. Свой исходный рейс не считается следующей доставкой.
5. Изменение текущего правила не меняет старые due/version; source snapshot immutable. Legacy выдачи без snapshot — UNCONFIGURED_LEGACY, не новый придуманный срок.
6. Две выдачи/частичные возвраты: FIFO исходных долгов, количество неотрицательно, storeBalance равен сумме outstanding. Машина→склад не закрывает долг повторно; planned return не увеличивает warehouseavailable.
7. Права warehouse_settings_edit для настройки, tare_view+actual binding для debt, tare_manage только явно разрешённому департаменту. чужие магазина/склад/driver rows скрыты.
8. UI смена scope/actor/trip сбрасывает актуальную версию; uncertain PUT требует нового read. Выбор timezone явный; no password storage.
9. Проверить actual slow SQL/window/index pushdown на своих bounded данных. Не утверждать миллионы/сутки по малому author-case.
Клиент/NEXT_DELIVERY ещё не независимо приняты; зафиксировать реальные результаты отдельно.
