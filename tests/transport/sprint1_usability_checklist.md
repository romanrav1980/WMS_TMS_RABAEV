# Sprint 1 — UI / UX checklist

Среда: frontend `http://127.0.0.1:3000/?page=transport`, API `http://127.0.0.1:8088`.

## Функционал таблицы СТ

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| U1.1 | Открыть страницу диспетчера | Заголовок «Диспетчер отгрузки», вкладка «Заявки», таблица СТ видны без ошибок | |
| U1.2 | Проверить заголовки таблицы | Есть колонки склад, паллеты, вес, объем, регион, адрес, СТ №, рейс, дата, %, район, тип ТС, стол, примечание, полнопалетная отборка | |
| U1.3 | Выделить одну СТ | Счетчик выбранных и PMV totals обновились | |
| U1.4 | Включить «Выделить все» | Выбраны все видимые СТ, PMV totals равны сумме таблицы | |

## Фильтры

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| U2.1 | Сменить дату СТ | UI отправляет `stdate`, список обновляется | |
| U2.2 | Ввести адрес/регион | UI отправляет `addr_mask`, остаются только подходящие строки | |
| U2.3 | Ввести номер СТ | UI отправляет `st_mask`, остаются подходящие строки | |
| U2.4 | Включить «НЕ эти СТ» | UI отправляет `st_mask_exclude=true`, указанная СТ исключается | |
| U2.5 | Выбрать тип ТС | UI отправляет `transport_type`, все строки имеют выбранный тип | |
| U2.6 | Включить «Только собранные» | UI отправляет `assembled_only=true`, строки имеют `% > 0` | |
| U2.7 | Включить «Только НЕ собранные» | `assembled_only` сброшен, UI отправляет `not_assembled_only=true` | |
| U2.8 | Задать `V<` и `M<` | UI отправляет `max_volume_m3` и `max_weight_kg` | |
| U2.9 | Нажать «Сбросить» | Все фильтры возвращаются к значениям по умолчанию | |

## Производительность и непротиворечивость

| # | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| P1 | Первичная загрузка таблицы до 500 СТ | API ответ не хуже 2 секунд на dev seed | |
| P2 | Пустая дата | API возвращает `[]` быстро, без тяжелого скана | |
| B1 | `PALLETS_COUNT`, `WEIGHT_KG`, `VOLUME_M3` | Значения неотрицательные | |
| B2 | `VERIFY_PERC` | В диапазоне 0-100 | |
| B3 | `ST_NUMBER` | Уникален в ответе | |
