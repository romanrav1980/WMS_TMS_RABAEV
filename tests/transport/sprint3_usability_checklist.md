# Sprint 3 — UI / UX checklist

Среда: frontend `http://127.0.0.1:3000/?page=transport`, API `http://127.0.0.1:8088`.

## Вкладка маршрутов

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| U1.1 | Открыть вкладку «Маршруты» | Таблица рейсов видна без ошибок | |
| U1.2 | Проверить колонки | Отгрузка, ID, паллеты, вес, объем, тип, машина, водитель, док, регионы, цена, ТК, логист, статус, биллинг | |
| U1.3 | Изменить дату маршрутов | UI отправляет `shipment_date`, таблица обновляется | |
| U1.4 | Включить «Кратко» | Второстепенные колонки скрываются, основные остаются | |

## Состав рейса

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| U2.1 | Кликнуть строку рейса | Открывается панель «Рейс #ID» | |
| U2.2 | Проверить таблицу состава | Есть СТ №, адрес, паллеты, вес, зона, окно, тип погрузки | |
| U2.3 | Проверить PMV рейса | P/M соответствуют строкам состава | |
| U2.4 | Сохранить примечание | `PATCH /tasks/{id}` проходит, текст виден после reload | |

## Бизнес-инварианты

| # | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| B1 | `ST_COUNT` в списке рейсов | Равен числу уникальных `ST_NUMBER` в составе | |
| B2 | `PALLET_COUNT` в списке рейсов | Равен сумме паллет состава | |
| B3 | Фильтр `task_id` | Возвращает ровно один рейс | |
