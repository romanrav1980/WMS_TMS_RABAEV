# Возврат содержимого связанной сборки TRADECASE

Статус: подготовлено, НЕ ПРИМЕНЕНО. Возврат выполняет прежний RRL_STOCK_CASE_RETURN_CMD: все места возвращаются по сканам исходных ячеек, резерв освобождается, сборка отменяется. Новая ветка допускает только физические lot связанной сборки и не применяет к обратному движению ограничения нового заказа. Право case_pick_manage и текущий operate по каждому собственнику проверяются отдельно.

RRL_TRADE_CASE_RETURN_UNIT сохраняет ссылки на физические единицы перед удалением временной связи CASE_CARRIER_LOT. Это история доступа, не остаток и не новое право записи товаров. Capture вызывается только существующим native return, сверяет контекст операции/транзакции и удержание unit/stock locks. Откат caller должен откатить историю вместе с движением. После завершения история позволяет повторно проверить текущего собственника до выдачи cached receipt. Обычные сборки вне TRADECASE не записываются в эту таблицу.

До физического возврата выполнить checkpoint, apply/verify/rollback/reapply/verify через OracleApply. Откат после записанной истории запрещён. Проверить role-only manage с BLC-only, отказ без manage/owner, неверную ячейку, caller rollback, commit/exact replay/отзыв owner после возврата и склад250/HARD10. Возврат1EA не делает исходный ошибочный отбор целого короба принятым.
