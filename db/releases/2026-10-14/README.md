# Установка RETAILCASE WMS/TMS с нуля

Версия комплекта: 14.10.2026. Схема: **RABAEV**. Основа — снимок действующей структуры Oracle и исходного кода хранимых программ, а не последовательное воспроизведение старых миграций.

## Состав комплекта

| Файл | Содержание |
|---|---|
| manifest.json | Список объектов, дата выгрузки, SHA-256 файлов, необходимые прямые права SYS |
| 10_sequences.sql | Последовательности; исходные значения сохранены, не сбрасываются в 1 |
| 20_tables.sql | Таблицы, типы полей, defaults, PK/UK/CHECK и связанные служебные объекты |
| 30_indexes.sql | Отдельные индексы, включая действующие индексы с историческими именами BIN$ |
| 40_views.sql | Представления |
| 50_packages.sql | Спецификации пакетов |
| 51_functions.sql | Отдельные функции |
| 52_procedures.sql | Отдельные процедуры |
| 53_package_bodies.sql | Тела пакетов |
| 60_foreign_keys.sql | Внешние ключи после создания таблиц |
| 65_catalogues.sql | Минимальные технические справочники и выключенная совместимость старой проводки |
| 66_comments.sql | Читаемые комментарии к таблицам/полям; повреждённые исходные комментарии перечислены в manifest |
| 70_triggers.sql | Триггеры, включая действующие legacy-объекты с историческими именами |
| 71_trigger_states.sql | Восстановление ENABLED/DISABLED каждого триггера |
| 05_contexts.sql | Прикладные контексты; в текущей схеме отсутствуют |

Все SQL-файлы — UTF-8. Табличные данные из рабочего dev-стенда не переносятся, кроме явно перечисленных технических каталогов. Заказы, паллеты, остатки, движения, сообщения интеграций, пользовательские пароли и журналы не входят в стартовое наполнение. История миграций остаётся в `db/migrations` для сопровождения действующих установок; повторно накатывать её поверх этого снимка не нужно.

## 1. Требования

- Oracle Database 19c с поддержкой используемых JSON/PLSQL функций; код снят с текущего dev-стенда. Промышленная редакция и лицензирование определяются отдельно.
- Пустая схема RABAEV в целевой базе. Переименование владельца не поддерживается: legacy-код содержит прямые ссылки на RABAEV.
- Проверенный dev-инструментарий: Python 3.13.3, Node.js 22.15.0, npm 11.12.1, .NET SDK 9.0.312.
- Python с `oracledb` и зависимостями API; Node.js/npm для React/терминала. Устанавливайте npm-зависимости по package-lock.json через `npm ci`.
- Для старого инструмента OracleApply нужен .NET SDK 9. Новый установщик ниже работает через Python.
- Git для получения этого репозитория. Локальные проекты SAP/SAP_INTEGRATION не нужны для установки WMS/TMS.

Не запускайте установку поверх действующей базы. Установщик проверяет отсутствие пользовательских объектов и прекращает работу до DDL, если схема не пуста. Он не удаляет схему и не выполняет автоматическое восстановление после ошибки.

## 2. Создание владельца

Администратор целевой Oracle выполняет один раз, задавая собственный пароль. Пример ниже — шаблон, а не готовый секрет:

```sql
CREATE USER RABAEV IDENTIFIED BY "REPLACE_WITH_YOUR_PASSWORD"
  DEFAULT TABLESPACE USERS TEMPORARY TABLESPACE TEMP
  QUOTA UNLIMITED ON USERS;
GRANT CREATE SESSION, CREATE TABLE, CREATE SEQUENCE, CREATE VIEW,
      CREATE PROCEDURE, CREATE TRIGGER, CREATE TYPE, CREATE SYNONYM
  TO RABAEV;
GRANT EXECUTE ON SYS.DBMS_LOCK TO RABAEV;
GRANT EXECUTE ON SYS.DBMS_FLASHBACK TO RABAEV;
GRANT EXECUTE ON SYS.DBMS_CRYPTO TO RABAEV;
GRANT SELECT ON SYS.V_$SESSION TO RABAEV;
GRANT SELECT ON SYS.V_$SQL TO RABAEV;
GRANT SELECT ON SYS.V_$SQLAREA TO RABAEV;
```

Права должны быть прямыми: прав через роль недостаточно для компиляции definer-rights PL/SQL. SUPERMAG не является внешней compile-зависимостью текущего снимка; отдельный старый обмен с ним требует собственной настройки и не включается автоматически.

## 3. Проверка комплекта без изменения БД

Из корня репозитория:

```powershell
python -m pip install oracledb
python scripts/install_oracle_release.py
```

Команда проверяет контрольные суммы и границы SQL-операторов. Без ключа установки она не подключается к БД и не выполняет SQL.

## 4. Установка и минимальное наполнение

```powershell
$env:WMS_ORACLE_DSN = '127.0.0.1:1521/orcl'
python scripts/install_oracle_release.py --install-empty-rabaev
```

Установщик запросит пароль RABAEV и отдельный пароль администратора приложения; ввод не отображается. Для автоматизации разрешены переменные `WMS_ORACLE_PASSWORD` и `RETAILCASE_INITIAL_ADMIN_PASSWORD`, получаемые из внешнего хранилища секретов. Не сохраняйте значения в Git.

Порядок: проверка пустой схемы/прав → последовательности и таблицы → индексы → хранимый код/представления → FK и справочники → перекомпиляция → стартовые записи → триггеры и их состояния → проверка объектов и компиляции.

Стартовые записи:

- `GLOBAL_ADMIN` и пользователь `admin` с введённым при установке паролем. Все полномочия предоставляются существующей семантикой группы, без копирования паролей dev-стенда.
- Склад `1 / Initial warehouse` как исходная настройка администратора. Это не готовая топология РЦ: адреса и зоны создаются при настройке склада.
- Технические каталоги типов ресурсов, паллет и транспорта из списка `catalogue_rows` в manifest.
- Собственный пустой baseline `EMPTY-INSTALL-20261014`, активное ядро проводки и обязательные CONFIG/RELEASE ключи блокировок.
- `STOCK_LEGACY_TRIGGER_ENABLED=0`: физические движения выполняются явными командами нового ядра.

Завершённая установка открывает административный вход и настройку системы. Для приёмки, отбора и перевозки необходимо выполнить раздел 6. Пустая база не содержит вымышленных заказов или остатков.

Если установка прервалась, DDL Oracle уже зафиксирован. Сохраните ошибку и исправьте причину. Повторный запуск на частично созданной схеме будет отклонён. Не удаляйте действующую RABAEV; для повторения чистой установки администратор должен подготовить именно нерабочую пустую целевую схему.

## 5. API и интерфейсы

```powershell
python -m venv api/wms_api_server/.venv
api/wms_api_server/.venv/Scripts/python.exe -m pip install -r api/wms_api_server/requirements-release-20261014.txt
npm.cmd --prefix admin/wms_admin_frontend ci
npm.cmd --prefix terminal/wms_terminal_web ci
```

Задайте `WMS_ORACLE_USER=RABAEV`, `WMS_ORACLE_PASSWORD` и `WMS_ORACLE_DSN` в окружении процесса API. Переменные и допустимые настройки приведены в `api/wms_api_server/.env.example`; само наличие .env не заменяет передачу переменных стартовому процессу.

В отдельных терминалах из корня проекта:

```powershell
.\serv.bat
.\front.bat
.\terminal.bat
```

Скрипты освобождают свои целевые порты перед запуском. Используйте их на выделенном dev-хосте, а не как production service manager.

- API: `http://127.0.0.1:8088`; схемы: `/docs`, `/openapi.json`.
- ARM: `http://127.0.0.1:3000`.
- Raw административные страницы: `http://127.0.0.1:8088/wms-admin`.
- Терминал: `http://127.0.0.1:3010`.

Вход: `admin` и пароль, заданный при установке. Если используется dev-подстановка Basic Auth в ARM, до запуска front.bat задайте `VITE_ADMIN_BASIC_AUTH` в формате `admin:<ваш пароль>`; стартовый скрипт сохраняет заданное значение. Эта dev-подстановка попадает в клиентский bundle и недопустима для промышленного UI. Для боевого развёртывания задайте HTTPS, разрешённые CORS origins, способ запуска фоновых процессов, размеры пулов Oracle, резервирование и хранение файлов по [эксплуатационным документам](../../../wiki/index.md). Маршрутные провайдеры OSRM/Valhalla, печать, весы и реальные интеграции настраиваются отдельно; не подменяйте их ответами демонстрационного режима.

## 6. Настройка до первой операции

1. Заполнить реальные склады, зоны, адреса, недоступные/карантинные ячейки, топологию и точки отгрузки.
2. Создать пользователей и группы, ограничить области доступа; не использовать администратора для обычных складских операций.
3. Настроить файловый обмен SAP и загрузить артикулы/упаковки/единицы через ARTMAS10. Для каждого применимого SKU задать маркировку и допустимые способы сканирования.
4. Заполнить магазины, правила паллет, окна приёмки и ограничения подъезда. Настроить автопарк, водителей и ресурсы смены.
5. Настроить устройства, этикетки, пути файлов и фоновые процессы. Включать внешние отправки только после задания адресов и правил повтора.
6. Пройти согласованный сквозной сценарий на контролируемой поставке: основание → приёмка → размещение → заказ/СТ → отбор → контроль → погрузка → приёмка магазина.

## 7. Проверка установленной схемы

```powershell
python scripts/install_oracle_release.py --verify-only
```

Проверяются обязательные объекты, INVALID и выключенный режим старой проводки. Дополнительно используются предметные сценарии из `reports/retailcase/2026-10-13` и заданий на тестирование; структурная проверка не заменяет проверку склада.

Комплект сверяется с исходной живой схемой. Полная репетиция установки на отдельном пустом экземпляре в этой публикации не проводилась. Это ограничение зафиксировано, чтобы не выдавать экспорт SQL за проверенную промышленную установку.

## Обновление снимка сопровождающим

`python scripts/export_oracle_release.py` выгружает структуру только для чтения. Затем `api/wms_api_server/.venv/Scripts/python.exe scripts/finalize_oracle_release_metadata.py` добавляет комментарии, счётчики дополнительных объектов и версии библиотек из окружения API. Генераторы справочников: `scripts/document_oracle_release.py` и `scripts/document_api_release.py`. Обновление снимка — отдельный релиз; не подменяйте опубликованную версию без новой сверки.
