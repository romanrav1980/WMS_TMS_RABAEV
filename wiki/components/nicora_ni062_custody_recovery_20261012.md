# NI06.2: восстановление повреждённой операции передачи возврата

Checkpoint660, 12.10.2026. Владелец интерфейса — delivery. Бизнес-передача остаётся в прежнем return-custody API и Oracle-ядре; новых проводок и таблиц нет.

## Поведение
Сохранённая операция читается с проверкой структуры, типа действия, исходных ссылок, точных строк количества/массы, числа мест и состава сканов. Профиль допускает 80 байт UTF-8 по действующему контракту. Валидный исходник сохраняет operation_id и payload для точного повтора.

Повреждённый исходник блокирует новую передачу. Явное восстановление сначала сохраняет исходный текст в локальный архив, затем читает разрешённый текущему пользователю список ещё не подтверждённых передач. Очистка выполняется только в прежнем контексте API/пользователя/рейса/магазина/роли и при неизменившемся исходном тексте. Ошибка хранения, чтения сервера или изменение другой вкладкой сохраняет блокировку. Пароль не сохраняется.

Это восстановление интерфейса, а не доказательство результата неизвестной операции. Повторная бизнес-передача проверяется прежним сервером по оригинальному источнику и действующим ограничениям.
