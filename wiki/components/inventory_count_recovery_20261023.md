# Пересчёт: неизвестный исход и конфликт операции

23.10.2026. Исправлен обработчик POST /api/inventory/stock-posting/inventory/counts. Раньше он отвечал outcome_confirmed=true при REQUEST_DEADLINE, LOCK_RETRY_EXHAUSTED и конфликте содержимого операции. Первый тайм-аут мог удалить сохранённый запрос из inventory-count.js, хотя проведение не было подтверждено.

Отдельный catch StockPostingError удалён. Ошибки команды теперь обрабатывает существующий общий inventory/api/error_handlers.py, как для остальных stock-команд. Тайм-аут/неизвестный исход возвращает503, outcome_confirmed=false и разрешение повторить прежний запрос. Конфликт тела возвращает409, outcome_confirmed=false и operation_id_conflict=true. Проверенный отказ native-правила сохраняет409; проверка прав остаётся403. Алгоритм пересчёта, исполнителя и проводки не менялся.

Девять ASGI-проверок с подставленной ошибкой сервиса проверяют HTTP-код, исходный operation_id, точную строку количества, признак подтверждения и режим повтора. Вместе с task-scoped boundary прошли18проверок. Это проверка классификации ошибок API, не новый физический пересчёт и не аппаратное испытание. Oracle-записи и новые транзакции тест не выполняет; SQL/индексы не изменялись.

Файлы: api/wms_api_server/app/modules/inventory/api/inventory_count_routes.py; tests/retailcase/test_inventory_count_outcomes.py. Исправление загружено штатным рестартом без reload: текущий API PID78876/session69030. Полный T11-инвентаризационный цикл остаётся открытым.

## Проверка реального пересчёта 23.10

Codex создал ревизию 415 только на собственном складе 210564699 и пересчитал три маркированные партии 20+20+210 единиц. В каждой строке факт совпал с остатком: delta 0, без FOUND/LOST. Повтор прежней команды сохранил одну складскую операцию; изменение причины под прежним operation_id отклонено. После отзыва legacy-права повтор запрещён. Ревизия закрыта штатной REVIZION.close_revision, пользователь отключён, права удалены. Все 250 идентификаторов единиц, текущие паллеты и статусы сохранились; остаток 250/H0, INVALID0.

Протокол: `runtime/test-evidence/tradecase/2026-10-23/T11/inventory-equal-count.json`, статус PASS_EQUAL_COUNT_ONLY. 16 HTTP-вызовов включают подготовительные чтения до исправления тестового SQL. Пересчёт занял 1341 мс на 250 ключах. Свежий slow SQL содержит проверку допуска 8 мс и не даёт разложения всех фаз writer. Решение: сохранить ограниченный пакет; перед промышленным прогоном Codex должен снять фазы coordinator/native на большем наборе. Индекс без измеренного плана не добавлять. Недостача, обнаружение маркированного товара и физический бумажный режим этим тестом не приняты.

## Регистрация обнаруженной партии

При подготовке следующего участка найден отдельный обработчик StockPostingError в InventoryObservations.register_lot. Он терял признаки неизвестного исхода и конфликта операции: девять новых ASGI-проверок воспроизвели несовместимость с общим контрактом. Обработчик удалён; команда теперь передаёт ошибку существующему stock error handler, как пересчёт. Двадцать семь проверок классификации и task scope прошли. Права и native-проводки не менялись. Это проверка HTTP-границы с подставленной ошибкой writer, а не физическая регистрация найденного товара. Обновление работающего процесса после исправления ещё требуется.
