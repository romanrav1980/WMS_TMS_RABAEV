# Скорость чтения очереди складских заданий

Фоновая очередь отвечала до1037мс. Основной SQL имел60 исполнений со средним418мс; для каждой строки повторно вызывалась проверка прав по исходному и целевому складу.

Действующий RRL_ACCESS_API.allowed сначала проверяет активность пользователя, затем возвращает разрешение глобальному администратору. SQL использует тот же текущий is_admin один раз перед прежними построчными проверками. Для обычного сотрудника сохраняются прежние аргументы проверки, включая назначенного исполнителя. Проверка живёт в текущем SQL-снимке; авторизация между запросами не кэшируется. Индексы и схема не менялись.

## Проверка

В dev RABAEV/orcl выполнены6 пар чтений в одной READ ONLY транзакции; первое чтение каждого варианта сохранено отдельно, медианы рассчитаны по оставшимся5. Каждый запрос вернул те же500 строк в том же порядке, SHA содержимого совпал. Медиана SQL снизилась199.93→78.22мс. Это результат для этой очереди и активного глобального администратора, не пропускная способность склада.

[Живая проверка доступа](../../tests/tradecase/live_task_queue_acl.py) сравнила старый и новый SQL для действующего admin, нового глобального администратора и роли одного склада. Роль увидела только своё задание. После отзыва назначения и отключения глобального администратора новая проверка скрыла данные; прежние и новые результаты совпали. Оба QA отключены, назначение отозвано; товар не менялся.

Артефакты: runtime/test-evidence/tradecase/2026-10-23/T12/task-admin-final-benchmark.json и task-acl-live.json. Первоначальная попытка обернуть каждый allowed в scalar subquery дала около3% и не включена в код. Просмотр V$SQL_PLAN недоступен. Решение: принять сокращение повторной проверки администратора, индекс по этим данным не добавлять. Скорость обычных scoped очередей и соседнего available-sts остаётся отдельной работой Codex/T12.

После штатного перезапуска API77916/session9987 выполнены6 настоящих HTTP GET:500строк, медиана пяти повторных чтений305мс; первое497мс сохранено. Это проверка развёрнутого результата, не равное сравнение HTTP до/после; параллельные фоновые чтения влияли на разброс232–720мс. Артефакт task-http-deployed.json.
