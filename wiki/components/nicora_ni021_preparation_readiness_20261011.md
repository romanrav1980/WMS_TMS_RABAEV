# Готовность исходного SAP-заказа к прежней СТ
268 — отдельный READ ONLY preparation-readiness API в fulfillment, существующий customer-orders UI показывает причины на русском. Actor/customer_order_view/currentWARE проверяются до чтения товара; служебный SAP gateway не получает просмотр. Header/календарь/срок/агрегированная исходная потребность/параметры RRL_ARTICULS и прежняя picking cell — один Oracle snapshot. Не создаёт заказ, СТ, reserve, task или stock.

Проверяются допуск ERP/прежняя подготовка/операционный статус/адрес/текущий календарь и UTC offset/неистёкший picking finish. По товару — одна карточка, ячейка своего склада, положительные вложенность/масса/три размера, отсутствие изменения количества при точном исходном Oracle ROUND, целая упаковка. Одинаковые строки агрегируются до проверки коробок; разные базовые единицы отражаются как blocker. Максимум1000 товаров, превышение отвергается. Готовность является диагностикой перед операторской укладкой: команда всё проверяет снова, транспортный/юридический допуск не выдаётся. Прежняя prepare теперь дополнительно запрещает начало после picking deadline; сохранённый replay готовой подготовки сохраняется.
