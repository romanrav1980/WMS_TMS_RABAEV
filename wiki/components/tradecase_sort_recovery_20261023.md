# Разделение паллеты: восстановление команды

23.10 Codex исправил преобразование ошибок общей складской проводки в `trade_sort.py`. Прежний обработчик терял номер операции и признаки конфликта; сбой сброса соединения после проводки превращал в обычный отказ 409. Теперь ошибку получает действующий общий HTTP-обработчик. Сервер возвращает 503 и сохраняет требование повторить исходную команду, когда её результат неизвестен. Подтверждённый отказ остаётся 409 с отдельной причиной.

Экран также должен сохранять команду при явных `outcome_confirmed=false` или `operation_id_conflict=true`, даже если текст причины не совпал с известным названием ошибки. Дополнена существующая функция классификации; формат журнала и генерация operation_id не меняются.

## Проверки

Девять ASGI-проверок реального адаптера сначала завершились ошибкой, после исправления прошли. Они подставляют ошибки в writer: тайм-аут, исчерпание повторов, непригодное соединение, неизвестный результат, сбой сброса после проводки, конфликт тела, конфликт native, отказ правила и запрет доступа. Подстановка не доказывает разрыв настоящего Oracle-соединения после commit.

Настоящий API81672 отклонил перенос из ячейки в неё же на принадлежащем тесту складе219023232. Ответ содержит исходный номер, подтверждённый отказ и причину несовместимого адреса. Все10единиц, их идентификаторы, адреса, статусы и версии остатков сохранены; APPLIED операции нет, INVALID0. Артефакт: `runtime/test-evidence/tradecase/2026-10-23/T06/sort-recovery-boundary-live.json`.

Первый запуск обвязки остановился до HTTP из-за зарезервированного имени SQL-bind `uid`. Имя исправлено на `p_uid`; первоначальный FAIL сохранён отдельно. Настоящий отказ занял870мс после запуска API; новых записей slow SQL не было. Для одного отказа индекс не добавляется; задержка первого вызова остаётся в T12 для сопоставления с повторными чтениями и загрузкой пакетов.

Общий набор TRADECASE после серверной правки:273проверки прошли. Сборка CVnDDJG0 прошла8браузерных проверок при1440/390: первый503, первый409 с явным признаком неизвестного результата, перезагрузка,403 при повторе, неизменное тело и подтверждённое завершение. Ответы разделения подставлены; бизнес-POST в Oracle из браузера не поступали. Проверены подсказки, локальная справка и ширина; мобильный PNG просмотрен. Первые браузерные запуски выявили ошибки обвязки: действие до загрузки пользователя и ожидание видимости скрытого мобильного меню. Обвязка ждёт загрузки учётной записи, не раскрывая меню ради теста.
