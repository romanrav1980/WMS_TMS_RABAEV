# СНС/BLC: автоматическая повторная проверка документов

Исполнитель повторно проверяет сообщения, ожидающие справочников. После загрузки отсутствующего справочника он принимает документ либо сохраняет окончательный отказ. Исходная квитанция остаётся неизменной; карточка сообщения показывает отдельный текущий результат.

Администратор запускает исполнитель для указанных складов под существующей служебной учётной записью. Учётной записи нужны права импорта и просмотра этих складов. Финансовые основания обрабатываются только при отдельном праве их импорта. Исполнитель не создаёт учётные записи и не выдаёт себе права.

## Запуск

Из корня репозитория:

```powershell
python scripts/trade_deferred_worker.py --warehouse 123 --actor service_account --interval 30
```

Заменить склад и учётную запись действующими значениями. `--once` выполняет один цикл и завершает процесс. Без него процесс повторяет цикл; Ctrl+C прекращает работу после текущей транзакции. Интервал не меньше15секунд, за один цикл одного склада проверяются не более25сообщений. Один процесс обслуживает не более10явно заданных складов. Автоматический запуск на всех складах не включён.

Занятый другим исполнителем склад пропускается до следующего цикла. Ожидающие сообщения выбираются сначала по числу попыток, затем по времени последней проверки. Принятые и окончательно отклонённые сообщения повторно в пакет не попадают. Ошибка транзакции откатывает весь текущий пакет; после перезапуска сообщения остаются в очереди.

## Техническое приложение и доказательства

Владелец — integrations. `TradeDeferredWorker.reconcile` захватывает разделяемую блокировку версии доступа, проверяет текущие права, затем блокирует строку площадки через `FOR UPDATE SKIP LOCKED`. Порядок совпадает с native приёмом. Для каждого сообщения вызывается существующий `RRL_TRADE_DOCUMENT_API.retry_document`; новые правила приёма и товарные проводки не добавлены. Пакет фиксируется одной gateway-транзакцией вместе с текущими результатами и resolution-outbox. Другие склады обрабатываются отдельно. Новых объектов Oracle нет.
