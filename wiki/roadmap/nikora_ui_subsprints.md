# NIKORA: подспринты интерфейсов и функциональных сценариев

Дата: 15.09.2026. Уточняет [[roadmap/nikora_functional_sprints]] и [[roadmap/nikora_architecture_sprints]]. ТЗ: [[requirements/nikora_ui_workplaces_tz]], [[requirements/nikora_ui_quality_tz]], [[requirements/nikora_ui_reachtruck_tz]], [[requirements/nikora_ui_reachtruck_dispatch_tz]].

## 1. Единица планирования и порядок

Детализация для запуска агентов: [каталог индивидуальных ТЗ](../requirements/nikora_sprints/index.md), [[roadmap/nikora_agent_delivery_plan]]. **23 инкремента на этой странице — родительские группы; исполнимых функциональных карточек теперь 28.** F5.1 → F5.1a/F5.1b; F7.3 → F7.3a–F7.3e. Архитектурных карточек 10; S0 и P1/P2 отдельно. Требования экранов ниже сохраняются, бюджет и ограниченный scope определяют новые карточки.

F1–F7 теперь **функциональные этапы**, а не обещание семи двухнедельных спринтов. Ниже 23 законченных функциональных инкремента; каждый можно принять отдельно через UI+API+состояние данных. Их можно объединять в календарный спринт только после оценки команды, сохраняя отдельные gates. Каждый включает работающий сценарий, не только рисунок экрана.

Порядок для одной команды:

```text
A1 → F1.1 → F1.2 → F1.3
→ A2 + A2.Q + A3
→ F2.1 → F2.2 → F2.3 → F2.4 → F2.5 → F2.6 → F2.7
→ F3.1 → F3.2 → F4.1 → F4.2 → F4.3
→ F5.1 → F5.2 → F6.1 → F6.2
→ F7.1 → F7.2 → F7.3 → F7.4 → P1 → P2
```

Канонический перечень: F1=3, F2=7, F3=2, F4=3, F5=2, F6=2, F7=4, итого **23**. Нумерация этапов сохранена для ссылок AT; календарь пересчитывается по инкрементам и отдельной архитектуре.

Оценку «20 недель + пилот» прежнего плана нельзя сохранять после добавления полноценных ТСД, двух независимых контролей и весов. Для оценки предусмотреть отдельную трудоёмкость 23 функциональных и 4 архитектурных инкрементов, интеграций внешних WMS и оборудования. Длительность каждого определяется на refinement по коду/данным; дата завершения пока не обещается. Пилот P1/P2 остаётся отдельным.

Внешние адаптеры получают контракт на F1.2/F1.3 и реализуются владельцами параллельно дальнейшим этапам. F1.3 проверяет исходящие события на явно тестовых причинных fixtures; настоящие производители фактов подключаются в F2/F3/F4/F6 и проверяются end-to-end на F7.3. Нельзя выдать harness за готовность реального ERP.

## 2. Отдельный архитектурный поток

| Инкремент | Что строим, без продуктовой UI-работы | Отдельная приёмка |
|---|---|---|
| A1 | XML master data/OrderManifest/4 ERP events, inbox/outbox, ключи и версии, права/аудит; read contracts интеграционной очереди | Дубли/обрыв/зависимости/чужой source, dry-run без бизнес-эффекта |
| A2 | HU/состав/преобразования, parts, версии и баланс, custody | Aggregate/seam/repack, concurrency, legacy ID и NIKORA SSCC |
| A2.Q | Сессия качества, независимые проходы, scan facts, осмотр, измерение и версионируемый допуск; adapter seam весов | Q-01…10 через API, инвалидирование допуска, запрет stale PASS при погрузке |
| A3 | Плечи/волны/ворота, единый hard-validator и идемпотентный apply; projected worklists, resource claim и физические события | Ручная/auto-команда одинаково проверяются; LOADED не DEPARTED; concurrent claim |

Права, серверные блокировки и команды — архитектура; компоновка/сценарии/аппаратная интеграция поста — функциональность. A2.Q сначала проверяет возможность расширения текущих событий/lot-check; новые таблицы только если существующий механизм не хранит нужные независимые факты. Нет отдельной платформы workflow.

## 10. Общий gate каждого подспринта

Готово = законченное действие пользователя + реальный API/Oracle effect + отрицательный сценарий + наблюдаемость + права + инструкция. Для внешней зависимости различать contract-ready и production-ready. Каждый тест фиксирует SHA, fixture, версию схемы/правил, UI-результат и SQL evidence. На live-gates анализировать длинные запросы по [[runbooks/slow_sql_review]].

Эти документы и рисунки — проектирование. Их просмотр/локальные клики не означают прохождение ни одного функционального или аппаратного gate. После F7.4 — ручной пилот P1, затем ограниченный auto P2 по основному плану.
