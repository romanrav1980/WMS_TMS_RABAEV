# Следующий инкремент KPI: источник фактического времени

15.10.2026. Это план реализации, а не уже работающий API/Oracle ledger. Утверждённая формула времени реализована в [[../components/retailcase_picker_time_denominators_20261015]], бизнес-паспорт — [[../concepts/retailcase_kpi_passports_20261015]].

## Проверенные источники и пробел

Live USER_TAB_COLUMNS подтвердил: RRL_RESOURCE_SESSION.LOGIN_AT/LOGOUT_AT/heartbeat, RRL_RESOURCE_SHIFT.START_AT/FINISH_AT, RRL_RESOURCE_FACT_EVENT.EVENT_AT и CASE_PICK_EVENT.CREATED_AT — TIMESTAMP без timezone. CASE STARTED_AT_INSTANT и WAREHOUSE_TASK STARTED_AT_INSTANT/FINISHED_AT_INSTANT уже WITH TIME ZONE. Одного aware начала недостаточно для подтверждённых пауз, окончания и фактической смены. Исторические naive события нельзя молча интерпретировать как UTC/пояс браузера; план смены и heartbeat не заменяют фактическое время. [Фактические типы](../../reports/retailcase/2026-10-15/case-work-ui/kpi-native-time-types.json).

## Порядок реализации AK07

1. Resources owner фиксирует отдельные факты WORK_START/PAUSE/RESUME/WORK_FINISH и ACTUAL_SHIFT_START/FINISH. Выбор подтверждающего источника (оператор/старший/интеграция) оформляется явно. Логин в приложение сам по себе не является началом фактической смены.
2. Подтверждённый переход получает aware server instant, actor/operator, source_kind+source_id, рабочую сессию/ресурс/фактический склад, текущую версию и operation_id. При START/COMPLETE существующих задач запись производится в одной owner TX с соответствующим переходом; не вторым независимым коммитом. Native доступ под текущими scoped fences, не frontend-проверка.
3. Exact retry не добавляет событие, конкуренция проверяет версию и единственный активный интервал оператора. Передача ресурса/задачи не удваивает время. Коррекции — связанные неизменные факты и текущая подтверждённая редакция, без переписывания истории. Открытый/пропущенный интервал не достраивается произвольной границей между сканами.
4. Серверный read adapter отдаёт kernel подтверждённые интервалы и полноту WORK/PAUSE/ACTUAL_SHIFT в одном as_of. Только клиентский confirmed:true не создаёт полноту. При неизвестной части — NO_DATA, а не частично заниженный знаменатель.
5. Для группы складов объединение времени выполняется по каждому человеку до суммирования людей. Один оператор в двух одновременных задачах не даёт два человеко-часа. Ограниченная область доступа не должна выдавать неполное время за полное; правила отчёта по одному складу при переходе между складами требуют явного контекста интервалов.
6. После согласования числителей подключить строки/час и коробки/час по обоим основаниям. Групповой коэффициент — сумма подтверждённых объёмов / сумма соответствующих часов, без простого среднего индивидуальных коэффициентов. В UI — период, основание, версия, полнота и переход к событиям/справке.

## Что ещё согласуется

Определение завершённой строки и её начисление при нескольких исполнителях; EA/неполные коробки/переупаковка; учёт связанного возврата или исправления уже выполненного труда. Консолидация HU/повторный скан/взвешивание/приёмка магазином не становятся новым складским подбором. Для доставки вовремя отдельно выбирается подтверждённое прибытие либо начало разгрузки. Последние уточняющие вопросы владельцу пока без ответа; это не повод объявлять предложенную формулу утверждённой.

## Готовность

Codex: native owner/facts/aware clock/read adapter/права/конкурентные и rollback кейсы. Claude Code: явные действия паузы/возобновления/завершения и панели/локальная справка после готовности native контракта. Приёмка: ночь/DST, offline exact retry, две вкладки, отзыв роли, передача ресурса/склада, пропущенное событие, ноль часов, linked correction и bounded slow-SQL review. Старый naive журнал остаётся историей с неизвестным часовым основанием; массового недоказанного backfill нет.
