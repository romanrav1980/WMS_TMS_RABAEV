## Ключевые выводы

1. **WMS управляет физическим запасом, составом грузомест и складским исполнением; TMS — сетевым планом, плечами, слотами, маршрутами и доставкой.** ERP остаётся владельцем заказов/коммерческих данных и финансового учёта.
2. Для NIKORA недостаточно функции «crossdock» в каталоге. Нужны доказанные связи между разными WMS, plan/fact без двойного объёма, backward-readyBy, магазинами/календарями, качеством, HU genealogy и POD.
3. Интеграция первой: XML master+orders, бизнес-факты, durable inbox/outbox, сверка приход/расход/внутреннее перемещение/инвентаризация и четыре исходящих ERP milestone.
4. Самые рискованные WMS-кейсы: плавающий вес, неполный короб, FEFO на дату доставки, replenishment под волну, два прохода контроля, версия допуска, split по шву vs произвольный repack.
5. Текущий проект имеет полезную базу; заменять ядро или вводить микросервисы автоматически не требуется. Нужен gap по фактам и инвариантам, а не по сходству названий модулей.
6. Нет доказанного «победителя рынка». Заполнение по вендорам — **desk research**, не подписанный ответ и не тест. Публичные заявления не превращены в выдуманные баллы.

## Системы в сравнении

WMS: SAP EWM, Infor WMS, Manhattan Active WM, AXELOT WMS X5 + Blue Yonder, Oracle WMS Cloud, Infios WMS (конкретный продукт уточнить), EPG LFS, Mecalux Easy WMS.

TMS: SAP TM, Infor Nexus Global TMS, Manhattan Active TM, AXELOT TMS + Blue Yonder, Oracle OTM, Infios TMS, e2open, Alpega.

Пять дополнительных кандидатов в каждом домене подтверждены соответствующими публичными списками Gartner 2026. Это не присвоение им одинакового квадранта и не закрытая оценка Gartner.

## Как применять

Логистика/качество/розница/IT/финансы утверждают requirements и веса → вендоры дают построчный fit-gap/BoM → одинаковые D01–D12 → пилот → коммерческое и архитектурное решение. Для WMS/TMS одного вендора межсистемный тест всё равно обязателен.

Технический ранний пилот (2 источника, 3–5 магазинов, целые HU) и бизнес-пилот (4 категории, 20–30 магазинов) имеют разные цели. Первый не заменяет приёмку всех обязательных M-требований.
