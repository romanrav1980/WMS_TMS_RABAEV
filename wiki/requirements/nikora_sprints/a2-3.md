# A2.3. Перепаковка с сохранением баланса

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: architecture; родитель прежнего плана: A2. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** 2 HU перераспределены в 3 новых; количество каждой строки/партии сохранено, повтор не даёт вторую упаковку.

Входит:

- Repack N→M с lineBinding и происхождением по qty/batch/UoM.
- Определить новую тару/gross/geометрические параметры; новые HU IDs не теряют историю.
- Общий lock/version и запрет изменения loaded; события пригодности новой версии состава.

Не входит: Не создавать оптимизатор упаковки, UI или автоматическую выдачу PASS качества.

Зависимости для READY: [A2.2](a2-2.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Предлагается POST /api/nikora/handling-units/repack: inputs+expectedVersions, outputs с line allocations, tare/gross/geometry/policy. Ответ immutable operation/line provenance; all-or-nothing outputs.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- api/wms_api_server/app/services/ (HU commands)
- db/migrations/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. X1: баланс, provenance и пример 2→3.
2. H2: repack transaction/repositories.
3. X3: независимые property-based/Oracle fault tests.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. 2→3 и частичное выделение строки; catch-weight без постоянного коэффициента.
2. Два конкурирующих repack, rollback после частичного построения outputs.
3. Масса/тара по утверждённой политике, старые HU не остаются доступны повторно.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_a2_3.py и, если UI входит в scope, tests/ui/nikora_a2_3.cjs; плюс Oracle verify SQL и reports/nikora/A2.3/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **X — Критические инварианты**.

- Основной исполнитель: Codex gpt-6-astra high: контракт/опасное ядро; gpt-5.6-sol high: реализация.
- Независимая проверка/тесты: Claude Code claude-opus-5 high + Oracle concurrency tests.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **4 / 5 / 8** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **31–35** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 24.00 агент-часов (включая tool/test ожидание), 2.00 локальных server-hours, 24.00 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
