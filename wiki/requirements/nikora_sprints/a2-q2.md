# A2.Q2. Измерения веса и допуск версии HU

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: architecture; родитель прежнего плана: A2.Q. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Тестовое измерение завершает качественную сессию только при годных проходах/осмотре и актуальной версии состава.

Входит:

- WeightMeasurement: gross/tare/net, stable, device/calibration/time, policyVersion.
- Решение качества по HU+contentVersion; repack инвалидирует старый допуск.
- Catch-weight/unknown weights/manual override policy; server guard готовности к погрузке.

Не входит: Нет реальных драйверов весов и универсального процента допуска.

Зависимости для READY: [A2.Q1](a2-q1.md), [A2.3](a2-3.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

WeightMeasurement: measurementId/deviceId/measuredAt/stable/gross/tare/UoM/calibrationRef/policyVersion/HUcontentVersion. Ready endpoint выдаёт status/reasons/version, write-side loading guard проверяет снова.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- api/wms_api_server/app/services/ (quality policy)
- db/migrations/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. H1: measurement contract и параметры политики.
2. H2: admission guard + invalidation hooks.
3. H3: негативные и конкурентные тесты.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Q-06…10: out-of-tolerance/negative tare/stale device/unknown mass → HOLD.
2. Изменение HU после PASS блокирует погрузку на прежней версии.
3. Aggregate children не наследует упаковку/вес parent молча; loading race.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_a2_q2.py и, если UI входит в scope, tests/ui/nikora_a2_q2.cjs; плюс Oracle verify SQL и reports/nikora/A2.Q2/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **H — Сильный GPT, независимый Claude**.

- Основной исполнитель: Codex gpt-5.6-sol high.
- Независимая проверка/тесты: Claude Code claude-sonnet-5 high + Oracle/pytest.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **2 / 3 / 5** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **40–42** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 14.40 агент-часов (включая tool/test ожидание), 1.60 локальных server-hours, 14.40 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
