# F2.6. Водитель ричтрака: быстрый одноэкранный цикл

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: functional; родитель прежнего плана: F2.6. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Одна паллета перемещена на правильное место через один экран; сервер подтвердил завершение и выдал следующее задание.

Входит:

- UI-14: смена отдельно; источник→паллета→физическое взятие→назначение без смены страницы.
- Переиспользовать resource session/warehouse task commands, pending/custody.
- Автовыдача следующего после server ACK; короткая панель проблемы, без изменения бизнес-команд.

Не входит: Не поручать локальной модели изменение claim/transfer/stock transactions.

Зависимости для READY: [F2.2](f2-2.md), [A3.2](a3-2.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Reuse resource session/task execute APIs: taskId/version, scannedFrom/HU/to, commandId, custody event. ACK currentTask complete предшествует выдаче nextTask; scan source не доказывает подъём.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- wiki-raw/wms_admin_ui_reference/reachtruck-tsd.html (образец)
- terminal/wms_terminal_web/src/
- tests/ui/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. L1: один state-driven экран на существующих командах.
2. L2: быстрый поток скана/ошибки/планшетный вид.
3. T3: независимая проверка custody и реальное устройство.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. RT-01…08: wrong code не меняет шаг; повтор не перемещает дважды.
2. Нет связи после взятия сохраняет груз на технике; нет нового задания до сверки.
3. Терминал/перчатки/360 px, ноль переходов между страницами; новый backend write → H escalation.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f2_6.py и, если UI входит в scope, tests/ui/nikora_f2_6.cjs; плюс Oracle verify SQL и reports/nikora/F2.6/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **L — Локально, облачная приёмка**.

- Основной исполнитель: Aider + Qwen2.5-Coder-14B Q4 / Qwen3-Coder-30B Q4.
- Независимая проверка/тесты: Codex GPT-5.6 Terra medium + pytest/Playwright.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **2 / 3 / 5** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **74–76** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 14.40 агент-часов (включая tool/test ожидание), 12.00 локальных server-hours, 9.60 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

Параметры: 60% cache read / 15% cache write / 25% uncached; токены указаны суммарно по всем сессиям этого спринта, не размер одного контекста. Ваше время показано в часах, без перевода в доллары. Для локальной модели учитывается только электричество; покупка и амортизация не учитываются. ## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
