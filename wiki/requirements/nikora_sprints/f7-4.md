# F7.4. Релизный gate: права, оборудование и нагрузка

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: functional; родитель прежнего плана: F7.4. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Релиз-кандидат проходит измеренный функциональный/аппаратный/нагрузочный gate и допускается к ручному пилоту по подписи владельцев.

Входит:

- AT-01…36 и Q/RT/RD-UI, роли/sites, RU/KA, reconnect, device/scales, disaster drill.
- Зафиксировать workload, p50/p95, replay/RPO/RTO, бэкап/восстановление, slow-SQL decisions.
- Инструкции 15 ролей, feature flags, аварийный режим и release evidence.

Не входит: Не прятать новые функции и не закрывать внешние блокеры зелёным simulator-отчётом.

Зависимости для READY: [F7.3e](f7-3e.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Release manifest: SHA/schema versions/adapters/devices/roles/workload/test IDs/results/SQL decisions/rollback instructions. Непройденный обязательный gate явно BLOCKED.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- tests/nikora/
- tests/ui/
- wiki/runbooks/
- wiki/sources/

## 3. Ограниченные шаги реализации

1. H1: заморозить candidate и собрать missing regression tests.
2. L2: инструкции/отчёты/табличные fixtures.
3. H3: real load/device/recovery gate и go/no-go.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Не skipped вместо required gate; все критические paths работают на изолированном Oracle.
2. p95 event→UI/plan/scan по согласованному SLA и реальному workload; cold/warm cache отдельно.
3. Oracle slow log/top SQL/audit: rewrite/window/batch/index/stats/backlog owner на каждый длинный запрос.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f7_4.py и, если UI входит в scope, tests/ui/nikora_f7_4.cjs; плюс Oracle verify SQL и reports/nikora/F7.4/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **H — Сильный GPT, независимый Claude**.

- Основной исполнитель: Codex gpt-5.6-sol high.
- Независимая проверка/тесты: Claude Code claude-sonnet-5 high + Oracle/pytest.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **4 / 5 / 8** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **137–141** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 21.60 агент-часов (включая tool/test ожидание), 2.40 локальных server-hours, 21.60 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
