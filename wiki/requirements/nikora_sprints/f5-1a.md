# F5.1a. Безопасный savings и объяснение непопавших заказов

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: functional; родитель прежнего плана: F5.1. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Расчёт savings либо даёт допустимое предложение, либо явно оставляет неудовлетворённые заказы; ошибочный план не применяется.

Входит:

- Один solver savings: устранить выявленные нарушения type/windows/duration и silent unassigned.
- Общий hard-validator проверяет результат до любого apply; объяснение каждого исключения.
- UI-09 compare/manual preview, реальные координаты и depot без подстановки нулей.

Не входит: Не переделывать весь VRP и не добавлять OR-Tools в этот спринт.

Зависимости для READY: [F4.3](f4-3.md), [A3.3](a3-3.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Solver input — согласованная projection trip/stop/demand/vehicle/compartment; output assignments/unassigned/violations/duration/cost/seed/version. Общий validator обязателен после solver, до apply.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- api/wms_api_server/app/services/transport_service.py
- admin/wms_admin_frontend/src/components/TransportPlannerPage.tsx
- tests/transport/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. X1: Astra фиксирует constraints и эталон маленькой задачи.
2. H2: Sol ограниченно исправляет savings + explain projection.
3. X3: Opus проверяет контрпримеры и отсутствие silent drops.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Контрольные overweight/type/windows/geometry/section случаи из baseline probes.
2. Нулевые координаты в unassigned с причиной; unassigned не считается успешно обслуженным.
3. Реальный код solver и Oracle apply; fake-gateway не заменяет transactional gate.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f5_1a.py и, если UI входит в scope, tests/ui/nikora_f5_1a.cjs; плюс Oracle verify SQL и reports/nikora/F5.1a/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **X — Критические инварианты**.

- Основной исполнитель: Codex gpt-6-astra high: контракт/опасное ядро; gpt-5.6-sol high: реализация.
- Независимая проверка/тесты: Claude Code claude-opus-5 high + Oracle concurrency tests.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
