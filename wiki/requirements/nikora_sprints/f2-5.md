# F2.5. Весовой пост: один тип прибора

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: functional; родитель прежнего плана: F2.5. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Фактическое стабильное измерение одного реального прибора завершает допустимую сессию; out-of-range/нет связи блокируют.

Входит:

- Один заранее согласованный протокол/модель весов; adapter disconnect/stability/device/time.
- UI-06 gross/tare/net/expected/tolerance/policy, ручной режим только по праву.
- Связь с текущей quality session и admission guard.

Не входит: Не подключать все марки весов/универсальную метрологию; каждый новый протокол — отдельная оценка.

Зависимости для READY: [F2.4](f2-4.md), [A2.Q2](a2-q2.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Один adapter driver нормализует приборный frame в WeightMeasurement A2.Q2; UI не задаёт stable=true самостоятельно. Manual measurement помечен manual и проверяется отдельным правом.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- terminal/wms_terminal_web/src/
- api/wms_api_server/app/services/ (scale adapter)
- tests/nikora/

## 3. Ограниченные шаги реализации

1. H1: один device protocol и replay captured frames.
2. C2: экран/весовой adapter + error handling.
3. H3: аппаратная и Oracle приёмка.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Q-06…12: stale calibration, overflow, negative tare, catch-weight, malformed device frame.
2. Повтор measurementId, изменение состава после измерения, loss/reconnect.
3. Паспорт и реальные весы обязательны: simulator лишь contract-ready.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f2_5.py и, если UI входит в scope, tests/ui/nikora_f2_5.cjs; плюс Oracle verify SQL и reports/nikora/F2.5/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **H — Сильный GPT, независимый Claude**.

- Основной исполнитель: Codex gpt-5.6-sol high.
- Независимая проверка/тесты: Claude Code claude-sonnet-5 high + Oracle/pytest.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **3 / 4 / 7** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **70–73** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
