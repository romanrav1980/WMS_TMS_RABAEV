# A2.1. Стабильная часть заказа, HU и состав

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: architecture; родитель прежнего плана: A2. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Импортирован mixed-SKU HU одного магазина, строки связаны с исходными заказами, просмотр состава не требует фальшивого stock receipt.

Входит:

- Добавить стабильную FulfillmentPart/строки и общий HU/content с legacy mapping без второго заказа.
- Owner/order/line/part/SKU/batch/UoM, contentVersion, внешний SSCC и обычный legacy pallet ID.
- Read APIs поиска/прослеживания HU; состав, mass и custody без фиктивного приходного документа.

Не входит: Нет aggregate/repack, замены SHIPMENT_PART или нового stock ledger.

Зависимости для READY: [F1.2](f1-2.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Предлагается GET /api/nikora/handling-units/{id}, content и trace. HU: huId, identifier, identifierType, owner, destinationKey, sourcePartId, contentVersion, status; content rows: orderLineId/SKU/batch/expiry/UoM/qty/net/gross.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- api/wms_api_server/app/services/customer_order_service.py
- api/wms_api_server/app/services/ (новые HU repositories)
- db/migrations/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. H1: mapping legacy/новых ключей и миграция.
2. H2: HU/content repository и read contracts.
3. H3: import fixture + negative cases + Oracle verify.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Ведущие нули, дубли SSCC, чужой owner, неизвестная строка, PCE/KGM.
2. Legacy ID остаётся в обычной WMS; граница NIKORA требует валидного SSCC.
3. Oracle balance/readback, baseline picking и CRPT не изменены.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_a2_1.py и, если UI входит в scope, tests/ui/nikora_a2_1.cjs; плюс Oracle verify SQL и reports/nikora/A2.1/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **H — Сильный GPT, независимый Claude**.

- Основной исполнитель: Codex gpt-5.6-sol high.
- Независимая проверка/тесты: Claude Code claude-sonnet-5 high + Oracle/pytest.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **3 / 4 / 7** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **23–26** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
