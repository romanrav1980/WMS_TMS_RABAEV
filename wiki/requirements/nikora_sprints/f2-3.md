**Законченный проверяемый результат:** Сборщик завершил один отбор в правильный короб; неверный код не продвинул задачу, повтор запроса не удвоил количество.

## 2. Интерфейс и данные

Reuse case-pick start/scan/complete/short. Payload scanId/taskId/taskVersion/scannedCell/scannedItem/targetHU/qty/UoM; local state PENDING/CONFIRMED/CONFLICT отдельно от domain status.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- terminal/wms_terminal_web/src/App.tsx
- terminal/wms_terminal_web/src/store/localJournal.ts
- api/wms_api_server/app/services/case_pick_service.py
- tests/nikora/
- tests/ui/

## 3. Ограниченные шаги реализации

1. C1: переходы скана на существующих командах.
2. L2: состояния/ошибки/локализация и fixtures.
3. T3: Playwright+API+сканер acceptance.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Wrong cell/SKU/HU/store, повтор scanId и легитимный второй GTIN scan.
2. Offline draft/reconnect, чужое активное задание, partial qty/reason.
3. 360 px, hardware Enter, server readback; устройство нужно для финального gate.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f2_3.py и, если UI входит в scope, tests/ui/nikora_f2_3.cjs; плюс Oracle verify SQL и reports/nikora/F2.3/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **C — Claude Code Sonnet, Codex проверяет**.

- Основной исполнитель: Claude Code claude-sonnet-5 medium.
- Независимая проверка/тесты: Codex gpt-5.6-terra medium/high + тестовые runner.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **2 / 3 / 5** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **63–65** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
