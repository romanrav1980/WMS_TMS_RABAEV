# S0. Изолированный стенд и квалификация дешёвого агента

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: setup; родитель прежнего плана: S0. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Дешёвый агент делает ограниченный патч; независимые тесты ловят заложенную ошибку; нет доступа к production/секретам, сохранён baseline производительности.

Входит:

- Зафиксировать рабочую ревизию/patch существующих изменений; изолированный тестовый Oracle и очищенные fixtures.
- Инвентаризировать GPU/драйвер/PCIe; поднять локальный inference и 10 контрольных задач вне production.
- Сравнить Qwen14, Qwen30 и Luna на одинаковых задачах; выбрать прошедший профиль по цене принятого результата.

Не входит: Нет обучения модели, покупки сервера, production-доступа или автоматического исправления всей базы.

Зависимости для READY: нет; стартовая калибровка/стенд. Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Среда/артефакты: baseline SHA + patch hash; разрешённые пути; очищенная test DB; model digest, tool version, dataset hash, usage и accepted/rejected по каждому контрольному заданию.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- wiki/runbooks/nikora_agent_launch.md
- tests/nikora/ (новое)
- tools/oracle_apply/

## 3. Ограниченные шаги реализации

1. B1: стенд и baseline без изменения бизнес-кода.
2. B2: установка/проверка inference и пакет контрольных задач.
3. B3: независимая оценка, cost-per-accepted-task и выбор профиля.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Проверить 10 задач: чистая функция, 3 UI состояния, fixture, тест дубля, форматирование, документация, ошибка типизации, отказ от out-of-scope.
2. Допуск: ≥8/10 за ≤2 попытки, 0 нарушений области/секретов; дополнительно 3 сопоставимых shadow-задачи с ревью перед самостоятельными патчами.
3. Замерить tokens/s, prompt processing, VRAM, OOM, качество diff, затраты reviewer; отсутствие стенда не выдаётся за пройденный S0.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_s0.py и, если UI входит в scope, tests/ui/nikora_s0.cjs; плюс Oracle verify SQL и reports/nikora/S0/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **B — Калибровка локального исполнителя**.

- Основной исполнитель: Локальные Qwen14/Qwen30; Luna как контроль стоимости.
- Независимая проверка/тесты: Claude Sonnet 5 medium + фиксированные hidden tests.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **2 / 3 / 5** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **1–3** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 10.00 агент-часов (включая tool/test ожидание), 8.00 локальных server-hours, 12.00 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

| Роль | Модель | Вход, млн | Выход, млн | API $, базовая cache-модель |
|---|---|---:|---:|---:|
| 10 контрольных задач | Локальная Qwen | 1.000 | 0.100 | 0.00 |
| облачная контрольная выборка | gpt-5.6-luna | 1.000 | 0.100 | 0.22 |
| независимая оценка результатов | claude-sonnet-5 | 1.000 | 0.100 | 2.00 |

**API: $2.21**. Локальное электричество: $0.64. **Денежные расходы всего: $2.85; бюджет с резервом 50%: $4.28.** Консервативный вариант без cache hits, с платной записью cache и тем же резервом: $6.76.

Параметры: 60% cache read / 15% cache write / 25% uncached; токены указаны суммарно по всем сессиям этого спринта, не размер одного контекста. Output включает оплачиваемое рассуждение, если провайдер его учитывает. Смета API Standard, без подписок/налогов/инструментальных cloud fees/внешних подрядчиков. Ваше время показано в часах, без перевода в доллары. Для локальной модели учитывается только электричество; покупка и амортизация не учитываются. Цены и формулы: [[roadmap/nikora_agent_delivery_plan]]; исходные данные [budget.json](../../../wiki-raw/nikora_agent_plan_20260915/budget.json).

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
