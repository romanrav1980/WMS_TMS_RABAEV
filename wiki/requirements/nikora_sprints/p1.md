# P1. Ручной наблюдаемый пилот

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: pilot; родитель прежнего плана: P1. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Владелец бизнеса принимает наблюдаемые результаты периода и явно решает: продолжить/скорректировать/остановить.

Входит:

- 20–30 магазинов, четыре потока, оператор подтверждает выпуск, дежурные назначены.
- Ежедневная сверка quantities/trace/ERP/OTIF/dwell, инциденты и baseline cost.
- Отдельный decision log; исправления только небольших дефектов из резерва, новые функции — новый sprint.

Не входит: Затраты операторов складов/магазинов, перевозок и поставщиков оборудования не включены в AI-смету; труд техлида/QA показан отдельно.

Зависимости для READY: [F7.4](f7-4.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Daily evidence dataset: manifest demand, top-HU quantities, actual legs/receipts, original promise, exceptions and owner; подписанный manual pilot report.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- wiki/sources/
- tests/nikora/

## 3. Ограниченные шаги реализации

1. P1: наблюдение и daily reconciliation.
2. P2: разбор инцидентов на ограниченных данных.
3. P3: итоговый бизнес/технический go/no-go.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Нельзя заменить десять рабочих дней наблюдения часом генерации кода.
2. Нет необъяснённой потери/двойного эффекта, у каждого отклонения есть owner/решение.
3. Экономические выводы только по сопоставимой выборке; SQL review после каждого meaningful case.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_p1.py и, если UI входит в scope, tests/ui/nikora_p1.cjs; плюс Oracle verify SQL и reports/nikora/P1/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **P — Наблюдаемый пилот**.

- Основной исполнитель: Локальные отчёты; новые функции в пилоте не разрабатывать.
- Независимая проверка/тесты: Claude Sonnet 5 medium: разбор инцидентов; операторы/QA принимают.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **10 / 10 / 10** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **142–151** от готовности ресурсов. Внешнее ожидание не включено. Период наблюдения нельзя ускорить генерацией кода.

Ориентиры: 10.00 агент-часов (включая tool/test ожидание), 5.00 локальных server-hours, 40.00 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

|---|---|---:|---:|---:|
| сводки измерений | Локальная Qwen | 1.000 | 0.100 | 0.00 |
| разбор инцидентов и отчёт | claude-sonnet-5 | 1.000 | 0.100 | 2.00 |

**API: $2.00**. Локальное электричество: $0.40. **Денежные расходы всего: $2.40; бюджет с резервом 50%: $3.59.** Консервативный вариант без cache hits, с платной записью cache и тем же резервом: $5.85.

Параметры: 60% cache read / 15% cache write / 25% uncached; токены указаны суммарно по всем сессиям этого спринта, не размер одного контекста. Output включает оплачиваемое рассуждение, если провайдер его учитывает. Смета API Standard, без подписок/налогов/инструментальных cloud fees/внешних подрядчиков. Ваше время показано в часах, без перевода в доллары. Для локальной модели учитывается только электричество; покупка и амортизация не учитываются. Цены и формулы: [[roadmap/nikora_agent_delivery_plan]]; исходные данные [budget.json](../../../wiki-raw/nikora_agent_plan_20260915/budget.json).

## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
