# F7.2. Read-only панель OTIF, dwell и затрат

Дата: 15.09.2026. Статус: DRAFT к реализации, не выполнено. Тип: functional; родитель прежнего плана: F7.2. Обязателен [[requirements/nikora_sprint_contract]]. Общий план: [[roadmap/nikora_agent_delivery_plan]].

## 1. Результат и границы

**Законченный проверяемый результат:** Руководитель видит показатель и воспроизводит его из событий; одна поставка на двух плечах не задвоена.

Входит:

- Один read-only dashboard по утверждённой методике: arrivals/store/day, OTIF полного заказа, dwell, trace, cost.
- Drill-down в первичные события, одинаковая выборка baseline/pilot, versioned tariff inputs.
- Вычисления pure/read-only; запрет пересчёта юридического billing.

Не входит: Если потребуется менять экономическую методику/Oracle write, local scope закрывается, отдельный H-ticket.

Зависимости для READY: [F7.1](f7-1.md). Требуются решения бизнес-владельцев и реальные контрагенты/устройства, указанные ниже. BLOCKED/CONTRACT_READY не превращается в ACCEPTED по эмулятору.

## 2. Интерфейс и данные

Read-only GET KPI projection: window/site/store, completeness flag, numerator/denominator/sourceEventRefs, methodVersion/tariffVersion. Не отдавать агрегат без drill-down или смешения валют/UoM.

Все новые URL/имена — предложение к согласованию с действующим API, не описание уже реализованного endpoint. Любая write-команда сохраняет expectedVersion, correlation и аудит. Контракт не ослабляется ради удобства UI.

Точки расширения (перед ticket выбрать точный allowlist, не переписывать папку целиком):

- admin/wms_admin_frontend/src/components/
- api/wms_api_server/app/routers/transport_kpi.py
- tests/nikora/

## 3. Ограниченные шаги реализации

1. L1: чистые вычисления по утверждённым формулам и fixtures.
2. L2: read-only таблица/детали/фильтры.
3. T3: независимая сверка итогов и SQL review.

Каждый шаг — отдельный handoff с patch/test evidence. Local подзадачи только по готовому контракту; изменение инварианта/миграции переводится в H/X. Максимальный scope и stop-rule — в общем контракте.

## 4. Проверки и критерий приёмки

1. Известные fixtures full/partial/late/return; исходное обещанное окно сохраняется.
2. Нет двойного HU count, веса/валюты/единицы не смешаны; источник отсутствует — incomplete.
3. Независимый reviewer проверяет формулу; живые bounded SQL/планы обязательны.

Дополнительно обязательны права/дубли/ошибка связи/конкурентная версия, legacy regression и SQL review по общему контракту. Приёмку подтверждают независимый reviewer и владелец сценария; авторский summary недостаточен.

Целевые test artifacts после реализации: tests/nikora/test_f7_2.py и, если UI входит в scope, tests/ui/nikora_f7_2.cjs; плюс Oracle verify SQL и reports/nikora/F7.2/<run>/. Это **планируемые** файлы, их наличие/прохождение сейчас не заявляется.

## 5. Кто программирует и тестирует

Профиль **L — Локально, облачная приёмка**.

- Основной исполнитель: Aider + Qwen2.5-Coder-14B Q4 / Qwen3-Coder-30B Q4.
- Независимая проверка/тесты: Codex GPT-5.6 Terra medium + pytest/Playwright.
- Локальные помощники: только утверждённые механические/изолированные patches и fixtures. Детерминированные pytest/Playwright/SQL runner не расходуют LLM-токены сами по себе.
- Установка и параметры: [[runbooks/nikora_agent_launch]]. Для решения нового класса сначала S0/shadow test, затем повторное использование профиля.

## 6. Время и стоимость — оценка, не обещание

Рабочие дни: **2 / 3 / 5** (нижняя / базовая / верхняя оценка). Базовое окно в последовательном плане: дни **120–122** от готовности ресурсов. Внешнее ожидание не включено. Спринт включает создание тестов, review, исправления и техническую приёмку.

Ориентиры: 14.40 агент-часов (включая tool/test ожидание), 12.00 локальных server-hours, 9.60 часов техлида/QA. Эти часы **не суммируются** в календарную длительность: часть работы идёт параллельно, время людей уже учтено в базовых днях.

| Роль | Модель | Вход, млн | Выход, млн | API $, базовая cache-модель |
|---|---|---:|---:|---:|
| узкие правки и тестовые fixtures | Локальная Qwen | 4.800 | 0.480 | 0.00 |
| независимый обзор и приёмочные тесты | gpt-5.6-terra | 0.720 | 0.072 | 1.58 |

Параметры: 60% cache read / 15% cache write / 25% uncached; токены указаны суммарно по всем сессиям этого спринта, не размер одного контекста. Output включает оплачиваемое рассуждение, если провайдер его учитывает. Смета API Standard, без подписок/налогов/инструментальных cloud fees/внешних подрядчиков. Ваше время показано в часах, без перевода в доллары. Для локальной модели учитывается только электричество; покупка и амортизация не учитываются. ## 7. Условия остановки и передачи

Остановить ticket при повторяющемся дефекте, выходе за контракт/allowlist, нарушении баланса/прав, отсутствии обязательного внешнего факта или исчерпании бюджета. Не ставить зелёный статус и не менять тест под ошибочный код. Handoff: сделанное, diff, failing case, израсходованные токены/деньги, следующий ограниченный шаг. Новый функционал сверх scope — отдельная карточка с пересчётом.
