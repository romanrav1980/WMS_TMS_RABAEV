## Правила исполнения

Минимум 80% усилий на функционал. Перед новой реализацией использовать существующих владельцев WMS/TMS. Поставка — законченный бизнес-сценарий с рабочим интерфейсом, адресной проверкой и одним отчётом/скриншотами на блок.

Готовность кода, независимое ревью, реальная внешняя интеграция/оборудование и промышленный пилот учитываются отдельно. Неподтверждённые внешние результаты не объявляются завершёнными; их ожидание не блокирует дальнейшую разработку кода. Обязательный runtime gate внешней системы сохраняется по применимости товара.

## Непосредственная последовательность B01

1. Плановый тип паллеты из настроек адресата → явное переопределение в сборке; фактический тип передаётся в контроль и погрузку.

3. Существующая волна/задания → частичное исполнение и оставшееся количество → CASE/HU → контроль версии.
4. Staging/ворота → погрузка → выезд, с повтором той же команды при неизвестном результате.
5. Один показ рабочего сквозного пути, адресные проверки изменённых эффектов и один отчёт. Выявленные пробелы фиксировать внутри блока; не создавать новые подсистемы без подтверждения необходимости.
