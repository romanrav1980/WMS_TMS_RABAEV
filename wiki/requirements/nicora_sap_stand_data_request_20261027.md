# NICORA: данные для стендового обмена SAP — WMS

Редакция 2 · 27 октября 2026

## Пакет данных

Для первого прогона выберите один склад-источник и его магазины. Для каждого набора укажите систему-источник, момент снимка, период и ответственного.

- **Магазины и склады:** коды, адреса доставки, активность и действующая связь склада с каждым адресом.
- **Товары:** SAP-код, название, активность, базовая и заказные единицы, коэффициенты для каждого товара, штрихкоды и данные упаковок.
- **Каталог:** дерево категорий с кодом родителя, конечным признаком, датами действия и привязкой товара к конечному узлу. Передайте параметры категорий, применяемые автоматическим слоттингом.
- **Остатки:** единый момент снимка, склад, место хранения, товар, владелец, партия, срок годности, количество, единица, резерв и блокировка. Не смешивайте эти количества.
- **Заказы:** открытые заказы и строки, адрес, склад-источник, единица, плановое окно, отгруженное, отменённое и открытое количество. Приложите изменения и связанные поставки.
- **Прогнозы:** прогноз продаж по магазинам и товарам на месяц вперёд. Прогноз перемещений передайте отдельно: он используется для добивки.
- **Добивка:** настройка «Добивать» и предел X дней задаются для адреса получателя. Добивку рассчитывать только при включённой настройке и загруженном прогнозе перемещений, не дальше X дней.

## SAP-формат

Передайте исходные IDoc XML из тестовой системы SAP. Для каждого типа приложите message type, базовый тип, расширение, направление и структуру WE60. Укажите, как передаются создание, изменение и отмена. Конкретные типы и сегменты подтвердите по системе NICORA.

Если прогноз или справочник не передаётся действующим IDoc, приложите CSV из набора примеров. Этот CSV — формат стендовой проверки, не стандарт SAP и не замена IDoc.

## Количество и единицы

Сохраняйте исходные количество и единицу. Пересчёт выполняйте по настройкам товара. При несовпадении с единственной единицей обработки округляйте вниз до заданного шага. Если округление запрещено, строку всё равно загружайте вниз и сохраняйте ошибку интеграции. Запишите исходное и обработанное количество, разницу и причину ошибки. Без коэффициента не рассчитывайте количество наугад.

Пример: коробка = 12 штук; заказ 25 штук → 2 коробки / 24 штуки, разница 1 штука. При запрещённом округлении результат тот же, строка помечается ошибкой.

## Перед отправкой

Проверьте уникальность ключей, ссылки на склады, адреса и товары, даты действия, единицы, коэффициенты и целостность дерева. Повтор одинакового заказа не должен создавать дубликат; тот же ключ с другим содержимым должен выявлять конфликт.

Примеры синтетические. Они не подтверждают соответствие реальным IDoc NICORA или готовность промышленного обмена.
