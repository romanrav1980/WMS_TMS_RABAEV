## Границы ответственности

Codex владеет общей roadmap/wiki, backend contracts, Oracle DDL/пакетами/индексами и ядром проведения; сейчас warehouse-tasks raw UI и маленькими helpers цепочки заданий. Claude — только файлы текущей принятой задачи. Его семь ведущих спринтов: NI02.2, NI05.3, NI06.1, NI06.2, NI06.3, NI07.1, NI08.1 (UI). Девять остальных открытых спринтов ведёт Codex. Это не запрет согласованной передачи ограниченного блока.

В каждой задаче закрепляются конкретные файлы. Общий файл — CONTRACT_REQUEST → решение владельца → изменение одним исполнителем. До RELEASE другой исполнитель файл не меняет. Для следующих этапов новые file locks объявляются ACK; таблица выше сама по себе не резервирует все frontend-файлы.

## Критерии блока и связь

Результат — работающая функция + один адресный сценарий + существенный отказ/повтор, если менялась команда; один quality gate и encoding на законченный блок, отчёт/скриншот. Не запускать массовые проверки для каждого текста/кнопки. SQL ограничивать складом/периодом/страницей в Oracle; индекс добавлять по существующим индексам/плану/замеру, а не по предположению. Строки количества точные, не Number для расчётов запаса.

Обмен: C:\projects\TMS\coordination\nicora-claude, CODEX_TO_CLAUDE.md / CLAUDE_TO_CODEX.md. Сообщение не означает запуск агента: только ACK подтверждает принятие. Отчёты reports/nicora/2026-10-13, Claude — подпапки claude/Cxxxx.
