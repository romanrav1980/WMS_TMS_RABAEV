Назначение и границы
Используйте профиль для подготовки стендового пакета и сопоставления с реальными полями SAP. Все значения примера синтетические; они не задают ассортимент, упаковки, категории или нормы NICORA.
CSV дополняет исходные IDoc и не выдаётся за стандарт SAP. Для каждого реального сообщения передайте XML, базовый тип, расширение и структуру WE60 из вашей системы. Непроверенные сегменты и квалификаторы не подставлять.
Документ задаёт требование к обмену. Пример не подтверждает реализацию загрузчика, промышленное подключение или работу автоматического слоттинга.
Общие форматы и обязательность
CSV: UTF-8, запятая, первая строка — точные имена полей. Кавычки по RFC 4180: кавычку внутри поля удваивать. В архиве окончания строк LF; контрольная сумма считается по фактическим байтам. В Excel идентификаторы открывать как текст.
ID — непустая строка до 128 символов Unicode; TEXT — до 1000. Это границы предлагаемого стендового профиля, а не длины продуктивного SAP. Превышение согласовать; не обрезать значения.
UOM — код до 16 символов. EA/BOX/BLK/G/KG — единицы примера. Исходные SAP-коды сохранить и сопоставить в uom_mapping. Коэффициент BOX/BLK задаётся для товара, а не для всех товаров сразу.
DEC — десятичное число до 18 значащих цифр и 9 знаков после точки; без экспоненты и разделителей тысяч. Количества неотрицательные, кроме явно указанной широты/долготы. В JSON передавать количества строками. INT — целое; POSINT — положительное целое до 18 цифр; REV — положительная возрастающая редакция одного объекта.
BOOL — только true/false. ENUM — одно из значений поля. COUNTRY — ISO 3166-1 alpha-2. DATE — YYYY-MM-DD. TIME — HH:MM:SS. TIMESTAMP — ISO 8601 с обязательным смещением, например 2026-10-28T09:00:00+04:00. TZ — IANA, например Asia/Tbilisi.
«Да» запрещает пустое поле. «Условно» требует поле при условии из его описания. Пусто — неизвестно или неприменимо; 0 — известное нулевое количество. Пустота не разрешает добивку и не заменяет отсутствующий коэффициент на 1.
Настройка действует на интервале [valid_from,valid_to); последняя дата не включается. Пустой конец — окончание не задано. Перекрывающиеся действующие редакции одной настройки запрещены.
Порядок и повтор загрузки
Сначала проверить паспорт и manifest, затем адреса/склады/адресатов/источники, товары и единицы, дерево и словарь параметров/привязки/параметры, собственников и партии, единый снимок запаса, заказы/строки/графики, прогнозы/поставки/связи.
FULL описывает только объявленный охват. Отсутствие записи вне охвата ничего не удаляет. Удаление внутри охвата нужно явно согласовать; этот пример не задаёт автоматического удаления. DELTA не использовать без отдельного правила UPSERT/DELETE и диапазона меток источника.
У документа сохранять идентификатор и редакцию. Точный повтор не создаёт второй заказ или резерв. Тот же ключ/редакция с другим содержимым — конфликт. Более старая редакция не заменяет новую. Изменение настройки товара не пересчитывает молча уже принятую строку.
Округление выполняется вниз по шагу единицы обработки SKU. При выключенном разрешении строка в иной единице тоже загружается вниз, но сохраняет ошибку интеграции. Исходное количество и единица остаются отдельными. При неизвестном коэффициенте хранить исходную строку без выдуманного обработанного количества; нулевой результат не создаёт нулевого задания.
Как читать архив
field_dictionary.csv — машинный словарь: file (имя CSV), field (имя колонки), type (тип выше), required (да/нет/условно), meaning_and_validation (значение и проверка). Ключ — file+field. Это описание, не бизнес-справочник.
expected_order_import.csv и expected_controls.json — ожидаемые результаты проверки, не документы к загрузке. Остальные CSV — входной пакет примера. Архив не содержит транспортных справочников: машины, секции, нормативы, массы и размеры нужно передать по действующим источникам при проверке маршрутов.

## product_uom.csv

Ключ: product_id + uom + conversion_revision. quantity_base = quantity_uom × numerator / denominator. Масса и размеры относятся к одной указанной единице; фактическая масса партии не восстанавливается из номинальной.

| Поле | Тип | Обяз. | Значение и проверка |
|---|---|---|---|
| product_id | ID | да | Ссылка на products. |
| uom | UOM | да | Единица количества или упаковки. |
| numerator | POSINT | да | Положительный числитель пересчёта в базу SKU. |
| denominator | POSINT | да | Положительный знаменатель; ноль запрещён. |
| net_weight | DEC | нет | Номинальное нетто одной упаковки. |
| gross_weight | DEC | нет | Брутто одной упаковки, не меньше нетто. |
| weight_uom | UOM | условно | G или KG; обязательно при наличии массы. |
| length | DEC | нет | Положительная длина упаковки. |
| width | DEC | нет | Положительная ширина упаковки. |
| height | DEC | нет | Положительная высота упаковки. |
| dimension_uom | ENUM | условно | MM, CM, M; обязательно при размерах. |
| conversion_revision | REV | да | Редакция коэффициента. |
| base_scale | INT | да | Десятичные знаки в базе SKU: 0…9. |
| quantity_step | DEC | нет | Положительный шаг в uom этой строки. |
| valid_from | DATE | да | Начало действия включительно. |
| valid_to | DATE | нет | Конец действия исключительно. |

Контрольные результаты
Продажи: 93 строки, 31 день и 3 пары адрес/товар. Итоги: S001_A1/100001 — 744 EA, S001_A1/100003 — 38.750 KG, S002_A1/100002 — 372 EA. Количества разных товаров и единиц не суммировать.
Запас товара 100001: 120 EA физически, 12 EA блокировки, 24 EA резерва, 84 EA свободно. Снимок не является командой повторной приёмки.
Перемещение S001_A1 на 28.10: 4 BOX; SUP01 покрывает 1 BOX; остаётся 3 BOX до ограничений запаса, кузова и срока. Смена состояния SUP01 не создаёт второе вычитание.
У S001_A1 добивка включена, X = 3. Прогноз 31.10 вне горизонта 28–30.10. У S002_A1 добивка выключена. WH002_A1 показывает настройку адреса склада-получателя.
O1: 25 EA при BOX = 12 EA → 2 BOX / остаток 1 EA. O2: тот же пересчёт с false → 2 BOX и сохранённая ROUNDING_NOT_ALLOWED. O3: 1250 G → 1.250 KG при шаге 0.001 KG. O4: 1 BLK = 6 EA → 0 BOX / разница 6 EA, без задания, с диагностикой ZERO_AFTER_ROUNDING. Коды и статусы результатов здесь предложены для стенда, не объявлены текущими кодами продуктивного адаптера.
Проверить отдельно: иной пакет с прежним идентификатором, неизвестный товар, отсутствующий коэффициент, нулевой знаменатель, цикл категорий, слоттинг на родительскую категорию, две активные конечные привязки и пропущенный день прогноза. Не подмешивать эти ошибки в положительные CSV незаметно.
Локальная проверка архива сверяет обязательные поля, ширину CSV, ссылки, базовые коэффициенты, дерево, арифметику заказов и 31-дневные итоги. Это не заменяет запуск загрузчика API/Oracle или промышленную приёмку SAP.
