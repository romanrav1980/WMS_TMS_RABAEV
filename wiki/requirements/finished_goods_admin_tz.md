# Техническое задание: страница администрирования готовой продукции

Дата: 2026-05-17.

Статус: проектирование и реализация MVP.

## 1. Назначение

Страница `Готовая продукция` в админке WMS должна быть отдельным рабочим экраном для управления SKU готовой продукции, складами/буферами готовой продукции, партиями выпуска, паллетами, SSCC и остатками.

Страница не заменяет старый WMS-механизм остатков. Остатки читаются из старых таблиц WMS, а любые будущие изменения остатков должны идти через согласованные WMS/MES-процедуры и журналы движений.

## 2. Основные зоны страницы

Страница состоит из четырех рабочих зон:

1. `SKU готовой продукции`
   - список артикулов, которые являются готовой продукцией;
   - настройки маркировки, агрегации, SSCC, вылежки и качества;
   - связь с GTIN и Честным Знаком.

2. `Склады готовой продукции`
   - склады с флагом `FINISHED_GOODS`;
   - буферы выпуска с флагом `PRODUCTION_BUFFER`, если они содержат товар сразу после производства;
   - выбор складов управляет отображением остатков и паллет.

3. `Партии выпуска`
   - производственная партия;
   - производственный заказ;
   - артикул, GTIN, даты выпуска и срока годности;
   - статус качества;
   - вылежка и дата разрешения к планированию;
   - статусы Mercury/CRPT.

4. `Остатки и паллеты`
   - паллета;
   - SSCC;
   - партия выпуска;
   - артикул;
   - ячейка;
   - количество;
   - статус качества;
   - статус Честного Знака;
   - статус агрегации.

## 3. SKU готовой продукции

Для каждого SKU нужно отображать:

- артикул;
- наименование;
- GTIN;
- единицу учета;
- признак `является готовой продукцией`;
- признак обязательности Честного Знака;
- признак обязательной агрегации;
- признак обязательного SSCC;
- признак обязательной этикетки паллеты;
- норматив вылежки, если задан;
- группу продукции;
- комментарий технолога/склада;
- активность.

## 4. Склады готовой продукции

На страницу попадают склады, у которых включен хотя бы один флаг:

- `FINISHED_GOODS`;
- `PRODUCTION_BUFFER`.

Буфер выпуска нужен отдельно, потому что часть товара уже является готовой продукцией, но еще не размещена на основном складе.

## 5. Партии выпуска

Партия готовой продукции должна показывать:

- `PROD_BATCH_ID`;
- номер партии;
- производственный заказ;
- артикул;
- GTIN;
- количество;
- дата выпуска;
- срок годности;
- склад/буфер выпуска;
- статус качества;
- статус вылежки;
- дата разрешения к планированию;
- Mercury status;
- CRPT status;
- количество паллет;
- количество кодов маркировки;
- количество агрегаций.

Важно: `IS_SHIPMENT_ALLOWED` не является жесткой блокировкой старого WMS. Этот статус должен использоваться модулем комплектации и планирования.

## 6. Остатки и паллеты

Остатки отображаются по выбранным складам и выбранному SKU/партии.

Минимальные поля:

- склад;
- ячейка;
- паллета;
- SSCC;
- артикул;
- наименование;
- партия выпуска;
- дата выпуска;
- срок годности;
- количество;
- резерв;
- доступно;
- статус качества;
- статус CRPT;
- статус агрегации.

## 7. Права

Нужны отдельные права:

- `finished_goods_view`: просмотр страницы;
- `finished_goods_edit`: изменение настроек SKU готовой продукции;
- `finished_goods_stock_view`: просмотр остатков и паллет;
- `finished_goods_batch_view`: просмотр партий выпуска;
- `finished_goods_export`: выгрузка списков.

Названия прав не должны отображаться на рабочем экране пользователя.

## 8. API

Минимальные endpoints:

- `GET /api/finished-goods/skus`
- `PATCH /api/finished-goods/skus/{articul}`
- `GET /api/finished-goods/warehouses`
- `GET /api/finished-goods/batches`
- `GET /api/finished-goods/remains`

## 9. MVP

Первый этап:

- создать таблицу настроек SKU готовой продукции;
- добавить права;
- создать API;
- создать RAW-страницу `finished-goods.html`;
- подключить пункт меню `Готовая продукция`;
- показать SKU, склады, партии и остатки.

Второй этап:

- добавить действия по статусам качества;
- добавить связь с DataMatrix-кодами;
- добавить просмотр состава SSCC-агрегации;
- добавить экспорт.
