# Анализ состояния проекта TMS

> Файл поддерживается AI-ассистентом. Последнее обновление: 2026-05-20.

---

## Общая оценка

Проект находится в **управляемой модернизации** — не хаотичном переписывании, а планомерном замещении легаси-слоёв. Oracle-схема сохраняется как система отсчёта; вокруг неё строится FastAPI + React-стек. Архитектурное решение обосновано: регуляторные требования (Меркурий, Честный знак) требуют надёжности, а легаси C# и Tserver продолжают работать параллельно без риска простоя.

---

## Что работает уверенно

### Операционное ядро
- **Wave picking** — самый проработанный контур. Реализованы: резервирование (SOFT/HARD), пополнение pick-face (4 режима: IMMEDIATE, WAIT_MINIMAX, QUEUED, WAIT_FREE_CELL), FEFO-отбор, сборка клиентских паллет (case-pick), стейджинг. Весь цикл покрыт load-тестами с артефактами.
- **MES-интеграция** — BOM → производственный заказ → выдача сырья → завершение производства → ГП на склад. Проверено smoke-тестом.
- **Oracle-схема** — 40 миграций применены, 458 объектов валидны, 0 невалидных.

### Инфраструктура разработки
- Evidence-driven тестирование: каждый процесс сдаётся с load-тестом + скриншотами по стейджам
- API audit + replay: полное логирование запросов/ответов, dry-run воспроизведение
- Outbox-паттерн для всех внешних интеграций
- Топология склада: 1500 pick-face, 25 стеллажей, матрица расстояний, U-routing, маршруты подбора

### Последняя реализованная крупная фича
Топология склада (миграция 040, коммиты до 2026-05-20). Детерминированный layout, admin-UI с редактированием и визуализацией, инварианты линейных маршрутов.

| PostgreSQL | Не оценивался | Сознательно отложен |

Первые два блока — **внешние зависимости**, не технический долг.

## Технический долг: оценка

### Управляемый (известно, задокументировано)
- Tserver (legacy TCP) — совместимость сохранена, замена идёт через Web-PWA
- Form1.cs 1.1 МБ — монолит, но не трогается: вся новая логика в API
- Открытые пароли в RUSERS — известно, отложено до SSO/hashing
- Нет распределённых локов (Redis/etc.) — Oracle-последовательности держат

### Требует внимания
- **Прямые записи из C# и Tserver мимо API** — риск рассинхронизации состояния, нужен аудит
- **Транспортный модуль только в легаси** — `RRL_TRANSPORT_TASK`, `RRL_TR_VEHICLE`, `RRL_TR_VODITEL` не покрыты API, управляются напрямую из WinForms

---

## Риски

1. **Операционный**: система достаточно сложная (40 миграций, 23 API-роутера, 4 фронт-приложения) — онбординг нового участника требует усилий. `AGENTS.md` и `wiki/` частично закрывают это.
2. **Регуляторный**: до получения сертификатов Mercury/CRPT система не может сдать полный операционный цикл — остаётся зависимость от legacy C# для части отгрузки.
3. **Транспортный контур изолирован**: отгрузка паллет на транспорт (`RRL_SBORKA_PALLETS.TRANSTASK_ID`) не интегрирована с wave picking через API — разрыв между операционным ядром и физической отгрузкой.

---

## Итоговая оценка

Проект здоров. Движется по плану. Без критических технических долгов в активно развиваемой части. Главный текущий разрыв — **транспортный контур** живёт только в легаси C# и не связан с современным API-слоем.
