# Промпты для генерации UI: Рабочее место управления рейсами

> AI-ассистент. Дата: 2026-05-21.
> Промпты предназначены для v0.dev, Claude, Figma AI, или любого
> генеративного UI-инструмента. Технологический стек: React 19, TypeScript,
> Ant Design 5, Tailwind CSS (по вкусу), Leaflet.js для карт.

---

## Как использовать

Каждый промпт — отдельный экран или компонент.
Рекомендуемый порядок: начинать с промпта 1 (общий layout),
затем каждый вложенный компонент по отдельности.

Контекст системы для прикрепления к любому промпту:
> «Это рабочее место диспетчера отгрузки пищевого завода.
> Основная сущность — Рейс (транспортное задание).
> Диспетчер назначает на рейс Сборочные задания (СТ) — группы паллет для одного адреса.
> Данные: паллеты, вес, объём, адрес, район, тип ТС, прогресс сборки.
> Стиль: профессиональный, плотный, тёмная боковая панель + светлый рабочий контент,
> без лишних украшений. Язык интерфейса: русский.»

## Промпт 1 — Общий Layout (DispatchBoard)

```
Создай React-компонент DispatchBoard — трёхпанельный layout рабочего места диспетчера отгрузки.

Структура:
- Верхняя шапка (высота 52px): логотип «Управление рейсами», выбор даты (DatePicker),
  переключатель режимов «Планирование | Назначение» (SegmentedControl), имя пользователя.
- Левая панель (ширина 320px, фон тёмно-серый #1a1a2e): список карточек рейсов,
  кнопка «+ Новый рейс» вверху.
- Центральная область (flex-grow): таблица доступных СТ с фильтрами сверху.
- Нижняя панель (высота 280px, border-top): состав выбранного рейса.
- Правый край нижней панели: строка итогов P=... M=... V=...

Состояния:
- Режим «Планирование»: левая панель скрыта, центр занимает вся ширина, показывается карта.
- Режим «Назначение»: три панели как описано.
- Левая панель скроллируется, карточки рейсов добавляются снизу.

Технологии: React 19, TypeScript, Ant Design 5, CSS Grid/Flexbox.
Используй переменные CSS для цветовой темы.
```

## Промпт 2 — Карточка рейса (TransportTaskCard)

```
Создай React-компонент TransportTaskCard — карточка одного рейса в левой панели диспетчера.

Данные карточки:
- Номер рейса (#1042) + статусный badge: СОЗДАН (серый) / ПЛАН (синий) /
  ДОК (фиолетовый) / ПОГРУЗКА (жёлтый) / ОТПРАВЛЕН (зелёный)
- Строка: иконка грузовика + номер ТС (А123ВС) + имя водителя (Иванов)
- Строка: время отгрузки (14:00) + дата + список районов (маленькие теги)
- Два прогресс-бара:
    Паллеты: [████████░░] 8/10 (80%) — при > 100% красный
    Вес:     [████████░░] 820 / 1000 кг — если вместимость не задана: прочерк
- Строка метрик: 🛣 18.2 км · ⏱ 2.4 ч · 💰 4 100 ₽
- Строка дока: 📦 Дока Б2 · 14:00–15:00

Состояния:
- default: фон #242438
- selected: левая синяя полоска 3px + фон #2d2d50
- hover: фон #2a2a45
- warning: жёлтая иконка ⚠ если паллеты > вместимость
- error: красная иконка 🚫 если нет машины или водителя

Клик по карточке — выделяет (isSelected=true), вызывает onSelect(taskId).
Ширина: 100% левой панели (288px с padding). Высота: auto (~120px).
```

## Промпт 3 — Таблица доступных СТ (AvailableOrdersTable)

```
Создай React-компонент AvailableOrdersTable — таблица сборочных заданий (СТ),
доступных для назначения на рейс.

Фильтры (строка над таблицей):
- Toggle «☑ Только нераспределённые» (по умолчанию ON)
- Input с debounce 300мс: «Адрес / регион»
- Input с debounce 300мс: «Номер СТ»
- Select multi: «Склад» (ЦС, ЮС, ЗС)
- Кнопка сброса фильтров

- ☑ (checkbox, 40px)
- Цвет (8px цветная плашка по полю raion — цвет по хешу строки, 12px)
- Адрес (flex, кликабельно — раскрыть паллеты)
- Район (тег-badge, 90px)
- СТ (моноширинный, 80px)
- Палл (число, 50px)
- Вес кг (число, 70px)
- Объём м³ (число, 70px)
- ОРД (число, 50px, сортировка по умолчанию ASC)
- ТС (иконка: ❄ реф / 🔧 гидробортник / 🚛 обычный, 40px)
- ПРОВ% (цветной badge: ≥100% зелёный, ≥80% жёлтый, <80% красный, 60px)

Expand row: клик на ▶ раскрывает список паллет в строке:
  «PAL-00123 | 12 кор мол | 85кг | 0.43м³»

Строка итогов (sticky bottom, фон акцентный):
  «Отмечено: ☑ 5 СТ | P=12 палл | M=1 140 кг | V=4.2 м³ | Адресов: 4»

Кнопки действий (sticky bottom, справа):
  [→ Добавить в рейс #1042]  [+ Создать новый рейс]  [⚡ Авто-группировка]

Поведение:
- При выборе хотя бы одного чекбокса кнопка «→ Добавить» становится активной.
- При нулевом выборе кнопка «→ Добавить» disabled.
- Высота таблицы: calc(100vh - высота шапки - высота нижней панели - высота фильтров).
- Виртуализация строк (react-window) для списков > 50 элементов.
```

## Промпт 4 — Нижний грид состава рейса (TaskPalletsTable)

```
Создай React-компонент TaskPalletsTable — таблица паллет выбранного рейса.

Шапка компонента:
- Заголовок «Состав рейса #1042» (серый, мелкий)
- Кнопки справа: [⚡ Оптим. маршрут]  [📋 Манифест]  [🔍 Похожие СТ ±5 км]

Колонки:
- ≡ (drag handle для drag-and-drop, 30px)
- ПОР (номер с жирным шрифтом, 45px) — первый адрес выделен ⭐
- Адрес (flex)
- СТ (80px, моноширинный)
- Палл (50px)
- Вес (70px)
- ПРОВ% (badge, 60px)
- Тайм-слот (100px, формат «14:15 – 14:35», серый)
- ✕ (кнопка удаления строки, 40px)

Функциональность:
- Drag-and-drop строк для изменения порядка (react-beautiful-dnd или @dnd-kit).
  При перетаскивании строка становится полупрозрачной, курсор grab.
  После drop — строки перенумеровываются, отправляется PATCH на сервер.
- После нажатия «⚡ Оптим. маршрут»:
  а) строки подсвечиваются анимацией вычисления (skeleton + spinner),
  б) появляется diff-подсветка: строки, которые переедут — голубые,
  в) кнопки «Принять порядок» / «Отмена» заменяют [⚡].

Высота: 280px, overflow-y scroll.
Пустое состояние: «Выберите рейс в левой панели».
```

## Промпт 5 — Карта адресов (PlanningMap)

```
Создай React-компонент PlanningMap — карта доставки для режима Планирования.

Технология: Leaflet.js (react-leaflet), тайлы OpenStreetMap.

Что отображается:
1. Точка склада (◎, синяя, крупная) — фиксированная точка.
2. Для каждого адреса из списка СТ:
   - Кружок, цвет = цвет района (тот же хеш-алгоритм что в таблице)
   - Размер кружка = пропорционален числу паллет (min 8px, max 24px)
   - Нераспределённые СТ — яркие, непрозрачные
   - СТ уже на рейсе — полупрозрачные (opacity 0.35)
   - Hover: всплывающий tooltip: «ул. Ленина, 5 | СТ 0441 | 3 палл | 320 кг»

3. Если выбран рейс: рисуется маршрутная линия (полилиния от OSRM /route).
   Линия синяя, стрелки направления через каждые 50 пикселей.

4. Панель поверх карты (левый верхний угол):
   «📦 47 СТ нераспределено | 🚛 12 машин свободно | ✅ хватит»
   Если не хватает: «⚠️ недостаток 28 палл»

5. Легенда районов (правый нижний угол): цвет → название района.

6. Кнопки управления картой (правый верхний угол):
   [Показать все] [По рейсу] [🔍+] [🔍-]

Карта полностью заполняет центральную область в режиме Планирования.
Высота: calc(100vh - 52px - высота панели авто-плана).
```

## Промпт 7 — Gantt доков (DockScheduleGantt)

```
Создай React-компонент DockScheduleGantt — диаграмма занятости погрузочных доков.

- Вертикальная ось: доки (А1, А2, Б1, Б2, Б3)
- Горизонтальная ось: время суток 6:00–22:00, шаг 30 мин, текущее время = вертикальная линия
- Строка заголовка: временна́я шкала, текущее время подсвечено

Слоты:
- Занятый слот: цветной прямоугольник (цвет = тип ТС рейса).
  Текст внутри: «#1042 · А123ВС» если ширина позволяет.
  Hover: tooltip «Рейс #1042 · Иванов · 8 палл · 14:00–15:00».
  Клик: выделяет рейс в левой панели.

- Пустой слот: светло-серый, курсор pointer.
  Клик: открывает mini-modal «Назначить рейс на Дока А2 в 14:00–15:00?»

- Конфликт (два рейса на одном доке): ярко-красная заливка + иконка ⚠.

Разметка:
- Прошедшие слоты — полупрозрачные (opacity 0.5).
- Текущий момент — синяя вертикальная линия с анимацией.

Высота: 220px (фиксированная, с вертикальным скроллом если доков > 8).

## Промпт 11 — Статистика дня (PlanningDaySummary)

```
Создай React-компонент PlanningDaySummary — дашборд-строка статистики
планирования на день.

Размещение: горизонтальная полоса между шапкой и картой в режиме Планирования.

Блоки (равномерно распределены по ширине):
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│  47 СТ   │ 183 палл │ 18.4 т   │ 112(61%) │ 10 машин │ ✅ Хватит│

  ✅ зелёный если ёмкость машин ≥ нераспределённые паллеты

Все числа — анимированные счётчики (CountUp при первой загрузке).
Обновление в реальном времени при изменениях (WebSocket или polling 30 сек).
