# Legacy Rights Model

## Назначение

Старая WMS уже имеет собственную систему пользователей и прав. Новая админка не должна заводить параллельную модель авторизации. Все новые административные разделы должны использовать те же таблицы:

- `RUSERS`: пользователи, пароль, признак входа в админку, группа пользователя;
- `USER_GROUP`: справочник групп;
- `RIGHTS`: права групп через поле `RIGHT1`.

## Как Работает Старая Проверка

В Oracle есть функция `RRL_HAS_WRIGHT(user_id, wright_name)`.

Логика:

- если пользователь находится в группе `GLOBAL_ADMIN`, функция возвращает `1`;
- иначе функция ищет строку в `RIGHTS`, где `RIGHTS.USER_GROUP = RUSERS.USER_GROUP` и `RIGHT1 = wright_name`;
- если право найдено, возвращается `1`, иначе `0`.

Админский вход старой системы проверяется через `RUSERS.ID`, `RUSERS.PASS`, `DELETED = 0` и `PRAVO_ADMIN_LOGIN = 1`.

## Новые Права Админки

Новые страницы админки используют тот же `RIGHTS.RIGHT1`:

- `API_AUDIT_VIEW`: просмотр журнала API;
- `API_AUDIT_REPLAY`: реальный повтор API-вызовов;
- `REGULATORY_ADAPTER_VIEW`: просмотр будущего журнала адаптеров Меркурия и Честного Знака;
- `REGULATORY_ADAPTER_RETRY`: повтор отправок во внешние сервисы;
- `RIGHTS_ADMIN_VIEW`: просмотр пользователей, групп и прав;
- `RIGHTS_ADMIN_EDIT`: изменение групп пользователей и прав.

В Python API эти права нормализуются к lower-case именам: `api_audit_view`, `rights_admin_view` и т. д. Это только внутреннее представление backend; в Oracle права остаются в старом стиле `RIGHTS.RIGHT1`.

## Текущий Admin

Локальный администратор должен быть строкой в `RUSERS`, а не hardcoded учетной записью:

- `RUSERS.ID = 'admin'`;
- `RUSERS.PASS = 'admin123'`;
- `RUSERS.PRAVO_ADMIN_LOGIN = 1`;
- `RUSERS.USER_GROUP = 'GLOBAL_ADMIN'`.

Такой пользователь получает все права за счет старого правила `GLOBAL_ADMIN`.

## Новая Страница Настройки Прав

Страница:

- `wiki-raw/wms_admin_ui_reference/rights-admin.html`;
- endpoint prefix: `/api/admin/rights`;
- просмотр требует `RIGHTS_ADMIN_VIEW`;
- изменение требует `RIGHTS_ADMIN_EDIT`.

Функции страницы:

- просмотр пользователей из `RUSERS`;
- просмотр групп из `USER_GROUP`;
- просмотр прав группы из `RIGHTS`;
- назначение группы пользователю;
- добавление и удаление права группы.

## Правило На Будущее

Новые административные блоки должны добавлять свои права в `RIGHTS.RIGHT1`, а не в отдельные таблицы и не в код. Если нужно дать полный доступ, используем группу `GLOBAL_ADMIN`, сохраняя совместимость со старой системой.

## Важная Особенность Восстановленной Базы

В живой восстановленной базе справочник `USER_GROUP` может быть неполным: фактические группы также встречаются в `RUSERS.USER_GROUP` и `RIGHTS.USER_GROUP`. Страница настройки прав должна показывать объединение этих источников, иначе будут видны не все группы.

Миграция `2026-05-17-007-backfill-user-group-reference` восстанавливает строки `USER_GROUP` из уже существующих значений `RUSERS.USER_GROUP` и `RIGHTS.USER_GROUP`. Это не создает новую модель прав, а приводит справочник в соответствие с фактическими legacy-данными.
