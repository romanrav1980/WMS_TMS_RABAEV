# Аудит Адаптеров Меркурия И Честного Знака

## Назначение

Реальные адаптеры Меркурия и Честного Знака должны подключаться поверх уже созданного слоя API audit/replay. Цель: видеть не только факт бизнес-операции в WMS, но и полный технический след отправки во внешний сервис, включая сертификат, подпись, очередь, попытки, внешний идентификатор и ответ.

## Текущая Точка Опоры

- Входящие вызовы API пишутся в Oracle `RRL_API_CALL_LOG` и локальный JSONL-журнал.
- Админка показывает журнал в блоке `API: журнал и повтор вызовов`.
- Повтор вызовов доступен через `POST /api/admin/api-calls/replay` по ID, периоду, методу и пути.
- Регуляторный контур уже имеет `RRL_REGULATORY_OUTBOX` и `RRL_REG_OPERATION_JOURNAL`.

## Правило Для Реальных Адаптеров

Каждый исходящий запрос в Меркурий или Честный Знак должен иметь отдельную запись в outbox/adapter journal до фактической отправки. После отправки нужно сохранить:

- целевую систему: `MERCURY` или `CRPT`;
- тип операции: ввод в оборот, агрегация, отгрузка, ВСД, производственная операция, проверка статуса;
- business key: партия, паллета, SSCC, GTIN/DataMatrix, Mercury operation ID;
- request payload или канонический hash, если payload содержит чувствительные данные;
- response payload или диагностический фрагмент;
- HTTP/SOAP status, внешний document ID, error code и error message;
- certificate alias/thumbprint, срок действия сертификата и признак подписи;
- correlation ID, idempotency key, retry count, next retry time;
- статус очереди: `READY`, `SENT`, `ACK`, `ERROR`, `RETRY`, `CANCELLED`.

Секреты, закрытые ключи, пароли контейнеров и токены не пишутся в журнал. В журнал попадает только безопасный идентификатор сертификата и техническая диагностика.

## Очередь И Повтор

Первый практичный вариант для проекта: Oracle outbox плюс worker внутри Python API-сервера или рядом с ним. RabbitMQ/Kafka добавлять только когда появится реальная потребность в независимом брокере, масштабировании consumers или длительной истории событий.

Повтор должен работать на двух уровнях:

- повтор входящего API-вызова WMS через `RRL_API_CALL_LOG`;
- повтор исходящего adapter/outbox-сообщения в Меркурий или Честный Знак через adapter journal.

Так можно восстановить цепочку: операторский вызов -> изменение Oracle -> outbox событие -> отправка во внешний сервис -> ответ/ошибка внешней системы.

## Место В Админке

Текущий блок администрирования API находится в raw UI:

- файл: `wiki-raw/wms_admin_ui_reference/api-audit.html`;
- заголовок: `6. API: журнал и повтор вызовов`;
- скрипт: `wiki-raw/wms_admin_ui_reference/api-audit.js`;
- локальный адрес: `http://127.0.0.1:3000/api-audit.html`.
- право просмотра: `api_audit_view`;
- право повтора: `api_audit_replay`.

Следующий шаг для Меркурия/ЧЗ: добавить рядом вкладку или подблок `Внешние отправки`, который читает adapter/outbox journal и позволяет делать dry-run/retry по конкретным сообщениям.
