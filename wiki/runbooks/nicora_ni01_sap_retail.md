# NI01 — SAP Retail, приёмка и размещение

7 октября 2026 года. **NI01: implemented baseline with gaps** в существующей ORCL/orcl, схеме RABAEV. Прежняя формулировка о завершении реализации всего NI01 была слишком широкой: [анализ текущих путей](../components/nicora_global_reuse_analysis_20261007.md) выявил пробелы общего допуска запаса/карантина, прямого отбора и сквозного состава; они включены в NI03–NI05. Реальный обмен SAP, государственные сервисы и физический принтер не проходили приёмку. Бизнес/tests/regression/load не запускались по поручению владельца. Исторический import NI01: 369 маршрутов; текущий после NI02: 374. Это не подтверждение бизнес-сценариев.

## Реализованный поток

1. ARTMAS/ARTMAS10: неизменный XML/hash, sender/DOCNUM, durable inbox и атомарное применение к существующей RRL_ARTICULS. SAP управляет товарами/упаковками; маркировка настраивается в WMS. Неизвестная норма паллеты не подменяется выдуманной. Удаление артикулов и смена уже сопоставленной базовой единицы требуют отдельного решения.
2. WarehouseSupplyOrder v1 — рабочий нормализованный контракт шлюза: склад-получатель и ReceiveCell сверяются с существующим складом/DEFAULT_RECEIVE_CELL. Импорт создаёт план прихода без остатков. Новая Revision корректирует план после начала приёмки, сохраняя факты: нельзя уменьшить строку ниже принятого, заменить товар/единицу принятой строки или удалить её.
3. Экран предлагает паллеты по норме/остатку, приёмщик меняет укладку и число паллет. Факт содержит SSCC, количество в base UoM, партию поставщика, срок, дату производства и измерения при применимости.
4. Немаркированный товар — ШК штуки/коробки. Маркированный — все применимые версионные профили карточки и разрешённые ими QR единицы/BOX/PALLET. Агрегация требует известного состава. Физическая единица учитывается один раз при нескольких профилях; для кг/л хранится количество каждой единицы, сумма равна количеству паллеты.
5. CRPT: канонизация AI01/21 и компактного табачного GTIN14+serial7, сохранение raw, запрет дублей и связь с существующими кодами/паллетной агрегацией через RRL_PRODUCTION_API. ЕГАИС: полный уникальный код 68/150 символов; другие Track & Trace имеют самостоятельные пространства. Физическая регистрация идёт в журнал через RRL_REGULATORY_API. Криптография и государственное одобрение не объявляются выполненными; RESERVED/DRAFT не означают разрешение оборота.
6. Одна транзакция создаёт паллету, состав, факт, RRL_EVENTS type=1, PUTAWAY/SAP_RECEIPT и outbox. RRL_REMAINS меняет существующий event trigger. Guard защищает SAP-паллеты от старой автоматической перепаллетизации.
7. Размещение минимизирует расстояние до места отбора либо время пополнения. Для пары хранение–отбор вводится измеренное/рассчитанное время; иначе TIME использует явно нормативные скорости движения/подъёма. Учитываются блокировки, температура, остаточный срок, размеры/масса/объём, свободные слоты опубликованной топологии и резервы задач. Общая масса ячейки учитывает размещённые и зарезервированные паллеты; неизвестные измерения не проходят ограничения.
8. Размещение подтверждается сканами паллеты/источника/назначения; stock/DONE/outbox атомарны. Доступно переназначение пригодного адреса с причиной. Отмена освобождает резерв слота, оставляя товар на источнике; возобновление требует переназначения. В существующих экранах заданий/ричтрака добавлены PUTAWAY/SAP_RECEIPT. Автор команд берётся из серверной авторизации.
9. SSCC выдаётся после настройки собственного GS1 prefix. Доступны HTML/SVG GS1-128 и ZPL 203/300/600 dpi; отдельный скан этикетки подтверждает её, при приёмке статус USED. Этикетка поставщика допустима. Создание файла не выдаётся за физическую печать.
10. Закрытие с недостачей требует полномочия/причины, сохраняет план/факт/расхождение. Повторное открытие сохраняет историю и ожидает новую ревизию SAP. Излишек не разрешается автоматически.
11. XML outbox имеет стабильный EventId/hash. EXPORTED означает файл; ACKNOWLEDGED — подтверждение SAP с внешним номером. Проверяются отправитель, hash файла и MessageId. Отказы сохраняются, доступна повторная публикация. Worker имеет OS-lock каталога и автоматически восстанавливает processing-файлы после остановки; inbox дедуплицирует операции.
12. Composition API передаёт исходный факт, текущие позиции и целые физические единицы со всеми кодами/профилями/количеством. Сборка/отгрузка следующего этапа используют этот контракт в NI03/NI04.

## Запуск и настройки

Корневой `serv.bat`. Экран: **http://127.0.0.1:8088/wms-admin/receiving.html**. Карточка товара: `/wms-admin/finished-goods.html`.

```powershell
.\sap-artmas.bat
.\sap-supply.bat
.\sap-receipts.bat
.\sap-ack.bat
# Каждый worker принимает --root с согласованным каталогом.
```

Входы: `exchange/sap_retail/inbox`, `exchange/sap_supply/inbox`, ACK `exchange/sap_receipts/inbox`; выход `exchange/sap_receipts/outbox`. Готовый XML публиковать через rename. Archive/error сохраняют исходник/результат. После исправления настройки разрешён повтор того же ERROR XML; иной payload требует нового ID.

Настроить SKU policy, склад/приёмку/отбор/координаты; для печати — реальный GS1 prefix; для температуры — SKU/ячейки. Без физической топологии используется одна паллета на свободную ячейку. Legacy LIMIT_HEIGHT и метрический slot HEIGHT_M передаются отдельными полями. TIME не означает автоматически измеренный маршрут.

## Права и API

Карточка: finished_goods_view/edit. Обмен: sap_article_import, sap_supply_import/view. Приёмка/печать: warehouse_receipt_confirm. Задания: warehouse_task_view/execute, переназначение warehouse_task_assign. Сверка: warehouse_receipt_reconcile. Настройки: warehouse_settings_view/edit. Состав: traceability_view. GLOBAL_ADMIN сохраняет *. Группы настраиваются существующим rights-admin.

- `/api/integrations/sap/artmas`, `/supply-orders` — административный XML-вход и чтение.
- Очередь: `/api/integrations/sap/receipt-events`; ACK: `/receipt-events/acknowledgements`; retry: `/receipt-events/{event_id}/retry`.
- `/api/receiving/supply-orders/{order_id}/pallets`, `/labels`, `/close`, `/reopen`.
- `/api/receiving/labels/{label_id}` (format=html|zpl, dpi=203|300|600), `/confirm`.
- `/api/receiving/putaway/{task_id}/complete`, `/replan`; отмена — прежний warehouse-task endpoint.
- `/api/receiving/warehouses/{warehouse}/settings`, `/skus/{articul}/placement-rule`, `/cells/{cell}/placement-rule`.
- `/api/receiving/pallets/{pallet}/composition?after=...&limit=50` — страницы целых единиц, максимум 100.

## Установка и границы доказательств

Миграции **001–007** установлены в RABAEV. Логи и source hashes: `runtime/ni01/`. Первый запуск 005 остановился на синтаксисе до DDL; исправленный повтор и 006/007 — Errors=0. Прочитана metadata изменённых объектов. Откаты и XML-примеры не выполнялись. Других схем/инстансов нет.

Настоящие SAP XML ещё не сверены с предположенным mapper. Состав агрегаций должен поступать от шлюза/поставщика. Реальные CRPT/ЕГАИС вызовы требуют сертификатов и внешних договоров промышленной интеграции; фиктивных ответов нет. Warehouse cases, нагрузка, принтер и государственная криптография не считаются принятыми.

Slow SQL измерений нет: функциональные прогоны не выполнялись. Решения: PK/unique для identity, CODE(pallet,unit) и outbox(status,date) indexes, ограниченные страницы/1000 строк/10000 единиц. Поиск размещения ограничен складом, содержит сортировку и проверки общей ёмкости: **NI08, владелец backend/Oracle** — после разрешённого рабочего потока снять планы/длительности и выбрать окно/индекс/кэш. Это backlog, не заявление о скорости.
