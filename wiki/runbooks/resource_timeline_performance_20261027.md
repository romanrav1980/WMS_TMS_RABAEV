# Гант ресурсов: замер Oracle 27.10.2026

На складе `210069361` запрос таймлайна за шесть часов строил 640 строк погрузки для одного события выезда. В API 6-часовой ответ содержит одно событие и одно назначение; до фильтрации назначений ответ содержал 1281 назначение. События и назначения после изменения совпали с прежним результатом.

В Oracle execution-plan доступен индекс `RRL_LOAD_FORECAST_WD_I1` только по `WARE_ID`; временной предикат по `LOADED_AT`/`DEPARTED_AT` применяется после чтения строк. План оценил стоимость в 141. Фактический `DISPLAY_CURSOR ALLSTATS` недоступен пользователю БД: нет SELECT на `V$SQL_PLAN_STATISTICS_ALL`. Профиль полного запроса показал 51 717 buffer gets; транзакция до исправления заняла 3 062 мс.

Проверка разложила нагрузку: выборка фактов с фильтром времени — около 31 мс; ACL паллет — около 156 мс; фильтр типа ресурса — около 178 мс; проверка владельца/ключа складской операции — около 2 050 мс. У ворот есть торговая площадка, поэтому эта проверка требуется и не может быть удалена общим правилом.

Для администратора владелец всегда разрешён: действующая функция `RRL_TRADE_STOCK_GUARD.owner_allowed` сначала вызывает `RRL_ACCESS_API.is_admin` и сразу возвращает 1. Таймлайн теперь проверяет этот признак один раз и пропускает только повторные вызовы `owner_allowed` для администратора. Проверка одинакового 6-часового запроса до/после: медиана 3217 → 2811 мс (2 прогона каждого варианта); событие и назначение равны. `pytest tests/retailcase/test_resource_timeline.py -q`: 24 passed; RETAILCASE quality gate: PASS.

Остаток: Oracle-чтение всё ещё занимает около 1,5 с на `loading_rows`; тест администратора не измеряет неадминистративный ACL-путь. На складе 210069361 за 27.10 не нашлось сочетания обычного пользователя с обоими правами и фактами таймлайна; неадминистративный профиль остаётся непроверенным. Индекс не добавлялся: план не доказывает, что индекс устранит стоимость JSON/PLSQL проверок. Продолжить можно после появления безопасной QA-учётной записи и данных; область доступа не ослаблять. Фактический `A-Rows` требует права DBA на `V$SQL_PLAN_STATISTICS_ALL`.
