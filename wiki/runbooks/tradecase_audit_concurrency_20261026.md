# Аудит API и параллельное чтение — 26.10.2026

## Изменения

Обработчик аудита выполнял синхронные записи Oracle и файла в потоке HTTP. Записи начала и завершения перенесены в существующий пул потоков Starlette; ответ ждёт их завершения. Отдельная блокировка и одна запись строки сохраняют целостность локального JSONL при работе нескольких потоков. Контекст запроса переносится средствами AnyIO. Правила доступа, маскировка заголовков, ограничение тела и запрет рекурсивного replay сохранены.

Пять проверок прошли: медленный аудит не задерживает другой запрос, включая случай ошибки обработчика; идентификаторы запроса и вызова не смешиваются; параллельная запись 32 больших русскоязычных записей даёт 32 целых JSON-строки.

В чтении обеспеченности рейса объединены две обработки замороженного состава. Один запрос возвращает количества и число мест, которые нельзя однозначно связать со строкой заказа. Неполный состав по-прежнему даёт неизвестные количества, а скрытый собственник не раскрывается. Шесть настоящих рейсов дали ответы, равные прежней редакции. Дополнительно проверены вложенные, неизвестные, пустые и чужие листья через настоящий Oracle с синтетическим JSON без записи товара.

## Измерения

На шести рейсах по восемь чередующихся SQL-повторов медиана двух прежних чтений составила 11–26 мс, одного нового — 6–14 мс. Первый разбор нового SQL занял 175 мс и сохранён в исходных измерениях.

Общее ускорение HTTP не подтверждено. Восемь параллельных запросов до изменения занимали 827–1154 мс, после переноса аудита — 1022–1327 мс, после объединения SQL — 1018–1406 мс. Тёплые одиночные запросы остаются около 85–128 мс. Среда и нагрузка не фиксируют SLA; уменьшение SQL-части не выдаётся за ускорение всего API.

Для 13 настоящих запросов каждого контрольного пакета найдены 13 завершённых записей Oracle и 26 локальных записей начала/конца с правильными идентификаторами. Ответы равны прежним. Повтор закрытого выезда вернул прежний результат без новых событий; изменённый запрос получил конфликт. Чтение журнала аудита само помечено неповторяемым. Товар и резерв остались нулевыми, невалидных объектов Oracle нет.

Прямой параллельный вызов расчёта также замедляется: часть времени приходится на получение и очистку соединений, SQL-вызовы под нагрузкой дорожают. Новый процесс использовал пул min=1/max=12/increment=1; после трёх пакетов было открыто 4/5/6 соединений. Причина общего ограничения пропускной способности пока не установлена. V$OSSTAT недоступен текущему пользователю; дополнительные привилегии не выдавались. Codex/T12 продолжит разбор ожиданий пула, Oracle и клиента на повторяемой нагрузке. Индекс и кэш по этим данным не обоснованы.
