# Восстановление запроса назначения или запуска

Локальная статья `metadata-intent-recovery`: подготовлена к публикации владельцем. CASE UI реализует восстановление. Общие клиентские контракты поддерживают TASK ASSIGN/START, но отдельное рабочее место TASK этим изменением не создаётся.

## Работа

Если исход назначения или запуска неизвестен, **не создавайте новый запрос**. «Прочитать результат» получает исходную квитанцию либо подтверждение прекращения. 404, отсутствие связи или отказ доступа не разрешают сбросить журнал.

Если запрос больше не должен исполняться, откройте «Запрос не должен выполняться?», укажите причину и явно подтвердите прекращение. Отдельный запрос прекращения сначала сохраняется на устройстве. С этого момента повтор исходного действия блокируется даже после перезагрузки и в другой вкладке.

При потере ответа можно прочитать результат либо повторить **то же прекращение**. Номер запроса, причина и исходное действие сохраняются. Если запись на устройстве повреждена, сохраните её для разбора старшим смены.

Сервер возвращает одно из двух доказательств:

- Исходный запрос уже обработан: показывается его сохранённая квитанция выполнения или отказа.
- Запрос прекращён: сервер подтвердил, что исходное действие больше не выполнится. Само складское задание продолжает существовать. После подтверждения обновите задание перед новым действием.

Доступ проверяется для исходного оператора на исходном сервере и по текущим правам. Журнал другого пользователя сохраняется; войдите исходной учётной записью. Серверное прекращение с другого устройства допустимо только при точном совпадении исходного запроса; чужая квитанция не подходит.

## Источники и границы приёмки

API: `/api/resources/metadata-intents/abandonments`, `/resolution`, `/abandonments/{operation_id}`. Native owner: RRL_RESOURCE_INTENT_API; исходные CLAIM/START/ASSIGN receipts сохраняют прежний контракт.

UI: `terminal/wms_terminal_web/src/features/inventory/resource-intents/` и интеграция `case-work/useCaseRecovery.ts`. Основной CASE-журнал и отдельный журнал прекращения сохраняют исходные байты. Блокировка browser journal охватывает отправку исходного запроса и прекращения.

Новые UI-проверки с mock API отдельно от native/HTTP/физической приёмки. Клиент не исполняет количественные команды. Публикация help и runtime evidence фиксируются владельцем после проверки.
