# Явная регистрация фактического времени комплектовщика

## Работа

В рабочем месте заданий откройте «Фактическое время». Выберите свою
проверенную рабочую сессию и явно начните фактическую смену. Начало сборки,
пауза, возвращение после паузы и завершение сборки — отдельные действия с
комментарием. Завершение сборки не закрывает задание и не подтверждает товар.
Фактическая смена заканчивается отдельной кнопкой после завершения работы.

Состояние и время события подтверждает сервер. Открытие страницы, запуск
складского задания и сканирование сами по себе отметок не создают.
При открытой смене используется её исходная сессия; при открытой работе —
её исходное задание. Переключение карточки не переносит текущую работу. Если личный поток был начат
для складского задания, пауза, продолжение и завершение сохраняют исходный
тип `WAREHOUSE_TASK` и ID. Новая работа из этого экрана начинается только
для открытой CASE-карточки; она не подменяет уже открытый источник.

Если ответ потерян, сначала прочитайте квитанцию. При необходимости повторите
исходный запрос: сохраняются прежний номер и содержание. Потеря связи, отсутствие квитанции,
отзыв доступа или повреждённый ответ не разрешают очистить журнал и создать
новую отметку. Не удаляйте данные браузера для обхода блокировки; обратитесь
к старшему смены при повреждении локального журнала.

Данные другой операции задания могут временно запрещать новые отметки.
Чтение и точный повтор уже сохранённой отметки времени остаются доступны
исходному оператору; сервер заново проверяет доступ.

Ручные отметки не подтверждают полноту покрытия времени сборки: такой KPI
остаётся «нет данных». Фактическая смена доступна только по закрытым
подтверждённым интервалам и включает паузы. Строки/час и коробки/час эта
панель не рассчитывает.

## Источники и границы

- UI: `terminal/wms_terminal_web/src/features/inventory/picker-time/`.
- Native API contracts: `api/wms_api_server/app/modules/resources/contracts_picker_time.py`.
- Отдельный журнал: `wms.picker-time.journal.v1:<origin>:<actor>`;
  Web Locks и проверка неизменности перед сохранением/отправкой.
- Только явные шесть metadata-команд, без товарных проводок и QC-допуска.
- Статья для локальной публикации: `picker-actual-time`; её публикация
  выполняется владельцем базы знаний отдельно от исходного Markdown.
