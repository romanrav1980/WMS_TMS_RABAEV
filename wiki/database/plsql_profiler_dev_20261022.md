# Профилирование PL/SQL в dev

Подготовлена миграция `2026-10-22-plsql-profiler-dev`; применение ещё не выполнено. Она создаёт только стандартные таблицы и последовательность профилировщика в RABAEV, без выдачи прав и изменения бизнес-пакетов. Установленный DBMS_PROFILER.GET_VERSION вернул2.0; исследуемые пакеты скомпилированы INTERPRETED.

[Документация Oracle19c](https://docs.oracle.com/en/database/oracle/oracle-database/19/arpls/DBMS_PROFILER.html) задаёт состав таблиц и единицу времени — наносекунды. Профили собираются только отдельным тестовым процессом; сервер API не включает их автоматически. Перед бизнес-транзакцией необходимо проверить отсутствие прежней транзакции; запись диагностики не должна менять её границы. Семантика start/stop проверяется отдельной пробой до складского сценария. Значения параметров запросов не сохраняются.

[Миграция](../../db/migrations/2026-10-22_plsql_profiler_dev/apply.sql) отказывается заменять существующие объекты; [откат](../../db/migrations/2026-10-22_plsql_profiler_dev/rollback.sql) запрещает удаление накопленных профилей. Бизнес-количества, блокировки и код исполнения сохраняются.
