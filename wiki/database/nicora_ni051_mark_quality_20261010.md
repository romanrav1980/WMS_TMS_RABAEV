# NI05.1: уникальные марки при контроле

062 APPLIED в RABAEV/orcl. Пакеты RRL_STOCK_QC_MARK/QC_GATE/PALLET_QC_CMD и stamp/invalidation triggers VALID; checkpoints332–333. [Migration](../../db/migrations/2026-10-10_ni051_mark_quality/apply.sql), [own case](../../scripts/ni051_mark_quality_case.py). Продолжает [[nicora_ni051_weight_policy_20261010]], не закрывает весь спринт.

Маркируемый SKU определяется существующей карточкой WMS: MARKING_REQUIRED, CRPT_REQUIRED или applicable RRL_SKU_RECEIPT_PROFILE. OUTGOING_PALLET_CHECK SCAN с нулём ошибок требует точного покрытия всех физических единиц всеми активными профилями. Используются существующие RRL_WMS_RECEIPT_UNIT и CODE registry; raw QR нормализуются прежним canonical_mark и сервером превращаются в code_hash. Root проверяет принадлежность каждой марки current physical composition/profile и сумму BASE quantity. Одна единица с двумя профилями не становится двумя единицами.

SCAN_MARK_PROVED и SCAN_PHYSICAL_UNIT_COUNT добавлены к существующей СТ и защищены root QC guard. Shipment маркированного товара требует текущей scan подписи и доказанного покрытия независимо от legacy BLOCK_IF_NO_PROOVE и хорошего веса. Вес сам по себе не доказывает уникальные коды. Signature включает кодовые hash/profile associations, physical identities, SKU profiles и упаковку; кодовый состав/конфигурация/изменение строк отзывает допуск. Несоответствие не оставляет изменения качества/P/H благодаря одной root транзакции.

API /outgoing-quality/scan принимает actual raw scans по системе/профилю. Read возвращает applicable profile choices и число физических единиц, без выдачи ожидаемых QR оператору. ARM warehouse-tasks: выбранный профиль + scanner input, сохранённый список, stale composition требует очистки/повторной сверки. Финальный result сохраняется до отправки и повторяется неизменным. Native LOT_CHECK старого формата без unique evidence не может положительно подтвердить marked SKU; native terminal adapter ещё требует подключения нового QR прохода.

Targeted case passed: private SKU, physical3EA с CRPT+EGAIS6 кодами, существующее marked birth/task scan draft/actual move/fullpal binding; weight-only и waiver не допускают shipment; count-only, missing profile, foreign code, duplicate и stale signature denied; raw-code API bridge, successful3-unit proof/replay, quantity edit/restore invalidation; exact shipment + wave DONE, own P/H cleaned root. Browser/independent controller и другие regulatory adapters не объявляются принятыми.

Границы slice: complete whole marked allocation, до10000 физических единиц/20000 unit-profile scans/50 profiles на SKU,200 legs. Split allocation одной physical UID и shipment document по другому legacy пути не закрыты. Приёмка известной агрегации и её composition registry уже существуют, но QC aggregation scan здесь не заменяет unique-unit proof — отдельный ticket NI04.2/NI05.1. Государственный ACK и legal circulation gate остаются NI04.3.

Slow SQL: раньше потенциальный unit-by-unit profile/code SELECT заменён bounded matrix cursor + one indexed scan-registry join и framed in-memory exact coverage map. Query6zt85gd6035fh ~0.91ms/14, matrix03umcuruq1b0v ~0.51ms/14; existing task draft3.02ms. Existing code UID/UNIT and SYSTEM/HASH indexes и unit current index используются; новый индекс не нужен по этому case. NI08 owns pallet-code volume capacity; эти цифры не подтверждают миллионы операций.
