# Отмена пустого задания СНС/BLC

Миграция `2026-10-22-trade-empty-case-cancel` прошла применение, откат и повторное применение, INVALID0. Шесть прямых native проверок подтвердили точную привязку исходного резерва и сохранение допуска наполненного CASE; неправильный скан, версия, чужая партия и отсутствие явной отмены отклонены.

На CASE1164 отмена пустого задания остановилась с `TRADE_RETURN_CASE_LOT_BINDING_REQUIRED`. Отбора не было; ядро отмены объявило исходный резерв2EA, а проверка TRADECASE требовала товарную партию внутри CASE. Поэтому резерв остался действующим: WARE220793322 —8EA/HARD6.

Исправление допускает снятие исходного резерва только при явной отмене пустого задания: текущее задание, склад, этикетка и версия должны совпасть; отбор и состав CASE отсутствуют. Резерв должен принадлежать той же волне и связанному заданию отбора, исходной паллете и строке заказа TRADECASE. Остальные проверки ядра отмены, области, владельца и фактических количеств сохраняются. Возврат наполненного CASE использует прежнюю проверку партии.

SQL и сохранённое прежнее тело: [миграция](../../db/migrations/2026-10-22_trade_empty_case_cancel/apply.sql), [откат](../../db/migrations/2026-10-22_trade_empty_case_cancel/rollback.sql). После применения нужно повторить неизменную отмену, проверить8EA/HARD4 и отключить тестового комплектовщика; результат пока не заявляется.

Повтор той же отмены прошёл первый допуск и остановился с `TRADE_RETURN_COMPLETE_ATTRIBUTES_REQUIRED`: запись возвращаемых физических единиц вызывалась и для пустого задания. Количество не изменилось, резерв остаётся6. Подготовлена вторая миграция `2026-10-22-trade-empty-case-capture`: она пропускает запись единиц только для уже проверенного и замороженного домена `empty_cancel=true` с пустым составом. Дважды выполненная native проверка отмены и фактический возврат наполненных мест сохраняются. [SQL](../../db/migrations/2026-10-22_trade_empty_case_capture/apply.sql) и [откат](../../db/migrations/2026-10-22_trade_empty_case_capture/rollback.sql) сохранены до применения.

До отказа отмены на настоящем API прошли два одновременных повтора ручного измерения с одной записью, неизменный повтор, конфликт изменённого запроса, неверный скан, старая версия, нулевой вес, чужое задание, отзыв/восстановление владельца и назначения. Повторное измерение пустой тары0.2кг сохранило отдельную запись и стало текущим. История: `runtime/test-evidence/tradecase/2026-10-22/T07/manual-tare-live.json`; пользователь пока активен, товар не отбирался.
