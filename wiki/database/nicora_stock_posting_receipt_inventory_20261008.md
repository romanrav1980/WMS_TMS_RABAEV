# Переход проводки: приёмка, инвентаризация и локальные адаптеры

08.10.2026. Продолжение [[nicora_stock_posting_continuation_20261008]]. Все изменения — в существующей RABAEV/orcl. Полный переход остаётся незавершённым; режим PREPARED, B0/cutover не выполнены, compatibility по умолчанию OFF.

## Реализовано и установлено

- Компоненты 131–135: RECEIPT_REVERSE и адаптер RRL_STORNO_ORDER3. Операция сохраняет исходные паллеты и историю, проверяет исходное поступление, отсутствие расхода/недостачи и HARD, нахождение товара в зоне приёмки, состав маркировки, задания размещения. Списание, отмена неисполняемых заданий и обязательное SAP RECEIPT_REVERSED входят в транзакцию ядра. При потреблении/недоказанном происхождении нужна отдельная коррекция; автоматического удаления истории нет.
- Компоненты 136–141: RRL_INV_CREATE_LINE2/3/4 и RRL_REVIZION_CELL_KOR используют INVENTORY_REGISTER_LOT / INVENTORY_COUNT. Требуются реальная ревизия, пользователь и сохранённый ID операции; неоднозначные партии не объединяются. BOX переводится точно. Маркированная корректировка без состава отклоняется; положительный capture ещё не реализован.
- Компоненты 142–143: RRL_STOCK_METADATA_TX и receipt_task_metadata сериализуют replan/cancel с проводкой через RELEASE/CONFIG до блокировок документов. Контекст записи остатков не выдаётся. Replan сравнивает POSTED_BASE_QTY с физическим количеством; cancel отклоняет IN_PROGRESS/DONE.
- Локальные task_stock_move / task_reservation в ACTIVE читают проведённый TASK_COMPLETE вместо повторения прежних эффектов. WarehouseTaskDomainSyncService дополнительно проверяет количество, паллету и ячейки. Четыре конкретных локальных writer зарегистрированы ADAPTED.
- Компоненты 145–146: перенос выбранных единиц между физическими UID допускается в той же ячейке; исходные коды и опубликованные государственные агрегации сохраняются. StockPosted contract 3 содержит before/after и признак PHYSICAL_REPACK_PROPOSED / PENDING. Это предложение внешней обработки, а не подтверждённая переагрегация или завершённая складская матрёшка.
- Компонент 147: пять процедур автоматической приёмки/отката заменены после ACTIVE на явный отказ с указанием существующего экрана SAP. PREPARED fallback ограничен ACCESSIBLE BY; оригиналы сохранены в парных rollback SQL. WinForms кнопки открывают receiving.html с выбранным receipt_document_id, без изменения статуса до факта. Адрес переопределяется WMS_RECEIVING_URL; локальное значение соответствует front.bat (127.0.0.1:3000).
- Экран receiving.html получил отдельный receipt-reversal.js: обязательная причина, durable localStorage intent с изоляцией по API/пользователю, повтор прежней команды при неизвестном исходе. API обращается к ReceiptReverse через application port и composition-root factory; автор берётся из аутентифицированной сессии. Успешный браузерный сценарий пока не подтверждён.
- Существующий SAP API получил точный lookup накладной /by-receipt-document/{document_id}; это открывает нужный заказ даже вне последних 100 поставок. Экран получает выбранный документ после авторизации.
- Компонент 148: сторно учитывает только доказанно принятые исходные паллеты, сверяет полный физический итог с исходным поступлением. Плановые PAL без поступления не объявляются запасом. Инвентаризация существующей партии отклоняет противоречащий срок годности; replay восстанавливает исходную команду.
- MES ошибки RESULT_UNCERTAIN сохраняют команду клиента и возвращают неизвестный исход для повтора с тем же ID.

## Доказательства и границы

Source checkpoints и парные rollback находятся в runtime/stock_posting_20261008 и SQL каталоге. Полная копия базы или VM не создавалась. Установки до 148: Errors=0. Миграции 047–056 представлены в 150_receipt_inventory_ledger.sql.

Свежий реестр после 149: 19 ADAPTED, 5 RETIRED, 7 UNCONVERTED. Пять RETIRED — именно прежняя автоматическая приёмка/удаление; их замена — существующая SAP pallet receipt и задания, а не фиктивная адаптация. Реестр отражает рассмотренные кандидаты, не доказывает отсутствие косвенных вызовов.

Python syntax и receiving.js syntax проходят. Encoding check выявил только прежний raw TRANSPORT_TASK_PACKAGE_BODY.sql с U+0420 U+00A0; raw не переписывался. Полная сборка WinForms, браузерный сценарий и физическое проведение этим этапом не подтверждены. Режим ACTIVE не включался для обхода незавершённых функций.
