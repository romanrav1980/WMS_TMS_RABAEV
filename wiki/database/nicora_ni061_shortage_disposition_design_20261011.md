# Подтверждение транспортной недостачи после частичной приёмки
295: товар уже списан со склада отправления фактической отгрузкой; частичная приёмка291/292 породила только принятое количество. Подтверждение утраты не списывает недостачу со склада повторно и не создаёт недостающий запас.

Два явных действия через единственный RRL_STOCK_POSTING_API: INTERWARE_SHORTAGE_REPORT текущим диспетчером склада назначения и INTERWARE_SHORTAGE_CONFIRM другим текущим согласующим store_return_approve этого склада. Основание, документ и точное недостающее количество обязательны. Получатель исходной приёмки может согласовать чужой акт: независимость относится к автору акта. Администратор не обходит разделение автор/согласующий.

Один неизменяемый request на partial receipt и один confirm на request/receipt. Точное original_source_units minus source_units, BASE/UOM, текущие ISSUED/исходные UID/cell/version/отсутствие резерва проверяются при планировании и вновь после ожидания. До10000units. Блокировки RELEASE/CONFIG shared, OP10, domain ROW20, HU30, UNIT60, outbox UNIQUE70 в общем сортировщике; stock50 не нужен: P/H не меняются. Разные перевозки параллельны. Cached result требует текущих прав/WARE до и после ожидания.

Единая короткая транзакция: stock-operation journal + report/confirm + confirmed missing-unit book + SAP intent/common outbox. Нет innerCOMMIT/внешнего HTTP. Нет изменения UID рождения/QR/BASE/unit status; подтверждённые отсутствующие единицы остаются исторически ISSUED, но confirmed-loss book запрещает дальнейшую обычную мутацию/приёмку этих единиц до отдельной корректирующей операции. Государственная юридическая операция/квитанция не выдумывается.

295 не освобождает ответственность рейса и не разрешает выезд автоматически. Следующий296 должен явно завершить ответственность на основании actualAccepted+confirmedShort=originalDeclared и использовать для следующего плеча только acceptedUID/acceptedQty. Исходный заказ и непоставленная потребность сохраняются. Ready общего количества не подменяется утверждением «полностью получено». Позднее найденный товар требует отдельной восстановительной/корректирующей операции с независимым основанием; подмена уже подтверждённой потери недопустима.

Rollback295 запрещён при сохранённых report/confirm. Достаточные dev-кейсы: ordinary/marked own partial291/292, report/confirm differentactors, exact replay/collision/race/outerrollback, currentWARE revokedafterwait, acceptedP1/unreceivedP0/protected20-20 unchanged, missing-unit mutation denied. Независимое/browser/hardware/external принятие отдельно.
