# Допуск добивки по паллетоместам

Добивка теперь отказывает, пока для товара и планируемой перевозки не подтверждены тип паллеты, число мест и правило штабелирования. API не показывает количество подходящих коробов, не сохраняет предложение и не резервирует запас. Отказ возвращает `TOPUP_PALLET_PLACE_MAPPING_REQUIRED`.

Проверка не выводит паллетоместа из объёма короба, `COUNT_IN_ROW × ROWS_IN_PAL` или поля `ALLOW_TOP_STACKING`: их значения и смысл не подтверждены. В просмотренных 64 активных правилах товара тип паллеты не задан; у 32 заполнено количество коробов на паллете, но этого недостаточно для допуска. В плановых строках TRIP нет типа паллеты и количества мест. Положительный расчёт поэтому не заявляется.

На реальном Oracle/API для склада `226192056`, рейс `T1`, запросы на 1 и 100000 коробов получили блокировку; просмотр добивки и сохранение предложения получили 409. Число предложений, резервов и активных резервов до и после осталось `1/3/0`. Максимальная длительность HTTP — 378 мс; slow-SQL за прогон не записал запросов. Это не проверка реального рейса или внешней доставки.

Остаётся определить и заполнить источник данных «товар → тип паллеты и коробов на место», правило штабелирования и тип/места уже назначенных строк рейса. После этого нужны положительная граница и превышение лимита на отдельном подтверждённом наборе. Предложения, созданные до изменения, по-прежнему можно подтвердить нативной проводкой; их проверку следует закрыть отдельно.

Изменённые модули: `trade_capacity.py`, `trade_topup.py`. Проверки: `test_trade_floor_capacity.py` (9), существующие проверки вместимости и добивки (82), полный TRADECASE (381 passed, один несвязанный сбой создания `%TEMP%` pytest-каталога). Экран вместимости показывает объяснение каждого известного отказа, скрывает расчёт при блокировке и помечает весовой/объёмный предел как оценку. Экран проверен без заглушки на живом API/Oracle при 1440 и 390 px; shared API 8088 ещё не перезапущен и отдаёт старый ответ до штатного обновления. Quality gate, encoding и architecture прошли. Полные доказательства: [RESULT_C0178](../../coordination/retailcase-claude/RESULT_C0178.md) и [RESULT_C0179](../../coordination/retailcase-claude/RESULT_C0179.md).
