# NI04.2: SSCC малой коробки

Миграция 2026-10-11-203-case-logistic-sscc. Новый идентификатор выдаётся только пустому CASE до отбора. Общая последовательность приёмки и складской настройки GS1 повторно используется; назначенный компании префикс обязателен. CP сохраняется в неизменяемом архиве. Обновление идентификатора и версии, архив исходной команды и ответа — одна существующая metadata-транзакция CONFIG; количества и резервы не меняются. Повтор той же команды возвращает исходный ответ; другое содержимое отвергается.

Подтверждение требует сканирования прикреплённого SSCC. Тип CONTAINER с FINAL_WEIGHT_REQUIRED требует подтверждения до первого отбора в исходном native CASE, включая повторную проверку под блокировками. Обычные старые места без этого признака сохраняют текущий путь. После выдачи SSCC его замена запрещена. Печать использует существующие GS1-128 SVG/ZPL, без планового количества на этикетке пустой коробки. Это логистическая этикетка; ответ государственной системы агрегации отдельно.

Восстановление: свежие CASE package и labels.py сохранены в 000_before/checkpoint.json; пустые новые объекты обратимы paired rollback. При появлении архива необходима корректирующая миграция с сохранением истории. Копия базы не создаётся.
