# Переход REVIZION на явные проводки

08.10.2026. Продолжение [[nicora_stock_posting_receipt_inventory_20261008]]. RABAEV/orcl остаётся PREPARED; полной замены всех путей и B0/cutover ещё нет.

## Изменения

- 151 RRL_STOCK_REVISION_ENTRY: адаптеры существующего пересчёта в EA/BOX. Данные ревизии и партий читаются до входа в команду без DML; изменение запаса выполняет INVENTORY_COUNT. Если несколько положительных партий, требуется пересчёт по паллетам; распределения общего отклонения между партиями нет.
- Повтор сначала восстанавливает CANONICAL_REQUEST и сравнивает пользователя/исходные параметры, затем возвращает сохранённый результат. Изменённые количества с прежним ID отклоняются. Состояние закрытого документа не препятствует повтору уже проведённой команды.
- 154: revision_row_id входит в lock plan до исполнения. При выполнении повторно проверяются документ/товар/ячейка и отсутствие других положительных партий для старого общего поля. COUNT1, COUNT_KOR и отметка операции записываются в той же транзакции, что и журнал/остатки/outbox.
- 155: создание инвентаризационной паллеты использует INVENTORY_REGISTER_LOT. Сохраняются MOD_ID, веса брутто/нетто, количество коробок и процент брака. Неправильные значения/модификация другого товара отклоняются. Источник — ревизия, PRIHOD_NAKLAD_ID сохраняет договор ядра -revision_id; прежний инвентаризационный приходный документ указан в legacy_facts команды.
- 157: разрешены разные явно идентифицированные паллеты одного SKU/ячейки в одной ревизии. Положительный запас другого источника/документа запрещает новую первоначальную загрузку поверх него. Граница ячейки сериализует проверку с движениями.
- 152/156: публичный REVIZION сохраняет метаданные/снимки и прежние сигнатуры с optional operation_id. Прямые delete остатков и insert событий из его физических функций убраны. Прежняя реализация — в REVIZION_SP_OLD, ACCESSIBLE BY(REVIZION), только PREPARED. Подсчёт паллет сам по себе не превращается в количество товара; удаление/обнуление и очистка минусов направлены на явный пересчёт с основанием.
- Ревизии.InventoryCommands.cs подключён к существующей WinForms форме и csproj. Для ACTIVE редактирование EA/BOX использует Decimal, штатный Oracle PL/SQL-вызов и StockCommandIntent, сохраняющий параметры до запроса. При неоднозначной партии открывается существующий inventory-count.html с revision_id/cell. Создание паллеты тоже сохраняет ID и Decimal факты. Ошибка не оставляет оптимистически проведённое количество в таблице.
- inventory-count.js умеет открывать указанную ревизию/ячейку после авторизации. Форму множественных партий не создавали повторно.
