# NI08.1: очередь и чтение складских заданий по текущему складу
Действующие команды уже проверяют склад144, но публичные list/detail/progress/sync читают legacy service без actor warehouse. Добавить единый read-only scope с текущими RUSERS/right/WARE и существующим RRL_WAREHOUSE_TASK_ACCESS для конкретного task. Все факты каждого ответа и права читать одним snapshot.
Оставить прежние SQL сортировки, фильтры, лимиты и getters. В списках применить текущий FROM/TO WARE до ограничения; GLOBAL_ADMIN сохраняет все склады. Не выполнять permission-функцию для каждой строки всех заданий. Domain sync и progress получают тот же bound gateway; никаких новых проводок, replay или mutation при чтении.
Внутренние старые сервисные вызовы сохраняются; публичные HTTP routes обязаны передавать проверенный scope. Фактическое освобождение ресурса при отмене — следующий отдельный ticket.
