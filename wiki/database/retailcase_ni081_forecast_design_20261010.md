# NI08.1 — исполненная история для прогноза,133: проект реализации

Вход: существующие RRL_TT_HU_LOAD_FACT со статусом DEPARTED и aware DEPARTED_AT, frozen COMPOSITION_JSON. Native WMS/TMS и источник заказа сохраняются. Истории forecast/stat/daily таблиц в live RABAEV нет; прежние RRL_TRANSPORT_TASK_HISTORY/SBORKA_PALLETS_HISTORY не имеют подтверждённого товарного состава нового ядра.

Владелец transport для фактической отгрузки и производной истории. Прогноз не пишет P/H, не создаёт рейсы/заказы и не назначает людей. Единственный товарный writer — прежний Root. Материализация идёт отдельно, короткой транзакцией одного фактического места, без блокировок складских остатков/общего CFG. Права текущего warehouse-bound transport_dispatch_edit для материализации, transport_dispatch_view для чтения; GLOBAL_ADMIN существующий all-rights.

Read model: immutable источник с original LOAD ID/hash/aware departure/WARE/result, immutable строки по SKU/BASE/классу работы, daily counters по UTC-дню; отдельная идентичность CASE-происхождения предотвращает повторный спрос одного CASE lot. Только STOCK leaves, один верхний физический груз; несколько профилей/вложенная тара не увеличивают количество или машиноместа. CASE отбирается в исходном warehouse_CASE_TASK; в следующем плече тот же CASE не считается новым отбором. FULLPAL отдельно от CASE; старые неоднозначные даты не переинтерпретируются.

Проектор использует собственный private transaction-scoped пакетный контекст для guards аналитических таблиц; source PK -> CASE origin keys в стабильном порядке -> day header -> SKU keys в стабильном порядке. Конкурентный повтор исходного места возвращает сохранённый результат; источник/hash другой — отказ, не повторный counter. Oracle RRL_STOCK_MATH.quantity остаётся authoritative decimal parser. Нет отдельных commit внутри процедур. Worker/API обрабатывает bounded100 источников, каждый отдельным Unit of Work; исходные load факты immutable, публикации их не изменяются.

Прогноз читает daily aggregates в одном READ ONLY snapshot, до90 UTC-дней/500 SKU-series. Минимум активных дней задаётся явно, текущий неполный день отдельный режим с долей экспозиции. Calendar-day mean — объяснимый первый метод, без выдуманной сезонности/производительности людей. CASE-demand/FULLPAL/outbound workload не выдаётся за окончательные продажи клиенту; промежуточное плечо отдельно от исходного CASE-demand. При не материализованных источниках или недостаточной истории рекомендация блокируется. Локальные software fixtures не подтверждают качество реальной истории.

Отдельными следующими tickets остаются ресурсные нормы/вывод людей, рекомендации диапазонов со сравнением отбора/пополнения и утверждением/вымыванием, общий validator ручного/автоплана и реальные operational inputs. Готовые VRP/карта/Ганта не переписываются.

Author slice: projection own departed sources, repeat/no double counters, nested CASE/frozen leaves, current actor/foreign WARE, exact Decimal aggregation, current partial-day flag and missing history gate; no stock writes. Slow SQL — решение по исходному warehouse/status/departure index и bounded aggregate reads. Независимая приёмка/полный NI08.1 остаются открыты.
