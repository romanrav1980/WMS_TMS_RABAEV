# Входящая машина по основаниям поставки

Программа TRADECASE revision27 требует запись входящей машины, плановое время и ворота приёмки. Прежний двор принимал только исходящие рейсы. Полученное основание SUPPLY содержит состав паллеты и собственника, но не номер машины: номер вводит сотрудник при записи визита.

Миграция [2026-10-23-yard-inbound](../../db/migrations/2026-10-23_yard_inbound/apply.sql) связывает входящий визит с одним или несколькими принятыми основаниями поставки. Она сохраняет версии оснований. До приезда сотрудник проверяет номер машины; изменившееся основание требует отменить ожидание и создать актуальный визит. При регистрации приезда система проверяет текущие основания, доступ к собственникам и занятость машины. Ворота назначаются действующей командой двора; приёмка и размещение товара остаются отдельными действиями.

## Техническое приложение

Добавляются таблица RRL_YARD_VISIT_SUPPLY и helper RRL_YARD_SUPPLY_API. Запись связей разрешена только из native владельца визита; связи неизменяемы. Пакет RRL_YARD_VISIT_API сохраняет исходящий контракт, добавляет текущую проверку всех собственников входящего визита перед изменением и повтором. Список и история скрывают недоступные визиты до ограничения. Визиты сериализуются действующей блокировкой площадки, занятость машин и ворот защищают прежние уникальные индексы. Команда получает savepoint для атомарного отката нескольких связей при отказе.

Изменение не создаёт товарных проводок. Новых полей ERP для машины не объявляется. API ожидает либо прежний trip_id, либо supply_ids и введённый vehicle. Существующее восстановление команды по operation_id сохраняется.
