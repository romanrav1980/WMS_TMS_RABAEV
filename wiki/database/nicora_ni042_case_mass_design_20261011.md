# NI04.2: доказанная масса CASE в отгрузке
207 использует действующие HU/read/loadbox/store reader. Физическое место CASE не дублируется новым RRL_PALLETS BOX: его логическая идентичность CASE:id/SSCC сохраняется. В существующей таблице frozen box mass различаются обычный pallet BOX и измеренная CASE-коробка; conditional FK использует виртуальный PALLET_BOX_UID и обычный CASE FK, старые факты не переписываются.
Для CASE с собственным актуальным v3 QC исходные брутто/тара/нетто, capture/QCoperation, TEST/HARDWARE, подпись и измеренная/текущая версии доступны в существующем HU snapshot. Количества остаются на прежних STOCK листьях. Сумма массы дерева включает CASE брутто один раз и внешнюю тару, а не исходный gross паллеты поставщика. Листья, покрытые массой CASE, не добавляют её повторно.
Существующий loadbox compiler автоматически замораживает серверную CASE-массу; пользователь не меняет её ручной строкой. Обычные manual BOX сохраняют прежний путь. Полное покрытие/исключение перекрывающихся вложенных коробок/масса внешней тары и обязательная магазинная WEIGHT_PHOTO policy сохраняются. Original root фиксирует frozen box rows вместе с фактической погрузкой; отдельной товарной проводки нет.
Магазин получает immutable departure snapshot и frozen box gross/tare/net/SSCC/source/provenance/version; внешний вес исходной паллеты или справочный вес SKU не подменяют эти факты. Реальный hardware pilot отдельно от TEST.
Свежие пакеты/guard/точные constraints/column shape сохранены перед изменением. Additive metadata/conditional FK без изменения старых фактов. Paired rollback до CASE load facts, затем forward repair; копии базы нет. [Oracle virtual columns](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/CREATE-TABLE.html) и [constraints on generated columns](https://asktom.oracle.com/ords/f?p=100%3A11%3A0%3A%3A%3A%3AP11_QUESTION_ID%3A9537322600346444039) подтверждают выбранную декларативную связь.
