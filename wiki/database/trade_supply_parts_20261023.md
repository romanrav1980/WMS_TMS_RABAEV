# Состав поставки частями

Кандидат C0163rev1, checkpoint `50240d01`, дополняет приём полного документа поставки. Миграция `2026-10-23-trade-supply-parts` пока NOT_APPLIED. Root проверяет применение и реальные сценарии. Этот внутренний API не описывает промышленный протокол SAP.

Отправитель передаёт части с одним заголовком и итог с числом кодов и контрольной суммой. Итог может прийти первым: система сохраняет его и показывает недостающие части. Полный сверенный состав поступает в прежний приём документа под постоянным идентификатором события. Потеря ответа не создаёт второй документ. Физический приход выполняет прежняя операция склада, а не приём частей.

Повтор сохраняет исходный идентификатор события. Другому событию нельзя присвоить уже записанный номер части или событие итога. Исправление состава получает новую версию и передачу. Поздняя старая часть не заменяет принятую новую версию. Полный документ ограничен прежним1МБ; превышение фиксируется как отказ передачи.

## Проверки перед применением

Root добавил в неприменённый кандидат сохранение END-only истории при откате, отдельность идентификаторов частей/итогов и проверку собственника перед записью окончательной квитанции. Эти изменения не расширяют физическую проводку. Пустой откат проверяется до накопления истории; при наличии любой передачи откат должен отказать.

Автор проверил модели и интерфейс с подставленными ответами. Root должен проверить порядок END→2→1 и2→END→1, повторы/конфликты, версию, отзыв доступа, конкуренцию и восстановление после приёма. Исходящие подтверждения состава и раннее закрытие сборки остаются отдельной задачей C0164; весь T02 не завершён.
