# NI04.1: физический слот и измерения матрёшки

053 APPLIED в RABAEV/orcl. RRL_STOCK_HU_SLOT/read/cmd/task и RRL_HU_TASK_PLAN_GUARD VALID. [[retailcase_ni041_hu_tasks_20261010]].

Существующее MANUAL/PUTAWAY фиксирует TO_CELL_SLOT_ID и HU_MEASUREMENTS_JSON: масса брутто, ширина/глубина/высота в SI, origin MANUAL_CONFIRMED и версия состава. Это подтверждение оператора, а не доказательство измерения устройством. Габаритный объём округляется вверх до 9 знаков. Масса не может быть ниже тары плюс известной KG-массы листьев.

Проверяются текущая опубликованная топология, активный STORAGE_SLOT, одно машиноместо, размеры без автоматического поворота, масса/объём, температурные правила каждого SKU и блокировки ячейки. Старый LIMIT_HEIGHT применяется только с явно настроенным HU_CELL_HEIGHT_UNIT M/CM/MM в RRL_RECEIPT_WARE_SETTINGS. Неизвестная единица не угадывается. Историческая масса товарной паллеты не используется после изменения её количества.

В первой версии сохраняется ограничение пустой ячейки на одно верхнее HU. План занимает слот через существующее открытое warehouse task: receipt placement уже исключает слот по TO_CELL_SLOT_ID. Завершение требует скан SLOT_CODE, повторно проверяет ограничения под упорядоченными CELL/SLOT/HU/ROW/stock/unit/reserve ресурсами, переносит P/H и создаёт один OCCUPIED RRL_RECEIPT_SLOT_CLAIM за верхним контейнером с настоящим TASK_ID. Количественных строк у контейнера нет; резерв каждого листа получает тот же target slot. Существующая отмена планового задания освобождает плановый слот статусом CANCELLED; отдельная очередь резервирования слотов не создана.

Возврат целого HU в свободную рабочую ячейку удаляет прежний parent claim в той же проводке. Вскрытие в занятой слотовой ячейке запрещено до реализации атомарного освобождения дополнительных физических мест. Несколько HU в одной ячейке, агрегированная нагрузка, same-cell смена слота и CASE-вложения остаются следующими slices.

API target-slots и существующий ARM позволяют выбирать код слота; warehouse task показывает код и принимает скан. Новые отсутствующие optional поля исключаются из canonical payload, чтобы не ломать повторы старых сохранённых операций.

Адресный dev case scripts/ni041_hu_slot_case.py: приватный бизнес-склад в той же RABAEV (не новый экземпляр), TOP/BOX/лист5/H2; неверная версия измерений, превышение габаритов, неопределённая единица legacy высоты и неверный скан отказали; plan/assign/start/complete/replay сохранили owner, одну stock fact и один claim. Возврат в рабочую ячейку/unpack/освобождение HARD/обнуление собственного P через root выполнены. Остаток неудачного cleanup предыдущего fixture также очищен тем же способом. Независимая приёмка драйвера, нагрузка и browser ещё не объявлены выполненными.

SQL после случая: HU snapshot SQL_ID 3uwrpkb9x39z1 — 3.50 мс/75 выполнений, API snapshot 0w1m750nc3a9r — 7.43 мс; claim lookup 70u5hvudut25w — 1.07 мс. Slow-log за последний час пуст. Решение: оставить bounded200 nodes/depth16 и key lookups, новый индекс без доказанного bottleneck не добавлять. Диагностические запросы V$SQL из оценки исключены. CELL fence пока сериализует размещения одной ячейки; owner inventory/NI08 должен уточнить ресурсную гранулярность после поддержки нескольких мест с сохранением проверки суммарной нагрузки.
