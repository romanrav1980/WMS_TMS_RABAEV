# Целая паллета при передаче добивки волне — 26.10.2026

На тестовом складе 223214750 согласованная добивка удерживала 600 единиц на трёх целых паллетах по 200. План создавал CASE_PICK без ячейки отбора вместо FULL_PALLET; выпуск волны останавливался до движения товара.

Первая правка неверно трактовала active_reserved_qty как HARD. Этот показатель считает SOFT. Комплект 2026-10-26_topup_whole_pallet не прошёл живую проверку и откачен: 8 операторов, 0 ошибок. Его нельзя применять повторно.

Причина находилась в снимке заблокированного остатка: REMAIN-HARD_RESERVED_BASE давал ноль при собственном полном удержании добивки. Комплект 2026-10-26_topup_whole_pallet_v2 использует физический REMAIN только для добивки. Доступное количество по-прежнему берётся из hold_free конкретного предложения и строки; исходные условия выбора целой паллеты сохранены. Обычный отбор продолжает учитывать свободный остаток.

V2 применён, проверен пустой откат и повтор: 8/8/8, INVALID 0. Коммит 1cb04567; действующий SHA тела RRL_PICKING_API: 242BD8D6FA3AB6542B426AB1C7C2AF69375017FA79F8E1F56893287E0DDFD8A2.

Живая проверка дала CASE_PICK для удержания 100 из 200 и три FULL_PALLET по 200 для полного удержания. Новая волна приняла те же 600 физических единиц и reservation_id без второго резерва. Старые волны и предложения закрыты штатными командами. Отмена волны не отменяет отдельный SOFT-план; собственные старые планы 2275/2277/2279 отменены отдельно перед повторной проверкой.

Выполнены 33 штатных перемещения, привязка к отгрузке и исходящий контроль 6600 синтетических кодов. LOAD всех 33 паллет и UNLOAD восстановили 6600/H6600; точные повторы первого LOAD и UNLOAD проверены. Найден отдельный пробел проверки габаритов кузова, поэтому первоначальный прогон не подтверждает вместимость. Полный T08 остаётся открытым.
