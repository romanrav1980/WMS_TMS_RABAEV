# NI08.1: предварительный контроль прежнего транспортного плана (163)

Владелец transport. Предварительный API повторно использует RRL_TRANSPORT_PLAN_RULES.check_vehicle/assert_actor; правила вместимости, массы, типа машины, гидроборта и ограничений адреса не продублированы в Python. Результат не является разрешением физической погрузки или сохранённым validation token.

GET /api/transport/preflight/plans/{id} читает существующий PAYLOAD; POST /api/transport/preflight/trips/{id} проверяет прежний рейс с предлагаемыми additional_st_numbers. Требуется transport_dispatch_edit и текущий активный RUSERS; склад каждой найденной СТ проверяется нативно до возврата её данных. Одна READ ONLY transaction для всего снимка. Никаких TT/ST/P/H/записей применения.

Показаны текущие source rows, отсутствующая/чужая/отгруженная СТ, несовпадение ID/госномера, машина/вместимость/масса/адрес, строгие окна без подтверждённого расписания, отменённый/отгруженный/выставленный в счёт рейс. Сохранённый относительный schedule отображается как источник, но не снимает native strict gate. Ограничения водителя, перерывов и складской готовности остаются unverified, operational_admission=false. Уже применённый план показывается как исторический; исходный native replay применения не изменён.

Структура ограничена100маршрутами/200СТнамаршрут/2000СТвплане/5000исходныхстрок/4MBJSON. Входной JSON/дубли/некорректные ключи отвергаются. UI планировщика запускает чтение по кнопке, показывает понятные причины и инвалидирует результат при смене plan_id; запоздалый ответ не относится к новому плану.

Авторские случаи: scripts/ni081_transport_preflight_existing_case.py — текущий633 с двумя отсутствующими СТ, прежний632 уже применён/машина retired,33523отменён; реальные HTTP plan/manual/422/404, количествоTTнеизменно/P20H20. Изначальное предположение автора, что vehicleID162 отсутствует, оказалось неверным: машина существует, сохранённая тестовая plate ей не соответствует; проверка исправлена и несовпадение показывается явно. scripts/ni081_transport_preflight_scope_case.py — исходный личный Q134: временное право/WARE1/DELETED только rollback; чужой склад403, текущий свой источник доступен, отключённый403; всё восстановлено.
