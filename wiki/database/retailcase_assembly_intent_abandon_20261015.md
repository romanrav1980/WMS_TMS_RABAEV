# Сборка: отказ от несозданного запроса

Статус APPLIED (DDL/source, бизнес-приёмка впереди), migration `2026-10-15-assembly-intent-abandon`. Owner inventory; native authority `RRL_ASM_INTENT_API`, metadata transaction через OracleGateway. Единственный товарный writer StockPosting не меняется.

При потерянном ответе исходный неизменный запрос повторяется с прежними идентификаторами. Если неверный запрос никогда не создал сессию/шаг, оператор может явно запросить отказ с причиной. Native под общим CONFIG X, revision и CASE fences повторно проверяет текущего назначенного исполнителя, отсутствие сессии/шага/канонической Stock operation/STEP_USE. Для OPEN_STEP дополнительно проверяет исходного оператора родительской сессии. Только доказанное отсутствие получает долговечную квитанцию ABANDONED. Позднее создание под тем же исходным идентификатором блокируют hooks в open_session/open_step. Созданная работа требует чтения/точного повтора либо [[retailcase_assembly_recovery_20261015]], не удаления.

Новый append-only `RRL_ASM_INTENT_ABANDON`: actor, CASE, kind, session/step/original operation, исходное тело/SHA и неизменный результат. Прямые записи запрещены trusted-context trigger. Exact receipt replay повторно проверяет текущие права. Поддержаны только OPEN_SESSION/OPEN_STEP; close/finish/recovery не отменяются этим контрактом.

API: POST `/api/inventory/assembly-scale/abandonments`, GET `/{operation_id}`. Identity из Basic, поле actor запрещено. Клиент сохраняет отдельно исходный запрос и control-запрос; GET404 и HTTP409 не являются разрешением удалить журнал. Strict ABANDONED ACK либо строгий успешный ACK точного исходного запроса разрешает завершить восстановление.

Комплект: [SQL](../../db/migrations/2026-10-15_assembly_intent_abandon/apply.sql), checkpoint и свежая before-image текущего REC+WH assembly body. До применения сохранены exact source/namespace empty/INVALID0. Пустой журнал допускает paired rollback при остановленных writers; непустая история сохраняется, дальнейший ремонт только вперёд. Применение: начальный compile guard остановил комплект на private IDENTITY_KEY в SQL. Ошибка исправлена предварительным вычислением scalar; failed body сохранён, complete_after_compile_fix.sql завершил5 statements/0 errors. Readback:4 sources EXACT, USER_ERRORS0/globalINVALID0/ledgerAPPLIED. Реальные native concurrency и slow-SQL acceptance пока не выполнены.
