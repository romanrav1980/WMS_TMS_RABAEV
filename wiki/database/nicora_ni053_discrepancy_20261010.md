# NI05.3 — фактическая приёмка и расхождения
10.10.2026.086 APPLIED, RABAEV/orcl; пакеты и guards проверены live. [[nicora_ni053_store_barcode_20261010]], [[nicora_ni053_photo_archive_20261010]].

Одна команда STORE_RECEIPT принимает точные десятичные количества в BASE отдельно для каждого исходного товарного листа. Принято + недостача + отказ + повреждено = неизменное отправленное количество. Излишек — отдельное сообщение о найденном товаре, не пополняет известный состав и складской запас. Полное уникальное покрытие исходных листов, точность BASE_SCALE, обязательная причина расхождения проверяются в Oracle повторно под исходным root closure.

В одной транзакции: receipt/frozen source, строки, OPEN разбирательство и положительные построчные обязательства, прежний исходящий outbox. P/H и первоначальная отгрузка не изменяются. Возврат, признание потери и повторная доставка требуют отдельных решений и действий. Новые таблицы RRL_STORE_DISCREPANCY_CASE и RRL_STORE_DELIVERY_OBLIGATION защищены от прямых записей и переписывания истории. Исполнитель — прежнее ядро; helper RRL_STOCK_STORE_DISPOSITION доступен только receipt command.

Старый body полной приёмки не дополнен default полями при canonical construction: сохранённые прежние операции продолжают replay. Для неизвестного ответа UI сохраняет exact operation/body; изменение причины с тем же ID отклоняется. Driver panel показывает отдельные счётчики без арифметики binary float. Диспетчер использует существующую авторизацию transport_dispatch_view, адресную страницу разбирательств и досье; числа выдаются строками, нет автоматического разрешения возврата.

Первое подтверждение обнаружило использование positive-only quantity для нулевого счётчика; исправлен private nonnegative parser, без изменения общего строгого парсера положительных движений. scripts/ni053_disposition_existing_case.py продолжил тот же fixture: accepted2/missing1/extra1, OPEN investigation+excess obligations, replay/conflict/duplicate/foreign leaf/duplicate leaf/total/no-reason refusals, outbox1/quantity events0. scripts/ni053_case_dossier_case.py: actual HTTP exact decimal dossier/cursor/no false approval.
