# NI08.1 / NS59 — атомарная настройка прежнего слотирования,142

RRL_PICK_FACE_ARTICUL — существующий основной справочник назначения SKU к адресам; RRL_PICK_FACE_ASSIGNMENT — временное назначение конкретной волны, не второй справочник. Dynamic range recommendations должны использовать эту основу. Обнаружено: assign_pick_face_articul фиксирует базовый assign_articul и расширенные параметры двумя разными транзакциями. Ошибка второй части оставляет полунастройку.

Исправить только существующий API назначения SKU: native assign_articul и текущий extended UPDATE в одном cursor-bound UOW под штатным CONFIG6 fence. Право pick_topology_edit включить в действующий RRL_STOCK_CONFIG_API whitelist, сохранив прочие правила. Проверять активного исполнителя/WARE фактического pick face и соответствие переданного row ID. Количества/укладку DTO читать Decimal, без новых количественных эффектов.

Смена ключа, выключение отбора или активного назначения не должны отключать ещё занятый старый диапазон: при P/H или входящем/активном задании требовать вымывание. Новые range approval/drain рекомендации следующий этап;142 не объявляется их реализацией. Существующий callable/native tables сохранены; новые guards на все прежние топологические CRUD пока не вводятся и незакрытый legacy configuration path должен быть отмечен.

Кейс: свой существующий fixture slot/sku, не новое движение. Ошибка extended enum/check после изменённой базовой priority должна оставить исходную настройку целиком. Подходящая настройка/повтор возвращает прежний ID. Попытка отключить занятый отбор denied, qty/hard/tasks untouched. После meaningful case проверить bounded slow SQL. Никакой копии базы или широкой проверки.
