# СНС/BLC: приёмка коробом и поштучный отбор

Подготовлена миграция `2026-10-21-tradecase-case-receipt-modes`; применять после сохранения checkpoint. Проверка ещё не выполнена.

Приёмщик сканирует заводской короб по составу поставщика. Комплектовщик затем отбирает отдельные штуки, если профиль получателя разрешает вскрытие короба. Настройка способа сканирования при приходе не должна запрещать эту операцию.

Существующий допуск отмеченных сборок допускает только товары, принятые с настройкой поштучного сканирования. Меняем только эту проверку. Количество, собственник, МРЦ, годность, разрешение вскрытия и покодовый резерв проверяются действующими правилами.

## Техническое приложение

Владелец: inventory, authoritative admission `RRL_TRADE_CASE_ACCESS.execution_allowed`. Разрешён фиксированный EA, один профиль CRPT/TOBACCO, без весового товара, активной сборки на весах и внешнего родителя. SCAN_MODE приёмки допускает UNIT/BOX/PALLET/UNIT_OR_AGGREGATION. Отбор CASE по-прежнему принимает конкретные unit_scans/unit_keys, закреплённые за строкой native резерва. Скан короба при отборе и автоматическое внешнее подтверждение агрегата это изменение не добавляет.

Миграция заменяет только package body; исходное тело выгружено из live Oracle. Парный rollback возвращает прежнее условие, физические данные не меняются. Для приёмки нужен новый native CASE по BOX-профилю, запрет до изменения, разрешение после, поштучный факт/повтор/неверный код и отзыв прав. Отдельно проверить независимость профиля получателя, сохранность количества и SQL.
