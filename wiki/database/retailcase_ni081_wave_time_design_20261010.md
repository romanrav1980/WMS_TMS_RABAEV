# NI08.1 — утверждённое окно существующей волны,140

NS33: перенос плановой комплектации меняет временную нагрузку. Владелец resources, исходная RRL_PICK_WAVE сохраняется. Не создавать вторую волну или новое складское задание. Рекомендация остаётся предварительной; уполномоченный логист явно утверждает окно и указывает причину.

Вход: operation_id, wave_id, expected_version/source_token, aware start/finish, явный UTC/Europe-Moscow/Asia-Tbilisi часовой пояс, причина. Право pick_wave_launch, текущий RUSERS/WARE. Чтение context — pick_wave_view. One metadata UOW/родной CFG6→wave lock; no P/H/reservation/task assignment writes. START/FINISH позитивные<=24ч. DONE/CANCELLED и уже исполняемые CASE/warehouse tasks не переносить.

Версионный immutable aware план связан с оригинальной волной. Одновременно обновить существующие PLANNED_START_AT/FINISH_AT как локальное плановое wall time указанного региона; это новое планирование, не переинтерпретация исторических actual DATE. Monitor использует aware plan только при совпадении действующих legacy дат/WARE/route/dock с версией; неизвестное legacy изменение делает окно stale, не молча UTC. explicit preview остаётся отдельным неприменённым расчётом.

Replay возвращает сохранённый результат после актуальной проверки прав/WARE; изменённый payload отклоняется. Expected version/source token запрещает stale approval. Ошибка/savepoint откатывает всё. После утверждения пересчитать актуальные demand/attendance и показать дефицит; утверждение окна не сертифицирует отсутствие дефицита, временные ограничения рейса или физическую погрузку.

Связанный перенос рейса не выводить из совпадения route/dock: нужна проверенная связь оригинальных ST/wave source. Этот срез утверждает только существующую волну; transport coordination следующий. Авторский кейс использовать собственную ещё не начатую wave395/CASE1031+1032/P20H20 из135, без новой товарной заготовки.
