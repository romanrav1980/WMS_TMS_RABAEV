# NI08.1: освобождение занятого ресурса при отмене задания
Действующий start_task устанавливает RRL_RESOURCE_SESSION.CURRENT_TASK_ID, но cancel_task этот указатель не освобождает. QualifiedCandidates исключает занятую сессию, поэтому отменённое задание может удерживать ресурс.
Использовать существующий run_existing_task_action/CONFIG X/current task warehouse guard. Resources владеет маленьким release helper, legacy service вызывает его через resources.public. Освободить только прикреплённую SESSION_ID и только когда CURRENT_TASK_ID равен отменяемому TASK_ID. Чужое/новое текущее задание, inventory pointer, состояние/позицию/смену сессии не менять. Сохранить CANCELLED resource fact в той же metadata-транзакции, с фактическими полями старого задания; не брать session/equipment из клиентского тела.
Повтор CANCELLED после текущего scope возвращает прежнее состояние без нового события/даты. DONE/foreign отказы выполнять внутри текущего scope. HTTP cancel должен использовать уже существующее warehouse_task_edit, как native metadata wrapper. P/H/units/outbox не изменять этим helper. Предметная отмена wave/HU/slot/reservation остаётся у прежних владельцев; этот ticket касается рабочего ресурса.
