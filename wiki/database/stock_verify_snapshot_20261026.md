# Проверка остатков большой волны

## Причина

Волна636 отдельного набора660мест не укладывается в30секунд HTTP. После исправления захвата защитных строк подготовка проходит за13,64секунды; исполнение не закончило диагностический вызов за45секунд и было полностью откачено. Остаток6600, жёсткий резерв0, волнаPREVIEW, зарегистрированного результата команды нет.

Профиль Oracle показал повторное чтение одного снимка остатков: суммирование прежнего количества заняло4481мс, получение списка ячеек —2117мс. Проверки физических единиц по ячейке также занимают время; существующий индекс начинается с идентификатора паллеты. План V$SQL_PLAN недоступен этому пользователю; полный просмотр таблицы по плану не подтверждён.

## Изменение

Комплект `2026-10-26-stock-verify-snapshot` разбирает неизменный снимок один раз в локальные карты Oracle NUMBER. Проверки журнала, физических единиц, собственника, состава и жёсткого резерва сохраняются. Индекс `RRL_UNIT_CELL_GUARD_IX` начинается с CURRENT_CELL и поддерживает проверки ячейки. Откат восстанавливает прежнее тело и удаляет только этот индекс.

Анонимный прототип на Oracle выполнил48 сравнений количества и проверил множества ячеек в4наборах: пустой снимок, пустые остатки, повторные записи, дроби, разные регистры идентификаторов, отсутствующие значения и новая ячейка. Получено равенство; товарные записи не менялись. Это проверка компонента, не успешный запуск волны.

До индекса40 последовательных проверок собственных ячеек заняли420,69мс; медиана8,28мс, максимум86,72мс. Один локальный проход не задаёт SLA.

## Применение и доказательства

Состояние: **APPLIED** после checkpoint23584714. Применение11операторов, пустой откат10, повтор11; ошибок0, INVALID0. Тело RRL_STOCK_INVARIANT_CORE имеет SHA FDBD5747…, индекс соответствует4колонкам.

После индекса те же40ячеек дали176,03мс суммарно, медиана3,01мс, максимум29,12мс. Native подготовка15648мс и исполнение44041мс закончились результатом LAUNCHED/660; затем вся операция откачена, остаток6600/H0 и PREVIEW подтверждены. Это успешное исполнение с откатом, не рабочий HTTP-запуск.

Профиль следующего откатного прогона подтвердил сокращение проверки ожидающего выкупа с4641 до486мс; инструментированный execute снова превысил45секунд. Для WAVE_LAUNCH выбран отдельный общий предел90секунд, поскольку атомарная проверка660мест занимает около60секунд. Остальные команды сохраняют30секунд, одна попытка блокировок6секунд, общий deadline не перезапускается при повторе. Клиент React не обрывает запрос собственным30секундным таймером; точный повтор сохраняет operation_id.11проверок runner прошли, включая единый90секундный deadline на двух попытках. Это ограничение исполнения, не утверждённый SLA; ускорение полного запуска остаётся задачей Codex.
