# NI08.1: утверждение часового пояса прежней ARM-цепочки — 248
Решение использует существующий TT и RRL_TT_OPERATIONS, не создаёт второй календарь/назначение/расчёт маршрута. Новая append-only RRL_TT_TIME_APPROVAL хранит operation ID, версию TT, actor, canonical request hash, source hash, explicit region, reason, frozen aware operation result и дату решения. Никакого изменения старых DATE или фактов.
Контекст читает один READ ONLY snapshot, текущего действующего диспетчера/WARE каждой СТ; пустой рейс только owner/global. Source hash включает TT state/date/time/машину/водителя/dock/membership/полную bounded цепочку с плановыми и фактическими датами. До200 операций и200 membership rows, overflow refuses.
Утверждение: current rights before metadata CFG6, затем TT row lock, права и source after wait; expected version+source hash обязательны. Новое решение только planned/unbilled/nondeleted TT, заданная машина/водитель/положительная цепочка без уже начатых фактов или физических LOADED/DEPARTED. Повтор своего operation/body returns historical result after current scope, отличающееся содержание rejects. No internal commit, metadata context cleanup, late error rollback.
UTC/Europe-Moscow/Asia-Tbilisi explicit interpretation of source wall times only; immutable accepted snapshot. Context APPROVED только пока текущий source hash совпадает; изменение original plan =>SOURCE_CHANGED. Это не legal driving/rest certification, не доказательство реального маршрута/складской готовности и не разрешение физической отгрузки. Эти проверки остаются оригинальным native departure и будущим общим admission.
Migration must compile/live verify/manifest+wiki; targeted own metadata-only TT case rollback/repeat/stale/sourcechange/current scope, no goods creation or broad tests. Qwen acceptance separately. Raw UI uses durable pending operation so uncertain write repeats same ID/body; current decision read separate from mutation.
