# NI03.3: целая паллета и фактическая СТ

040–043 APPLIED в RABAEV. [[retailcase_ni033_execution_20261009]], [[retailcase_ni032_alternative_faces_20261009]].

## Физическая привязка

PICK_PALLET_BIND_SHIPMENT проходит через RRL_STOCK_POSTING_API: выполненное WAVE/PICKING_MOVE, APPLIED физическая операция, скан фактической паллеты, текущая версия остатка, собственный полный HARD, состав существующей СТ в BASE. Подготовка СТ не считается фактом отбора.

RRL_CUSTOMER_ORDER_FULFILLMENT хранит PICKED_WAREHOUSE_TASK_ID, PICKED_OPERATION_ID физического перемещения, PICKED_PALLET_UID и PICKED_STOCK_VERSION. Состав/количество/единица и исполнитель фиксируются вместе с журналом/outbox. Привязка не меняет P/H. Другая СТ не может забрать уже связанную физическую паллету.

SHIP_PALLET для такого исполнения разрешён только по привязанному UID/версии и исходному заданию отбора. Нельзя заменить паллету другим запасом того же заказа либо уменьшить СТ после привязки и списать часть целой паллеты. Изменения/повторы проверяются под общим порядком anchors/fences.

API GET/POST /api/warehouse-tasks/{id}/full-pallet-shipment; раздел существующего ARM складских заданий, сканы паллеты и подготовленной СТ. Утерянный ответ повторяется сохранённым запросом пользователя, без нового ID.

## Исправление полного отбора

Новый сквозной случай выявил прежний пробел: PICKING_MOVE не передавал свой HARD в общий допуск источника и требовал свободный запас. 041 выбирает собственный резерв, проверяет полное покрытие целой паллеты и отсутствие чужих владельцев перед физическим движением. Нельзя обойти ограничения просто количеством 0 в eligibility: полный собственный объём проверяется отдельно под блокировками.

## Покрытые планы пополнения

043 не оставляет отбор навечно заблокированным избыточной строкой очереди: если весь выбранный состав уже покрыт фактическим допустимым HARD, у строки нет выделенного источника и незавершённого физического задания, WAVE_PICK_RELEASE закрывает её без движения в своей транзакции. Открытое физическое пополнение или выделенный источник по-прежнему блокируют допуск.

## Адресные реальные случаи

- Целая паллета 3 EA → физический PICKING_MOVE → СТ 0.125 BOX → PICKED 3 EA с provenance → SHIPPED 3 EA. Другой собственный запас заказа 3 EA не списан.
- До физического исполнения привязка запрещена, до привязки отгрузка запрещена; точные повторы без второго эффекта.
- После изменения документа до 1 EA отгрузка целой паллеты отклонена, P/H остались 3/3; восстановленный документ проведён.
- Фактическое пополнение 3 даёт покрытие 3; невыделенная лишняя строка очереди закрывается в команде допуска, P/H остаются 3/3.

Очищены только приватные P/H через ядро. История сохранена. UI syntax/encoding проверены; независимый браузерный и промышленный прогон не объявлены выполненными.

## SQL-решение

Full-pallet preview cdm2zkbyrutwh ~62.39 ms; запись PICKED ~2.7 ms; подбор привязки ~2.77 ms. Readiness ~14.36 ms/15 чтений, закрытие лишнего плана ~5.5 ms. Решение: существующие ключи и окна ≤200/500, без спекулятивного индекса. Рост ≥500 ms разбирать по плану/статистике и slow log; масштаб пока не подтверждён.

NI03.3 в работе: остаются полный жизненный цикл завершения волны, многопаллетное/несколько ячеек и согласованные стыки контроля/отгрузки. Независимая приёмка открыта.
