# СНС/BLC: фактическая отгрузка для SAP и СКМ

## Разрыв и изменение

В разделе 6 программы от 21.10 SAP должен получить фактическую отгрузку, а СКМ — отправленные коды. Раздел 8 требует передавать только отправленные 60 из 80 коробов. Проверка рейса 33683 обнаружила общий журнал выезда с тремя местами и 600 кг, но без отдельных сообщений с 600 кодами. [Прогон частичной отгрузки](tradecase_partial_80_20261026.md) сохраняет этот результат.

Комплект `2026-10-26-trade-shipment-events` добавляет подготовку двух сообщений в существующей транзакции выезда. Один заказ получает отдельные записи для SAP и СКМ в общей очереди обмена. Содержимое включает заказ и строку, физические ключи, коды, количество в базовых единицах, собственника на момент выезда, МРЦ, годность и погруженные места. Остаток другого рейса не включается. Запись сообщения не меняет товар и не отменяет последующий выкуп.

Подготовка сообщений вызывается из действующей команды выезда после перевода её погрузок в состояние выезда и до commit. Ошибка полноты состава должна откатить выезд и обе записи. Унаследованные рейсы без торговой привязки проходят прежним путём. Полномочия и проверки выезда остаются в существующем StockPosting; новый пакет закрыт от прямого вызова.

Извлечение единиц использует действующие связи коробной сборки и целых паллет. Проверка исходной подписи погрузки подтверждает неизменный набор списанных единиц. Контроль суммы и уникальности останавливает потерю или двойное включение кода. Идентификатор события вычисляется по операции, складу, заказу и стороне; его длина 76 символов укладывается в существующее ограничение очереди 100 символов.

## Проверки до применения

Запрос проверен без записи на пяти закрытых наборах: частичные рейсы на 600 и 200 единиц, вложенное место на 10, основной рейс с добивкой на 6600 и два режима выкупа на 500. Количество и физические ключи совпали с погруженными составами. Полная процедура скомпилирована в анонимном блоке без создания объектов. Пробная запись событий с последующим rollback дала два сообщения на заказ; после отката записей не осталось. Закрытые складские состояния не менялись.

Для набора 6600 единиц пробная подготовка четырёх сообщений заняла 5641 мс; снимок основного заказа содержит около 2,7 МБ JSON. Этот размер сохранён для проверки транспорта сообщений. Индекс по этому измерению не добавляется; Codex/T12 должен разделить стоимость SQL, проверки подписи, сборки JSON и записи CLOB при повторе на новом выезде.

Статус до применения: **NOT_APPLIED**. Комплект защищает исходники SHA, содержит парный откат и проверку компиляции. Приёмка должна проверить применение/пустой откат/повтор, настоящий новый выезд 60/20, rollback всей команды, потерю ответа после commit и повтор без новых сообщений. Независимая проверка другим агентом пока недоступна.

## Технические границы

Новый пакет `RRL_TRADE_SHIP_EVENT` доступен только `RRL_STOCK_TRIP_DEPART_CMD`. Сохраняются общий `RRL_EVENT_OUTBOX`, транспорт `TRADECASE_BUS` и существующий механизм повторов. Два вида события: `TRADECASE_SHIPMENT_SAP` и `TRADECASE_SHIPMENT_SKM`; получатели берутся из настройки площадки на момент выезда. Payload сохраняет исходную операцию, версии заказа/рейса и время с часовым поясом.

Сообщение очереди не подтверждает бизнес-приёмку внешней системой. Форматы промышленного SAP/СКМ, их ответы и нагрузка остаются отдельной проверкой. История прежних выездов не дополняется задним числом. Откат кода не удаляет сохранённые сообщения.

Прототипы: `runtime/test-evidence/tradecase/2026-10-26/T02/shipment-query-prototype.json`, `shipment-body-rollback-prototype.json`, `shipment-body-rollback-regression.json`. Пробы выполнял Codex; новые обращения Claude не использовались.
