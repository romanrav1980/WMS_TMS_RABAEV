# NI05.1: допуск актуального состава

060 APPLIED в существующей RABAEV/orcl. Пакеты RRL_STOCK_QC_GATE, RRL_STOCK_SHIPPING_CORE, RRL_STOCK_PALLET_QC_CMD и три metadata guard/invalidation triggers VALID. Checkpoints328–329, versioned apply/rollback: [migration](../../db/migrations/2026-10-10_ni051_quality_binding/apply.sql). Это первый slice NI05.1, не завершение спринта.

Переиспользуются OUTGOING_PALLET_CHECK, native scan/weight/LOT_CHECK, существующая СТ и единое stock ядро. Успешный контроль теперь рассчитывает тот же подтверждённый физический состав, что SHIP_PALLET. Отдельной QC очереди и второго исполнителя P/H нет. При legacy BLOCK_IF_NO_PROOVE=1 shipment требует актуальный scan или weight stamp; флаги PROOVED сами по себе недостаточны. При BLOCK_IF_NO_PROOVE=0 обязательность сохраняет прежнее поведение.

В существующей RRL_SBORKA_PALLETS добавлены подписи состава и operation_id отдельных scan/weight результатов; вес сохраняет метод, expected и tolerance. Подпись включает строки СТ/UOM, actual allocation UID/quantity/owner, партию/сроки/упаковку, профили и physical unit identities, CASE membership и warehouse HU link epoch. Технические версии P/H и местонахождение не являются составом: целое перемещение не должно само отменять контроль. Изменение/добавление/удаление строки отзывает подписи и при возврате прежнего количества не восстанавливает старый допуск. Metadata триггеры не проводят запас.

Новый API /api/outgoing-quality/{identifier} показывает состав/допуск/причину, /scan и /weight используют прежнюю root команду с authenticated actor и expected_composition_signature. Сохранённый на клиенте результат повторяется тем же operation_id/body. ARM панель подключена к warehouse-tasks.html; права outgoing_pallet_check, серверные права прежние. Native legacy callers пока не передают клиентскую подпись; это отдельная доработка фактического прохода, а не доказательство полного NS44.

Точечный dev case ni051_quality_binding_case.py прошёл: private business warehouse, physical3EA → ST0.125BOX; запрет без QC и с одним legacy flag; stale scanned signature rejected; scan/replay; mismatched quantity rejected; edit/restore requires new approval; включительная граница веса и нулевая тара; failed weight отзывает ранее успешный scan; новое подтверждение → shipment и wave DONE/replay. Own P/H очищены root, история сохранена. Новые маршруты доступны в OpenAPI, JS syntax passed. Browser/marked-unit independent acceptance не выполнены.

Выявлен отдельный legacy пробел: RRL_TT_POGRESHNOST возвращает константу3.5, RRL_PALLET_WEIGHT2 опирается на cached ORDER_WEIGHT и старый carton conversion. Это не выполнение требования половины самой лёгкой коробки. Следующий ticket: явные SI mass policy и точный расчёт по UOM/составу; независимые роли, выборка, помарочное доказательство, исправления, labels/override тоже остаются открыты.

Slow SQL: изменённый bounded ST rows read f60u62wmk098f ~2.92ms, row writes ~3.8–4.4ms; metadata introspection ~299ms вне operator hot path. Решение: ограниченные окна200 legs/10000 units/16 hierarchy retained, PK predicates; новый индекс не требуется по этому dev case. Миллионы операций этим не доказаны; NI08 owns capacity/plan evaluation.
