# T06: составная корневая паллета, 29.10.2026

## Применение Oracle

Применены шесть миграций multi-order root HU: исправления JSON в QC и Shipping Core, независимый контролёр QC и ветка исполнения. `RRL_STOCK_SHIPPING_CORE` package/body имеют статус `VALID`; `USER_ERRORS` пуст.

## Подтверждённый прогон

Стендовый run `MT289C802082F` собрал корневую паллету `MT289C802082F.PAL` из двух CASE: KG 9.6 и EA 4. Один ST содержит два заказа одного получателя. Контроль веса записал gross 30.2, tare 20.0 и net 10.2 с источником `MANUAL_CONFIRMED`.

`LOAD` создал одно верхнее место и две allocation slices. Точный повтор `LOAD` не добавил движение. `DEPART` перевёл одну корневую паллету в `DEPARTED`; повтор не повторил списание. Сценарий не использовал SAP, оборудование или физические измерения.

## Приёмка магазина

Приёмка магазина `PAPER_COUNT` приняла KG 9.6 и EA 4 по идентификатору корневой паллеты. Два параллельных точных повтора `STORE_RECEIPT` вернули одинаковый HTTP 200. В `RRL_STORE_RECEIPT_FACT` осталась одна строка для погрузки. Складской остаток повторно не списан.

Прогон использовал синтетические данные, внутренние API и ручной ввод. SAP, СКМ, внешние весы и другое физическое оборудование не подключались.

## Быстродействие

Для прогона записано 38 API-вызовов. `RRL_SQL_SLOW_LOG` сохранил запуск волны 596 ms и изменение транспортного задания 591 ms. Журнал содержит название операции, но не текст SQL и не план. До получения текста SQL и плана индекс или переписывание запроса не назначаются; задача записана как `PERF-T06-20261029`.
