# NI06.3 ticket098 — отдельный количественный баланс тары
Источник правила: процесс11, NS15/NS55. Существующие RRL_PALLET_TYPE/RRL_TR_VEHICLE/RRL_TRANSPORT_TASK/store receiver/driver bindings переиспользуются; RRL_TT_OPERATIONS — график операций, а не количественный регистр. Нового двигателя рейсов нет.
Owner inventory, транзакция RRL_STOCK_POSTING_API; API/posting через public, PL/SQL authoritative. Товарные RRL_REMAINS/P/H/SSCC/вложенность не меняются.
Первый срез: баланс по владельцу-складу/типу/состоянию GOOD|DAMAGED/держателю WAREHOUSE|VEHICLE|STORE. Корректировка наблюдённого количества только с ролью tare_adjust, причиной/решением и ожидаемой версией; история сохраняет дельту. Передача OFFER без изменения баланса, ACCEPT другим текущим участником перемещает фактически принятое количество, не более предложения. Непринятое остаётся у источника, расхождение явное; ни отрицательного баланса, ни доступности планового возврата.
Четыре направления: склад→машина, машина→магазин, магазин→машина, машина→склад. Складской пользователь привязан к складу; водитель к фактическому водителю существующего рейса; магазин к адресу существующей поставки. Двое разных участников. Чужая машина/магазин/неактивный рейс запрещены.
Каждый commit: immutable offer/accept or correction + tare journal + необходимые балансные строки + общий outbox. Root replay/body/actor сохранены. Согласованные виртуальные row locks предшествуют native balances, текущий контекст/остаток перечитывается под блокировками. Одновременные приёмки не могут потратить одну тару дважды.
Следующие срезы: сроки магазина/client NEXT_DELIVERY|DAYS|SAME_DAY, возвратные обязательства/FIFO provenance, повреждение/списание с решением, пригодная тара в планировании, UI обеих сторон/водителя. Не объявлять весь NI06.3 выполненным первым срезом.
