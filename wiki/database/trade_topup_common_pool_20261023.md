# Добивка из общего пула

## Изменение

Миграция `2026-10-23-trade-topup-common-pool` меняет три тела пакетов без изменения спецификаций. Кандидат Claude C0157 сохранён в checkpoint `d28e2e6a`; root проверяет применение и бизнес-сценарий. До применения это описание не подтверждает доступность функции.

Согласованная добивка уже имеет собственный HARD. Расчёт общего пула вычитает это удержание из потребности строки, чтобы не обещать тот же товар второй раз. При запуске волна забирает прежнее удержание, не требует для него дополнительную SOFT-долю. Если у строки осталась активная доля старого расчёта пула, запуск требует пересчёта. Заблокированная или отменённая добивка не получает долю пула.

Обычная строка заказа сохраняет прежний расчёт доли и преобразование SOFT в HARD. Самостоятельный расчёт строки для планирования не изменён. Общая проводка, коды физических единиц и проверка текущих прав сохраняются.

## Проверка root

Свежая проверка до применения: RABAEV/orcl, INVALID0, три исходных SHA и все файлы manifest совпали. Доказательство: `runtime/test-evidence/tradecase/2026-10-23/T08/common-pool-preflight.json`. Следующий шаг — применение, пустой откат и повторное применение через OracleApply; затем действительное согласование, запуск, повтор и отмена на имеющемся запасе склада210564699. Исходный остаток250EA/HARD0, новых приходов не создавать.

Частичная передача одного удержания недостижима через текущий контракт планирования: количество принятой строки равно согласованному количеству, а план переносит каждое удержание целиком. Проверка ветки через прямое изменение товарных данных не заменяет бизнес-сценарий. Частичная вместимость рейса и распределение нескольких предложений остаются отдельными требованиями T08.
