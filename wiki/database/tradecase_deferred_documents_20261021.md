# СНС/BLC: ожидание справочников

Миграция `2026-10-21-tradecase-deferred-documents` применена в локальной RABAEV; пустой откат и повторное применение проверены. Перед применением сохранён коммит `ad6b4a37`. Oracle/API и экран проверены автором; независимой и промышленной приёмки нет.

При отсутствии связанного справочника приём сохраняет исходное сообщение и ответ «ожидает справочник». Документ не появляется среди принятых оснований. Повтор исходного события возвращает прежний ответ; изменённое тело с тем же идентификатором отклоняется.

Оператор повторяет проверку сохранённого сообщения после загрузки справочников. Сервер заново проверяет импорт в области склада, активный источник и отдельное право финансового основания. Проверка использует текущие версии и все действующие бизнес-ограничения. Окончательный результат хранится отдельно от исходной квитанции; исходный запрос не изменяется. Два одновременных повтора сериализуются по площадке; основание и окончательное исходящее сообщение фиксируются одной транзакцией.

## Техническое приложение

Владелец: integrations. Единственные правила приёма остаются в `RRL_TRADE_DOCUMENT_API.validate_payload`; физический writer не вызывается. Внешних HTTP-вызовов в транзакции нет.

`RRL_TRADE_DEFERRED` с PK/FK `(WARE_ID,SOURCE_ID,EVENT_ID)` хранит WAITING/ACCEPTED/REJECTED, число проверок и текущий результат. `RRL_TRADE_MESSAGE` остаётся неизменным журналом первоначальных квитанций. `current_result` добавляется в карточку и страницы сообщений. Новые отложенные документы создаются только для MASTER_MISSING, не для неактивного справочника или произвольной ошибки. Старые REJECTED-сообщения автоматически не переоткрываются.

API: `POST /api/tradecase/warehouses/{warehouse_id}/messages/{event_id}/retry`; тело отсутствует, повтор использует сохранённый запрос.22.10 добавлен [отдельный исполнитель](../components/tradecase_deferred_worker_20261022.md) с явными складами и действующими правами;7живых проверок прошли. Для автоматического повторения его запускают отдельным процессом. Полный T02 этим изменением не закрывается.

SQL: [миграция](../../db/migrations/2026-10-21_tradecase_deferred_documents/apply.sql), парный rollback блокирует удаление непустой очереди; до испытания откат проверяется на пустой таблице. Перед изменением выгружены package spec/body; нормализованное тело совпало с последней миграцией NEED. Oracle до изменений: RABAEV/ORCL/orcl, INVALID=0.

Проверить: отсутствие справочников, два зависимых основания, повтор WAITING, поздняя загрузка, две конкурентные проверки, окончательный отказ, версии, потеря ответа после commit, запрет чужого склада/отзыв/отдельное финансовое право, caller rollback, один resolution-outbox, неизменные количества. Сравнить SQL и задержки с тем же объёмом.
