# NI03.3: повтор создания плана комплектации
Дата: 14.10.2026. Результат1236 — адресно проверен в dev, полный B01 открыт.

## Изменение
Существующий POST /api/picking/plans принимает необязательный operation_id. Старый вызов без него сохраняется. RRL_PICK_PLAN_CREATE_API делегирует расчёт прежнему RRL_PICKING_API. Таблица RRL_PICK_PLAN_CREATE_OP хранит неизменяемый результат, SHA256 нормализованного запроса, пользователя, заказ и склад. Защита RRL_PICK_CREATE_OP_GUARD ограничивает запись владельцем команды.

Операция включается ресурсом OP ранга10 в прежний план блокировок RRL_PICK_PLAN_ADMISSION. После захвата существующих блокировок RRL_PICKING_API повторно читает результат команды. Сохранение результата и план/резервы входят в одну транзакцию API. При другом содержимом того же ID — 20886. Перед возвратом кэша проверяются текущие права и склад.

Первый вариант1233 записывал receipt до admission и был отклонён DIRTY_TRANSACTION; план не создавался. Исправление1235–1236 сохраняет чистый вход в admission: до него нет DML, блокировок или SAVEPOINT. При сбое после возврата planner используется его savepoint rrl_pick_plan_begin; внешний API откатывает транзакцию. Защита ядра не ослаблялась.
