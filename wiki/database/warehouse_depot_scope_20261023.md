# Адрес склада по назначенной роли

Проверка настоящего HTTP23.10 выявила отказ403 у сотрудника с назначенным warehouse_settings_edit на свой склад. API требовал legacy-права; native scope и общий metadata helper также проверяли только старую группу. Первоначальный QA отключён, синтетический адрес помечен удалённым, настройка склада очищена; товар не изменялся.

Миграция [warehouse_depot_scope](../../db/migrations/2026-10-23_warehouse_depot_scope/apply.sql) добавляет begin_warehouse_change(actor,ware) в RRL_STOCK_METADATA_TX. Она проверяет назначенное право до и после существующих блокировок ACCESS_REV/политик. Прежний begin_change сохраняет прежнюю проверку и использует тот же общий fence. RRL_WARE_DEPOT_API проверяет область через RRL_ACCESS_API; API пропускает аутентифицированного сотрудника до этой authoritative проверки. resolve использует ту же область и блокировки.

Исходные три объекта экспортированы свежими, SHA до/после записаны в manifest; before.sql и rollback.sql возвращают прежние источники. Количества, резервы, схема назначений и глобальные права сотрудников не меняются. Статус перед применением: кандидат; компиляция, применение/откат/повтор и HTTP ещё не приняты.
