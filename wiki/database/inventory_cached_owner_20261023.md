# Инвентаризация: право собственника при повторе после полного списания

23.10 Codex обнаружил ошибку при настоящей приёмке C0166. Ревизия418 списала20единиц партии до нуля. После отзыва права выполнения операций с собственником повтор исходной команды вернул200. Новая команда восстановления при тех же правах вернула403. Существующий допуск обходил только положительные остатки и пропускал полностью списанную партию. Товар восстановлен штатным разрешённым действием; итог250/H0, исходные идентичности и атрибуты сохранены.

## Исправление

Комплект [2026-10-23_inventory_cached_owner](../../db/migrations/2026-10-23_inventory_cached_owner/) дополняет существующий `RRL_TRADE_STOCK_GUARD.assert_command_stock`. Только для INVENTORY_COUNT и нулевых строк остатков из исходного запроса он проверяет текущих собственников единиц по тому же адресу через действующий assert_owner. Отсутствующие торговые атрибуты дают отказ. Проверка не меняет товар, журнал потерь, результат исходной команды или правила других складских операций.

Склад и адрес выводятся из действующих справочников и строк исходной команды. Чужие нулевые строки прошлых перемещений не включаются в проверку по одному совпадению идентификатора паллеты. Повтор остаётся неизменным, но доступ к сохранённому результату требует текущих полномочий.

Комплект прошёл apply/rollback/reapply5/5/5, но повтор всё равно вернул200. Проверка выявила неверный слой исправления: этот guard вызывается только при исполнении, а сохранённая квитанция возвращается раньше. Комплект штатно откачен, before-body восстановлен, INVALID0; SQL не переписывался. Новый кандидат меняет существующий допуск перед повтором: [[inventory_current_owner_20261023]]. Воспроизведение и прогон: `tests/tradecase/live_inventory_loss_found.py`, evidence `T11/inventory-loss-found-live.json`.
