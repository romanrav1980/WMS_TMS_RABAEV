# СНС/BLC: погрузка отдельных коробов

Статус22.10: отдельный короб погружен через настоящий API/Oracle; непогруженные места остались в экспедиции. T07 принят частично: перепланирование остатка, конкурентная погрузка, реальные внешние документы и полный выезд этого набора ещё не проверены. Основание — программа Drive revision27, раздел6/пункт2: работник разбирает паллету, сканирует каждый загружаемый короб, непогруженные короба остаются в экспедиции; скан исходной паллеты не включает их в машину.

## Выбранное изменение

Действие `POST /api/transport/loading/confirm-bulk-box` использует существующий HU_SHIP для самостоятельного BOX либо LOAD_SHIPMENT для отдельного CASE-короба с настроенным финальным весом. В неизменяемую команду добавляется серверный признак `bulk_box_scan=true`. Обычная команда погрузки сохраняет прежние параметры. Маркер не принимается из пользовательского тела; семь offline HTTP проверок подтвердили выбор действия, обязательную подпись состава и восстановление после403/конфликта/503.

Миграция `2026-10-22-bulk-box-loading` меняет только body RRL_TRADE_STOCK_GUARD: для этого явного действия требует самостоятельный CONTAINER/BOX без родителя и прежней отгрузки. Native компилятор продолжает проверять замыкание, версии, товар, заказы, рейс, собственника, контроль, маркировку и вместимость. Паллетная команда остаётся отдельным действием. Снятие BOX с исходной паллеты выполняется штатной распаковкой, не скрытой частью скана.

Миграция `2026-10-22-bulk-case-carton` добавила самостоятельный CASE с типом CONTAINER/FINAL_WEIGHT_REQUIRED=1. Обе миграции прошли применение, откат и повторное применение, INVALID0. Первые две попытки второй миграции остановились из-за склеенного SQL-токена; каждый раз восстановлено прежнее тело. Исправление сохранено в4997627c. Сверены шесть действующих тел, включая этикетку и ручную тару.

## Скорость

В23HTTP малого погрузочного прогона медиана212мс, самая долгая операция — чтение контроля1119мс; SQL-транзакция этого чтения982мс. Ещё8равных HTTP-чтений дали340мс первым и67–107мс следующими. Отдельный процесс с новым пулом и настоящим Oracle/audit дал6равных ответов за292–628мс: получение первого соединения340мс, QC38–194мс, очистка соединений10–46мс в разобранном повторе. Индекс не обоснован; сохраняются права, аудит и очистка. Codex/T12 продолжает исследование холодных чтений и сетевых задержек. Запуск волны2715мс и первый отбор2547мс также остаются открытыми, без заявления об ускорении.

## Следующие проверки

1. Проверить погрузку двух независимых BOX с полностью подтверждёнными вложенными CASE и конкурентный повтор.
2. Пройти физический скан исходной паллеты, чужой рейс, старую версию и устаревший вес в полном API-прогоне.
3. Перепланировать непогруженные отгрузки отдельным штатным действием, затем проверить выезд без них. Текущий набор сохраняет их назначение рейсу; блокировка выезда ожидаема.

Внешнее подтверждение нового состава СКМ и транспортные документы остаются отдельной приёмкой с реальным подключением. Синтетические ответы будут помечены в протоколе. Наличие новой API-команды не означает выполнения T07.
