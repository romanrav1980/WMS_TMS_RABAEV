# NI06.3 ticket100 — повреждение и решение о потере тары
Процесс11, отдельный баланс098/срок099. Root TARE_DAMAGE переводит GOOD→DAMAGED внутри того же holder/owner/type, количество сохраняется. Факт осмотра с причиной/ссылкой создаёт immutable resolution, не корректирует товарный P.
Root TARE_WRITE_OFF — отдельное разрешение tare_writeoff, другой актор относительно наблюдения повреждения, исходный DAMAGE, причина/решение, qty≤неиспользованное количество документа и актуальный DAMAGED balance. В первом срезе holder исходного damage совпадает с местом списания: переместившееся повреждение требует отдельной доказанной связи, не свободного списания чужой тары.
Для магазина обязательна исходная выдача/оставшийся долг. Повреждение переносит её открытую часть из GOOD в DAMAGED, сохраняя deadline/provenance. STORE write-off уменьшает магазинную обязанность ровно один раз; возвращённая повреждённая тара закрывает DAMAGED долг фактическим ACCEPT STORE→VEHICLE, последующая складская приёмка не закрывает повторно.
Исполнитель inventory/Root; текущие actor bindings/типы/holders и единый CONFIG fence. Старые записи не удаляются. Перед новой миграцией checkpoint TARE CMD/root/view. Целевой own case: магазин2→GOOD0/DAMAGED2, независимый writeoff1→долгDAMAGED1/физтара1; товарныеP/H неизменны. Остаток повреждённой тары сохраняется, промышленная/независимая приёмка не утверждается.
