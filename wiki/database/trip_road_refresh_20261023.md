# Обновление дорожных плеч выбранного рейса

Кандидат добавляет команду обновления дорожного времени только между соседними точками выбранного рейса, включая выезд и возврат на настроенный склад. Использует существующие OSRM/Valhalla и RRL_ADDR_DISTANCE_MATRIX. Прямолинейный расчёт не принимается за дорожное время. Внешний вызов выполняется после закрытия транзакции чтения.

Перед записью существующий metadata fence и блокировка рейса защищают повторную проверку прав, состава, версии, хеша и координат адресов. Меняются только нужные пары адресов; все пары справочника не пересчитываются. Запись кэша и квитанции выполняется в одной транзакции. Повтор того же operation_id возвращает сохранённый результат после текущей проверки доступа; изменённый запрос отклоняется. Обновление кэша меняет основание расчёта времени и требует повторной проверки окон и утверждения рейса.

Миграция [2026-10-23-trip-road-refresh](../../db/migrations/2026-10-23_trip_road_refresh/apply.sql) добавляет только журнал квитанций RRL_TT_ROAD_REFRESH с уникальным ключом и запретом изменения истории. Общие package bodies не заменяются. Откат разрешён только при пустом журнале; бизнес-историю не удаляет. Схема остатков, количества и резервы не меняются.

Состояние: установлен в dev после checkpoint2bc43bdb; apply/rollback/reapply6/4/6,0ошибок. Источник ошибки/таймаута провайдера даёт неподтверждённый результат и сохраняет исходную команду в UI. Живой дорожный сервис и полный маршрут должны быть проверены отдельно; подменённый ответ не доказывает реальную маршрутизацию.
