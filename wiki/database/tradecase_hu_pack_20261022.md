# СНС/BLC: вложение и извлечение грузовых мест

Подготовлена миграция `2026-10-22-tradecase-hu-pack`, пока не применена. В действующем RRL_TRADE_STOCK_GUARD команды HU_ATTACH/HU_DETACH отклоняются общим требованием отгрузочного основания. Подтверждение: отдельный контейнер над retained SORT-остатком3EA на складе219023232 получил409 TRADE_ORDER_BINDING_REQUIRED. Три новых пустых контейнера HU22b8de9bfdce.0/.1/.2 созданы штатным API; физические количества не изменены.

Миграция добавляет только HU_ATTACH/HU_DETACH в перечень команд без обязательного отгрузочного основания. Нижняя проверка owner-operate остаётся для каждого затронутого товара. Native HU сохраняет текущий склад исполнителя, сканы, версии/замыкание дерева, запрет циклов, двойного родителя и открытых заданий. Перемещение HU и отгрузка не добавляются в перечень. Листья сохраняют физические количества, собственников и исходные коды; контейнер не становится внешне подтверждённым агрегатом СКМ.

Отдельная воспроизведённая ошибка чтения: роль warehouse_task_view на219023232 без owner-grant получила состав3EA. QA HV229850d88847 отключён, назначение отозвано. В подготовленном Python исправлении весь состав проверяет текущий owner-view в той же READ ONLY транзакции до возврата результата; скрытый или неполный TRADECASE состав даёт403 целиком. При отсутствии достоверной текущей связи с физическими единицами архив на TRADECASE складе также закрывается, а не раскрывается по предположению. Обычные склады без TRADECASE атрибутов сохраняют прежний допуск.

Источники до изменения и SHA сохранены в `runtime/test-evidence/tradecase/2026-10-22/T06/`; `hu-owner-before.json` и `hu-pack-state.json` содержат воспроизведение. Перед применением нужны локальный checkpoint, apply/rollback/reapply, проверка scoped роли/owner-revoke/exact retry/конкуренции и количества10/HARD0. Доказательства готовности после применения будут добавлены сюда; текущая запись их не заменяет.
