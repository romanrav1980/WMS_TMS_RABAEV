# C-0169 — задержка селекторов складов и водителей (T12) (Claude)

**Итог:**
- `GET /api/admin/warehouses`: подтверждённое узкое место устранено правкой одного SQL. Результат равен прежнему по строкам и порядку во всех режимах фильтров. Полный список ~460 → ~56 мс (SQL), но малые отфильтрованные наборы стали медленнее, ~8 → ~26 мс (компромисс ниже).
- `GET /api/admin/transport/drivers`: прежние значения не воспроизвелись, правка отклонена.
- Права, фильтры, порядок и лимит не менялись; native, индексы и кэш не добавлялись. API не перезапускался: живой HTTP после правки измерит root. Локальные медианы — не p95 и не SLA; T12 не закрыт.

## Данные
367 складов, 67 519 ячеек, 1 544 строки остатков (отрицательных и NULL нет). Источник задачи — slow log C-0167: warehouses 805–1030 мс (hash 9cf9…), drivers 564/590 мс.

## Варианты (`bounded.json`, n=10 на каждый: первый + 9 тёплых, все замеры сохранены)
| Случай | Строк | Было, мед. | group by по всем складам, мед. | **Ограниченный CTE (выбран)**, мед. / первый |
|---|---|---|---|---|
| все (500) | 367 | 460.2 | 48.8 | **56.4** / 178.5 |
| по умолчанию 200 | 200 | 296.0 | 37.8 | **50.4** / 135.7 |
| лимит 5 | 5 | 46.0 | 42.1 | **45.8** / 168.7 |
| роль FINISHED_GOODS | 5 | 66.9 | 42.0 | **56.4** / 244.5 |
| MES=1 | 4 | **7.8** | 41.7 | **25.8** / 130.3 |
| MES=0 | 363 | 477.5 | 42.4 | **51.5** / 196.4 |

- Строки равны в порядке у обоих вариантов во всех 6 случаях.
- **Выбран ограниченный CTE** (по review Codex): сначала тот же отфильтрованный, упорядоченный и ограниченный набор складов, агрегаты ячеек и остатков только по нему, затем left join с nvl 0. Хинтов и второй ветки запроса нет.
- **Компромисс:** на MES=1 (4 склада) медиана 7.8 → 25.8 мс (+18 мс) — оптимизатор строит соединение остатков с ячейками дороже точечного коррелированного доступа. Группировка по всем складам медленнее (41.7). На больших списках CTE на ~7–13 мс медленнее group by.
- План Oracle прочитать нельзя: `V$SQL_PLAN` недоступен (ORA-00942).

## Ограничения T12
- Живой HTTP после правки не измерен: нужен перезапуск API root.
- Холодные первые вызовы (130–245 мс) не разбирались — анализ холодных QC и плана за root.
- Регресс малых отфильтрованных наборов (+~18 мс) оставлен как компромисс; решение о второй ветке запроса — за Codex.
