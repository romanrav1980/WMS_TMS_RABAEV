## Результат
Закрой оставленную в C0152 границу stock core: утверждённое списание должно уменьшать реальный остаток штатной проводкой, фиксировать точный состав списанных кодов и исходящий документ в одной транзакции. Ответ внешней системы остаётся отдельным состоянием; SAP недоступен, подтверждение не выдумывать. Основание — BP11 принятой программы TRADECASE, не новый сценарий.

1. Проверь реальных владельцев товарного остатка, кодов, резервов и outgoing document; используй существующий stock posting runner, журнал operation_id и transactional outbox. Не создавай второй ledger и не проводи бизнес-DML из HTTP/Python. Если существующая операция уже решает задачу, используй её.
2. Добавь узкий posting kind для утверждённого дела качества, если его действительно нет. В одной TX проверяются текущие права/склад/owner, версия и неизменность замороженного состава, отсутствие несовместимых резервов/погрузки, реальное списание, статус дела, журнал и исходящий документ с составом. Частичный эффект при ошибке недопустим. Конкретные правила состава бери из действующих владельцев, не угадывай столбцы.
3. Доработай предложенный тобой native quality-hold guard: активное удержание запрещает стандартный выпуск/перемещение/отбор/отгрузку во всех фактически найденных путях, разрешает штатный пересчёт и именно авторизованную проводку этого дела. Проверки после блокировок должны закрывать гонку с открытием/решением дела. Обход по одному command_kind без проверки дела недопустим. Найденный путь, который guard не покрывает, явно исправить либо указать как открытый блокер.
4. В существующий экран исключений добавь команду проведения только после готового native контракта. Сохрани WAITING_POSTING для ещё не проведённого, POSTED только при настоящем товарном эффекте; внешнее ожидание показывай отдельно. Используй прежний журнал, exact retry и помощь.
5. Подготовь versioned migrations с fresh before SHA, preflight/apply/verify/rollback и recovery для собственных тестовых данных. Shared stock package не раздувать: новый владелец операции отдельным пакетом по принятому модульному контракту, в dispatcher — минимальная регистрация. Сохрани совместимость. Native apply root выполнит после ревью и checkpoint; запрет своей среды не обходить.
