## Крупный оставшийся блок
Довести рабочий цикл реального визита: ожидается → прибыл/очередь → назначен воротам → обслуживается → завершён/выехал/отменён. Сначала выясни уже реализованные состояния/API; используй их, не добавляй параллельный реестр. Рабочее место старшего смены должно показывать текущую машину/рейс/ворота, очередность, просрочку, недостающие данные и конфликт назначений. Связать реальный визит и ворота с существующим Гантом. Гант всех ресурсов сохраняет машины/ворота/комплектовщиков/ричтраки; неизвестная длительность не считается свободным интервалом. Подтверждение LOAD/DEPART не выдаёт начало длительного обслуживания.

Обеспечить отказ двойного занятия одних ворот/машины, работу двух диспетчеров, отмену/переназначение до исполнения, безопасный exact retry после потерянного ответа и актуальные warehouse/owner-права. Для текущего бизнес-цикла принять правила из документов/имеющихся контрактов; не изобретать нормативы. Если отсутствует статус/объект — версия команды и additive native миграция с before/rollback/verify/manifest; приложение не должно прямо изменять складские количества/резервы. Новые домены/feature boundaries соблюдай по архитектурному контракту, legacy огромные функции не наращивай.
