# C0158 — плановые интервалы ворот в Ганте

C0157/d28e2e6a получен. Root принимает native общий пул и бумажный режим; ты берёшь независимый оставшийся пункт T10 — плановые интервалы ворот. Прочитай AGENTS.md, wiki/index.md, актуальные T10/двор страницы и исходные документы СНС/BLC. Не смешивай кейс с RETAILCASE и не создавай второе решение, если нужный механизм уже существует.

Сначала найди текущие плановые окна ворот/визитов, native-владельца, ресурсный Гант и источники норм. Если часть уже работает, используй её. Реализуй недостающий рабочий путь: сотрудник назначает или переносит будущий интервал конкретных ворот для машины/рейса или входящей поставки, видит его рядом с фактическими посещениями и получает отказ при конфликте. Фактическое прибытие/начало разгрузки не подменяется плановым временем. Если источник не задаёт длительность, сотрудник указывает начало и конец; нормативы не выдумывать. Задержки показывай по реальным данным, без обещания автоматического пересчёта, которого нет.

Используй действующие роли склада/собственника и общий native порядок блокировок. Одни ворота нельзя забронировать двум машинам на пересекающееся время; конкурентные записи, перенос/отмена, одинаковый повтор и конфликт тела должны иметь определённый результат. Старый ответ выдаётся только при текущем допуске. Фактическая занятость остаётся за существующим двором, а план не объявляется гарантией свободных ворот. Учитывай принадлежность ворот реальной площадке и межскладской контекст машины.

До правок ACK точных путей и пакетов. Не меняй RRL_STOCK_POSTING_API, pool/topup пакеты, CASE paper, generic task или count handlers: они у root. Добавления должны иметь модульные границы, не расширять огромные legacy-функции. Если нужна Oracle-миграция, отдельный NOT_APPLIED комплект со свежими before SHA, apply/rollback/verify/manifest. Сопроводи минимальным diff и локальным checkpoint; root применит и проверит Oracle. Не переписывай ранее применённые миграции.

Проверь экран1440/390, реальный Гант, подсказки/help, старые поля/late response/отзыв прав, сериализацию времени и неизменный повтор. Укажи отдельно реальные чтения и подставленные ответы; не засчитывай фиктивное подтверждение записи. Нативные мутации и fixture DML не выполняй. Данные из существующих складов не резервировать и не перемещать. Новых приходов нет. SAP-проекты/remote git не публиковать.

Сдай пакет целиком: API/native контракт, UI, справку, тесты, SQL-замеры и незакрытые ограничения в reports/tradecase/2026-10-23/claude/C0158/. Совместную сборку dist согласуй, затем RELEASE точных путей. Весь T10 не объявлять завершённым одним интервалом ворот.
