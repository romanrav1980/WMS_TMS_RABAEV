## Запрос №1 — C0121: интерфейс передачи и приёмки поддеревьев

Передать Claude только после наличия `API_READY_C0121.md`:

> Прочитай AGENTS.md, wiki/index.md, coordination/retailcase-claude/PLAN_TWO_REQUESTS_FINAL.md и API_READY_C0121.md в той же папке. Выполни законченный UI-сценарий передачи частей вложенного груза нескольким магазинам по готовому API. Магазин видит только свои места/количество, сканирует внешний или дочерний идентификатор паллеты, принимает своё поддерево, фиксирует ручной вес либо пересчёт/сканирование согласно стратегии, видит расхождения и завершает приёмку; оставшийся груз остаётся в машине. Не использовать массу внешнего места как массу выданной части. Для обычных и внутренних идентификаторов не навязывать SSCC-only. Сохрани operation_id при неизвестном результате, исключи повторную отправку как новую операцию. Доработай связанные складские переходы только в рамках файлов, разрешённых API_READY. Навигация сохраняет магазин/склад/рейс и возвращает в исходный контекст; 390 px, понятные ошибки, подсказки действий и статические URL help. Не переделывай готовые Гант/KPI. Сначала один ACK с файлами владения; затем реализация и проверки до одного RESULT_C0121.md/RELEASE с изменёнными файлами, фактами проверок и ограничениями. Не менять backend/Oracle, не выполнять сторонние бизнес-записи, не публиковать GitHub. Если API противоречит контракту, точно зафиксируй дефект и заверши независимые части, не подменяй API моками.
