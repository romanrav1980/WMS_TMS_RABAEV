# C-0168 — заводская иерархия при приёмке (T03, TRADECASE) (Claude)

**Итог:** состав поставщика теперь выражает заводскую паллету SSCC с коробками; один скан SSCC принимает всю паллету через существующую приёмку. Изменение — только Python-разбор заказа поставки; native, второй writer, новый формат или таблица не добавлялись. **Живая приёмка не выполнена:** работающий API (8088) должен загрузить новый разбор, а перезапуск — за root. Готов живой сценарий `tests/tradecase/live_factory_hierarchy.py`. До его прогона T03 по этой части частичный.

## Требование источника и что было
- `wiki-raw/tradecase_source_review_20261019/functional_current.txt`:
  - «Единственный источник состава»: SAP, API или DESADV, без смешения;
  - «Приёмка по основаниям»: доверительная приёмка по SSCC при подтверждённом составе, повторный скан не создаёт второй приход;
  - «Формирование паллет».
- Roadmap T03 открыт: «иерархия заводских мест, DESADV, полный отрицательный набор».
- Было (код и Oracle READ ONLY):
  - заказ поставки `POST /api/integrations/sap/supply-orders` (XML `WarehouseSupplyOrder`) с агрегатами BOX или PALLET, каждый — **плоский** список единиц → `RRL_SAP_TRACE_AGG` (раскрытый состав узла, неизменяем при повторе);
  - приёмка `POST /api/receiving/supply-orders/{id}/pallets`: скан агрегата раскрывает его состав (`ReceivingMarks.resolve` → `aggregation_members`), режимы профиля BOX/PALLET/UNIT_OR_AGGREGATION, повтор единицы отклоняется, `RRL_WMS_RECEIPT_AGG`, регуляторный родитель `RRL_CRPT_AGGREGATION`;
  - привязка TRADECASE `stock/bind` (собственник, МРЦ, срок, коды); BOX10 проверен 21.10;
  - дерево `children` было только у `WmsTraceManifest.v1` (источники INVENTORY и MES).
  - Паллета не могла ссылаться на свои коробки.

## Решение (`api/wms_api_server/app/modules/integrations/domain/supply_order.py`)
- У агрегата уровня PALLET допустим `Children/Child/Code` — ссылки на BOX-агрегаты той же строки, системы и профиля в том же сообщении (1..1000). Свои единицы паллеты допустимы рядом с коробками.
- `expand_factory_pallets`: состав паллеты = свои единицы ∪ единицы её коробок. Каждый узел (паллета и каждая коробка) пишется существующим кодом в `RRL_SAP_TRACE_AGG` со своим раскрытым составом, поэтому коробки остаются сканируемыми по отдельности.
- Отказы при импорте:
  - ребёнок неизвестен, не BOX или из другой строки или профиля;
  - коробка в двух паллетах или дважды;
  - пересечение единиц или кодов между коробками;
  - `Children` у BOX;
  - пустой `Children`;
  - вне 1..10000 единиц.
- Сообщения без `Children` разбираются как раньше.
- Приёмка без изменений кода:
  - скан SSCC (профиль PALLET или UNIT_OR_AGGREGATION) раскрывает все коробки;
  - коробки поштучно (профиль BOX) тоже работают;
  - паллета вместе со своей коробкой отклоняется существующим «scanned more than once»;
  - неизвестный SSCC, неверное количество и одна коробка вместо паллеты — 409 существующими проверками.
- `composition_source` остаётся «SAP». DESADV и API-адаптеры (промышленные) не реализованы и не заявлены.
- UI: на экране приёмки (`wiki-raw/wms_admin_ui_reference/receiving.html`) подсказка в разделе сканирования: «Паллета» и только её код, коробки отдельно не сканировать.

## Ограничения
- Иерархия хранится как раскрытый состав каждого узла; связь «коробка → паллета» отдельно не сохраняется (в `RRL_SAP_TRACE_AGG` нет такой колонки, native не менялся). При скане SSCC регуляторный родитель создаётся для паллеты; дочерние коробки в `RRL_CRPT_AGGREGATION` не создаются.
- Подтверждение состава коробок внешней СКМ и DESADV/API-источники вне этого инкремента.
- Связь «коробка → паллета» не сохраняется отдельной колонкой: native ради неё не расширялся.
