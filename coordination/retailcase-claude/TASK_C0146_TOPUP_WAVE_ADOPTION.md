## Обязательные условия
- По программе Drive revision27, разделы7/11, SAP присылает отдельный заказ И обновлённый рейс, содержащий этот заказ. До обоих документов задания не допускаются. Заказ, источник, склад, рейс, получатель, SKU/МРЦ/собственник/единицы должны совпасть. Отменённые предложения не допускаются только потому, что их внешний заказ ещё активен.
- Найдено двойное вычитание вместимости: _confirmed добавляет SAP_ACCEPTED поверх TRIP, уже содержащего тот же заказ. Исправь учёт пересечения по количеству/единицам; не вычитай весь заказ слепым флагом. Учитывай обновление need.current_trip_quantity. Старый CAPACITY_BASIS предложения не должен сам запрещать законное обновление TRIP; проверяй актуальные ограничения.
- RRL_STOCK_POOL_READ.line_snapshot_json считает HARD через PICK_PLAN_LINE_ID, TOPUP без него не виден; свободный пул P-H также исключает удержанное. Не делай глобальное увеличение свободного количества. Отдельно учитывай common-pool SHIP_FROM_STOCK, не обещай другой волне уже удержанные единицы.
- RRL_STOCK_RESERVE_CORE.move_coverage сохраняет общий HARD: полный перенос возвращает прежний RID, частичный делит запись. При необходимости добавь узкую core-команду связывания с PICK_WAVE/PLAN_LINE/TASK в существующем StockPosting-контексте. Никакого прямого DML резервов из integrations. Точные UNIT ключи можно передать через существующие UNIT_CORE в одной TX под заранее объявленными блокировками; не выбирай случайные свободные единицы.
- Compile должен объявить все резервы/units/proposal/HOLD/контекст рейса и потребности до lock. Сохрани порядок блокировок, owner и command rights, актуальный доступ до cached replay, неизменный operation_id/hash.
- ADOPTED удержание не освобождается обычной отменой предложения; сохраняй историю и связь с волной. Гонка launch/cancel и повтор после потерянного ответа не должны менять количество второй раз.
