## Результат

1. Измерь настоящие GET `/api/transport/loading/bulk-box-preview?identifier=099999990000026027` и `/api/outgoing-quality/099999990000026027`; прочитай реальные callers/native источники. Раздели стоимость допуска, поиска места/склада, состава и получения соединения. Сначала подтверди, что задержка воспроизводится; не приписывай весь PL/SQL call отдельному SQL без измерения.
2. Если подтверждена, устрани первый доказанный узкий участок минимальной правкой. Сохрани точные бизнес-ответы, фильтрацию/отзыв прав, owner scope, состав/версии/коды. Не кэшируй допуски или количество, не пропускай проверки. Сначала переиспользуй имеющийся точный поиск склада/места вместо общих обходов; не добавляй индекс без причины и плана.
3. Сравни до/после при том же составе и объёме, явно укажи число проб, первый и тёплые вызовы/новое соединение. JSON сравни полностью; если время ответа по определению меняется, перечисли только эти поля, не скрывай другие различия. Нужен итог: ускорение с доказательствами либо мотивированное отклонение кандидата без изменения runtime.

Native изменения — только NOT_APPLIED пакет с fresh before/after SHA/rollback/verify, backend READY/точный RELEASE. Бизнес-данные, source settings, права и физические fixtures не менять.
