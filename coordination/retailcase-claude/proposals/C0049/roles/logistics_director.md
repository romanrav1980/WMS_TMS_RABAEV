# Директор логистики сети

`logistics_director` · Руководство сети и РЦ · группа доступа (предложение): `RL_LOG_DIR`
Область назначения: вся сеть · устройства: desktop, планшет · рабочее место: **основного экрана нет**

## 1. Место в организации

- **Руководитель:** — (верх иерархии)
- **Подчинённые роли:** Администратор доступа, Аналитик, Аудитор (только чтение), Директор распределительного центра, Региональный руководитель магазинов, Директор транспорта
- **Заместитель:** Директор распределительного центра
- **Передача смены / замещение:** Не сменная роль. На отпуск — временное назначение роли директору РЦ основного склада с valid_until; по истечении срока назначение перестаёт действовать само.
- **Эскалация:** Владельцу бизнеса — срыв поставок сети более чем на сутки или выход затрат за утверждённый бюджет месяца.

**Отвечает за:**
- Цикл заказ → РЦ → рейс → магазин по всем РЦ: решения, которые не может принять один РЦ
- Перераспределение запаса и рейсов между РЦ (межскладской поток)
- Сетевые нормативы и политики (контроль отгрузки, сроки возврата тары) — утверждение, не ввод

**Не вправе:**
- Не выполняет и не подтверждает складские, транспортные и магазинные операции
- Не меняет права групп и назначения

## 2. События, решения, смена

**Смена:** Рабочий день. Два обзора: утром — итог ночного цикла; после отсечки заказов сети (профиль РЦ, по ТЗ 16:00) — риски вечернего цикла.

**Входящие события:**
- РЦ не обеспечит заказы магазинов к отгрузке (дефицит запаса или мощности)
- Межскладской план с несоответствием SSCC на получателе
- Расследование поставки магазину, не закрытое в срок
- Доплаты перевозчикам дня выше порога РЦ

**Решения:**
- Перенести заказы/рейсы на другой РЦ или на следующий цикл
- Поручить межскладской подвоз и назначить срок
- Принять превышение затрат или вернуть на разбор

**Сценарии:**

1. *обычный* — **Утренний обзор.** Открывает список исключений сети: по каждому — РЦ, объект (волна/рейс/расследование), влияние (сколько магазинов/СТ не получат товар), ответственный, срок. Закрытых исключений не видит. Открывает факт: исключение → рейс → СТ → грузовое место.
2. *дефицит/конфликт* — **Дефицит в РЦ-1 при запасе в РЦ-2.** Исключение «необеспеченные СТ» у РЦ-1. Поручает директору РЦ-2 межскладской план (его создаёт диспетчер с transport_dispatch_edit); следит за статусом плана до приёмки SSCC получателем. Если не успевает — согласует с директором транспорта перенос доставок.
3. *отказ/потеря связи* — **Сводка РЦ не загружена.** Плитка РЦ показывает «данные не получены, последнее успешное чтение 07:42», а не нули. Решения по этому РЦ — по звонку директору РЦ; исключения остальных РЦ доступны.
4. *передача* — **Отпуск.** Администратор доступа назначает директору РЦ роль сети на период (valid_from/valid_until, основание). Права самого директора РЦ не меняются; по окончании назначение не действует.

## 4. UI

- **Первый экран:** Список исключений, отсортированный по влиянию на план; над ним — плитки РЦ с временем последнего чтения
- **Главное действие:** Открыть исключение и перейти к факту
- **Таблица:** РЦ · вид · объект (ссылка) · влияние (магазинов/СТ) · ответственный · срок · возраст
- **Массовые операции:** Нет
- **Ввод:** Мышь; планшет — крупные строки
- **Ошибки, нет данных, нет связи:** Нет данных РЦ — отдельная плашка с временем последнего чтения; исключения других РЦ не скрываются
