# Согласующий затрат

`cost_approver` · Финансы, аналитика, ИТ и контроль · группа доступа (предложение): `RL_COST_APPR`
Область назначения: склад · устройства: desktop · рабочее место: **работает на существующих экранах без ролевой главной**

## 1. Место в организации

- **Руководитель:** Директор распределительного центра
- **Подчинённые роли:** —
- **Заместитель:** Экономист / транспортный биллинг
- **Передача смены / замещение:** Расходы на стадии FINANCE.
- **Эскалация:** Директору РЦ — расход выше лимита.

**Отвечает за:**
- Финансовая стадия решения расхода (expense_finance_approve по фактическому складу)

**Не вправе:**
- Не меняет ставки (create_tt_price не выдаётся)
- Не решает FINANCE по своему расходу или расходу, где решал LOGIST (native guard)

## 2. События, решения, смена

**Смена:** Дневная.

**Входящие события:**
- Расход прошёл стадию LOGIST

**Решения:**
- Утвердить/отклонить FINANCE

**Сценарии:**

1. *обычный* — **FINANCE.** Расход LOGIST_APPROVED → решение → событие признания в outbox.
2. *дефицит/конфликт* — **Корректировка расхода.** Решение по корректировке проверяется сервером (assert_correction_decision).
3. *отказ/потеря связи* — **Неизвестный исход.** Повтор тем же operation_id.
4. *передача* — **Передача.** Ожидающие решения.
