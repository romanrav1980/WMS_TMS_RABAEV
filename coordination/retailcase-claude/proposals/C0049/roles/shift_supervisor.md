# Начальник смены

`shift_supervisor` · Управление складскими операциями · группа доступа (предложение): `RL_SHIFT` · действующие legacy-группы: `ST_SMEN`
Область назначения: склад · устройства: desktop, планшет · рабочее место: **работает на существующих экранах без ролевой главной**

## 1. Место в организации

- **Руководитель:** Руководитель складских операций
- **Подчинённые роли:** Старший участка экспедиции, Старший участка отбора, Старший участка контроля (руководитель качества), Старший участка приёмки, Старший участка хранения и пополнения (диспетчер ричтраков), Планировщик волн и обеспечения
- **Заместитель:** Старший участка отбора
- **Передача смены / замещение:** Список передачи: волны (обеспечено/решение), красные теги с владельцем, начатые задания с подтверждённым грузом и местом, открытые срочные остановки. Принимающий подтверждает.
- **Эскалация:** Руководителю операций — нехватка ресурса; диспетчеру — рейс не будет готов к сроку.

**Отвечает за:**
- Транспортный план смены: волны, пополнение, запуск, комплектация, контроль, экспедиция (ТЗ процессы 2–5)
- Общая очередь и исключения
- Выход, отсутствия, перерывы
- Решения при неизвестной позиции ресурса

**Не вправе:**
- Не подтверждает недостачу, созданную им самим
- Не меняет права

## 2. События, решения, смена

**Смена:** Вечерняя смена по профилю РЦ (ТЗ основного РЦ: ричтраки с 18:00, комплектация ~20:00, волны обеспечены за 2 ч до конца).

**Входящие события:**
- Волна рассчитана, не обеспечена
- Пустая ячейка у комплектовщика
- Задание не принято в срок
- Позиция ресурса неизвестна

**Решения:**
- Утвердить время и запустить волну
- Назначить ближайший ресурс на срочную работу
- Подтвердить/отклонить недостачу
- Передать неначатое задание

**Сценарии:**

1. *обычный* — **Запуск волны.** Панель смены: волна рассчитана, пополнение 100% → утвердить время → запустить. Комплектовщики получают задания на ТСД.
2. *дефицит/конфликт* — **Волна не обеспечена.** Видит незавершённые подачи и исполнителей; приоритет подачи под ближайшую волну получает её срок; перенос волны — с логистом при влиянии на рейс.
3. *дефицит/конфликт* — **Пустая ячейка.** Инвентаризация (комплектовщик или ближайший аудитор) → срочное пополнение; таймер профиля. Нет кандидата — команда dispatch-nearest возвращает отказ с причиной, начальник назначает вручную.
4. *отказ/потеря связи* — **Потеря связи ТСД.** Ресурс сохраняет последнее состояние. Начатое задание не передаётся без подтверждения количества и места груза.
5. *передача* — **Передача смены.** Список передачи подтверждается принимающим; открытые пункты сохраняют владельца.

## 4. UI

- **Первый экран:** Монитор смены: волны с обеспеченностью, готовая работа без исполнителя, свободные сотрудники, ожидание принятия, красные ячейки с таймером
- **Главное действие:** Запустить обеспеченную волну / назначить ближайший ресурс
- **Таблица:** Задание · уровень · операция · откуда→куда · волна/рейс · исполнитель · этап · ожидание · срок
- **Массовые операции:** Передача нескольких неначатых заданий — отдельная команда на каждое с причиной
- **Ввод:** Планшет: поиск по SSCC сканером
- **Ошибки, нет данных, нет связи:** Неизвестный исход блокирует новую команду по объекту до чтения статуса
