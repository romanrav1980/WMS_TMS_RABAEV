# Карта UI: ролевые главные экраны и переиспользование

Состояние на 15.10.2026. Ролевых главных экранов в продукте нет. Каждая роль сейчас работает через существующие страницы: 56 raw-страниц с меню `admin-nav.js` по правам, React admin и терминал PWA. Сводка по каталогу:

| Состояние рабочего места | Ролей |
|---|---|
| только существующие экраны | 28 |
| реализуется в C0056 (блок 4) | 6: директор РЦ, диспетчер, комплектовщик, водитель + экраны администратора доступа и редактора знаний |
| основного экрана нет | 7: директор логистики, КРО, двор, перевозчики, регион, магазин, аудитор |

## Общий каркас ролевой главной (`features/workspaces`)

1. **Выбор рабочего места** — только среди ролей, которые уже дают права пользователю; выбор не меняет серверных прав. Источник ролей — `GET /api/access/me` (до READY: `GET /api/admin/auth/me` и permissions).
2. **Плитки «требует решения»** — исключения с объектом, влиянием, ответственным и сроком. Нет данных — плашка с временем последнего чтения, а не ноль.
3. **Переход до факта** — каждая строка открывает существующий экран-владелец (raw/React) с параметром объекта.
4. **Помощь** — у каждой кнопки tooltip «что произойдёт и зачем», `help_id`, «Подробнее» → статья; mouse/focus/Escape/mobile.
5. **Ошибки:**
   - 401 — вход;
   - 403 — «нет права X в области Y» плюс объяснение доступа (после READY explain);
   - сеть/5xx — «не получено», данные с меткой времени, кнопка «Повторить чтение».

   Команды на главной не выполняются, кроме явно перечисленных ниже.

## 1. Директор РЦ — первый экран

| Блок | Поля (источник) | Действие |
|---|---|---|
| Волны смены | `wave_code`, `status`, `planned_finish_at`, `launched_at`, `task_count`, `hard_reserve_qty` (`GET /api/picking/waves`) | Открыть «Панель смены» с волной |
| Рейсы дня | `ID`, `CONDITION`, `TRANSPORT`, `DOCK`, `READY_PERC`, `UNREADY_COUNT`, `ST_COUNT`, `PALLET_COUNT` (`GET /api/admin/transport/tasks?shipment_date=&include_readiness=true`) | Открыть диспетчеризацию/Ганту с рейсом |
| Срочные восстановления отбора | `GET /api/inventory/recovery-shorts` | Открыть «Складские задания» |
| Персонал | сессии `status`, `last_heartbeat_at`, `zone_code` (`GET /api/resources/sessions`) | Открыть «Ресурсы» |

- **Исключения на первом экране:** рейс с `UNREADY_COUNT > 0` при приближении выезда; волна без `launched_at` после срока профиля; сессия без heartbeat дольше N мин.
- **Порог времени** — параметр, а не константа. Пока профиля нет, порог не применяется, показываются факты.
- **Передача:** экран не выполняет команд; передача смены — у начальника смены.

## 2. Диспетчер — первый экран

| Колонка | Источник | Пусто/ошибка |
|---|---|---|
| Рейс, состояние | `ID`, `CONDITION` | — |
| Машина / перевозчик | `TRANSPORT`, `TRANSTYPE`, `TK_NAME` | «не назначена» |
| Водитель, телефон | `VODITEL_NAME`, `VODITEL_TEL` | «не назначен» |
| Ворота | `DOCK` | «нет» |
| Готовность склада | `READY_PERC`, `UNREADY_COUNT` (`include_readiness=true`) | `null` → «нет данных» |
| Операции рейса | `operation_code`, `plan_start/plan_end`, `fact_start/fact_end`, `delta_min` (`GET /api/admin/transport/tasks/{id}/operations`) | нет факта → «нет отметки» |
| Окна магазинов | `GET /api/transport/preflight/trips/{id}/delivery-windows` (уже в TransportRouteSchedule) | ошибка — текст сервера |

- **Действия:** открыть рейс в существующей диспетчеризации (правка машины/водителя/ворот — `PATCH /api/admin/transport/tasks/{id}`); подтвердить выезд — `POST /api/transport/loading/{id}/depart` из «Погрузки и выезда».
- **На главной команд нет**, только переход. Так не дублируется логика повторов существующих экранов.
- **Несколько РЦ:** до AK05 доступен один склад; фильтр по разрешённым РЦ появится вместе с областями.
- **Передача смены:** список рейсов по состояниям копируется в «Передачу смены» (GAP: объекта передачи нет; пока — печать/экспорт списка).

## 3. Комплектовщик (ТСД) — первый экран

- **Карточка «Моё задание»** (`GET /api/case-pick/tasks`, фильтр по `assigned_to` = я):
  - `wave_code`, `customer_name`, `sscc`, `pallet_type_name`;
  - прогресс `picked_lines/total_lines` и `task_progress_pct`;
  - блокировка `blocking_reason`/`blocking_cell_code`.
- **Главное действие** — «Продолжить сборку»: открывает существующий «ТСД сборки». Вся логика строк, весов, недостач и закрытия места уже там с operation_id.
- **Нет задания** — «Заданий нет: ждите выдачи по обеспеченной волне». Кнопки «взять любое» нет.
- **Блокировка** (`blocking_reason`) — крупным текстом: что случилось и кого звать (старший отбора).
- **Нет связи** — последнее известное задание с отметкой времени; команды недоступны до восстановления.
- **Передача** — в ТСД сборки (закрыть место или передать старшему); главная только показывает статус.

## 4. Водитель (телефон) — первый экран

- **Мои рейсы** — `GET /api/driver/trips`, проверка привязки учётной записи.
- **Операции рейса** — `GET /api/driver/trips/{id}/ops`: следующая незавершённая операция крупно, кнопки «Начать»/«Завершить» (`POST /api/driver/ops/{id}/start|done`), безопасный повтор.
- **СТ и адреса** — `GET /api/driver/trips/{id}/sts`.
- **Нет привязки** — «Учётная запись не связана с водителем — обратитесь к диспетчеру» (существующий ответ API).
- **Нет связи** — нажатие помечается «не подтверждено» и не считается выполненным до ответа сервера.
- **Акт магазина, тара, возвраты** — существующие панели `StoreReceiptPanel`, `TarePanel`, `ReturnCustodyPanel` в `DriverMobilePage`. Главная водителя переиспользует их; правка `DriverMobilePage.tsx` — только по file-lock.

| Нужно | Компонент/экран | Владелец |

| Ганта/операции рейса | `TransportGanttPage` + helpers | transport |

## Меню

Ролевой пункт «Моё рабочее место» добавляется в общий App/навигацию через integration patch Codex. Существующее меню `admin-nav.js` по `data-permission` не меняется. Ролевая главная — дополнительная точка входа, а не замена страниц.
