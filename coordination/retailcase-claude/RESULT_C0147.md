## Отличия и границы

1. **Порядок при смешанных ошибках.** Раньше проверки шли по одному коду, теперь проверки дубликатов для всего набора идут раньше проверки GTIN. Если в одной паллете одновременно есть дубль и чужой GTIN, сообщение может быть другим. Эффекты одинаковы: транзакция откатывается целиком, частичного commit нет.
2. **Не измерено живьём.** Нативная компиляция SAP_RECEIPT объявляет около 2000 именованных блокировок (UNIT на единицу и MARK на код). `ADD_AGGREGATION_ITEM` считает элементы по индексу только на AGGREGATION_ID, это примерно O(n²) на сервере. Оба пункта — серверная работа и, вероятно, входят в TRANSACTION 2034 мс. Без живого замера и согласования изменения RRL_STOCK_POSTING_API/RECEIPT_PLAN не трогал.
3. **Для приёмки Codex** нужен повтор исходного неизменного тела с `operation_id` `T3.receive.505b15a0` после выката процесса 8088 с этим кодом.
