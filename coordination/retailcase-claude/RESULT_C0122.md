## 1. Блокеры C0121 исправлены (`case-handoff.js`, `case-handoff-dialog.js`)

- **Доказательство исхода — только неизменная квитанция.**
  - `proven()` по текущему исполнителю удалён. Вместо него `receipt()` делает GET `/transfer-receipt?offline_event_id=…`.
  - `receiptMatches` (`case-handoff.js:75`) требует совпадения всех признаков:
    - `case_pick_task_id`;
    - `status=TRANSFERRED`;
    - тот же `offline_event_id`;
    - `actor` = текущий пользователь;
    - `outcome_confirmed=true`;
    - `source=IMMUTABLE_TRANSFERRED_EVENT`;
    - каждое из 9 полей тела (`sameRequest`, `:71`).
  - Опущенное поле равно null только для nullable-полей DTO (все, кроме `to_resource_id`).
  - Другой ключ, автор, источник, неподтверждённый исход или иное поле тела (скан, ресурс) — исход «не подтверждён».
  - Ответы 403, 404 и 503 квитанции — тоже «не подтверждён». При 404 экран пишет, что это не подтверждает отмену.
- **После неизвестного исхода запрос не снимается.**
  - Отказ 400/403/404/409/422 оставляет запрос и блокировку новой передачи; затем проверяется квитанция.
  - Без доказанного исхода запрос снимается только при отказе на первой отправке (`:110`).
  - Явное «Снять в архив» удалено. Вместо него «Копия для разбора» (`copy`, `:129`): копия сохраняется рядом, запрос и блокировка остаются.
  - Серверная отмена (ABANDON) не изображается. Подписи и справка `/help/case-handoff.html` (`#receipt`, `#resolve`) переписаны.
- **Повреждённая запись.**
  - Повтора нет, копия не разблокирует.
  - Блокировку снимает только подтверждённая квитанция по ключу `HANDOFF:…`, извлечённому из текста записи. Тело сравнить нельзя, поэтому сверяются задание, ключ, автор, источник и `request.offline_event_id`.
  - Если ключа в записи нет, блокировка остаётся до разбора.
- **Legacy-запросы `case.handoff:*`.** Исход по-прежнему всегда неизвестен. Снимаются только ответом 200 на точный повтор или квитанцией.

## 2. Мобильная страница CASE целиком (`case-page-mobile.css`, `case-pick-management.{html,js}`)

- Новый `case-page-mobile.css` действует только для `body.case-mgmt`, глобальный `styles.css` не менялся. На ширине ≤900 px:
  - снят `min-width: 1280px`;
  - сетка `.app` становится блоком, боковая навигация — горизонтальной лентой;
  - шапка и фильтры переносятся, KPI, сетки и карточка выстраиваются в колонку;
  - таблица прокручивается внутри своей рамки, кнопки действий не меньше 44 px.
- Кнопка «Повторить сохранённые решения по недостачам» больше не наезжает на заголовок:
  - стоит в потоке в начале `.case-page`;
  - видна только при наличии сохранённых решений;
  - получила `title` и `data-help-id`.

## 3. Native-навигация и доступ (`admin-nav.js`, `case-access.js`)

- В `admin-nav.js` добавлен helper `window.wmsNativeAccess`: кэш `/api/access/workspaces` на пользователя и API.
  - Пункты «Комплектация» и «ТСД сборки» (`picking`), «Погрузка и выезд» (`dispatch`), «Грузовые места» (`warehouse_tasks`) раскрываются по готовой READ capability.
  - Если склад из адреса есть среди разрешённых, ссылка получает `?warehouse_id=<текущий склад>`.
  - Общий `auth.permissions` не меняется.
- `case-access.js`: экран открывается по плоскому `case_pick_view` или по `picking` хотя бы одного склада.
  - Одно ACTIVE-назначение, например только вход в оболочку, доступа больше не даёт.
  - Выбор «Склад» вверху страницы заполняется складами с `picking`. Выбор пишется в `warehouse_id` и фильтрует список и недостачи (`ware_id`) на сервере.
  - Отказ и ошибки чтения очищают строки, как в C0121.

## 4. Гейты погрузки

- Секция «Выезд» в `transport-loading.html`: вместо плоского `transport_dispatch_close` — плоское право или native `dispatch`. До проверки секция скрыта.
- `warehouse-hus.html`:
  - гейт страницы: плоское `warehouse_task_view` или native `warehouse_tasks`/`dispatch`. Отказ скрывает разметку, а не удаляет её: обработчики `warehouse-hus.js` не падают;
  - секции «скан внешнего места», «Упаковать / вскрыть» (в неё вложена отгрузка целого места) и «Отгрузка целого места» — плоское право или native.
- Сервер по-прежнему решает каждую операцию.

## Оставшиеся ограничения (не блокеры UI)

- `C0121/scripts/c0121_check.cjs` проверяет отменённую семантику «Снять в архив». Он устарел, его заменяет `c0122_check.cjs`.
- **Остались плоские гейты**, о которых сервер не сообщал как о scoped; их не трогал:
  - «Выгрузить до выезда» — `transport-loading.html:26`, `stock_posting_shipping`;
  - «Создать пустой контейнер» — `warehouse-hus.html:11`, `warehouse_task_execute`;
  - сохранение окна доставки — `delivery-window.js:31`, `transport_dispatch_edit`, файл root;
  - прочие пункты меню без native capability (`admin-nav.js:94`).
- **Сессии вручную.** Есть GET `/api/case-pick/tasks/{id}/resource-sessions`, но в контракте C0121/C0122 он не передан. Поэтому номер сессии вводится вручную, как прежде.
- **Широкий выбор склада у admin.** У admin с «*» список складов на странице CASE равен ответу `workspaces`, который сервер может обрезать (`has_more`). Склад из адреса всегда добавляется в список.
- **Таблица на 390 px.** На узком экране таблица заданий прокручивается внутри своей рамки; страница горизонтально не прокручивается.
