# C0175 — единицы заказа при загрузке

Владелец снова прямо поручил совместно продолжать все спринты. C0174 принят Codex через настоящий HTTP. Это одно крупное новое задание; зарегистрировано до передачи в claude-budget.json. Прочитай AGENTS.md, wiki/index.md, wiki/requirements/nicora_order_units_20261027.md и действующие архитектурные правила. Никаких новых агентов или запросов владельцу по рабочим деталям не требуется.

## Результат

Реализуй загрузку строк заказов в штуках, коробках, блоках, граммах и килограммах по настройке конкретного SKU. Сначала проверь действующие входные контракты и native demand binding: не добавляй второй независимый пересчёт. Сохрани текущую совместимость EA/BOX. При одной единице обработки и отличающейся входной единице округлять вниз до разрешённого шага SKU. Флаг округления включён — загрузка. Выключен — та же загрузка с устойчиво записанной ошибкой интеграции, не откат/отклонение всей строки. Сохранять исходные количество/единицу, обработанные количество/единицу, разницу в базе, версию настройки и диагностику. Точное повторение не создаёт второй заказ/резерв.

Не превращай каждый кг в целый: шаг и точность берутся из SKU. Нет коэффициента — не выдумывать количество. Нулевая после округления строка сохраняется с диагностикой, без нулевого задания. Заказ сам не создаёт запас. Не смешивать прогноз продаж и перемещений.

## Владение и границы

Твой домен: integrations, входные SKU/ORDER контракты и нормализация/загрузка заказа, адресные tests и собственные fixtures. Перед общим изменением публичного контракта пришли короткий CONTRACT с путями и формой: root транспорт не затрагивает эти контракты, но подтвердит границу. Не трогай live_program_orders.py, транспортные назначения, погрузку, root-набор210069361, общие wiki/index.md/wiki/log.md/RESUME, serv.bat, frontend dist. Самостоятельно API не перезапускай. Если нужен native — подготовь точный комплект с исходником, apply/verify/rollback и SHA, NOT_APPLIED; применение делает root после проверки и checkpoint.

Используй nicora-api-integrations/nicora-oracle/nicora-acceptance по необходимости. Не публикуй SAP/SAP_INTEGRATION или вообще GitHub. Не добавляй неподтверждённую конкретную SAP IDoc-версию. Эта задача про рабочую границу текущего стенда, не про выдуманную промышленную приёмку.

## Проверки и передача

Свои таблицы/склад/заказы отдельно. Сравни вход25EA при коробке12 →2BOX/остаток1: флаг true и false, второй случай загружен с ошибкой. Проверь дробный вес/шаг, блоки, неподдержанный коэффициент, ноль, изменение версии, точный повтор/конфликт и текущие права. Настоящие API/Oracle при доступности и SQL-стоимость; исходники и unit tests не выдавать за весь end-to-end. Gate/encoding. До окончания дай ACK с конкретными путями, затем RESULT_C0175.md с коммитом, RELEASE, доказательствами и честными остатками. Не снимай ограничения ради зелёного теста.
