## Найденные и исправленные дефекты (на реальных данных)

1. **Стадия волны после сборки была статической.** Волна 613 (склад 220793322, CASE1169 CONTROLLED) стояла в «Открытых блокировок нет»; 605/606 (CONTROLLED) и 607/612 (SHIPPED) — так же.
   - Теперь стадия берётся из статусов CASE волны: открытые → «Сборка», WAIT_CONTROL…READY_TO_SHIP → «Собрано: контроль, погрузка», все SHIPPED → «Отгружено, волна не закрыта».
   - Набор состояний тот же, что closed states в `case_close_state.py`; неизвестный статус → стадия не угадывается.
   - Блокировки готовности приоритетнее фактов сборки; DONE/CANCELLED → архив; PREVIEW → подготовка.
   - Если выборка сборки упёрлась в лимит 200, стадия по CASE не определяется: невидимое открытое задание не превратится в «отгружено».
   - Карточка волны: строка «Сборка по факту».
2. **Отменённое пополнение показывалось риском «Пополнение ждёт»** (волна 613, строка 1673 CANCELLED, wait_reason = причина отмены) и входило в счётчик «Пополнения» (было 4).
   - Теперь DONE и CANCELLED не считаются ни в риске, ни в счётчике, ни в карточке.
3. **Недоступный источник выдавался за отсутствие риска.**
   - При ошибке/403 сборки или недостач, непрочитанном списке волн, упавшем пакете shift-overview или выборке сборки на лимите панель рисков показывает «Проверено не полностью — отсутствие риска не подтверждено» с перечнем.
   - Плитка блокировок помечается «проверено не полностью».
   - Закрытые волны пробелом не считаются.
4. **Работа, назначенная ресурсу без времени, терялась.** Склад 9807, рейс 33564: 12 операций назначены машине, время без пояса.
   - Было: карточка работы «Ресурс не назначен», карточка машины «Назначений в окне нет».
   - Теперь строка Ганта: «без времени 12» (и в title); карточка ресурса: раздел «Назначены без времени»; карточка работы: ресурс с пометкой «времени на шкале нет».
   - Поиск и точный фильтр волны учитывают такие работы. Длительность не рассчитывается, состояние «Неизвестно».
5. **Внутренние коды в карточке работы** заменены текстом:
   - время: AWARE_*/TIME_UNRESOLVED;
   - утверждение рейса: approval_status, SOURCE_CHANGED → «источник изменился после утверждения — время не подтверждено»;
   - роль: исполнитель/техника/ворота/машина.
6. **Риски с действием «Панель смены»** (непрочитанный источник, неразрешённый отбор, неизвестный тип блокировки) вели обратно на это же рабочее место. Теперь действия нет: в приложении нет экрана разрешения отбора, ссылку не выдумываю.
   - Кнопку «Панель смены» в карточке волны оставил: её нажимает регрессия `tests/tradecase/shift_wave_navigation_ui.cjs`. Сейчас это прямая ссылка на ту же волну; решение за Codex.

## Backend-пробелы (контракты не выдумывал)

1. **Пояс склада.** `warehouse_time_zone=null` у всех 341 склада с resource_timeline: Гант везде в UTC, время транспортных операций без пояса уходит в очередь.
   - Нужно: пояс склада в timeline (поле уже есть в контракте).
2. **Доступность.** `availability=UNKNOWN` у всех ресурсов, attendance-интервалов нет ни на одном складе: «свободен» не показывается нигде (корректно), смена не видна.
   - Нужно: план выхода/смены по ресурсу в `events[kind=ATTENDANCE]` + assignments.
3. **Ворота в операциях рейса не назначаются.** Склад 9807: DOCK_ASSIGN/LOADING рейса 33564 назначены только `VEHICLE:QC241EDE877F6D1`, `DOCK:9807:B01c0c2a00c` без assignments. На 220639789 WAREHOUSE_TASK 1221 и DOCK TFP22.1221 не связаны.
   - Ни на одном складе нет события с несколькими ресурсами: multi-resource проверен только fixture.
   - Нужно: assignment ворот для операций рейса с назначенными воротами.
   - Воспроизведение: `GET /api/resources/timeline?warehouse_id=9807&start_at=2026-10-15T00:00:00+03:00&finish_at=2026-10-22T00:00:00+03:00`.
4. **Ричтраки без работ пополнения.** REACHTRUCK есть на 51365792 и 220639789, но событий пополнения на них нет: связь «пополнение волны → ричтрак» в timeline не приходит.
5. **Двор/визиты.** Журнала визитов, очереди машин и времени у ворот в API нет. Экран двора (не мой файл) уже честно помечает пробел; общую сводку за журнал не выдаю.
6. **Разрешение отбора.** Риск «Отбор не разрешён» без экрана-владельца: в приложении нет UI release.
   - Нужно решение Codex: экран/контракт или оставить как информационный риск.
7. **Сборка по волне.** `case-pick/tasks?scope=all&limit=200` без фильтра волны и курсора: при >200 заданиях стадия по CASE не определяется.
   - Нужно: `pick_wave_id`-фильтр или `has_more`/курсор.
