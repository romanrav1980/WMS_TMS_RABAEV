Предыдущий документ wiki/requirements/retailcase_claude_parallel_tasks_20261014.md — каталог возможных задач; CC-01…04 сейчас НЕ назначены.

## Канал обмена
Общая папка: C:\projects\TMS\coordination\retailcase-claude.
- CODEX_TO_CLAUDE.md: пишет только Codex, читает Claude.
- CLAUDE_TO_CODEX.md: пишет только Claude, читает Codex.
- CLAUDE_STATUS.md: поддерживает только Claude; статус, текущая задача, занятые файлы, блокеры, последний прочитанный ID Codex.
- TASK.md и README.md: условия назначения; меняет Codex после согласования изменений границ.
- Предложения изменений чужих файлов: proposals/; автор Claude, применение владельцем этих файлов.
- Рабочие отчёты: reports/retailcase/2026-10-13/claude/NI07.2/ и NI08.1/.

Сообщения дописывать в конец своего журнала. Формат: ID (C-0001 или K-0001), дата/время с часовым поясом, тип ACK/QUESTION/CONTRACT_REQUEST/RESULT/BLOCKER, ссылка на задачу, содержание, требуется ли ответ.
Не переписывать сообщения другой стороны. Подтверждать конкретный ID, не использовать неявное «ок».

## Порядок
1. Claude читает TASK и C-0001; отвечает ACK со списком занятых файлов и заполняет CLAUDE_STATUS.
2. После ACK начинает назначенные задачи без дополнительного согласования владельца.
3. Каждый агент читает входящий журнал перед новым блоком изменений и после его завершения; при активной длительной работе — не реже одного раза в 15 минут.
4. Перед изменением общих API/файлов Claude пишет CONTRACT_REQUEST: зачем, точный файл/контракт, вход/выход, обратная совместимость. Пока нет ответа — продолжает независимые части, чужую область не меняет.
5. Codex не редактирует зарезервированные файлы Claude до RESULT + явного RELEASE файлов. Claude не редактирует код Codex.
6. Для готового блока Claude публикует RESULT: файлы, сценарии, отчёт, скриншоты, ограничения и RELEASE. Codex читает результат и отвечает отдельным сообщением о принятии либо конкретном остатке.
7. Это обмен через файлы, без автоматического уведомления. Если сессия агента не запущена, сообщение ждёт следующего чтения. Принятие поручения подтверждается только записью ACK Claude; стартовый статус WAITING_FOR_ACK не означает, что Claude уже работает.

В случае отдельного checkout указать абсолютный путь в ACK; до согласования синхронизации не считать локальные файлы общим каналом.

## Непрерывное выполнение (уточнение владельца 14.10)
Очередь TASK.md заранее разрешена. После RELEASE сразу читать последние сообщения CODEX_TO_CLAUDE.md и начинать следующий разрешённый блок, не ждать ответного ACK. Если всё назначенное сдано и требуется поручение ведущего, оставаться в активном ожидании канала с интервалом не более60секунд; не ставить разовое ожидание на30минут и не объявлять очередь пустой по старому последнему сообщению. Во время реализации достаточно читать канал перед новым участком/после результата, без постоянного прерывания работы.
Это правило требует активной сессии исполнителя; файловый канал сам не запускает остановленную сессию. Источник фактического прогресса — ACK/RESULT с актуальным последним C-ID и занятыми файлами в CLAUDE_STATUS.
