## Конкретный результат

TransportDispatchPage.tsx: loadAvailableSts сейчас вызывает /api/admin/transport/available-sts без page/page_size. API уже выполняет страницу в Oracle (report53), миграция1381 VALID. Подключи серверную загрузку страниц по200 в существующую таблицу; кнопка следующей страницы или «Загрузить ещё» с явным числом загруженных строк. Не загружай все страницы автоматически. Выбери вариант, сохраняющий действующие операции выбора СТ и назначения рейсов.

## Обязательные условия

1. Пагинация и применимые фильтры на сервере; не фильтруй по складу только загруженные строки, создавая ложное «ничего нет». Прочитай существующий каталог складов и используй его. Если нельзя в рамках файлов — CONTRACT_REQUEST, без выдуманного списка.
2. Ясно отдели «загружено» от общего количества, локальной сортировки/итогов. CSV и «выделить всё» должны явно описывать область; не включать скрытые/устаревшие выбранные СТ в проведение.
3. Смена фильтров сбрасывает страницу/старые результаты и выбор безопасно; медленный прошлый ответ не перезаписывает текущий. Не запускать полную выборку при каждом вводе, сохранить debounce. Ошибка API не подменяется demoAvailableSts: показать ошибку и повтор.
4. Сохранить существующее назначение/проверку вместимости/действия. Не создавать второй allocator. После мутации обновить текущий набор; не показывать устаревшую готовность.
5. Не ограничивай молча доступную историю новым скрытым периодом. Текущая дата/диапазон остаются видимыми.
6. Новый код в небольшом transport helper/hook, не раздувать legacy-компонент; итоговый debt не повышать.
