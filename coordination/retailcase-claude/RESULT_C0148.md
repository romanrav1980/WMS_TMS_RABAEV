## Реализовано

**Связь точки с получателем — только по ключам.** Новый READ ONLY `GET /api/tradecase/warehouses/{w}/trips/{trip}/route-points` (`integrations/infrastructure/trade_route_plan.py`):
- точки — это RRL_SBORKA_PALLETS привязанного рейса склада (тот же источник, что у нативного route-context);
- связь: паллета сборки → RRL_CASE_PICK_TASK.LEGACY_SBORKA_PALLET_ID или выполненное задание FULL_PALLET той же паллеты → RRL_CUSTOMER_ORDER → RRL_TRADE_ORDER_LINK → получатель;
- по названию ничего не сопоставляется.

Статусы точки:

| Статус | Значение |
|---|---|
| LINKED | получатель и заказы найдены |
| UNLINKED | NO_ORDER_FOR_POINT или NOT_A_TRADECASE_ORDER |
| AMBIGUOUS | у точки заказы разных получателей или нет документа получателя |
| HIDDEN | у пользователя нет права на собственника строк — получатель, заказы и количества не раскрываются |
| OTHER_WAREHOUSE | точка другого склада — адрес и получатель не раскрываются |

- **Проверки поверх связи** (связь из них не строится): клиент получателя (`wms_customer_id`) = клиент заказа; адрес точки ∈ активные RRL_CUSTOMER_ADDRESS клиента (CONFIRMED с типом / NOT_IN_CUSTOMER_ADDRESSES / AMBIGUOUS / ADDRESS_MISSING).
- `blocked_reason`: TRIP_NOT_BOUND или POINT_RECIPIENT_LINK_INCOMPLETE. Неизвестный рейс → 404, нет `tradecase_view` → 403, всё в одной READ ONLY транзакции.

**План приезда, обслуживания, ожидания и возврата.** Отдельный планировщик не создавался: экран вызывает существующий `GET /api/transport/preflight/trips/{id}/delivery-windows` (RRL_TT_TIME_API + RRL_TT_ROUTE_SCHEDULE.calculate, `time_zone=UTC`, без выдуманного пояса).
- `RoutePlan.tsx` (новый) в `TripRoute.tsx` по каждой точке показывает: получатель и проверки, окно, приезд и начало разгрузки, ожидание и опоздание, причины.
- По рейсу: выезд, возврат, итог («нарушений окон нет» / «окна не подтверждены: …»).
- Коды нативного расчёта переведены в текст; неизвестный код → «другая причина источника».
- Всегда видна пометка: «Расчёт — план; выезд и доставку он не подтверждает».
- Карта без координат не строится.
- Справка `#route` переписана.

## Ограничения / оставшийся объём T09

1. **Данных для расчёта нет.** Депо, дорожные плечи и правила точек для торговых рейсов не заданы: время, окна и пример 11:00/11:55/12:40 на настоящих данных не принимаются. Нужна настройка этих источников существующими командами транспорта (`RRL_WARE_DEPOT_HISTORY`, route input, destination rules).
2. **Целая паллета.** Связи нет: паллета сборки не ссылается ни на задание, ни на заказ. Нужен контракт сохранения этой ссылки при создании паллеты сборки или версионная команда привязки. Сохраняемую привязку не делал, чтобы не создавать параллельный источник без согласования.
3. **Адреса клиентов.** Адрес точки не найден среди адресов клиента ни у одного проверенного получателя — проблема данных QA, показывается как предупреждение.
4. **Не реализовано:** правило «до предельного времени 30 мин — заезд 15 допустим, 45 отклоняется» как отдельная политика согласования заезда; запрет новых точек; изменение времени и пробега при согласовании. Нативный расчёт даёт нарушения окна, но команды согласования нового заезда нет.
5. **Выкат.** `/route-points` на 8088 не выкачен: процесс сервера не перезапускался. Живой HTTP нового эндпоинта и права через ASGI — за Codex.
6. **Права.** Расчёт окон требует `transport_dispatch_edit` (это существующий эндпоинт): при 403 экран так и пишет.
