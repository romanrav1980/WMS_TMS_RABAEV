## Результат
Оператор при отказе ТСД должен получить бумажное складское задание с однозначным идентификатором, выполнить работу и затем внести/сверить факт штатными командами системы. Печать сама не выполняет работу и не изменяет количество. Повтор печати или ввода факта не создаёт второе задание и повторный товарный эффект.

1. Найди существующие печать/выгрузку, warehouse task/pick/CASE commands, назначение исполнителя и восстановление неизвестного результата. Если задача уже обеспечена — свяжи экран и справку, исправь конкретные пробелы, не делай параллельный процесс. Task ID может уже быть достаточным уникальным номером; не создавай новый журнал/сущность без требования из источника.
2. Доведи понятный операторский цикл: выбрать разрешённые задания → распечатать читаемый бланк с нужными адресами/идентификаторами паллет/товаром/количеством/исполнителем и отметкой состояния → после восстановления сверить актуальное задание и внести факт через существующий authoritative владелец. Устаревшая версия/переназначение/отмена/изменившийся состав должны давать конкретный отказ/действие, а не подтверждать старую бумагу. Не разрешать ввод за другого исполнителя без существующего полномочия.
3. Офлайн-бумага не обходит текущие права склада/owner, блокировки и журналы operation_id. Сохраняй неизвестный исход и неизменный повтор. Печатный лист не должен раскрывать скрытые строки. Не выдумывать отсутствие скана как подтверждение маркировки; если нативное исполнение требует коды, оператор должен сверить/ввести их штатным способом.
4. Экран и справка: для сотрудника, конкретные действия; кнопки с title/help, 1440/390 и печатный лист/PDF без обрезания полей. Не разрабатывать универсальную отчётную платформу и новый офлайн-движок. Используй browser print/действующие шаблоны, если этого достаточно.
