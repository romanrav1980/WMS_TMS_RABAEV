# Канал Codex ↔ DeepSeek

Рабочая папка: C:\projects\TMS. Кодировка UTF-8. Назначения Codex лежат в INBOX; DeepSeek читает D001, затем D002. Обе задачи разрешены к выполнению, D002 начинается после RELEASE D001. При блокировке D001 можно перейти к D002, сохранив описание блокера.

До правки создай ACK/<номер>.md: задача, закреплённые файлы, состояние исходного рабочего дерева. После правки создай RESULT/<номер>.md и RELEASE/<номер>.md. В RESULT укажи изменения, оставшееся, проведённые проверки или «не запускались». В RELEASE перечисли точные файлы и передай ответственность Codex. Наличие RELEASE не означает приёмку; её Codex фиксирует в ACCEPTED/<номер>.md.

STATE.md ведёт DeepSeek: последний прочитанный номер, активная задача, статус, файлы, блокеры. Codex не перезаписывает этот файл. Вопросы клади в QUESTION/<номер>.md; ответы Codex — в ANSWER/<номер>.md. Мелкие технические решения принимай сам.

Сначала прочитай AGENTS.md, wiki/index.md и релевантные разделы wiki/roadmap/transport_execution_plan.md. Сохрани существующие незакоммиченные изменения. Не используй reset/checkout для очистки. Не меняй файлы вне задания; предложения по ним перечисли в RESULT. Не коммить общую рабочую копию и не публикуй без отдельного поручения.

Приоритет владельца: сначала разработка, затем общий этап отладки. Не запускай pytest, браузерные сценарии, нагрузку или live API/Oracle операции. Прочитай собственный diff; обязательную проверку кодировки выполни перед передачей. Непроверенные изменения пометь как awaiting_validation. Не ослабляй критерии тестов ради зелёного результата.

После каждого блока читай новые INBOX и ANSWER. Если среда поддерживает ожидание, проверяй канал раз в 3 минуты, без повторных сообщений idle. Если фонового режима нет, честно укажи это в STATE; не утверждай, что наблюдение запущено.
