## Ограничения и риски
- Асинхронный режим (`async_response=true`) не используется: сервер не отдаёт полный результат по job_id (SSE `done` даёт только `plan_id/score/routes_count`; `/planner/metrics` возвращает `routes` числом, а не массивом). Поэтому применяется прямой синхронный solve, который отдаёт полный план.
- Ручное редактирование маршрутов (drag-and-drop) не передаётся в apply: контракт `VrpApplyRequest` принимает только `plan_id` + `shipment_date` + `dock`. Существующая подсказка «Применить план создаст исходный план» сохранена.
- Сквозная проверка (живой UI + Oracle) не выполнялась: только статическая проверка типов и кодировки.

## Для Codex — недостающий контракт (не блокирует текущий результат)
