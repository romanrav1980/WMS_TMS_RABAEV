## Реализовано
D002:
1. `GET /planner/solve/{job_id}` возвращает полный результат конкретной задачи (scope/права `TRANSPORT_DISPATCH_EDIT`, результат в памяти store). Async solve/cancel подключены к UI: `POST ?async_response=true` → SSE → `done` → `getJobResult`. Синхронный `runSolve` сохранён для совместимости.
2. SSE через `fetch` + `Authorization` (не URL), не EventSource; потеря соединения/отмена/завершение/ошибка — разные состояния; устаревший ответ не заменяет новый расчёт (генерация + AbortController); таймер и поток закрываются при отмене/смене контекста/размонтировании.
3. Payload применения (plan_id + дата) фиксируется до POST; повтор/перезагрузка/повторное нажатие повторяют исходный payload; 4xx снимает intent, неизвестный исход сохраняется с предупреждением.
4. Ручное редактирование маршрутов (drag-and-drop) не применяется в Oracle: контракт `VrpApplyRequest` принимает только plan_id/дату/dock. Существующая подсказка «Применить план создаст исходный план» сохранена — серверное сохранение версии не добавлялось (сверх ТЗ).
5. Экспорты через index.ts.
