## Что будет сделано
1. Прямой `VrpPlan` показывается из ответа `POST /planner/solve` (синхронный, полный с `routes`); убрано «подбирание последнего плана истории» и чтение `metrics` как результата.
2. Принятая дата/параметры расчёта фиксируются на момент solve; применение использует эту дату, смена фильтра не меняет payload применения.
3. Применение запрещено без `plan_id` и без маршрутов; повторное параллельное нажатие блокируется; payload повтора не меняется (тот же `plan_id`+дата).
4. Убраны мёртвые ветки: SSE-поток с относительным URL без авторизации, `cancelled` → история, кнопка отмены (нет серверного результата по job_id). Таймер решения очищается при размонтировании.
5. Убран пользовательский текст про backend 500/CORS/порт 8088; ошибки JSON/соединения выводятся с указанием следующего действия.
6. Логика solve/apply вынесена в `plannerRun.ts`; архитектурный baseline не расширяется; зависимости не добавляются.
