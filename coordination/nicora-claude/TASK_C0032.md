# C0032 — восстановление утверждения времени рейса после reload

Спринт NI08.1. Подтверждённый пробел: TransportTimeApproval.tsx сохраняет pending intent в localStorage, но не предлагает восстановить его поля после reload. reason и loadedReview не восстанавливаются, для точного повтора оператор вынужден угадывать прежний ввод. Backend уже поддерживает operation_id/replay — использовать его.

Владение: admin/wms_admin_frontend/src/components/TransportTimeApproval.tsx и новые локальные TransportTimeApproval* helpers/styles. Не менять TransportTimePreflight, RouteInput, native SQL, API, main, VehiclePhysicalProfile. Компонент не раздувать: извлечь recovery hook/helper при необходимости.

Результат:
- При наличии pending показать рейс, часовой пояс, основание, фазу и действие восстановления. Область хранения apiBase + actor сохраняется.
- После восстановления повторить точный intent с прежними operation_id/version/hash, не подменять его прочитанным свежим контекстом. Для другого рейса показать понятный переход/указание открыть его; не отправлять команду от текущего рейса.
- Не терять intent при сетевой ошибке, 5xx, malformed response. Удалять только достоверно завершённую команду либо подтверждённый отказ согласно существующему контракту; не добавлять опасное «забыть» для неизвестного результата.
- Блокировать конфликтующий новый ввод, показать понятную причину. Проверить восстановление AFTER_LOADING_REVIEW и переключение actor/trip/zone. Если parent zone не совпадает — явно предложить выбрать сохранённый timezone, не менять чужой компонент без CONTRACT_REQUEST.
- Не дублировать серверные бизнес-правила.

Критерий: браузерный адресный сценарий abort/перезагрузка/тот же payload; допустим перехват POST с явной отметкой mocked evidence, реальный рейс повторно не утверждать. TypeScript и screenshot законченного блока, SQL новых запросов нет. Отчёт reports/nicora/2026-10-13/claude/C0032/. После RESULT/RELEASE сразу C0033.
