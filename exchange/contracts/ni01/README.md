# Рабочие предположения XML NI01

Эти файлы — примеры контракта, созданные разработчиком по поручению владельца. Они не являются экспортом SAP и не отправлялись в live inbox. Указанные склад/ячейка/SKU — пример: заменить согласованными значениями до рабочего импорта. Примерные коды маркировки не являются государственными марками.

ARTMAS10: EDI_DC40 с DOCNUM/SNDPRN/CREDAT/CRETIM; E1BPE1MATHEAD/MATERIAL; E1BPE1MARART/BASE_UOM/EAN_UPC; E1BPE1MAKTRT/MATL_DESC; E1BPE1MARMRT/ALT_UNIT/NUMERATOR/DENOMINATR/EAN_UPC. Ключи остаются строками. BOX/CAR/CS/KAR — рабочие алиасы коробки, PAL — паллеты. Коэффициент альтернативной единицы — NUMERATOR / DENOMINATR в базовых единицах. Это предположение о полях, не подтверждённая схема customer extension вашей SAP 2020.

WarehouseSupplyOrder version=1 — нормализованный контракт шлюза для SAP-заказа на склад; не стандартный IDoc SAP. WarehouseId — WMS RRL_WARES.ID, ReceiveCell — DEFAULT_RECEIVE_CELL того же склада. Revision монотонна, MessageId уникален у Sender. Новая версия меняет план, сохраняя принятые строки/факты: нельзя сменить товар/единицу принятой строки, удалить её или уменьшить количество ниже факта. Явно закрытый заказ сначала требует команды reopen, затем новой Revision.

Aggregations необязательны: LineNumber/System/Profile/Level/Code, известные Units/UnitId/Code. UnitId связывает одну физическую единицу между профилями. Для весовых/объёмных единиц допускается Unit/Quantity в базовой UoM; без неё нужна однозначная физическая упаковочная норма SAP. Для штучной UoM Quantity=1. Скан агрегата должен совпадать с манифестом; он не заменяется GTIN. Для GS использовать <Code encoding="base64">...</Code> (base64 UTF-8). Состав без уникальных кодов не принимается.

HTTP — запасной административный вход: POST /api/integrations/sap/artmas и /api/integrations/sap/supply-orders, raw XML; основной транспорт — файлы через sap-artmas.bat и sap-supply.bat. XML UTF-8, до 4 MiB, без DTD/entities. Завершённый файл публикуется шлюзом через rename.

Результаты — WmsReceiptEvent version=1 через sap-receipts.bat. Шлюз дедуплицирует EventId. EXPORTED означает файл. Подтверждение WmsReceiptAcknowledgement version=1 принимает sap-ack.bat: Sender, MessageId, EventId, PayloadHash (SHA-256 точных опубликованных байтов), Status=ACCEPTED|REJECTED, ExternalDocumentId (обязательно для ACCEPTED), необязательный Error. Sender совпадает с исходным SAP отправителем; ACKNOWLEDGED требует реального ответа, не локальной отметки. [Пример ACK](receipt-acknowledgement.example.xml) содержит placeholders и не импортировался.

CRPT канонизируется по GS1 AI01/21; компактный табачный профиль — GTIN14+serial7. Исходные сканы сохраняются. Для ЕГАИС хранится полный уникальный код, для иных профилей — отдельное пространство системы. Это локальная идентичность, не проверка криптографии/внешнего статуса. Основания: [GS1 AI](https://www.gs1.org/gs1-application-identifiers), [GS1 logistic label](https://www.gs1.org/standards/gs1-logistic-label-guideline/1-3), [оператор CRPT о табачном КИ](https://markirovka.ru/knowledge/tovarnye-gruppy/tabachniye-izdeliya/sredstvo-identifikatsii-kod-markirovki-i-kod-identifikatsii-kak-otlichit-i-gde-ispolzuyutsya-nsp).
В исходящем XML имена полей образованы из ключей результата в CamelCase; массивы/объекты передаются JSON-текстом с атрибутом encoding=json. Профили принятой агрегации полностью сохранены в RESULT_JSON факта, индексная запись агрегации хранит первичный профиль.
