# wms_twin_3d — 3D-двойник склада и транспорта

Изометрическая 3D-визуализация процессов склада и связанных рейсов в стиле «стратегии» (по механизму WareTrack / NuriTrack). Принципы: [`wiki/concepts/warehouse_transport_digital_twin_principles.md`](../../wiki/concepts/warehouse_transport_digital_twin_principles.md). Страница подпроекта: [`wiki/subprojects/wms_twin_3d.md`](../../wiki/subprojects/wms_twin_3d.md).

## Запуск

```powershell
cd twin\wms_twin_3d
npm install
npm run dev        # http://localhost:5181
```

Сборка: `npm run build` → `dist/` (относительные пути, открывается с любого статического хостинга). Проверка типов: `npm run typecheck`.

Параметры URL:

- `?seed=123` — другой детерминированный прогон симуляции;
- `?source=live` — данные API ТМС, только чтение (прокси `/api` → `http://127.0.0.1:8088`, переопределяется `TMS_API_URL`). Нужен `.env` с `VITE_ADMIN_BASIC_AUTH` (скопировать `.env.example`; файл `.env` в `.gitignore`). Дополнительно: `&ware=ID` — склад (по умолчанию склад с наибольшим числом открытых операций; топология — его последняя опубликованная, как в WMS), `&topology=ID` — явно выбрать топологию для просмотра, `&from=YYYY-MM-DD&to=YYYY-MM-DD` — период рейсов (по умолчанию −2…+30 дней), `&freeSts=0` — не грузить свободные СТ.

## Механизм

```
Источник (TwinSource)            стор (Zustand)                 представления
 ├─ мок-симуляция (src/sim)  ──►  world: TwinState  ──►  3D-сцена (src/scene, useFrame + сглаживание)
 └─ live-адаптер ТМС          tick() 10 Гц             панели (src/hud, KPI из того же состояния)
    (src/adapters/tmsLive)    version / hudVersion /
                              entitiesVersion / stockVersion
```

- **Единый контракт** — [`src/contracts/twin.ts`](src/contracts/twin.ts). Сцена и панели зависят только от него.
- **Модель отдельно от сцены.** Симуляция шагает в модельном времени (1 реальная секунда = 8 модельных на ×1, шаг ≤ 1,5 с), сцена догоняет позиции экспоненциальным сглаживанием на 60 FPS.
- **Детерминизм.** PRNG mulberry32, один seed — одинаковый прогон.
- **События** в духе EPCIS: что / объект / где / почему / кто / источник.
- **Производительность.** Стойки, полки, груз и метки пустых ячеек — InstancedMesh (≈2 900 ячеек — несколько draw call), подписи — HTML-оверлеи drei.

## Что моделируется

Рейсы с бронью ворот и окном дока → въезд, очередь, постановка задним ходом → погрузка или выгрузка → выезд → в пути → доставлено. На складе: отбор СТ комплектовщиками по строкам, контроль, выставка у ворот рейса, погрузка погрузчиками; приёмка, размещение и пополнение ричтраками; зарядка техники. Коллизии: пустая ячейка отбора, затор в проходе, очередь ричтраков, очередь к воротам, машина ждёт СТ, опоздание рейса, низкий заряд.

## Структура

| Путь | Назначение |
|---|---|
| `src/contracts/twin.ts` | контракт TwinState, сущности, события |
| `src/sim/` | мок-источник: геометрия и маршруты (`layout.ts`), справочники (`catalog.ts`), начальное состояние (`seed.ts`), транспорт (`transport.ts`), склад (`warehouse.ts`), коллизии (`collisions.ts`), оркестратор (`engine.ts`) |
| `src/adapters/` | интерфейс источника и каркас live-адаптера ТМС |
| `src/store/twinStore.ts` | стор, такт, выбор объекта, точка фокуса камеры |
| `src/scene/` | 3D: окружение, здание, стеллажи, ворота и коллизии, машины, техника, камера |
| `src/hud/` | верхняя панель с поиском, KPI, поток площадки, карточки, путь СТ, график ворот, журнал КПП, события, таблица рейсов/техники |
| `src/ui/` | форматирование и агрегаты KPI |

## Подключение данных ТМС

Реализовано (14.10.2026, сверено с живым API): топология склада → layout/ячейки/ворота, рейсы → `Trip`, СТ рейсов и свободные СТ → `St`. Правила сопоставления, находки по данным dev-стенда и решения по долгим запросам — на странице подпроекта [`wiki/subprojects/wms_twin_3d.md`](../../wiki/subprojects/wms_twin_3d.md#live-сопоставление-рейсы-ворота-ст--только-чтение).

- [`src/adapters/tmsMapping.ts`](src/adapters/tmsMapping.ts) — чистые функции сопоставления (без сети), их можно проверять на сохранённых ответах;
- [`src/adapters/tmsLive.ts`](src/adapters/tmsLive.ts) — загрузка (только GET), обновление раз в 60 с, статус в верхней панели.

Складские операции (14.10.2026, по [`wiki/requirements/warehouse_operations_digital_twin.md`](../../wiki/requirements/warehouse_operations_digital_twin.md)): задания техники и CASE-сборка → [`src/adapters/tmsOperations.ts`](src/adapters/tmsOperations.ts) в контракт `warehouse-twin-operation/1`, обновление раз в 15 с, вкладка «Операции склада», слой [`src/scene/OperationsLayer.tsx`](src/scene/OperationsLayer.tsx). Без опубликованной топологии с полным покрытием ячеек операции показываются списком «нет на схеме» — требования к головной системе: [`wiki/requirements/twin_source_system_requirements.md`](../../wiki/requirements/twin_source_system_requirements.md).

В live нет машин на дворе и заполненности ячеек: ТМС не хранит состояния двора, а топология — остатки. Это следующие источники (складские задания, ресурсы, GPS, операции рейса).

Двойник никогда не пишет в Oracle и не вызывает мутирующие API.
